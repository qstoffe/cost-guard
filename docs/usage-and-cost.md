# Usage and cost reference

Detailed counting and display contracts for Cost Guard. Start with the [README](../README.md#core-concepts) for the product introduction and core concepts.

## What Cost Guard counts

Usage includes all canonical provider IDs. **CCost** values observed tokens using replaceable GitHub reference rates, independent of subscription/billing. Unknown prices yield partial/unknown CCost, never billed-cost substitution. **Billed** needs reported spend or explicit subscription/zero-billing evidence; otherwise `N/A`. Legacy monetary fallback is not actual billing. A quota credential does **not** prove historical request-account attribution.

**CCost scale:** 1 CCost = 1 GitHub Copilot AI-credit-equivalent of reference value; currently $1 of Copilot reference value = 100 CCost. It is not verified billing or credits deducted from a Copilot account. OpenAI/Anthropic subscription usage can have positive CCost with Billed $0.00. Actual billing, balances, budgets and native quota-to-money information remain monetary.

**Numeric display:** CCost is naked (`437`, `?437`), including Token Mix % parentheses. Exact zero is `0`; positive amounts below 0.1 show `<0.1`; 0.1–<1 use one upward-rounded decimal; amounts ≥1 round upward to whole CCost. Internal Decimal analysis is never display-rounded. Rates/limits preserve source precision without unnecessary zeros. Used AI credits round upward; Remaining and Remaining/day/workday round downward, retaining tenths below 1 (`<0.1` for smaller positives). No quantity uses thousands separators; intentional K/M/B abbreviations remain.

Successful reference/current-price fallback is Diagnostics-only. Missing reference pricing still warns of incomplete CCost, even when actual billing is known.

Date totals de-duplicate exact fork-cloned requests; session views retain available history. Child/subagent work and eligible synthetic continuations belong to their initiating prompt. Model work that OpenCode resumes after a background job (for example a backgrounded shell) ends, or after another invisible synthetic notice such as a subagent completion, stays on the prompt that was running; waiting adds Duration only, never Calls or CCost, and native job IDs are never shown. Only explicit completion/failure/cancellation notices or the service no longer listing the job end that wait. Completed `/compact` remains separate, including native V2 checkpoints without billable summaries. `Calls` counts model requests, not OpenCode assistant records: when one response emits several tool calls, OpenCode V2 may store each further call as a tool-only record with zero usage; it counts only with its response when the same provider response id or, without ids, the absent model latency proves that. Ambiguous zero-usage records still count, and their tools, failures and durations always remain visible.

Reports reflect available history. Watch's `Total today` CCost combines available usage since local midnight with request observations retained for the current process; deletion after observation does not erase it. It cannot recover usage deleted before Watch could observe it, and restarting Watch rebuilds only from then-available history. This is process-local state, not a persistent ledger.

A plain session report is a single snapshot, never an implicit Watch. Active rows retain `[RUNNING]`; their observed token mix and incoming/extra CCost use completed-report definitions and rounding when telemetry, attribution and prices support them. Missing categories make percentages unknown; missing prices never become zero or billed-cost substitutions. Totals include supported running observations, with unknown aggregate diagnostics when active evidence is incomplete. Elapsed running duration uses the report observation clock without inventing completion. Printed output never refreshes; request `<session-id> --watch` explicitly for tracking. Date and Watch modes retain their existing projections.

## Account-period CCost

Normal `Accounts Overview` sections show numeric `CCost today` and a separate `CCost this month`, with rolling CCost beside each existing quota percentage (`5h … 35% (37)`, `Week … 62% (150)`). No separate rolling-cost rows, provenance paragraphs or account footer are printed. Month-to-date uses the configured local calendar month from its first day's 00:00 through now for **all** detected providers, including subscriptions without a native monthly quota. It is not an extrapolation or sum of overlapping windows. History acquisition is independent of the latest-100 model-comparison sample; missing/deleted source history cannot be reconstructed.

Watch uses the same request valuation: `Today: <CCost>` before Remaining on monthly/fixed quota rows; `<percentage>% (<CCost>)` for each duration-bearing window. No month-to-date comparison line appears in Watch. Unknown percentages retain textual `CCost: ...`, never fabricated bars. Both account surfaces use `0` for no observed requests only after the selected period has been acquired, and `—` for unavailable, wholly unpriceable or ambiguous scopes. Account CCost displays the known priced subtotal without a partial marker, using ordinary upward rounding (`37.2` → `38`, tiny positive values → `<0.1`). If some requests lack price data, this subtotal may understate the period's complete reference valuation. Global/prompt/session partial markers are unchanged. A credential's attribution capability alone does not prove available history. Windows can overlap; never add them to estimate disjoint spend. Overall Total today and provider-window figures can differ because scopes and attribution differ.

The **canonical request provider** owns grouping, not the model publisher: GPT through Copilot stays with Copilot; Claude Code subscriptions remain separate from direct Anthropic API. Supported Copilot enterprise and Codex aliases are normalized only for compatible usage grouping. Verified request account references support account-specific figures. With exactly one compatible detected account, otherwise unassigned requests may contribute to a **provider-attributed estimate**, not verified account/billing attribution. Several possible accounts leave unassigned usage unknown; the report explains safely observed provider totals once without copying them to each account. History proven to another account is never reassigned. An API key alone proves no subscription entitlement.

Native reset plus duration defines a rolling accounting interval only while its reset is usable. A provider-proven `not started` window without a reset may show an **observed trailing lookback** (for example the last five hours); this is not a provider-certified quota interval. Missing, expired or inconsistent anchors otherwise remain unknown. Daily/monthly boundaries use the configured local timezone, including DST. CCost is reference valuation, not native quota consumption, remaining allowance or billed spend; percentages, units, resets and Remaining/day/workday retain their independent native meaning.

Watch acquires necessary daily/rolling history after its first useful dashboard in bounded slices and reuses revision-proven analysis. Unchanged quota refreshes query a cached period index rather than initiating history scans or repricing a month. Observed requests survive source deletion within the process-local retained scope; restart can use only then-available history.

### Copilot Unaccounted usage

Each detected GitHub Copilot account in the normal `Accounts Overview` has one `Unaccounted usage` row: **GitHub-reported native AI credits used − canonical deduplicated OpenCode Copilot CCost in the same native period**. This signed reconciliation residual is an **estimate in AI-credit-equivalent units**, not independently metered external usage, verified credits charged, billed cost or an invoice adjustment. Positive values have `+`, negative values are retained, and exact zero is `0`. Only presentation rounds the absolute magnitude upward using ordinary CCost rules (for example `+37.2` → `+38`, `-0.15` → `-0.2`).

The comparison supports a provider-reported fixed monthly reset at the first day, 00:00 UTC; its start is the preceding calendar-month boundary, not a fixed 30-day lookback. Unknown, expired or unsupported reset evidence leaves `—`. History is independently acquired through that start using the existing report scope/index, without a new provider endpoint or polling path. The existing `CCost this month` still uses the configured **local** month, so it can differ from the CCost used internally for this row, including near UTC/local month boundaries and DST.

Missing native used credits, incomplete acquisition through the required start, any unpriceable relevant request or ambiguous multi-account attribution yields `—`, never a fabricated zero or a partial residual. A completely acquired, priced empty period can reconcile to `0`. Native percentages, balances, budgets and limits never substitute for used credits. Copilot aliases and model publishers follow existing provider/account attribution: a sole compatible account may include a non-verified provider-attributed estimate; proven foreign-account requests stay foreign, and unassigned requests are not duplicated among multiple accounts. Existing account CCost can still show its known partial subtotal independently.

Positive or negative residuals can reflect Copilot Code Review or other non-OpenCode consumption, deleted or previously unobserved OpenCode sessions, discounts/reference-price mismatch, or upstream reporting lag. Neither positive nor zero proves whether a review was free. No row is added to Watch, other providers, prompt/session reports or Token Mix.

## Model comparison

Normal reports show Publisher, Model, Relative CCost and Release date. `--all-models` retains the full GitHub catalog and adds `GitHub USD/M I/C/W/O`: original USD per million input/cache-read/cache-write/output tokens, with exact numeric precision, all tiers and current promotions. `→` separates exact tiers; context boundaries remain visible even without an observed comparison mix. `-` means a category has no published rate. This reference column does not change CCost, Watch or quotas.

Relative CCost applies the I/C/W/O token mix of the latest 100 priced completed prompts separately to every published tier. A prompt qualifies when at least one of its requests is priceable (real usage, complete I/C/W/O telemetry and resolvable reference rates for that request's model and tier); only those requests form the mix, and unpriceable prompts are skipped in favor of older history. The normal Token Mix % sample uses the same request rule but also admits running/aborted prompts. All tiers divide by the same cheapest positive comparable **base-tier** price, never a separate long-context reference. Cache-write fallback remains the existing input-rate rule only when the write rate is missing; published zero is zero. No input-only shortcut or arbitrary doubling is used.

For example, `8.0x → 16.0x (>200K)` (illustrative) means eight times the reference at base context and sixteen times above 200000 input tokens. `≥` is inclusive; exact K/M boundaries are never rounded. Additional levels extend the chain. Promotion markers, each multiplier, arrows and boundaries occupy dynamically aligned internal fields; colors are applied after width measurement. Numeric cells remain intact on narrow terminals (the table can exceed terminal width rather than lose prices).

Both modes use one deterministic sorter: descending full-precision base price; for exact ties, descending next-tier price then ascending actual price-increase boundary, repeating for later tiers; alphabetical name last. A missing extra tier means unchanged price, an unknown rate stays unknown, and equal-price tiers introduce no artificial boundary ordering. Multipliers show exactly one decimal; only presentation rounds.

Without eligible token data, Relative CCost stays blank and the existing hidden synthetic 2/96/1/1 mix drives the same sorter. It is never reported as observed Token Mix %. Completed-prompt eligibility, availability filtering in normal reports, full-catalog selection in `--all-models`, promotions, release dates and New Models seven-day eligibility remain unchanged.

### New Models first-sighting highlight

An eligible model name receives bold lime text and a ✦ prefix while `now < first_seen_at + 12 hours`. Report and Watch share one atomic UTC timestamp keyed by the provider-qualified model ID in the Cost Guard SQLite cache; subsequent reports, catalog refreshes and restarts reuse it. Models already eligible when this is first enabled get their first record on their first eligible display. The highlight expires on Watch's live status wake without removing the model. Existing release-date eligibility (and Watch's existing undated-discovery visibility) still controls the seven-day list; expiry never changes release dates, metadata or ordering.

Recognized stable GPT/Claude/Gemini/Grok versions are faded when a numerically newer version of the same manufacturer, family and meaningful variant appears in the current table. Named tiers/families are matched generically, so GPT-6 Luna fades GPT-5.6 Luna and Claude Fable 5.1 fades Claude Fable 5, while GPT-5.6 Terra stays normal without a newer Terra. For xAI's standard Grok names, showing Grok 4.7 fades Grok 4.5 and 4.6, not 4.7. This means only **superseded in this comparison**, not officially deprecated or better. Unknown, preview, experimental and fast-mode names remain untouched. Availability-filtered normal reports and full-catalog reports can intentionally classify the same model differently.

The presentation modifier attenuates each cell's original color independently (including gold promotions and green recent-release segments), adapting to the built-in dark/light themes and resolved custom colors. Borders/headers are unchanged. No model-comparison table rows, rates, multipliers, token mix, ordering, promotion semantics or CCost are changed; New Models notice highlighting is separate. Plain output is byte-for-byte equivalent in information and geometry.

## Account acquisition

Local read-only credential discovery shares OpenCode auth/SQLite reads, preserves per-integration V2 priority, legacy fallback and explicit file-only paths, and never copies credentials into Cost Guard storage. Other supported identities such as Claude CLI remain separate. Presence is a candidate, never proof of a plan or entitlement.

Normal reports overlap analysis with at most four provider jobs and a 15-second final wait. Watch reserves one bounded lane per configured adapter, with 20-second attempt deadlines and no overflow for stuck calls. Failures/timeouts retain unknown/partial/error semantics, never false zero capacity; provider defects use sanitized RuntimeErrors logging.

Watch's first view never waits for HTTPS. Independent start-anchored 30-second healthy refreshes and main-thread one-second publication wakes target ≤60-second visible freshness for whole-provider acquisition ≤20s and responsive local dispatch/rendering. Credential revisions are checked every five seconds; failed credentials get bounded targeted recovery without replaying healthy neighbors as observations. Quotas become stale on error or after 60s and expire after five minutes even without new output. Expired/old-generation replies are ignored, and shutdown discards pending work. [Freshness contracts](account-support.md#watch-freshness-budget) explain external limits and privacy-safe Diagnostics evidence.

Three independent concepts:

- **Usage:** observed input/cache/output/reasoning token activity and requests.
- **CCost / Billed:** independent reference valuation and actual monetary spend. Included subscription work can have positive CCost and zero Billed.
- **Quota / limits:** account-native windows, credits, budgets and availability; provider identity is not account identity.

Reports retain Copilot's native $0.01/AI-credit conversion; Watch omits that conversion/unit. Percentage-only quotas never imply dollar capacity.

## Symbols and token categories

- `I` = **uncached input**, `C` = **cache read**, `W` = **cache write**, `O` = **output** (including separately reported reasoning).
- Token Mix % divides raw counts (`Input`/`Cache`/`Write`/`Output` = I/C/W/O). Largest-remainder rounding selects tenths summing to exactly 100%; trailing `.0` is omitted. Tiny shares may round to `0%`. Incomplete telemetry or zero totals show `--`; no samples show `no token data yet`. Absent fields are not zero. Normal-report and Watch Token Mix % contain only priced requests, so their shares and parenthesized CCost come from one request set and carry no `?`; `--token-mix` keeps all history and partial-pricing markers.
- Category CCost uses each request's model/tier; the four unrounded amounts reconcile with the same requests' CCost. Rounded cells need not sum exactly; `0.4% (24)` is a small but expensive share.
- `~` marks approximate diagnostics (`~Ictx`, `~Ictx CCost`, `~Extra CCost`), never pricing provenance or Relative CCost.
- `?` before a CCost cell means only the priced subset of an all-usage scope (prompt, session, date, `Watch total CCost`, `--token-mix`) is shown. Completely unpriced workloads show `N/A`. Account-specific CCost instead uses `≥…` / `—` as described above.
- Watch shows `CCost · Watch: <run> · Total today: <CCost>`, without a deletion disclaimer in the dashboard. Today uses the configured local date from 00:00; it resets at local midnight without resetting the run total. From 00:00 until 03:00 local time the label is `Total YYYY-MM-DD`. The first daily load may show Pending; later enrichment/failure/recovery holds the last complete same-day publication and atomically replaces it, allowing legitimate corrections downward. Midnight starts a new scope, never yesterday's value relabeled. Existing CCost rounding and incomplete-pricing markers apply.
- `N/A` means unavailable.
- A trailing `*` on a model means linked child/subagent work used an additional model.
- Watch's numbered `*1`, `*2`, ... context-warning markers follow `Next Ictx` on each displayed session's latest relevant row and point to the shared footnotes below the table. Markers and footnotes reflect only current visible warnings.
- Watch uses `▶` for each running prompt and in a session header while any prompt in that session is running; the marker remains until that prompt stops. Existing `✓` completion and `!` abort/error markers keep their own lifecycle.
- `Δctx -> Next Ictx` describes approximate effective context, not billed-token volume: historical completion state on completed rows, continuing state on live rows.
- Request usage and continuing context are separate: every completed request contributes its own I/C/W/O, Calls, CCost and billing evidence. Next Ictx follows the best-supported persisted active history, so a smaller outgoing request does not by itself replace the continuing anchor. The V2 active-context message view distinguishes undo/redo history from requests retained only as historical usage; completed compaction remains an explicit shrink boundary.
- If active history cannot be established, an unexplained same-model request-context decrease is shown as unknown. The estimator is approximate: the active-message API does not expose exact tokenization of hidden system/tool content or future provider/runtime request rewrites.
- Watch reserves warning-marker space inside its fixed 20-character context cell. Delta, arrow and Next Ictx positions remain stable from no warning through `*99`; warning count does not widen the table.
- A Next-Ictx price-threshold warning shows `(Nx more expensive)`: the model's Relative CCost level after that threshold divided by the level before it, from the same sample/mix as the model table and rounded to one decimal. Without a priced tier ratio it keeps the `(Next Ictx CCost low–high)` range.

## Continuing context and history changes

An actual request's input/cache/output/reasoning usage remains the source of Calls, Token Mix, request CCost and billed-spend provenance. `Δctx` and `Next Ictx` are a separate, approximate estimate of the persisted active conversation carried into an ordinary next request. Before v80.52, a final request-local context replacement could become the sole anchor: a tiny real dispatch then replaced a much larger preceding context estimate. Now an active-history anchor remains usable only when the normalized request and V2 active-message evidence remain comparable; stored user/tool/model output after that anchor is included where available. Every small dispatch remains counted and priced from its own telemetry.

OpenCode V2 exposes `GET /api/session/{sessionID}/context` as active message history after the last compaction, alongside the all-message route used for historical accounting. The projection lets Cost Guard recognize that reverted messages are no longer active without deleting their historical model requests. `/undo` stages a boundary, `/redo` clears/restores it, and committing a revert changes the active view; these controls do not create a model call or a billed row. Forks use a distinct session identity.

Completed prompts and compactions keep context estimates supported at their completion, independently of eligibility for the **current next request**. A later model/effort/agent selection or location move does not erase the historical estimate. Better authoritative evidence may refine it; these are not frozen snapshots or exact provider payload measurements. Current continuation and price warnings still lose invalidated anchors until a qualifying request establishes a new one. Historical values do not revive obsolete warnings.

Historical deltas compare effective states from the same session. Across an effort-selection boundary, comparison requires the same provider/model, complete retained message history through the new request and complete compatible input/cache/output telemetry with no unexplained input decrease. Otherwise a qualifying prompt starts from its own observed incoming context, not an unrelated old epoch. Unknown rewrites, removed or incomplete history and unsupported decreases yield `N/A` where a value or comparison cannot be defended. Missing counters are not zero. Compaction alone owns its explicit reduction; accounting, Calls, Token Mix, CCost and duration are independent.

Completed manual and automatic compactions remain explicit events: the compaction row owns the negative delta, and a following prompt compares with the post-compaction estimate. In-progress or incomplete compaction does not establish a result baseline. The active-message projection does not expose exact tokenization of baseline system instructions/tool definitions or silent provider/runtime rewrites. Such hidden changes cannot be independently distinguished when they leave no active message or boundary evidence; Next Ictx is therefore an approximate persisted-history estimate, not a promise of the exact next provider payload. Missing active-history or usage evidence and unsupported history changes remain unknown; absence of a compaction record alone is not proof that history stayed unchanged.
