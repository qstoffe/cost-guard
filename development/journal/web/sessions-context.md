## Source and lifetime

`context_fields` in the scalar-summary owner selects the latest non-subtask prompt
of the root session, then uses `session_watch_context` and `ContextEpochs` just as
Watch's session guidance does. Later compaction supersedes earlier requests; model,
reset, move and active-history boundaries cannot revive retired context. Running
root/tool steps and explicitly labeled provisional text estimates remain canonical
estimates, not exact future measurements. Completed/archived roots use the current
continuation anchor, not a maximum, prompt-input field or sum of prompt sizes.

Complete same-provenance/revision snapshots qualify a numeric scalar or a known
unavailable anchor. Compact/partial evidence cannot finalize a CTX global sort and
repeated partial reads use existing bounded failure/Retry handling. Algorithm 3
invalidates only old disposable session summaries; unrelated analysis caches stay
usable. Running/active roots bypass persistent scalar reuse. Changed revisions clear
obsolete CTX before preparing display tokens; same-revision outages can retain a
muted, accessibility/help-labeled estimate. Proven zero renders `0`.

CTX shares the existing whole-catalog numeric comparator, ID tie breaks,
unknown-last policy, requested/applied sort contract, progress, cancellation,
recovery, four-root/two-second admission slices and stable 50-row epochs. Merely
displaying Activity/Name or another page does not request unvisited histories.
Header touch help shares the sort button; row nodes and help targets are retained.
