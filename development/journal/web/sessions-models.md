# Sessions main model and role help — FR000698

## Delivered behavior and boundaries

Web Sessions uses the latest request-bearing main prompt, not the largest-CCost
contributor or last child/compaction completion. A saved selection without executed
request evidence cannot replace it. Canonically absent main evidence stays N/A or
pending; known children are never relabelled as main. Confirmed distinct recorded
provider/model selectors across the same root tree produce the trailing star.

`reports/session_models.py` derives first-observed, role-separated model facts from
existing canonical requests and same-root ancestry/positive compact child links.
Provider-qualified identities remain distinct even when their friendly labels or
effective pricing model coincide. Each role has deduplicated bounded entries; the
union keeps the existing 64 identities / 256-character identity bound. Effort facts
are bounded per identity, and prepared help is capped below 32 KiB with explicit
omission/coverage qualification. Running, partial, compact-only, missing-role,
unknown-model and truncated evidence never becomes exhaustive final coverage.

`application/model_help.py` prepares heading/bullet paragraphs, recorded aliases,
labelled current-catalog estimates and applicable ordinary default-effort copy.
Only a known role gets a heading; a shared model appears in both role lists.
Existing ContextHelp owns all interaction, safe text rendering and open-help refresh.
No hover acquisition, additional icon or native title is introduced.

The Model comparator uses the main model label, independent of the star, with
existing ID ties, unknowns last and selected-period key qualification. Page size,
leases, epochs, retained/pending states and the separate Effort comparator are unchanged.
Scalar algorithm `session-summary-6` rejects role-less/malformed/old records and
rehydrates the affected root; alias/default-effort dependencies remain checked.

Only the scalar Web catalog requests the new model selection. The existing finite
CLI session-list representative, Watch/Mini, Session detail, canonical accounting,
token totals, CCost and source acquisition policies remain unchanged.
