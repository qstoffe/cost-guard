## Causal design and changes

Compared cosmetic fixture cleanup, increasing timeouts/workers, caching old PASS,
automatic per-feature selectors and a simple partition using existing tooling.
The latter removes actual standard-release work without another orchestrator:

1. `run_tests.py`: explicit 52-group unit/component Quick foundation, including
   the focused CI-selector regressions. All original 181 Full selectors are
   retained exactly once; 123 formerly Quick integration
   groups move to Full-only alongside the original six. HTTP servers, real child
   jobs/cache restarts, Node VMs, native launchers, mutation and scale checks are
   not ordinary Quick work. Existing focused patterns/profiles remain usable.
2. `ci_web_beta.py`: ordinary PR/push selects Quick plus the existing package
   validator; explicit `workflow_dispatch` selects Full. Summary requires the
   exact applicable Quick/Full report and complete counts. No fallback from
   missing Full evidence to Quick, no cached/relabelled old-head results.
3. `web-beta.yml`: keeps Linux Quick/validator, Chromium setup/smoke and honest
   scoped summaries for cumulative product/test/tool/workflow paths. Browser
   smoke is retained, not replaced by Node VM assertions.
4. `native-web.yml`: moves the existing native job intact to its own path-triggered
   workflow. Native modules, Web host/security/jobs/composition/Live, entry/config,
   launchers and native fixture/test/tool changes remain conservative triggers.
   Isolated assets and ordinary analysis/application calculations do not trigger.
   `web/benchmark.py` remains included because host construction owns that lane;
   only its pure application projection is excluded. Fixture-wide trigger is
   conservative, not a claim that every fixture is native. Renames/deletions follow
   GitHub path-filter semantics; the same anchored path set covers PR and push.

No native platform, phase, public-hosted-only guard, cancellation, real process
identity/cleanup, permission or Git protection is removed. No new runtime module,
dependency, scheduler, wrapper, permanent speed gate, test-addition approval,
watchdog, paid benchmark or telemetry store. Existing deadlines are unchanged.

### Protection trade-off and route limits

No product-behavior tests/assertions are deleted; CI-selection assertions follow
the intentional new route. **Universal ordinary hosted execution of the
129 Full-only groups is intentionally retired**, and native CI is no longer
unconditional. Their unique integration/process/security regressions may therefore
escape the smaller ordinary CI selection; Full, manual hosted Full, focused
development checks and risk-triggered native validation retain those protections
when executed. This is Test Health's authorized portfolio trade-off, not equivalent
Quick coverage or a waiver of actual production safeguards.
