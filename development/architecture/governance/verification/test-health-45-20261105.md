| Input (four requests/prompts) | Old one-second assertion | Actual outcome |
| --- | --- | --- |

false-positive mechanisms, **not which mechanism caused any particular CI run**.
No product performance regression, provider outage or safety denial was inferred.

## Replacement and retained risks

Keep the same four-root real-HTTP case and exact one-catalog/four-request/four-prompt
expectations, but fix only the V2 module's catalog-age clock for this fresh-batch
scenario. Real transport timeouts and performance measurements are not mocked.
Run acquisition synchronously; remove its test-owned thread, two Events, artificial
three-second hold, one-second SLA and four-second join. The ordinary outer 25-second
file bound still rejects a hang. This narrows the test to its intended invariant,
not a longer product timeout or an exception to a locked gate.

The unchanged 64-root companion still charges two seconds per actual full-catalog
fetch, requires all 64 requests/prompts, <=34 fetches and <=120 modeled seconds.
`test_source_history_loading.py` separately retains fresh-cache reuse, expiry
refresh, shared authoritative brackets and changed-tree-only retries. Other process,
shutdown, cancellation, authentication, privacy and source-loss tests are untouched.

Before/after: two Daily tests and identical Quick/Full/CI fanout. The second test
owns zero rather than one extra worker and zero rather than two Events. Removing
these coordination paths is demonstrated simplification, not measured project-wide
time/human-effort savings. No assertion about exact prose/internal file shape replaces
behavior; no new permanent test framework or evidence registry is added.
