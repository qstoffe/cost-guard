# Cost Guard development

Everything in this directory exists to design, maintain, test, validate and (locally) package Cost Guard. Runtime code under `src/` MUST NOT depend on development-only files. Root `AGENTS.md` is the first-stop router for a fresh AI coding session.

- **Implement/change:** read `MAINTAINER.md` first, then the active task/FR and `ARCHITECTURE.md` when boundaries are affected. Hosted/web AI uses only `python development/tools/run_tests.py --suite quick` plus `python development/tools/validate_package.py --working-tree` and never builds an archive. A local workstation session runs Full + validation + read-only live checks and then builds the ZIP for every completed feature, fix or version. Both hand off the authoritative working tree. Never commit or push automatically unless the user explicitly authorized Git commit, push, PR or merge through the current task or a development workflow they started; then follow [authorized Git delivery](MAINTAINER.md#authorized-git-delivery), which permits an isolated repository clone and builds no local ZIP unless packaging is requested.
- **Packaging:** `development/tools/build_release.py --full-verification` runs locally per completed version and for explicit requests (packaged ZIP, release candidate, GitHub/package release or archive handoff). See [packaging procedure](MAINTAINER.md#packaging-procedure); the builder retains its selected-tier, inventory, clean-extraction, executable-mode, exclusion and SHA-256 checks.
- **Brainstorm/design/Feature Requests:** read `FR_GUIDE.md`. Discussion does not modify Cost Guard until explicitly authorized and never builds a ZIP.
- **Architecture:** `ARCHITECTURE.md` owns runtime layering, dependency direction, source/provider contracts, cache ownership and Watch ownership.
- **Code navigation/evolution:** [CODE_MAP.md](CODE_MAP.md) maps responsibilities, feature placement and tests; [REFACTORING_REVIEW.md](REFACTORING_REVIEW.md) records the current inventory/refactor and proof limits. `python development/tools/code_inventory.py --json` emits a read-only AST map. `run_tests.py --profile structure` covers extracted contracts and growth/navigation guards.
- **HTTP account providers:** `simple-http-accounts.md` owns maintained definition/mapping limits, network/credential safety, provider evidence and extension guidance; complex providers stay first-class adapters.
- **Budgets:** `file-budgets.json` is the machine-readable authority for design warnings and hard file caps.
- **Growth ratchets:** `structure-policy.json` bounds routine statements/branches and seals legacy test-import edges. The validator rejects new coupling, unexplained growth and stale debt; it never writes/accepts a new baseline. Do not enlarge limits/exemptions to accommodate a feature; split its real responsibility and add focused tests.
- **Fixtures:** `fixtures/` owns deterministic synthetic non-secret inputs and reusable session/pricing/runtime builders. Import common setup there, not from another test module; fixtures never import tests and production never imports development code.
- **Tools:** `tools/` contains the stdlib-only test runner, release validator and release builder.

The exact filesystem state at the start of an implementation request is authoritative. Git history is never an automatic restore baseline. Current `main` is the recommended/latest supported distribution; packaged GitHub Releases are currently paused during rapid development. Every PR merged to `main` must include the sequential version bump, matching release date/history/README and affected current docs, including documentation-only and behavior-neutral work; verify against the latest base before merge ([versioning and history](MAINTAINER.md#versioning-and-history)). Versions do not require tags or GitHub Releases; local ZIPs follow the environment rule above, never a version number alone. Reversing this distribution policy requires an explicit decision, not a version threshold. Remote release changes need separate explicit authorization; retain the historical v80.0 tag unless its deletion is requested.

## Bounded test profiles and real-environment diagnostics

`python development/tools/run_tests.py` defaults to the bounded **Quick** suite; focused `--profile`/`--pattern` runs are available and `--suite full` is the unrestricted/local tier. `development/tools/collect_diagnostics.py` is the supported privacy-conscious environment collector for user machines and runs Full + distributable-view validation by default with progress; `--skip-validation` is for recursion/emergency diagnostics only. It must never include prompt text, session titles, auth tokens, raw auth files or raw OpenCode payloads.

Every `tests/test_*.py` module must match exactly one Quick/Full-only pattern in `tools/run_tests.py`, or have an exact relative path and reason in `EXCLUDED_TEST_MODULES`. The runner rejects missing, overlapping or stale assignments before executing any suite/profile/pattern.
