# FR 0160 — Clearer Codex quota sign-in hint and compact account CCost presentation

## Problem and intended result

After FR0140 (account-period CCost, Cost Guard v80.74) and FR0150 (method-aware OpenAI quota retrieval, v80.75), the core behavior is substantially better but **the text presentation is unnecessarily long and sometimes misleading**.

- A valid **OpenCode V2 "Sign in with ChatGPT"** / `chatgpt-token-sharing` connection can run OpenAI models, but Cost Guard cannot currently obtain **Codex subscription quota** through that token-sharing method. The new account message says model authentication is separate, without telling the user what *currently supported* OpenCode sign-in method actually works for reading the Codex quota. The owner eventually discovered a different method only by asking another AI.
- Report and Watch render `N/A` for **CCost today** in cases where the account had *no observed usage today* and the true display value should be **0**. This is especially visible on monthly-quota Watch account rows.
- The account-specific CCost/AI-credit figures sometimes show prefixed `?` partial-price markers; the owner does not want any question marks under account sections.
- The ordinary `Accounts Overview` prints verbose CCost provenance/period explanation rows per account (`CCost today: configured local calendar day; ...`, `CCost this month: ...`, `CCost 5h: native reset window; provider-attributed ...`, etc.), separate `CCost in 5h/Week window` rows, and an oversized final general paragraph beginning `Account CCost values available observed requests only...`. This bloats the report and duplicates CCost that can fit on existing quota progress-bar rows.

**One self-contained presentation FR** covers both the OpenAI hint and compact account CCost. This request does not reopen FR0140's period accounting, FR0150's credential routing or their original broader implementation.

## Evidence and specific current owners

- [FR0140 completed implementation](https://github.com/qstoffe/cost-guard/blob/main/development/backlog/complete/000140-watch-ccost-per-subscription-and-stable-today/COMPLETION.md) added independent today/month/rolling-window CCost and Watch percentages `(<CCost>)`, with the normal report retaining explanation notes. Account windows/attribution stay separate from native quotas and billing.
- [FR0150 completed implementation](https://github.com/qstoffe/cost-guard/blob/main/development/backlog/complete/000150-fix-chatgpt-quota-auth-method-with-local-validation/COMPLETION.md) verified **on the actual affected Windows OpenCode V2 installation** that the active valid `chatgpt-token-sharing` credential uses the OpenAI API resource, whereas the legacy Codex WHAM quota endpoint requires different credentials. No compatible read-only quota source was found for that installed token-sharing method; model sign-in itself was not broken. Historical 401 server cause is not claimed proved.
- `src/accounts/openai_subscription.py` currently defines `TOKEN_SHARING_REASON` as `OpenAI quota unavailable for this sign-in method (ChatGPT token sharing); model authentication is separate.`; unknown methods have separate fallback, and legacy `chatgpt-browser` / `chatgpt-headless` are the supported WHAM path. API-key credentials do not establish a **Codex subscription** quota.
- `src/reports/accounts.py::_period_scopes` can currently return `None` for an empty CCost period when account-level usage attribution is not complete, causing `N/A` even when the owner expects known zero. Separately `src/presentation/token_mix.py::comparison_cost_text` already formats a known empty observation as `0`; distinguish the absence of attributable activity from truly incomplete history.
- `src/presentation/report.py::_render_accounts_quotas` emits `account_ccost_lines(account)` **before** `capacity_lines`, then prints the long `Account CCost values...` prose. `src/presentation/accounts.py::account_ccost_lines` appends `account.ccost_notes` and separate 5h/Week numeric rows. `quota_parts` already supports `(<CCost>)` after a progress percentage, but `account_capacity_parts` passes CCost there **only when `watch=True`**.

These are public source-derived observations; no personal session, subscription credential, screenshot or Diagnostics archive should be committed.

## 1. Actionable OpenAI authentication hint

1. When the *actual known reason* is `chatgpt-token-sharing` (or equivalent classified token-sharing scopes), display a clear, **actionable but concise** account message in **both normal report and Watch**. State that authentication for model requests and access to **Codex subscription quota** are distinct; successful model prompts do not mean this quota endpoint is accessible.
2. Name the OpenCode options accurately, with their UI labels or closest current installed equivalents: **`Codex browser (legacy)`** and **`Codex device code (legacy)`** (supported legacy `chatgpt-browser` / `chatgpt-headless`) can currently be used for *Codex quota retrieval*. `Sign in with ChatGPT` (token sharing) and **API-key sign-in** do not currently provide Cost Guard with that **Codex subscription quota**. This says nothing about API-key billing/usage APIs or whether model requests work.
3. Proposed wording, to refine against actual width/readability before implementing (illustrative, not an immutable literal):

   > Codex quota unavailable with Sign in with ChatGPT. Model access and Codex quota access use different authentication. For quota display, use Codex browser (legacy) or Codex device code (legacy) in OpenCode for now. API keys also do not provide Codex subscription quota.

   A shorter Watch version may omit redundant words, but must retain **the useful method hint**; the ordinary report may show the complete explanation. Do not render the same advice twice in one account block.
4. Present the supported legacy methods as **currently compatible for attempting quota lookup**, not as a guarantee of a 200 response, current plan availability or future permanent workaround. Avoid saying that the user's OpenCode account is logged out, revoked, needs reconnection or that models are broken merely because this separate quota method is unavailable.
5. Only show the method-specific guidance when **method identity is established**. Preserve truthful separate behavior for unknown future OAuth methods, rejected legacy WHAM 401, 403, 429, expired tokens, inaccessible API accounts and other providers. No automatic provider/account switching, token refresh, sign-in, unknown endpoint, secret logging or OpenCode auth/database mutation. Report and Watch retain aligned compact wrapping, warning styles and sanitized Diagnostics.

## 2. Known zero CCost versus genuinely unavailable data

1. For an account with **no observable requests in the selected, sufficiently established period**, `CCost today` must show **`0`**, not `N/A`. Apply in both the **normal report** and **Watch**, including the `Today: 0` field before Remaining on monthly/fixed quota bars. The same known-empty principle applies to 5h/Week/month-to-date account period CCost where the selected period is actually available and contains no usage. Numeric zero must not depend on which provider/account type is being rendered.
2. **Do not fabricate zero** for a missing/unavailable/incompletely observed history, unknown attribution among multiple compatible accounts, absent period boundary, wholly unpriced usage, a failed acquisition or genuine unknown account source. Prefer a compact neutral **`—`** (or equally clear non-question-mark unavailable marker) under account-specific CCost for those cases. Distinguish no observed usage over a known/available period from inability to establish zero; source gaps and account ambiguity must remain honest.
3. **No `?` prefix or question-mark numeric placeholder anywhere in account-specific CCost or AI-credit/quantity displays** in either normal report or Watch. For a genuinely *partially priced* known CCost amount, use a compact non-question-mark lower-bound notation such as **`≥37`**, or a similarly accurate marker. Do not present `37` as a complete CCost when some observed requests were unpriceable. Keep native quota percentages, credits, capacities, units and billing distinct; avoid converting missing native credits to zero.
4. This is **account presentation scope**, not permission to remove `?` from unrelated prompt/session/global CCost summaries where it currently signifies partial pricing. Prefer one account-specific formatter with clear partial/unknown/zero semantics rather than changing `comparison_cost_text` globally and accidentally losing information elsewhere.

## 3. Compact normal Accounts Overview

1. **Remove the verbose per-account explanatory prose** produced from `account.ccost_notes`, including `CCost today: configured local calendar day...`, `CCost this month: configured local calendar month...`, `CCost 5h/Week: native reset window; provider-attributed...`, and `period boundary unknown` notes. Do this for **all providers/accounts**. Their descriptions and provenance contracts may remain in `docs/usage-and-cost.md`, but must not be printed per-account in the normal report. Keep needed uncertainty visible compactly in the numeric value, never by silently assigning unknown provider usage to a specific account.
2. Move the **actual CCost 5h and Week numeric amounts** from separate `CCost in 5h window: N` / `CCost in Week window: N` report rows to **the same row as the corresponding native quota bar/percentage**. Use the Watch grammar `5h ███░░ ... 35% (N)` and `Week ███░░ ... 62% (N)`, independent per window, retaining native usage/remaining/reset information. No duplicate standalone CCost line for a window when it has been rendered inline. If there is no percentage/bar, use a compact meaningful textual CCost next to that same window rather than inventing a bar.
3. Keep the **actual numeric** `CCost today: N` and `CCost this month: N` in the normal report when they serve distinct scopes and have no equivalent inline placement; these are useful **values**, unlike their extra explanatory paragraphs. Month-to-date remains separate from overlapping 5h/Week windows, and must **not** be introduced into Watch. Do not delete a distinct useful numeric scope merely to save a line.
4. Remove **the entire final explanatory paragraph** beginning `Account CCost values available observed requests only:...`, including `Overlapping windows must not be added`, history availability and partial-pricing prose. Do not replace it with another global footer, legend, footnote or repeated per-account note. Retain semantic explanations in documentation only.
5. Preserve the existing provider/account ordering, responsive account bars, percentage labels, reset time, native credits, balances, billed amounts, status/recovery warnings, entitlement boundaries and alignment at narrow/wide Windows terminals (both ANSI and plain text). The report's scope/attribution calculation must not change inadvertently. Remove unused explanatory field/render paths if safe; do not create a new presentation framework.

## 4. Keep Watch compact and truthful

- Watch already places rolling CCost in parentheses after percentages; preserve that location, applying the same known-zero/non-question-mark formatting across all supported accounts.
- For monthly/fixed quotas use `Today: 0` on an established no-usage day, otherwise a correctly rendered real known/partial/unavailable value; keep its placement before `Remaining`.
- No extra verbose account footnotes, extra month-to-date rows, duplicate explanatory prose or additional polling. Preserve existing responsive compact/split/vertical layout, startup nonblocking behavior, same-day `Total today` publication, provider quota acquisition, Window resets and refresh frequency.
- Rendering changes are **not** authorization to broaden account histories, cause expensive periodic rescans or conflate CCost reference value with API credit consumption or actual invoicing.

## Acceptance and proportionate verification

- **Method hint:** fixtures for token-sharing, legacy browser, legacy device, historical methodless Codex, API key, unknown method and legacy 401. Both surfaces give clear *applicable* guidance only for the right case, with the two legacy UI options and for-now qualification. No login side effects, credential leakage, new quota calls or incorrect promises of quota success.
- **Zero/unknown/partial:** today/month/5h/week with zero observed requests and a known observable scope render `0`; unpriced observed requests, partial pricing, unknown multi-account attribution and absent window/history never become fake zero. No `?` appears inside either account presentation for numeric CCost/AI-credit fields; partial values retain honest lower-bound information. Prompt/session/global partial-cost displays remain unchanged.
- **Compact report:** a synthetic account with both 5h and Week displays the correct distinct parenthesized CCost on **the existing quota-bar rows**, no duplicate `CCost in ... window` rows, and still retains separate numeric today and month where applicable. Zero extra `CCost ... configured/local/native reset/provider-attributed` prose rows and zero `Account CCost values available observed requests only` footer. Single-account and ambiguous multi-account cases remain accurate.
- **Layout:** ANSI/plain, 80/120/160-column rendering, multi-account reports, genuine unavailable quota and shared Watch horizontal/split/vertical layouts; no clipped native credit, reset or actionable quota message. Use existing provider-neutral render/projection tests rather than a new mandatory validator.
- Verify with existing targeted account-period CCost/account-presentation/OpenAI method tests and **only the repository's applicable existing shipped-source checks**. No paid model calls, credential changes, separate live authentication test, new permanent release gate or extra user approval is necessary for this visual/presentation FR.
