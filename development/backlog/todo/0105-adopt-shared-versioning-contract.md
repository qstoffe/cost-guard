# FR 0105 — Adopt Toolkit-owned versioning and retire Cost Guard's duplicate policy

## Problem and dependency
Cost Guard still has its own generic version-history rules in the large development maintainer/authoring material, overlapping but not identical to the Toolkit contract. New repositories should get the same predictable policy after `/repo-init` without each product copying the rules. This request is a local **adoption/migration** after Cost Guard FR 0100, and depends on delivery/installation of the Toolkit's shared release-policy FR 0175 and portable /repo-init infrastructure. If those dependencies are unavailable, report BLOCKED and leave this request pending. No future implementation release number is specified here.

## Required migration
- Make the currently installed, versioned **OpenCode Toolkit shared release/versioning contract** the single procedural authority for `/repo-backlog`, FR publishing and Toolkit maintenance applied to Cost Guard. Remove every competing **general explanation of how to number releases and maintain/roll up version history** from Cost Guard's `development/MAINTAINER.md`, `FR_GUIDE.md`, README/development routing and any copy of generic procedures that survived FR 0100. When FR 0100 already retired the file, do not recreate it just to remove instructions. Do not paste a replacement mini-policy into another Cost Guard document.
- Keep only genuinely **Cost Guard-specific facts/adapters**: source-of-truth version constants in `src/version.py`, `VERSION` / `RELEASE_DATE` and runtime/Diagnostics display, root README current product version, its real `VERSION_HISTORY.md` and existing validator limits, its actual distribution status (GitHub source distribution, no automatic release ZIP/tag) and product safety constraints. A short local development README may point by precise name to the Toolkit contract and explain the local metadata file mapping; a link is not a second normative rulebook.
- Reconcile the then-current Cost Guard and Toolkit histories **as policy input only**. Preserve Cost Guard's real historic entries and major baselines, and Toolkit's separate history; do not paste one product's actual release log into the other, backfill invented deliveries, renumber prior tags or change released behavior. Deliver this PR with the normal current source-derived version update specified by the newly shared central policy.
- Migrate local source/test/validator routing to the common contract without weakening Cost Guard's Python/Watch/account privacy, read-only OpenCode source boundary, branch protections, test scope or version-history file cap. Different repo-specific dates/display labels are a metadata adapter decision, not a reason to fork general versioning instructions.

## Acceptance and verification
- With Toolkit present, Cost Guard's next genuinely merged documentation-only/ordinary/maintenance delivery uses the same central release algorithm as a synthetic Toolkit repository but updates Cost Guard's real metadata paths, README/history and accurate evidence.
- Synthetic missing-Toolkit, stale-HEAD, aborted/unmerged, concurrent delivery and authorized 'new major' cases either succeed under one central rule or fail clearly without reserving/inventing a version.
- Static search demonstrates there is **one** normative shared procedural owner, and Cost Guard retains only product-specific metadata facts/links. Old history and real product source remain intact.
- Relevant deterministic version/metadata checks and current Cost Guard Quick/Full/validator gates follow the actual environment. No new third repository, no broad product code rewrite and no weakening of mandatory protections.
