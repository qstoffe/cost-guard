# FR 000525 — Show quota Used / Total and used-oriented progress consistently in CLI and Web

## Owner decision and observed problem

GitHub reports monthly Copilot AI-credit consumption as **Used / Total**. An actual comparison on 2026-10-28 showed GitHub **5,608 / 25,000 used** while Cost Guard rendered a 78% remaining bar with **19,392 / 25,000 remaining**. Both were numerically correct, but the opposing conventions led the user to suspect an accounting error.

The owner explicitly accepts a deliberate **breaking presentation change**: where a quota has a meaningful consumption denominator, the main bar, percentage and native fraction should all be **USED-oriented**, like GitHub. Keep the separately named **Remaining** per-day / per-workday pace as a distinct forward-looking measure. This replaces the earlier FR's remaining-first design; do not implement the old semantics by adding labels alone.

FR000490 already covers the Web Accounts layout; FR000190 covers the independent Copilot Unaccounted-usage estimate. This FR changes quota presentation consistently, not provider acquisition, billing, CCost valuation or account attribution.

## Required user-visible behavior

1. **A known finite quota shows Used throughout the primary indicator.** For GitHub Copilot and other quota windows that truly measure consumption against a defined capacity:
   - The filled portion of the progress bar is **used fraction**, not remaining fraction. The displayed percentage is **% used**; the displayed numeric fraction is **used / total**, not remaining / total. Under the same scope/window, the three must agree.
   - For example, 5,608 used of 25,000 gives **22% used**, **5,608/25,000 AI credits** and a bar with about 22% filled. Its complement, 19,392 remaining / 78%, may still inform genuinely remaining-specific calculations but must not be shown as the unlabeled primary fraction/bar.
   - In the full CLI Normal report and detailed Web Accounts, explicit `Used` labels and available units may be repeated for readability. In compact CLI Watch, use a single short `used` marker that unambiguously applies to both percentage and native fraction. *Illustrative, not mandatory character geometry:* `Month  ██░░░░░░░░ 22% used · 5608/25000 AI credits`. Preserve the existing reset, warning and native-money information where applicable, and keep the compact row as close to its current width as practicable.
   - Use the same used-oriented convention for finite quota bars in CLI Watch and Normal and Web Accounts/Watch; do not leave one view or provider inverted without an explicit, justified different capacity type.

2. **Remaining pace stays Remaining.** Existing `Remaining: X/day · Y/workday` indicates how many native credits can still be spent per day/workday through the reset. It must retain its current remaining-derived semantics, exact scope and calendar and its explicit `Remaining` label. Do not turn it into daily spending or confuse it with `Used`. Its presentation alongside a used-oriented Month bar is an intentional, clearly named exception.

3. **Watch has a strict space budget.** Retain ten-cell compact bars, existing alignment/wrapping/splitting and terminal-width fallbacks (including 80/120/160 columns). Prefer **one** `used` indicator adjacent to the percentage, not duplicated `Used` prefixes on the same line. Do not drop a critical reset/status, hide an account, truncate native counters, or create a much wider line to achieve the new labels. The normal report can be more explanatory. Keep account ordering and other Watch geometry.

4. **Unlimited subscriptions remain informative without fake capacity.** If the provider explicitly says a quota is unlimited, show `Unlimited` and any **provider-reported native used amount for the period** (e.g., `Month Unlimited · Used 5608 AI credits`) even without a total/denominator. Show no consumption percentage, filled progress bar, `Used/Total` ratio, or `Remaining X/day / Y/workday` pace when no finite remaining capacity exists. Do not suppress a valid native used amount merely because the plan is unlimited. If used is absent, label it unknown or omit that numeric field; `Unlimited` does not imply zero usage.

5. **Today is a separate measurement, not automatically native Used today.** Where a provider actually reports today's native used credits with a trustworthy daily window, display that as `Used today` (including on unlimited plans). However, Cost Guard's current `CCost today` / compact `Today` derives from observed OpenCode request pricing and is a **reference valuation**, not GitHub-reported credits used today. Keep showing that independent value on unlimited as well as finite subscriptions whenever available, but label/define it sufficiently as **CCost today** so it is never falsely presented as native `Used today`. No inference of GitHub's daily native consumption from monthly credits, CCost, or remaining pace; no new provider endpoint/API call for this FR.

6. **Keep monetary equivalents aligned with their labels.** The current Copilot report can show `remaining_money/limit_money` alongside remaining credits. After switching the native fraction to `used/total`, a visible dollar-equivalent fraction must also represent **used/total** when the provider's established AI-credit dollar equivalence supports it (example `$56.08/$250.00` for 5,608/25,000 credits), or be explicitly labeled `remaining` if it remains a separate remaining-specific fact. Never place an unlabeled remaining-dollar fraction next to a used-credit fraction. Preserve native-currency semantics, no generic FX or invented amounts, and never call this actual Billed spend. FR000526's optional CCost unit choice is independent and must not convert native quotas, balances or bills.

7. **Respect source capabilities and account status.** Only display absolute `Used/Total` when both belong to the same authoritative native quota window with a trustworthy denominator. An explicitly reported remaining percentage may be complemented to a **used percentage** only when it genuinely represents the remaining share of that finite quota; do not fabricate absolute used counters from percentages or unrelated spend. Preserve unknown vs zero, unavailable/partial/stale, unlimited, exhausted/blocked, not-started/expired, overage, missing reset and multiple-account cases. For native balance/spend surfaces lacking a meaningful quota capacity denominator, retain their correct textual units/status; do not manufacture a consumed-capacity bar. Colors and warnings must continue to represent *risk of exhaustion* correctly despite the reversed fill direction: 100% used is exhausted; 0% used is unused, not a critical state. Color is supplementary to explicit status text.

## Implementation boundaries

- Treat `remaining_fraction` and canonical quota/provider projections as the existing source of truth; derive used-oriented presentation from trustworthy underlying fields or verified complements in shared Python/report display primitives. Do not invert or rewrite stored provider telemetry, quota retrieval rules, calculations, Pace/Remaining, threshold detection, scheduling, or Watch acquisition.
- Reuse common presentation/report projections for CLI and Web; the Web must not invent its own provider-specific quota computations or silently change report periods. Keep authentication, historical/account attribution and privacy unchanged.
- Preserve `CCost` (reference valuation), `Billed` (actual monetary evidence), `Unaccounted usage` (comparison residual) and native `Used` (provider-metered consumption) as distinct concepts. No changes to the default report's overall scope or new CLI modes.

## Acceptance / regression evidence

- **Finite Copilot parity:** fixture of 5,608 native used / 25,000 total / 19,392 remaining gives `22% used`, an approximately 22%-filled progress bar, and `5608/25000 AI credits` (matching GitHub orientation) in Normal, Watch and Web; separately `Remaining` pace continues to derive from 19,392. Copilot dollar equivalents, when shown as a fraction, align to `$56.08/$250.00` used/total with clear reference meaning; reset time and labels are retained.
- **Unlimited Copilot:** native `used` present and no denominator shows `Unlimited` + the monthly used count, but *no bar/percentage/remaining pace*. If today's independent OpenCode CCost is available, it remains visible as `CCost today`; it must not masquerade as native `Used today`. If a provider supplies a genuine daily native used count, that is independently labeled `Used today`. Test unknown used and multi-account ambiguities.
- **Exhaustion and partials:** check 0% and 100% used, explicit blocked, stale, partial/missing limits, pct-only, expired/not-started, overage, valid unlimited, and non-quota balance providers without inventing numbers or changing correct warnings.
- **Space/consistency:** compare CLI Normal/Watch (80/120/160 columns, tight account rows, wrap/fallback), Web Accounts and compact Watch against the same normalized fixtures; one visible `used` marker is sufficient in compact Watch; no ambiguous remaining fraction or contradictory percentage/dollar figure. Verify shared provenance, no extra API requests and no CCost/billing/Unaccounted regressions.
- The owner has accepted the visible breaking direction change; tests and `docs/account-support.md` explain it instead of silently preserving the old remaining bar.

**Priority:** Normal, after existing pending FR000520 and FR000521. Relevant owners: `src/presentation/accounts.py`, `src/web/assets/render.js`, `src/application/display.py`, normalized quota presentation and account tests, plus `docs/account-support.md`.
