# FR 000300 — Secure loopback Web runtime and report API

## Outcome and dependency

After FR000290, provide an optional local Web application host that serves a minimal honest Beta/status page and read-only report APIs. A developer can run it in the foreground before native launchers exist. Follow the migration contract in FR000290/PLAN.md. Existing CLI entry points remain unchanged and usable; Web Beta also requires no extra package installation beyond the existing Python 3.11+ and OS/browser facilities.

## Required behavior

- Add an explicitly separate Web entry, provisionally `cost-guard-web.py`, rather than changing the meaning of `python cost-guard.py`. Keep Python 3.11+ compatibility unless separately approved. Implement a small, bounded loopback HTTP runtime with Python standard-library networking and synchronization facilities, without external ASGI/framework/server dependencies. No development autoreload. `http.server` is not secure by default: the implementation must enforce request parsing/limits, fixed routing and concurrency control, same-origin/host/session protections, cancellation and isolation explicitly. Reuse the minimal runtime-error boundary; no uncaught startup traceback containing private source data.
- **No new runtime dependencies or setup downloads.** Starting Web, tray and the browser must not invoke `pip`, install a virtual environment, ask to download a Python/web/GUI package, demand Node.js/Xcode/.NET SDK, or ship a precompiled executable. Use already installed Python, browser capabilities and in-box OS APIs. Keep Web-specific modules separate from CLI imports; launch must work offline after cloning/extracting source, apart from Cost Guard's existing independent upstream data connectivity. If an unavoidable technical conflict with the security/behavior contract is proved during implementation, stop and request explicit owner review before introducing any package or relaxing protections.
- Bind only an explicitly selected loopback address, initially `127.0.0.1`, with an OS-assigned port reported to the host. IPv6 support must remain loopback-only. No LAN binding option, proxy exposure, OS firewall exception, directory listing, CGI, debug console, arbitrary path reader, generic OpenCode proxy or shell-command route.
- Enforce exact expected Host/port and same-origin policy. Cross-origin sites must not read history or invoke control operations; CORS denial alone is insufficient. Protect sensitive reads and all mutations/control with per-instance authentication. A launcher-issued short-lived one-use bootstrap credential may be exchanged for a scoped HttpOnly SameSite browser session; keep persistent control credentials separate and off browser storage. Never put provider tokens or a reusable control token in URLs, browser JavaScript or logs. Avoid bootstrap secrets in query strings/access logs; erase any temporary URL fragment before navigation and reject replay.
- Validate methods, content types, size limits, path parameters and allowed origins, with CSRF protection for state changes. Serve only packaged assets from a fixed root with traversal/symlink protection. Render prompt/session text as text, not executable HTML. Supply a restrictive local Content Security Policy, no third-party runtime assets, no analytics and no service worker caching sensitive history. Do not claim protection from malware already executing as the same OS user.
- Expose explicit allowlisted report DTOs from FR000290. Route naming is implementation-owned, but distinguish session list/detail, overview/catalog and finite report jobs. Exact decimal strings/null/provisional flags survive JSON; labels and formatting retain CLI semantics. No second calculator in JavaScript and no direct browser calls to OpenCode/providers.
- Separate HTTP shell readiness, analysis readiness and source/account health. The page can be reachable while OpenCode is unavailable, loading or reconnecting. Empty, unavailable, partially loaded and genuine zero are different states. Publish sanitized error codes and safe user explanations, not raw exceptions or filesystem paths.
- Keep HTTP control/readiness responsive while expensive analysis runs. Queue finite jobs to a bounded owned execution boundary; coalesce identical work where useful, expose cancellation/progress and backpressure, and do not share mutable services unsafely. Large historical Token Mix must not block graceful shutdown. Use source-request timeouts and cancellation boundaries, not an unbounded thread per request. Later live work must not inherit one-shot account cleanup.

## Acceptance

Synthetic loopback tests cover healthy/empty/offline sources, slow/cancelled reports, malformed parameters, unauthorized reads, foreign Host/Origin including DNS-rebinding-style names, bootstrap replay, CSRF, traversal, HTML injection and secret-free errors/logs. Requests do not mutate OpenCode. Validate decimal/unknown parity with FR000290. CLI and Diagnostics work without any Web setup or optional environment; Web also launches without installing dependencies. A minimal local page opens with no external frontend network dependency; deferred UI areas are labeled unavailable rather than fake data.

Use proportionate tests in the existing workflow, not a new permanent gate. This FR does not add native icons, detached restart, automatic browser launch, login autostart or a release target. Full instance ownership follows in FR000310 before everyday background launchers are exposed.

Design references: Python's explicit warning about generic `http.server` security at https://docs.python.org/3/library/http.server.html and the SSE protocol at https://html.spec.whatwg.org/multipage/server-sent-events.html . Choosing the standard library is not by itself evidence of security; focused localhost adversarial tests and resource limits are mandatory for this feature's acceptance.
