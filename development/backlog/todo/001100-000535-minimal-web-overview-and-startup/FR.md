# FR 000535 — Make Web Beta Overview minimal: clean loading, model table first, compact accounts

## Owner observation and desired result

Web Beta's initial Overview currently shows far too much text, framing and UI chrome. The owner wants a quiet, compact page closer to the useful density of Cost Guard's CLI report: **one model-price table at the top, compact subscription/account cards below, and optional explanations hidden until requested**. The first load should show only the branded shell/navigation plus a centered, advancing progress bar and one short status line. Do not prematurely redesign other Web Beta report views.

This is a deliberately **last-in-backlog visual/interaction feature**, to be implemented after all presently pending FRs. Keep the accurate report data, security and CLI parity; simplify presentation rather than calculation.

## 1. Minimal common shell and clean Overview startup

- Keep the small **CG** brand icon, **Cost Guard** title and **Web Beta** label. Remove the always-visible header prose `Local, read-only · CCost is reference valuation, not billing`; retain that important definition in optional explanatory/help content instead.
- Do **not** show an always-visible healthy `Live connected` indicator, HTTP/source status paragraph or verbose connection banner. Tighten the vertical gap between branding and the Overview/Watch/Sessions/Models/Accounts/Reports/Token Mix navigation. Keep the active navigation selection obvious. When the already-loaded browser detects offline/disconnected, stopped host, lost authorization, source failure or other material unhealthy state, expose a **small, accessible warning/status affordance with explanatory hover/focus/touch tooltip** and actionable recovery information (and a compact visible error where required for discoverability). Do not make unavailable data look fresh, erase stale/error semantics or claim that an unserved page can render when its server never loaded.
- Remove the current long **global footer/footnote** about frozen reports, Watch and search/sort/page controls from the page chrome. This does not remove the underlying guarantees or any required explanation in the relevant page's optional details/help.
- On **Overview**, remove the redundant in-page `Overview` heading (the selected nav tab already names the page), `Refresh snapshot` and `Cancel` buttons, general `Search displayed report tables` / `Presentation filter only` control, snapshot-capture descriptions, snapshot date/source/frozen/acquisition paragraph, and explanatory status/capture boxes. No empty spacers should remain. These removals are **Overview-only** where other routes need independent scope controls, explicit history acquisition, refresh or cancellation.
- During first Overview acquisition (including bootstrap/authorization and waiting for the finite Normal report), render **no table, account cards, concept cards, placeholders, metadata blocks, headings, filters or background report skeleton**. Only the compact brand/nav shell, one **centered determinate visual progress bar** and one concise **status line immediately below it** should be visible. The bar should fill monotonically left-to-right (not bounce/marquee), show an intelligible `0–100%` value and meaningful CLI-like stage text (e.g. loading source, comparing models, acquiring accounts), using available canonical job/stage progress.
- Respect honest progress: Web jobs currently expose a phase and optional completed/total, **not one guaranteed global percentage**. Reuse existing CLI startup-stage/progress concepts where feasible. Any bounded stage-weighted estimate must be visibly approximate and monotonic, must not invent work completion or jump to 100% before a complete usable report is received, and must not cause extra source requests; actual completed/total is preferred when known. An unknown total must not silently be displayed as exact measurement. Clearly finish at 100% only on success, then remove the loading UI entirely.
- On initial failure/offline/authorization rejection/timeout/partial data, stop the progress state and show a **concise accessible actionable error/partial indication**, not a perpetual spinner or falsely complete 100%. Normal page reload may request a new Overview report; keep frozen result/refresh semantics honest. Do not silently refresh an already displayed frozen result on every live heartbeat just because Overview no longer exposes Refresh. Other routes retain their explicit acquisition/cancel behavior.

## 2. Overview ready state: plain model table is the first content

- Immediately below the compact navigation, the **first Overview content is the model table itself**: no visible `Reference models` caption/heading, no outer section card/border/shadow, no `Filter models`, no `N of N shown`, `CLI default order` or `Clear model filter`, and no search/filter/pager or explanatory metadata surrounding it. Retain a semantic/accessible table name off-screen as needed without adding a visible heading.
- Show **exactly four columns in this order**: `Publisher | Model | Relative CCost | Release date`. No extra column, model evidence pane or prices/metadata line. Keep the shared canonical CLI order by default, no Overview-only client-side repricing or independent ranking. The dedicated Models route and `--all-models` can retain their independent controls and extra catalog details.
- Make the **Publisher, Model and Relative CCost columns content-sized and as narrow as practical**, without ellipsizing or hiding the real publisher/model names. Avoid the current artificially roomy Model column and stretched Relative CCost cell. The **last column, Release date, alone may expand** to fill the remainder of a wide table, with the date text aligned consistently. No needless padding, arbitrary minimum widths or equal-width four-column layout; preserve readable spacing. Long names can wrap thoughtfully or be reached with horizontal scrolling on narrow screens, not destructive truncation.
- Fix the Relative CCost **header alignment, cell alignment and internal tier formatting**. Emulate CLI's carefully aligned promotion marker, base `Nx`, arrows, tier ratios and input-token thresholds across rows. Align the **whole column's** content consistently, never center the formatted values inside an oversized cell or stretch a `1fr` tier area across the page. Keep decimal/tier precision and existing new/promotional/superseded visual meaning; do not alter the canonical model comparison values or sort.
- Add **very subtle vertical dividing rules** between the columns, continuing consistently through header and body rows; use the same light/low-contrast treatment as the existing row dividers. Maintain legible contrast in light/dark themes and avoid a heavy spreadsheet grid or surrounding card.
- **Column headers must remain visually fixed** while the model rows scroll vertically. The visible **vertical scrollbar belongs to the rows/body region only** rather than seeming to run over/through the headers; header/body widths and separators must stay exactly aligned at all viewport sizes, including when a scrollbar appears. Preserve real HTML table semantics, keyboard and assistive-technology access, mouse/touchpad/touch/keyboard scrolling, stable text selection and an understandable horizontal-overflow experience on narrow screens. Coordinate with FR000529's general scrolling fix without undoing it. Keep **all available Overview model rows** accessible rather than silently replacing them with a truncated page.

## 3. Information hierarchy below the table

- Move the three explanatory concepts **CCost**, **Token Mix %** and **Relative CCost** **below the table**, behind **one collapsed-by-default `More information` / `Explanations` disclosure**. Nothing from those three cards is visible in the normal collapsed state. Expanding it exposes concise, legible explanations (simple text or compact cards is acceptable) including reference-valuation-not-billing and unknown-data caveats. No duplicated verbose text or nested click-through forest. Keep it accessible by mouse, keyboard and touch.
- **Remove the `Model/publisher evidence` block from Overview entirely.** In particular, do not surface obsolete FR000521 per-model/publisher weighting text after FR000534 changes Relative CCost to one common latest-100 eligible completed-prompt mix. Retain actual publisher attribution and Token Mix-by-publisher features in the dedicated historical report. Any optional Relative CCost explanation must match implemented FR000534 semantics (and token-category names from FR000533 when it has landed).
- Keep useful **price promotion** and **new models** notices/highlights below the model table, without enclosing them in bulky extra sections or turning them into permanent filler. Preserve their precise text/semantics and visual highlighting when genuinely applicable.
- Then show the **subscription/account cards**, visually smaller and substantially denser than today. In the collapsed/default state, use **one prominent subscription/account name only**; remove the second grey provider/plan/name repetition when it duplicates the header, as well as routine `Available`, `Available usage status unknown`, observation status prose and other non-actionable filler.
- The default account card should present only the **important values already surfaced in the CLI Normal account report** (relevant quota window/remaining or used values, reset/pace information where CLI shows it, CCost today/month and meaningful native Billed/credit/Unaccounted values where applicable). Reuse the shared server/CLI-defined formatting and unit/unknown rules instead of inventing new calculations or silently conflating reference CCost, native credits and actual billing. Keep a compact short warning for **real** stale/blocked/partial/error conditions; hide verbose provenance, billing component breakdowns, secondary labels and optional explanations behind **one `Details` disclosure per card**.
- Default/collapsed cards should form a consistent **equal-height compact grid** at each responsive breakpoint, without clipping crucial quantities or rendering fake zeros for unknown data. Expanding one card can grow to show complete details; avoid forcing every other card to become bloated. Work with zero, one and many accounts, partial/unavailable quotas, multiple quota windows, long names and mixed providers. The dedicated Accounts route can remain more diagnostic; do not strip real account facts from projections or change provider acquisition.
- Do not show the global explanatory **footer/footnote** at the bottom of Overview. At rest, the Overview visual hierarchy should be: **model table → one collapsed explanations disclosure → genuine promotion/new-model notices (if any) → compact account cards**, with no other clutter.

## Acceptance and visual regression

1. **Cold/slow Overview:** immediately shows the minimal CG/Cost Guard/Web Beta shell and nav with one centered filling progress bar and a short changing status line; **no other content** appears before report success. Percentage is monotonic, only reaches 100 on successful receipt, does not bounce, and does not claim exactness when only an estimate exists. Check ready, delayed, failed, timeout, offline, unauthorized and reconnect/stale cases. Reload and Back/Forward preserve legitimate frozen-result behavior.
2. **Clean ready Overview:** the table is visibly first; exact four columns, no Overview header, standalone Snapshot/Refresh/Cancel/Search/Filter/pager/model-evidence UI, counter labels, pricing metadata block or footer. The concept section starts collapsed; promotions/new models appear when relevant and account cards are compact with no duplicate name. Empty/warning states remain readable without reviving banners of noise.
3. **Table geometry:** test shortest/longest publisher/model strings, many model/tier lengths, long thresholds, promotion markers, superseded states, absent releases and at least 25 model rows. Header and body vertical rules align; relative-cost segments line up row-to-row as in CLI; the first three columns shrink to content, last column expands; no ellipsized model names. Scrollbar is restricted visually to rows, not header; all rows are reachable with mouse wheel, touchpad, keyboard and touch where available. Verify 360px mobile, common laptop and wide desktop viewports and light/dark themes in a **real browser**; DOM/CSS assertions alone are insufficient visual evidence.
4. **Account compactness and truth:** compare every default card's values against the same frozen CLI Normal report, for varied providers/plans, unknown/missing quotas, short/long names and native vs reference costs. Empty/unknown must not turn into zero. Healthy routine status clutter is absent; actual stale, partial, blocked and error states remain discernible and actionable. Accessible `Details` reveals the remaining supported facts without changing totals.
5. **No regressions:** all other Web routes retain important controls, explicit deep-history cancellation, focus, sorting/filtering where originally offered and snapshot/live identity. Shared status is quiet when connected but warns reliably when unhealthy; no false connected indication. No change to raw model order, CCost, token mix, quota snapshots, pricing notices, data provenance, host/process lifecycle, browser privacy or CLI. Update user-visible Web documentation/help where it describes controls or Overview layout that no longer exists.
