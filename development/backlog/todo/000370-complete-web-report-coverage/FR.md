# FR 000370 — Complete Web report coverage and cross-view navigation

## Outcome and dependencies

After FR000340, expose the remaining existing Cost Guard reports through the same navigable Web application. Integrate FR000350's live/freshness states when delivered. Follow FR000290/PLAN.md; this FR must not redefine metrics or hide missing feature parity behind attractive charts.

## Required behavior

1. Complete Models/catalog comparison, Accounts, date/date-range Reports, available Sessions N/all and historical Token Mix. Preserve a normal overview entry and links from global Live/session lists into session detail. Pages may share components or a menu section, but every existing user-facing report use case has a discoverable route, sensible empty/error/loading state and Back/Forward/deep-link behavior.
2. Models retains the existing independent sample scopes, eligibility, exact sorting, selectable-versus-all catalog distinction, tier boundaries, availability warning behavior, release/promotion facts and conservative fading. The all-models view retains its additional native rates. Do not rank by rounded display values, invent model availability/release dates or repurpose relative CCost as a bill.
3. Accounts preserves provider/account identity, native quota units/windows, remaining/Pace, source freshness and account-method errors. Keep report local-month CCost, rolling/Today values and Copilot Unaccounted usage in their established scopes; do not copy a monthly-only report quantity into Watch rolling semantics. Unsupported/ambiguous/missing values remain unknown and account-only partial-display policy stays distinct from global/prompt markers. No login, token editing, credential export or OpenCode/provider mutation is added.
4. Date/date-range reports use configured-local calendar boundaries, inclusive user date ranges and established DST behavior. Prompt/session links retain selected scope where useful. Totals and duration come from existing shared analysis, not summing rounded visible cells. An API validation error must not quietly normalize an impossible range into a different report.
5. Historical Token Mix remains an explicit deep-history operation, not automatic page prefetch. Show actual phase/progress and allow cancellation; missing history/prices and per-model prompt counting retain current semantics. Cache/reuse suitable immutable results by real source/config/pricing dependencies. Opening or cancelling the page must not start another independent account scheduler or stop global Live.
6. Global and per-table search/filter/sort are presentation controls unless an existing report scope is explicitly selected. Clearly distinguish filtered/page values from full-report totals; do not accidentally change the billing/history query through a client-side filter. Pagination/virtualization keeps every requested available row reachable. Decimal values and exact sorting remain safe from JavaScript floating-point drift.
7. The implementation agent may refine menus, typography, density, responsive tables, modest charts and helpful explanations based on the existing CLI information. Charts are optional presentation of returned aggregates, not a new metric/reconstruction engine. Do not add speculative settings editors, automatic updates, remote sharing, PDF generation or new provider integrations to finish navigation.
8. Ship local assets and incremental functionality on the same branch/release stream as CLI. Clearly show which data is a finite report and which is live. Preserve snapshot timestamps on frozen results; refresh is an explicit action except on designated live surfaces. Keep session/prompt content out of persistent browser storage and external requests.

## Acceptance

Complete FR000290's mode-to-view inventory with exact semantic parity tests for all report kinds. Use fixtures for multi-account ambiguity, native quota failure, unavailable model catalog, missing prices, tiers, period/DST boundaries, cancelled deep scans, archived sessions and empty history. Validate navigation/deep links, large result sets and concurrent report/Live work without source/account-call multiplication. Compare same-scope data, not independent live runs with different observation windows.

Demonstrate a working click-through path across overview, a session, models, accounts and a date report, with honest placeholders removed only where functionality is actually present. Record visual decisions for later owner feedback; do not require perfect design approval. Existing CLI output/launchers and source read-only policy remain intact. Use focused existing workflow checks, not a new permanent product gate or release version target.
