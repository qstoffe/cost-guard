# FR 0090 — Adopt Toolkit repository contract synchronization

## Goal
Make Cost Guard adopt compatible updates to OpenCode Toolkit's shared repository-development contracts before ordinary backlog work. Toolkit FR0191 must first be implemented and available in the installed runtime; the manual Toolkit handoff at FR0195 is still required. This FR is planning only and does not install a scheduler.

## Scope
Consolidate existing Cost Guard migration requirements FR0100, FR0105, FR0110 and FR0115: development layout, shared release qualification, folder-based backlog with safe attachments, unique priorities, completed retention, and central FR-only authoring. Preserve all unique requirements and product-specific safeguards from those requests and verify them against their Git history. Do not mark an unimplemented item completed.

Use the Toolkit-owned change-driven sync procedure and its persisted revision receipt. Preserve Cost Guard Python, read-only OpenCode access, privacy protections, functional-only product versioning, existing tests and validators, source distribution, and unrelated backlog FRs. Migrate the older flat backlog safely, without interfering with active work or deleting source evidence. Keep shared process rules centralized in Toolkit, not duplicated in Cost Guard.

## Acceptance
Verified installed Toolkit capability, safe and complete migration, authoritative merged-commit and state read-back, no repeated migration after checkpoint/resume, and unchanged product version for development-only changes. Test actual priority/attachment migration and local test inventory without weakening checks.

## Requirements retained from the four legacy requests
- **Former FR0100:** use portable Toolkit development layout and navigation: a short development README, one todo/complete backlog, an architecture overview with Mermaid module/workflow routing, hierarchical journal INDEX and owner leaves, and centrally scheduled architecture, test-health and performance maintenance. Consolidate generic MAINTAINER guidance only after rehoming every unique product safety rule. Maintain Cost Guard's test runner, fixtures, Quick/Full membership, validation, packaging/privacy checks and live-environment boundaries.
- **Former FR0105:** share Toolkit's deterministic release/version/history *procedures*, not each repository's release data. Cost Guard uses a functional-only adapter and preserves existing src/version.py VERSION/RELEASE_DATE, root README, root VERSION_HISTORY, historical releases and real source distribution. Only shipped code, launcher and runtime-behavior changes qualify for a version; documentation, FR-only, test/tooling, journal and maintenance-only changes do not. Never invent future release numbers or rewrite history.
- **Former FR0110:** migrate every safe legacy flat pending/completed FR to NNNN-slug/FR.md bundles with optional local sanitized attachments and relative links. Preserve original order, numerical identity, contents and references. Apply the *installed current* Toolkit retention limit, completion-order accounting and global non-reusable priority high-watermark, including any supported scalable numeric extension. No selected-FR rewrite, unsafe attachments, lost evidence or premature pruning.
- **Former FR0115:** one central Toolkit FR-authoring contract for both OpenCode and GitHub-only ChatGPT clients. Self-contained FRs describe behavior, evidence, constraints, ownership, verification and acceptance without reserving product versions. A user-authorized new major is only a designation, never an assumed target number. Brainstorming does not publish. Explicitly approved *FR-only* publication goes to verified main without PR or product release, while implementation delivery retains normal Git verification; no local duplicate policy.
- **Existing Cost Guard protection:** preserve Python 3.11+ stdlib-first, stable cost-guard.py entry, OpenCode read-only persistence/auth, disposable cache and isolated SQLite generations, normalized source/account/pricing boundaries, one shared analysis truth across Watch/report, independent usage-cost-quota semantics, Watch presentation geometry and fallback messages, private optional configuration, privacy-safe diagnostics, file budgets and structure ratchets. Continue all relevant tests and safe source distribution. Do not weaken controls merely to make migration pass.

## Implementation reconciliation
Audit the four superseded original FR files from the Git history identified above against this checklist. Keep genuinely unique further requirements and evidence before retiring any local maintainer or FR guide; remove stale references and rewrite guide-pinned regression tests to check real current Toolkit contract behavior instead of old static prose. An absent/mismatched installed Toolkit capability, incomplete test migration, ambiguous protected local rule or uncertain Git write must block cleanly. FR0120, FR0130 and FR0140 remain independent and pending.
