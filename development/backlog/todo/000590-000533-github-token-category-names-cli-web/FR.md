# FR 000533 — Use GitHub's exact token-category names in all Cost Guard CLI and Web displays

## Owner request and terminology

The owner wants Cost Guard to use the same explicit category names as GitHub Copilot's published token-pricing table, everywhere a human reads a four-category Token Mix or token reference-price breakdown. Current Cost Guard labels `Input / Cache / Write / Output` are misleadingly abbreviated: `Cache` is the cached-input (cache-read) bucket and `Write` is the cache-write bucket. The ambiguous names recur in CLI Normal/Token Mix output and Web Beta's historical model and newly added publisher Token Mix tables, metrics and help text.

GitHub's **exact current English column names** are **Input | Cached input | Cache write | Output** (note: the GitHub heading is **Cache write**, not **Cached write**). Reference: https://docs.github.com/en/copilot/reference/copilot-billing/models-and-pricing . Use those names as the authoritative user-facing terminology; do not independently coin a fifth category.

| Existing Cost Guard visible category | Required visible category | Existing underlying meaning |
| --- | --- | --- |
| `Input` | **Input** | Uncached input tokens |
| `Cache` | **Cached input** | Cache-read tokens |
| `Write` | **Cache write** | Cache-creation/write tokens |
| `Output` | **Output** | Output tokens, including observed reasoning |

This is a **display vocabulary/clarity fix**, not a change to how tokens are observed, normalized, sampled, priced or aggregated. These categories remain mutually exclusive; do not add Cached input to Input a second time.

## Required behavior

1. **Consistent names in all four-part displays.** Replace standalone `Cache` and `Write` category labels, headings, definition sentences, legends, hints and other human-facing token-category wording with **Cached input** and **Cache write**, respectively. Preserve Input and Output. Apply throughout CLI Normal, `--all-models`/model-pricing explanations, `--token-mix` (historical per-model **and per-publisher** tables), CLI Watch/run/prompt/session/date detail, and all corresponding Web Beta routes (Overview, Models including all catalog, Token Mix, Watch, Sessions/date/range, Snapshot/Live detail), plus help/tooltip/accessibility labels, documentation and examples where those categories are actually named.
2. **Preserve compact presentation without misleading shorthand.** Default table column headings and explanatory category lists must use the full GitHub words. For especially narrow four-value cells currently headed `I/C/W/O %` or `GitHub USD/M I/C/W/O`, a compact abbreviation may survive only where truly necessary for readability **with a plainly discoverable, locally adjacent or accessible expansion** mapping `I = Input`, `C = Cached input`, `W = Cache write`, `O = Output`. Prefer a shared `Token Mix %` label plus an explicit legend where clearer. Never leave an unlabeled `Cache` or `Write` as if it were an independently defined pricing category. Preserve numeric column order and exact value-to-category correspondence.
3. **Share presentation vocabulary rather than rewrite analytics.** Centralize/reuse the canonical four visible labels in the Python presentation and supported shared display-token boundary so CLI and Web cannot accidentally disagree; Web should not invent category semantics or reprice tokens. Existing DTO/internal field names such as `input`, `cache`, `write`, `output`, `cache_read`, `cache_write`, source `cache.read`/`cache.write`, persisted schemas, numeric sort keys and field orders may stay unchanged for compatibility. Only adjust labels, explanatory metadata and associated tests as necessary. Do **not** perform a breaking API/source/cache migration merely for wording.
4. **Audit related text carefully.** Update root README, usage/cost reference, Web Beta help, visible tooltips, static UI strings, tests and maintained reference examples/golden output. Avoid unscoped global search-and-replace of unrelated uses of `cache` (Cost Guard's own database/analysis cache, pricing metadata, estimated next-context cache, HTTP/browser cache) or code identifiers; do not replace `write` meaning file writes or unrelated workflow actions.
5. **Handle unavailable cache-write telemetry honestly.** A model having a published **Cache write price** does not prove OpenCode emitted any **Cache write tokens** in a particular history. Distinguish observed zero, unavailable/unknown usage, and a published `Not applicable` rate according to established source/pricing rules. Do not infer missing OpenAI cache-write tokens from catalog pricing or make zeros appear simply to populate the renamed column. The owner's observation of little/no OpenAI cache-write usage is a separate possible telemetry investigation, **not** authorization here to change provider adapters, pricing fallback, model classifications or source acquisition.
6. **Preserve other backlog ownership.** Completed **FR000521** already added the historical publisher Token Mix table; rename its category columns alongside the model table rather than adding another publisher column/table. Pending **FR000527** independently adds an absolute Tokens-per-model column; maintain its compatible compact width and unit/total semantics. Pending **FR000529** covers generic long-table scrolling and remains separate; this wording fix must not introduce unreadable tables at common terminal/browser widths.

## Acceptance / regression

- For representative matched canonical input, CLI and Web show the four categories **Input | Cached input | Cache write | Output** in the same order with exactly the same existing counts, percentages, per-category CCost, totals and partial markers. Assert both model and publisher rows, normal sample and historical/deep-history, plus available All Models price-reference semantics. No accidental switch of cache-read and cache-write values.
- CLI screenshots/text fixtures cover Normal, Watch, `--token-mix`, `--all-models`, session/date/detail and constrained 80/120/160-column rendering; the labels are legible, with wrapped or documented compact fields rather than clipped/misaligned rows. Browser DOM/accessibility checks cover Overview, Models, historical model **and publisher** Token Mix, Watch, session detail, desktop and 360px narrow layouts, light/dark as appropriate.
- No unexplained user-visible standalone `Cache`/`Write` *token-category* heading or obsolete definition survives. Explicit compact `I/C/W/O` is accepted only with a correct, accessible four-term mapping. Structured field names, historical stored state, report scope/order, source requests, monetary valuations, raw sorting, warnings and partial/unknown vs zero semantics remain unchanged.
- Include distinct tests for **observed zero cache-write tokens**, missing cache-write telemetry, a model with a published Cache write price but no observed write tokens, and a catalog `Not applicable` rate; do not manufacture observations or conflate pricing availability with metered token volume. All displayed token proportions still reconcile to the original four underlying fields.
- Use relevant `src/presentation/token_mix.py`, `src/presentation/report.py`, `src/presentation/definitions.py`, `src/application/display.py`, `src/web/assets/render.js`, `watch.js`, and existing report/Web/Token Mix golden/DOM tests. No model inference, external provider calls, OpenCode writes, Web promotion or unrelated source/valuation changes are required.
