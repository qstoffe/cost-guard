# FR 0100 — Migrate Cost Guard development into reusable Toolkit repo-backlog contract

## Problem and prerequisite
Cost Guard already has extensive repository-specific development guidance, FR backlog, tests, fixtures, package validators and product invariants. The user wants all future AI-driven repositories bootstrapped by OpenCode Toolkit `/repo-init`, with central Toolkit-owned generic skills, journal and maintenance logic. Cost Guard must become a standard consumer without losing its real behavioral/safety contract.

**External prerequisite:** The Toolkit FRs implementing portable /repo-init (Toolkit FR 0130), hierarchical repository journal and architecture routing (0140), shared maintenance skills (0150), deterministic maintenance scheduling (0160), Toolkit-side migration/contract stabilization (0170), shared release/version policy (0175) and central FR-authoring contract (0185) must first be verified as available in the active installed Toolkit version. This Cost Guard FR must **not** attempt to implement missing Toolkit functionality in Cost Guard, fork shared instructions or pretend a GitHub FR in another repo has been delivered. When dependencies are not available, stop clearly with FR pending. If both repositories' backlogs are being processed concurrently, ensure this prerequisite is observed.

## Required migration
Adapt `development/` to match the canonical portable Toolkit-created structure: short `development/README.md` for local entrypoints, standard `backlog/todo` and `backlog/complete`, architecture overview with a readable Mermaid orchestration/module graph and concise module routing, hierarchical `journal/INDEX.md` and targeted leaves, and a unified `development/tests/` owner for all deterministic and live/test integration material, with fixtures/suites organized sensibly inside it. Additional Cost Guard-specific tooling/docs may remain as explicitly useful sibling content under development/; **do not import the entire Toolkit development directory or invent unrelated starter files**. Check active Toolkit contract and migrate to that authoritative version instead of hardcoding stale assumptions from this FR.

Remove duplication of generic implementation, FR-authoring, Git delivery, test hygiene, architecture maintenance, journaling and scheduling procedures into central Toolkit capabilities. **Retire `development/MAINTAINER.md`** and condense local instructions into a short development README and actual owning architecture/docs/config validators. The user expressly requests review/removal of the maintainer file, but critical protected product invariants must be identified and preserved—not casually discarded—including:
- Python 3.11+, standard-library-first and no new third-party runtime deps without approval; stable thin `cost-guard.py` entry point.
- OpenCode persistence strictly read-only; local cache disposable and user-owned historical data never cache-only; SQLite schema generations isolated.
- Canonical source/provider normalization and one shared analytic truth for Watch/one-shot reports; responsibilities of `src/domain`, `sources`, `accounts`, `pricing`, `analysis`, `cache`, `reports`, `watch`, `presentation`, `bootstrap` retained or explicitly verified through legitimate behavior-preserving refactor.
- User-visible table/prompt/compaction labels, approximation/fallback warnings, Watch cadence/layout, usage/cost/quota distinct semantics, optional zero-config `config/user-config.jsonc` privacy/validation and provider credential redaction.
- Current repository budgets `development/file-budgets.json`, `structure-policy.json`, validator behavior, Git safety, platform launchers/Diagnostics and focused vs Full testing under correct environment; test fixtures cannot require private credentials or real OpenCode database.
- Open-source 0BSD/license/source-distribution privacy hygiene, no accidental bundled secrets, diagnostics archives not product releases. Existing user-controlled maintainer protection is intentionally migrated, not weakened.

**Test migration must be comprehensive:** Preserve existing `development/tests/test_*.py` and `fixtures/`, test runner `tools/run_tests.py`, quick/full profiles, Diagnostics, package validator and all exclusion/pattern matching after relocation/consolidation. Move product-specific test and live fixtures to appropriate `development/tests/` subfolders only where that improves the common contract. The test runner's exact path classification must remain correct: never drop tests silently, convert missing tests into ignored ones, or disable verification to get a clean result. Preserve useful CostGuard-specific docs under a suitable development subtree when still authoritative; obsolete docs may be consolidated/deleted with evidence.

## Versioning
A completed ordinary FR or maintenance delivery must increment one minor by default and update `src/version.py` VERSION/RELEASE_DATE, the root `VERSION_HISTORY.md`, root README current version and any other active metadata consistently, including documentation-only/behavior-neutral deliveries. Explicit FR-directed major is the exception. Preserve Cost Guard's existing `vMAJOR.MINOR` product identity, bounded net-change version history, current `main` source-distribution stance and historical tags. Do not fabricate version for an unmerged result. Migration itself follows current valid version controls until merged.

## Journal and maintenance
Each delivered FR/maintenance cycle **checks** whether new enduring journal evidence exists. Only when material new/revised knowledge exists, write and **consolidate** relevant leaves/index; retire stale discoveries, obsolete benchmarks and superseded decisions. No obligatory per-delivery journal entry. Each architecturally significant ordinary feature updates relevant Mermaid/map to match real code. Periodic Architecture Refactoring, Test Health and Performance execution is controlled centrally by Toolkit; Cost Guard records only local outcome/state and facts. Migration initializes scheduling state at a new explicit epoch with no retroactive maintenance flood.

## Verification and acceptance
- Compare before/after architecture, protected product invariants and test inventory with an explicit reconciliation checklist; no lost or deactivated tests.
- `development/MAINTAINER.md` removed only once its unique still-valid product rules have authoritative replacements and old references updated; short development README remains easy for new ChatGPT/OpenCode coding sessions.
- Run relevant Quick/Full/validator and safe real-environment tests according to the active environment; protect actual behavior, presentation, privacy and source-only distribution.
- Existing FRs and backlog numbering preserved; central Toolkit scheduling and /repo-backlog recognize Cost Guard without local copies of generic skills.
- Root version history, code version metadata and README consistent for this actual merged delivery.
- Journal, human-readable Mermaid overview, module navigation, reusable /repo-init structure and repo-local state validate; no broad context dump needed to understand normal module changes.
- Honest blocking if the Toolkit prerequisite or safe migration verification is unavailable: do not mark this FR complete.
