## Lowest demonstrated blocker, not an owner refusal

The supported `opencode debug paths` command identified the normal data paths.
A native directory read was gated with
`REPO_BACKLOG_PERMISSION_DELEGATE_REQUIRED` **before operation or owner prompt**.
On Delegate direction it was retired; the database was not opened by another
mechanism. The independently useful registered HTTP route then succeeded above.

Official SDK documentation identifies the Claude projects transcript layout.
A **single exact SDK-session filename glob**, derived from a saved native pair,
was also gated before operation/prompt. It was not retried through shell, SDK,
database or another access route. Thus file existence/readability remains untested.

Supported own-session and location-qualified agent API reads discriminate the
cause:

- The worker's actual agent is `build` and its session location is absolute.
- The owner-selected Private profile and installed configuration are byte-equal;
  no `OPENCODE_CONFIG`, `OPENCODE_CONFIG_CONTENT` or `OPENCODE_CONFIG_DIR`
  override is present.
- Native build/delegate IDs, Delegate subagent mode and the resolved Delegate
  system fingerprint agree with the installed definitions.
- Installed `repo-backlog-local-permission.js::loadedPrivateProfile()` compares
  **raw configured permission subsequences** with **loaded native permissions**.
  Both comparisons fail: configured `$HOME/...` patterns have become expanded
  Windows home paths with Windows separators in the native definitions.
- Expanding **only** `$HOME` and normalizing separators makes the complete
  contiguous subsequence match succeed for **both** agents. The installed
  comparison therefore rejects an otherwise matching Private profile, before
  the intended automatic typed-read grant can apply.

This is a demonstrated admission implementation mismatch, not revoked owner
consent, configured transcript denial, an absent transcript or a failed UUID join.
No permission was altered or repair tested. Fixing/installing/reloading Toolkit
is outside this Cost Guard task; shared OpenCode was not stopped.

The Delegate chose whole-FR On Hold rather than another access retry, owner
question or partial release. A one-time metadata export alone would not supply
the required durable live lookup and future-call verification. The expressly
allowed owner-run validator remains an alternative only if it can establish
the **same complete real source/product/UI/cache/restart acceptance**, not
merely repeat the already successful sanitized V6 identity report.
