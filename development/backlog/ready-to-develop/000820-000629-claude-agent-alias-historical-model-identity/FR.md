# FR 000629 — Identify Claude Agent aliases safely and correct historical model labels

**Owner-approved Ready Feature Request, 2026-11-07.** Permanent identity **000629**; Ready priority **000820**, deliberately **last**, after the existing lowest-priority FR000627 (000720). **Backlog publication only**: create this FR and advance the identity watermark; do not implement product changes, run model tests, alter release/version files, reselect or interrupt the active FR000624 worker.

## Owner report and evidence

In OpenCode Desktop V2 the model picker for a completed test session showed **Claude Agent / Sonnet 5.5**. The session's completed assistant model, however, was serialized as:

```json
{"providerID":"claude-agent","id":"sonnet","variant":"default"}
```

The session also contained the same alias on the initiating user message, one completed model call, ~25k incoming context and nonzero tokens. Cost Guard Web Beta (v80.203) displayed **Claude Sonnet 4**, **Default**, **CCost N/A**, and one call in Sessions detail. The sample session is from 2026-11-07. These are owner-observed UI/source facts, **not** proof that the underlying executed model ID was persisted as `claude-sonnet-5-5`. Omit personal paths, full session payload, identifiers and screenshots from the public FR.

The implementation currently has a concrete misleading-label path:

- `src/sources/opencode_v2_wire.py` and `src/sources/opencode_v2_normalization.py` preserve the alias `claude-agent/sonnet` without a version; this is faithful to the available V2 response.
- `src/analysis/comparisons.py::_model_display_name` asks `PricingCatalog.resolve(model_id)` for a display name, discarding the provider context for the lookup.
- `src/pricing/catalog.py::_match_closest` accepts substring matches and scores shorter candidates more highly. An ambiguous short alias `sonnet` can therefore receive the label **Claude Sonnet 4** merely because that is the shortest catalog match, even if the actual runtime selected a different release.
- Meanwhile `PricingCatalog.reference_valuation` uses `resolve_reference`, which requires exact or explicitly verified reference identity, so CCost can remain **N/A**. This combination is especially misleading: the visible, fuzzy-derived "Sonnet 4" label must not be treated as observed execution evidence or as the explanation for missing prices. Review other uses of `catalog.resolve` in session summaries, reporting and model timelines.

Anthropic documents `sonnet` as a **moving, provider-dependent alias**, not a fixed Sonnet 4 identifier. On the Anthropic API, Claude Code v2.1.284 / Agent SDK v0.3.284 or later resolve it to **Sonnet 5.5**, consistent with the owner's UI selection, but different provider routes, older installations, gateway/settings overrides and earlier historical periods may resolve differently. See:
- https://code.claude.com/docs/en/model-config
- https://claude.dev/blog/building-with-claude-sonnet-5-5/

**Diagnosis:** Cost Guard demonstrably mislabels an ambiguous alias. The supplied exported session alone does not unambiguously prove which concrete model actually executed. Do not blame OpenCode for correctly serializing an alias, or assert that OpenCode definitely executed 5.5 solely from the picker. A separate upstream improvement may be needed if the resolved per-request model is fundamentally absent from all supported source evidence.

## Desired change

1. **No invented version in display.** Stop mapping bare/versionless aliases such as `claude-agent/sonnet` to a specific Claude release using partial-name/shortest-string matching, regardless of price-catalog order. Keep original provider, selected alias, variant, and resolved-model evidence separate. When the concrete release is not proven, render a clear stable label such as **Claude Sonnet (version unverified)** rather than **Claude Sonnet 4** or a silently asserted **5.5**. Explicit, full version IDs continue to render normally.
2. **Resolve only from applicable evidence.** Inspect the existing OpenCode V2 session/message, provider/model catalog, native Claude Agent metadata and already-supported provenance for a trustworthy **request-time** resolved model identity. If a resolved ID can be established, use it consistently for the display and exact reference-pricing lookup. A model picker's name, current provider catalog, model-family token, provider-agnostic fuzzy match, release date alone or today's alias default must not silently become proof of an older request. Alias mapping must be provider-/backend-aware, time-aware and respect user overrides/fallbacks; do not assume all `sonnet` calls were 5.5. If reliable evidence is unavailable, leave identity/pricing unverified; do not probe credentials, use private APIs, add intrusive live requests or manufacture provenance.
3. **Correct reference CCost when justified.** For an invocation with a verified concrete version and a matching acquired GitHub Copilot reference rate, calculate its normal per-request CCost using the existing exact pricing/tier and token-coverage rules. For unresolved aliases or missing rate evidence keep `N/A` / existing partial semantics, not fabricated zeros or approximate Sonnet-4 pricing. Preserve the distinction between reference CCost and real subscription spend. Avoid loosening the exact reference-valuation policy globally merely to fix a display label.
4. **Fix existing history as well as future sessions.** All user-facing projections of already recorded prompts/sessions must use the corrected logic on reload: Sessions list/detail, Watch and Mini Watch history, CLI views, model/effort timelines, session dominant model, relevant aggregated model grouping, Token Mix, AI Stats and comparisons where affected. Recompute/reproject from original persisted observations or verified version evidence, with narrowly scoped cache invalidation/migration as necessary. Do not require deleting source sessions, manually clearing the whole SQLite cache, modifying native OpenCode history or re-running paid prompts. Preserve performance and freshness constraints of FR000624/FR000626; avoid an unconditional full-history reload just to repair labels.
5. **Historical uncertainty must remain visible.** A particular old alias-only invocation can become **Claude Sonnet 5.5** and be revalued **only when independently supported by source/request-time evidence**. Otherwise remove its false Sonnet 4 label and keep a version-unverified display / CCost N/A; do not globally reinterpret all historic `sonnet` calls based on current alias policy. The correction should be stable across later SDK upgrades, price refreshes, caches and viewing the same session again.
6. **Do not regress unrelated providers or reports.** Preserve legitimate exact catalog matches, pinned Claude releases, other model families, provider-specific aliases, effort variants, multi-model prompts/subagents, project-local model availability, cached monetary semantics and CLI/Web parity. Share model-identity rules centrally rather than patching only the Web Sessions table. Label display must not silently drive attribution, repricing or publisher grouping without sufficient evidence.
7. **Coordinate with FR000628 (CCost N/A tooltips).** Its historical owner assumption that earlier tests were *actually* Sonnet 4 may have been based on the very Cost Guard display bug described here. FR000628 remains a separate tooltip-only request: a tooltip on an alias-only request must say the concrete version/price match is unverified, **not** definitively claim "Claude Sonnet 4 is absent from the Copilot list." A truly verified Sonnet 4 invocation can still produce that reason when supported. This FR supersedes the *diagnosis* for ambiguous alias-only evidence, not FR000628's approved tooltip scope or queue position.

## Acceptance / regression checks

- Reproduce the exact synthetic V2 shape above (one `claude-agent/sonnet` assistant request, `default` variant, positive token usage) with catalog entries for Sonnet 4 and 5.5. The old behavior displays **Claude Sonnet 4**; the repaired behavior does **not** select a concrete release without proof, regardless of catalog order. It must not silently price this ambiguous call.
- With independently verified request-time `claude-sonnet-5-5` evidence and available exact rates, display **Claude Sonnet 5.5** and compute the correct normal CCost, including cache-write-heavy usage. With explicit `claude-sonnet-4` evidence, display **Claude Sonnet 4**, and respect actual rate availability. Cover other backend mappings and version overrides, including an older `sonnet` release.
- Verify alias turnover over time: two historical requests stored as `sonnet` must retain individually supported resolutions (or remain unresolved), even when the current alias now points to a newer version. No rewrites by today's provider defaults and no attribution of an assistant request based only on a mutable session selection.
- Compare fresh vs cached and older archived sessions across CLI/Web Sessions, Watch/Mini, historical model totals, model-specific Token Mix and CCost tooltips. Corrected results appear without manual cache deletion; genuinely unknowable histories remain honestly unverified. Verify unchanged source counts, token totals, request attribution and correct partial-CCost semantics.
- Target existing V2 source-normalization, pricing-identity, prompt-projection, history/cache and Web/CLI parity tests. Document which source evidence can prove a resolved Claude Agent model, which cases cannot, and any remaining upstream telemetry limitation. No paid live model execution is required to pass acceptance.
