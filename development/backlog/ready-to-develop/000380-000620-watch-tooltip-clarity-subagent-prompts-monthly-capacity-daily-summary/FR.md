# FR 000620 — Watch: simplify cost/model tooltips, show subagent prompt counts and monthly-equivalent quota capacity, clean Today summary

**Owner-approved Ready Feature Request, 2026-11-06.** Permanent identity **000620**; Ready queue priority **000380**, after existing FR000619 (000370). **Backlog documentation authoring only:** do not implement, run product tests, change product docs/version/release, or modify another FR in this publication.

## Owner's requested visible changes

This is a targeted **Full Watch Web Beta UI/help refinement**, not a new report, a calculation overhaul or a redesign of the tables and subscription cards.

1. **CCost (I + E) heading help:** remove the sentence **“A displayed zero shows two zero components in this unit, even when component evidence is unavailable.”** It is confusing and unnecessary. Also remove its final paragraph in full: **“N/A — Cost unavailable, not zero. / ? — Part of the cost cannot be priced. / I is a cost here, not the Input token share.”** Keep the meaningful concise explanation of estimated prompt CCost and the first-request **I** / other-requests/subagents **E** split, and the total relationship.
2. **Model column heading help:** preserve the two simple bullets **Main prompt** and **Linked subagents**, but amend the linked-subagent bullet to explain that hovering over, focusing, or tapping the **Model cell** (typically marked with `*`) can reveal the **models and effort levels actually used by linked subagents** when supported by recorded evidence.
3. **Model cell and CCost cell details:** remove the textual **price-tier descriptions** such as **“Default (0–272000 input tokens)”** (and analogous `Default 0 to 272 000 input tokens` text) from **both** tooltips. This tier interval does not help interpret the observed subagent model/effort/cost breakdown. **Do not remove price-tier selection from pricing calculations or grouping**; just stop putting the tier name/token-boundary argument in these two helper texts.
4. **Model cell must actually reveal linked subagents:** today a single-model main+subagent combination may show a `*` but not open a useful model tooltip. Ensure the Model value's contextual help is available whenever linked subagent evidence warrants it, **even if the same model ID was used by main and all subagents**. Show known main model/effort and the linked subagents' actual model and effort, preserving honest unknown/unreported fields. The heading's new promise must match this behavior.
5. **CCost cell tooltip — one new bullet:** keep existing **Input / Cached input / Cache write / Output / Subtotal** breakdowns for **Main prompt** and grouped **Subagents**, unchanged in meaning. At the **top of each Subagents group's bullets**, add **“• Number of prompts: N”** from actual canonical, distinct **subagent prompts** contributing to that group. Do **not** add the new bullet to Main prompt. The owner particularly wants to distinguish a grouping of e.g. ten same-model/same-effort subagent prompts from one. Avoid confusing number of prompts with number of distinct agent sessions or physical model-request Calls.
6. **Quota Capacity tooltip — comparable monthly equivalent:** for each **non-monthly primary or secondary quota** on Full Watch, add an additional **`Monthly Capacity`** line in that quota's **Capacity tooltip**, representing a **standardized 30-day-equivalent reference CCost capacity (guesstimate)** whenever a reliable same-window CCost Capacity and actual period duration exist. This allows approximate comparison between plans with five-hour, weekly and other genuine time-limited quota windows. Even when the **per-period Capacity is a native, actually fixed weekly allowance**, the 30-day extrapolation itself is always a **guesstimate**. Preserve the existing per-period Capacity exactly as now. Do not pretend that 30-day extrapolation is a genuine provider monthly limit or guaranteed spend.
7. **Watch's day summary above subscriptions:** retain only the existing **CCost Today** total and **today's prompt count**, along with essential error/partial/retained-source indicators. Remove **Token Mix %**, all four **Input / Cached input / Cache write / Output** daily-share items, and token-mix-specific explanation/clutter from that particular summary. Token Mix remains available on the dedicated page and per-prompt cells; no historical/usage data is deleted.

No changes are requested to the CCost numerical display in the Watch row, the original I+E accounting, source attribution, native quota balances, full Token Mix page, Mini Watch layout, or prompt-specific Token Mix column.

## Confirmed code findings and boundaries

### Watch heading help, row cells and Today summary

- `src/web/assets/watch.js::columns` presently contains **the exact unnecessary CCost heading sentence and last paragraph**. The Model heading has two bullets and currently says only that linked subagents may use other models, without describing the Model-cell hover/focus mechanism.
- The same file's row rendering obtains the Model value via `display(prompt, 'model_detail_help')` and CCost value via `display(prompt, 'cost_detail_help')` using shared `ContextHelp.value`. A model with linked subagents gains a visible `*` and an accessible label, but an empty detail-help string does not guarantee a popup. The real subagent model/effort details come from the application's canonical prepared tokens, not browser-side inference.
- `watch.js::daily()` renders `CCost Today`, `value.total`, **`value.prompt_count`**, **`Token Mix %`** and each token-category share from `value.mix`. `src/application/live_projection.py` publishes `daily_usage.prompt_count`, `prompt_count_complete`, `total`, `mix`, `day_start_ms` and the configured-local day end. This count **already means today's prompts with model activity, including activity before Watch opened**; do not relabel it as “prompts this Watch run”. Some current UI notices are derived from `value.mix`; simplify specifically token-mix notices while retaining legitimate partial **CCost** and **prompt-count completeness** warnings, unavailability and retained observation signals.
- `src/web/assets/render.js::quotaHelp(quota)` is shared with other quota contexts, and `src/web/assets/account-cards.js::quotaTrack()` binds `ContextHelp.value` to the actual **Capacity** text for primary and secondary quotas. A minimal change to their safe display tokens can supply the new line without new question-mark buttons or changing the card geometry. Mini Watch uses deliberately compact **primary-window** help; keep Mini's existing compact scope unless a separate approved change requests it.

### Price-tier copy and grouped subagent accounting

- `src/reports/prompt_costs.py::prompt_cost_parts()` groups canonical physical model requests within a prompt by session/provider/model/variant and **`price_tier`**; `_price_tier()` formats tier text like `Default (0–272000 input tokens)` when a model has multiple price tiers. The tier remains essential to pricing correctness and to avoiding aggregation of requests with different rates.
- `src/application/prompt_costs.py::grouped_parts()` then aggregates those values into main/subagents groups keyed by **role, provider, model, variant, price tier**. It provides `agent_count` (distinct linked session IDs) and `calls` (physical model requests), plus the four category costs and subtotals. `detail_tokens()` appends the price-tier text to both the **Model** and **CCost** group headings at present. **Remove it from both *presentations* only**, keeping underlying grouping and rates intact.
- `detail_tokens()` currently exposes `model_detail_help` only if `model_count > 1`. This explains the documented **same-model linked-subagent star without popup**, even when model/effort/agent evidence is available. Change tooltip eligibility to include correctly evidenced linked subagents, while allowing a meaningful “subagent usage/model not yet recorded” qualification when links are known but usage is absent. Keep the existing multi-model, same-model, model-switch-without-agents and provider-identity semantics.
- `agent_count` and `calls` are **not the requested “Number of prompts”**. A single subagent session can issue multiple prompts/requests; one logical prompt can issue many physical requests, and the same agent may contribute via multiple tier/model groups. Introduce a deterministic source-backed distinct **subagent-prompt identity/count for each exported group** using canonical causal attribution, not `len(entries)`, `calls`, `agent_count` or row counts. Prove the mapping to actual child prompt boundaries; the current `PromptCostPart` only carries `session_id` and request-derived fields, so additional narrowly scoped evidence may be necessary. Deduplicate requests belonging to one prompt **within the group**; retain group-specific membership if one agent's separate prompts use different efforts/models/tiers. Unknown/incomplete prompt boundaries show `N/A`/qualified observed count instead of fabricated exact `0` or `1`.
- Preserve the existing maximum 24 displayed role/model/effort/tier groups, omitted-groups count, attributed known subtotals and incomplete-agent/call notes. The grouped numeric amounts and prompt-count evidence must be computed server-side; the Web should receive only allowlisted bounded fields, not raw session IDs, prompt text or request payloads.

### Period Capacity and subscription semantics

- `src/application/quota_ccost.py::quota_ccost_tokens()` currently generates `ccost_capacity` and `capacity_basis`:
  - **native** for an explicitly recognized provider-included monthly AI-credit CCost limit on the compatible credit scale;
  - **ratio** for a reliable, fully valued same-window Used CCost divided by native fraction used;
  - **unknown/unlimited** otherwise.
- `src/application/projection.py::quota_record()` already exports **`period`**, **`duration_seconds`**, **`reset_at_ms`**, **`window_active`**, scope/model identity, provider/native status, and CCost context. Full Watch quotas use `watch_accounts.py::watch_quota()`, including *every* primary and secondary component.
- `src/analysis/period_ccost.py::quota_window()` accepts validated provider-native rolling durations (or a separately verified fixed monthly calendar period). `monthly_quota_window()` gives real UTC calendar-month semantics for actual provider monthly quotas. Neither should be replaced by a guessed period from a label like “weekly”. Any 30-day equivalent must use the **actual proven full quota window length**, not the *time remaining until reset* or an inferred reset recurrence.
- For valid non-monthly numeric `CCost Capacity = C` and provider-confirmed period duration `D` seconds, the **display-only reference estimate** is:
  **Monthly Capacity (30-day equivalent; guesstimate) = C × (30 × 24 × 3600) / D.**
  Use unrounded `Decimal` math in the application/display layer; round/format at the same final Credits/USD display boundary as existing capacity. Example: **a 5-hour window with C = 1000 CCost → 144 000 CCost / standardized 30 days**; a 7-day weekly window uses factor **30 / 7**. Choose the **fixed standardized 30-day reference**, rather than variable 28/29/30/31-day calendar months, so comparisons do not change merely because the current month is shorter/longer.
- The new value must be explicitly labeled **`Monthly Capacity (30-day guesstimate)`**, or similarly concise accessible wording that makes “not an actual monthly provider quota” unmistakable. This is a **theoretical repeatability/throughput comparison** if the quota capacity recurred each period, not an entitlement, bill, refill promise or spending forecast. Overlapping rolling windows, multiple primary/secondary quota limits, suspension/rate throttling, account/model scope, incomplete sources and variable consumption can constrain actual monthly usable capacity. **Never sum quota equivalences**, multiply costs by native quota-unit ratios when their reference CCost conversion is unverified, or treat an unlimited/unknown window as finite.
- **A fixed weekly allowance** that has authoritative *CCost-equivalent* per-period capacity can also receive the extrapolation (still a guesstimate). Where a provider's weekly native limit is **not** in verified reference CCost units and the same-window CCost ratio cannot establish `C`, leave Monthly Capacity **N/A with a concise cause** rather than pretending that native requests/USD/other credits are 1:1 CCost. If a safe explicit provider-backed unit mapping exists, use it; do not assume one based on a label alone.
- **Already monthly quotas** retain their original native/ratio per-month capacity, without a redundant extrapolated fake monthly line. If a provider reports an unusual window whose actual duration/recurrence cannot be verified, omit the estimate and explain that limitation. Preserve reset clock, Used/Remaining mode, progress bars and native quota values exactly.
- The new tooltip line applies to **both primary and secondary non-monthly Full Watch quota Capacity targets**, with consistent handling in the shared Accounts quota help if it uses the same renderer. Do not add a new visible card row or rewrite subscriptions in Mini, do not change subscription/account charging semantics or provider usage APIs.

## User-facing target example (synthetic values)

**Watch / model heading:**
- `• Main prompt — The model shown in this column.`
- `• Linked subagents — If marked *, hover/focus the Model value to see their recorded models and effort.`

**Watch / CCost (I + E) heading:**
- `Estimated reference cost of this prompt, not your bill.`
- `I — Incoming context cost on the first model request.`
- `E — Other cost: output, later requests and linked subagents.`
- `Total = I + E when fully priced, before display rounding.`

**A grouped CCost value tooltip** retains a main section and adds the line only in subagent sections, for example:

- `Main prompt — Model A · High` then the existing four cost-category bullets and subtotal.
- `Subagents — Model B · Low (10 agents)`, followed by **`• Number of prompts: 10`**, then Input / Cached input / Cache write / Output and Subtotal.
- `Total CCost: ...` as before.

**A non-monthly Capacity tooltip** keeps its existing source/Used/Remaining/capacity description and adds, for example: `Monthly Capacity (30-day guesstimate): 144 000 CCost` for a verified 5-hour, 1000-CCost reference window. The same example in USD is correctly formatted using existing reference-unit policy, not native billed money.

**Watch's daily summary** becomes the compact idea `CCost Today · <amount> · <N> prompts`, with existing contextual help and any justified partial/error notices but **no daily Token Mix category presentation**.

Examples are expected *display semantics*, not live measurements or new native quota facts.
