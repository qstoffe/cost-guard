# FR 000574 — Show full-session CCost and collapsible Earlier Sessions in Mini Watch

## Owner request and outcome

**Owner-approved executable feature request, 2026-11-04.** Permanent identity **000574**, Ready priority **000140**, after existing Ready FR000570–FR000573. This is a **CostGuard Web Beta → Mini Watch** presentation and shared projection change, to be implemented **after FR000572** (canonical incremental/persisted session CCost). It does not authorize implementation now.

The owner wants the compact Mini Watch to distinguish **whole-session cost** from **the current prompt's cost**, without extra bold colors, new wide metric columns or losing the precious session-title space. In addition to the existing running/recently ended prompt table, Mini should offer a **collapsed-by-default, separate Earlier Sessions table**, showing at most the three most recent eligible ended sessions. Both Mini session tables should scroll together.

The owner's final decision **does not** merge the prompt-number, prompt CCost or Duration columns, change the CTX position, or mix stopped-session rows into the running table.

## 1. Running table: `Session / Total CCost`

1. Change the first column heading from **`Session`** to **`Session / Total CCost`**. Keep the full running/recently-ended table order **`Session / Total CCost | # | CCost | Duration | CTX`**. `#`, `CCost` and `Duration` still belong to the **individual focal prompt**; the last `CTX` column stays in its existing position with its existing value/meaning. Preserve the separate queued FR000571 change that removes the visible CTX `~`.
2. Display each first-column value as **`<session title> / <full session CCost>`**, for example `Refactoring a long session… / 4 582` (illustrative amount only). The amount after the slash is the **total CCost of the entire canonical root/session**, not just the prompt, the currently visible rows, the current Watch run or today's CCost. The standalone `CCost` column remains **prompt-local**. Column/header help, accessible row labels and user documentation must explicitly distinguish these scopes.
3. **Always preserve the ` / <session CCost>` suffix in view.** The **session title alone** is the flexible, ellipsis-truncated part: retain its **beginning**, then `…` on its truncated end; the separator and correctly formatted total cost remain visible at the **right end of the same first cell**. The entire original title remains available on focus/hover and to assistive technology. If the session title is missing, retain the established canonical session-ID fallback.
4. Use a constrained flex/grid-like layout **inside the first cell** or equivalent: title `min-width: 0`, elastic and truncatable; separator and session-total display nonshrinking and nonellipsized. Do not append price to the title *before* CSS text-overflow such that the price disappears. Keep the complete `Session / Total CCost` header readable. Do not truncate a session total, prompt cost, prompt number, Duration, CTX or their headings to make the title longer. At extreme manually narrowed widths, allow horizontal **region** panning instead of clipping or overflowing the PiP document.
5. Reuse the **canonical full-session cost and reusable incremental SQLite-derived aggregate** introduced by FR000572, including usage **before Watch/Mini opened**, historical prompts, eligible compactions, causal child/subagent work and running provisional usage. Multiple concurrent prompt rows of one session must display the **same** session-total state, while maintaining distinct per-prompt `#`/`CCost`/`Duration`. No browser-side summation of visible prompts, no duplicate valuation and no new independent history scan.
6. Preserve authoritative Credits/USD unit selection, display formatting, actual zero vs missing data, partial/unknown pricing, corrections, source revisions and retained/stale states. A not-yet-available aggregate may say `Loading…`/`N/A` or use the application's corresponding truthful state; never substitute the prompt cost, daily cost or a fabricated `0`. Keep already valid figures stable during ordinary updates rather than flashing an unnecessary loading state.

## 2. Header action and expanded `Earlier Sessions` table

1. Add a compact **`Earlier Sessions`** disclosure control **in Mini's existing top header**, on the same normal-width row as the left **`Cost Guard · Watch`** return action and the right **`CCost Today`** summary (the wording `CCost Today` is owned by FR000571). A small neutral chevron/indicator may communicate expansion; avoid distracting saturated backgrounds or major chrome. Do not alter the existing return-to-Watch or daily-summary actions. At genuinely narrow/zoomed widths, allow accessible header wrapping rather than overlap.
2. **Collapsed by default** every time a fresh Mini window is opened. Clicking, tapping or using the keyboard expands/collapses it in place, with accurate `aria-expanded`, an associated labelled region and visible focus. Preserve the user's expanded/collapsed choice across ordinary SSE publications/re-renders while the same Mini window remains open; do not automatically expand after new history arrives.
3. When expanded, show a **second compact table immediately ABOVE** the existing running-prompt table. Its only headings, in order, are **`Session / Total CCost | CTX`**. Each row represents **one distinct earlier session**; do **not** add prompt number, prompt-local CCost, Duration, state badges or other columns. The first cell uses **exactly the same title-ellipsis plus always-visible ` / <full session CCost>` presentation** as the running table.
4. Show **at most three** earlier sessions, selecting the **three most recent eligible finished sessions** using the **existing canonical Earlier Prompts/history ranking**, not browser wall time or a new last-activity heuristic. Existing full Watch publishes up to five `history_cards` with canonical finished-time ranking; reuse its eligible, session-distinct data/selection and take the newest three, preserving its **oldest-to-newest** presentation order. If only one or two exist, show those; if none, give a compact honest empty/loading/unavailable state. Respect unknown finish timestamps and the existing deterministic fallback ordering rather than inventing completion times.
5. Keep **active/recently terminal-grace prompts** in the running table under the existing shared Watch lifecycle. Do not list the same root/session simultaneously in Earlier Sessions and running rows; respect canonical history eligibility and ~30-second terminal grace. Once genuinely eligible, a session can enter Earlier Sessions with its **full** cost, not just the last completed prompt. If that session later resumes, its history/running classification and cached cost must update coherently.
6. **Earlier CTX** is the established **latest valid session/current-next context** available from the shared Watch/session projection (as specified in FR000572), not a sum of prior prompt contexts, a fabricated new estimate or a random historical prompt's value. Preserve `N/A` and approximation explanation in accessible header help, with no visible leading `~` after FR000571. The **running table's current CTX semantics are unchanged** by this FR. Help text may clarify the different row scopes.
7. Reuse FR000572's session-scoped cost projection/aggregate for both tables, including cached historical totals and currency switching. Collapsing the earlier table may hide its DOM but must not require revaluing entire sessions on reopen; do not create another source of pricing truth.

## 3. One scrollbar for both Mini session tables

- Put the expanded earlier table and the existing running table **inside the same vertically scrollable Mini prompt/session region**. Both tables must share **one vertical scrollbar**, not one scrollbar each or a nested earlier-scroll area. Earlier is above; running is below. The earlier table has **max three rows**; the number of running/recently-ended prompt rows has **no artificial Mini-specific maximum** and remains reachable by scrolling.
- Preserve the current compact PiP opening dimensions, user resizing and shared bounded region height; opening Earlier Sessions must **not automatically grow the native PiP window** or push the subscription/account region permanently out of reach. The existing **subscription scroll region remains independent**; the new shared-scroll requirement applies only to the two session tables.
- Keep column headers readable with subtle existing Mini borders/theme colors. If sticky headers are retained for both tables, ensure they do not cover each other or the active rows while scrolling; preserve sensible keyboard scroll, focus, horizontal overflow and reduced-width behavior.
- Long titles and enlarged session-cost strings, including currency and `?`/unknown states, must not force unexpected wrapping, hide a cost or create a whole-document scrollbar. Use existing quiet Mini warning/status behavior: no new orange 'live' adornments or visually loud section backgrounds.

## Existing implementation and FR boundaries

Inspected CostGuard `main` and backlog on **2026-11-04**:

- `src/web/assets/mini.js::View` currently builds one five-column `mini-prompt-table` from `view.active_cards`, with `Session | # | CCost | Duration | CTX`. `drawPrompts` shows exact focal prompt rows, including canonical terminal grace. No `history_cards` are shown in Mini today. The header has `Cost Guard · Watch` left and the daily summary right; add the disclosure between/alongside these.
- `src/web/assets/mini.css` already sizes non-Session columns to intrinsic minimum, allocates remaining width to Session and uses ellipsis for the session title, from **completed FR000569**. Extend this without undoing prompt-metric width constraints.
- `src/application/live_projection.py` exports `active_cards` and `history_cards` in the same Live publication; `src/watch/cards.py` owns the historical session eligibility and ranking. **Completed FR000561** established the five distinct Earlier Prompts history slots and the full-size Watch's finished-time order. Reuse them rather than independently choosing a 'latest' list in Mini.
- **Ready FR000571** independently removes the visible Mini CTX tilde and changes `Total Today` to `CCost Today` in Mini and Watch; do not reverse it.
- **Ready FR000572** adds the canonical full-session CCost summary and persistent **incremental SQLite CCost cache** to full Watch; this FR **depends on FR000572 being implemented first** and extends that server-owned aggregate into Mini. It must **not reintroduce** the eager expensive full-history aggregation removed by FR000545.
- **Ready FR000573** changes browser-session lifetime and is unrelated; preserve existing authentication/host identity/SSE security behavior.
- `docs/web-mini-watch.md` explains Mini's current per-prompt scope, single Live/SSE owner, dimensions, session-title truncation, independent prompt/account scrolling and quiet status policy. Update these facts once this FR is implemented; do not alter historical completion records.

## Acceptance and verification

1. At ordinary requested **560-DIP Mini width**, also tested with **150% Windows display scaling**, the running table reads **`Session / Total CCost | # | CCost | Duration | CTX`**. A long title visibly ends in `…` **before** the permanently visible slash and **full-session** cost. At a smaller manual width, horizontal region scrolling preserves every heading/cost. Keyboard/hover disclose the complete title and the scope of both cost values.
2. One session with multiple simultaneously running prompts shows the **same session total** on each row while retaining each prompt's distinct ordinal, prompt CCost and Duration. Older history outside visible Watch rows, compactions, child contributions, provisional running requests, correction/repricing and partial/unpriced data agree with FR000572's canonical session aggregate; unit switches update without recounting.
3. The top `Earlier Sessions` disclosure is collapsed initially; it remains stable across many SSE updates, works by mouse/touch/keyboard and has accessible state. Expanding renders exactly **two columns** with **zero to three distinct session rows**, and uses the newest three canonical finished sessions, oldest-to-newest within that subset. No duplicates with active/grace rows, even during completion, restart, resumption and re-entry.
4. **Both session tables use one scrollable viewport.** With 0, 1, 3 and more than 3 eligible earlier sessions, plus 0, 1 and many running prompts, only three earlier rows are selectable/visible, all running rows remain scroll-reachable, and the separate subscription scroll and native PiP size remain useful. Check sticky headings, focus, narrow/high-zoom and light/dark modes.
5. Earlier rows display a **whole-session** CCost and the canonical session context/CTX, not a last-prompt CCost or stale prompt context. Loading, missing history, unknown finish times, partial cost, reconnect/reload, midnight and legitimate empty publications remain honest; stale retained data is never labelled newly observed.
6. Prove that opening/toggling Earlier Sessions and updating Mini rows adds **no second SSE, browser-side valuation, per-tab history acquisition, per-frame timer or expensive per-row full-session rescan**. Reuse FR000572's cache/projection work; verify long-session/no-op updates and browser reload behavior. Add focused Web view/browser and server-projection regression tests, and update `docs/web-mini-watch.md`.

**Scope boundary:** Mini Watch presentation, narrow typed Live projection if necessary, relevant tests and user help. **Non-goals:** changing full Watch's new FR000572 visual summary, the Sessions page, CLI, account/daily accounting, prompt CTX computation, subscriptions, theme palette, source database or security. **Backlog publication only:** add this approved Ready FR and advance identity-state; no product-code change, release/version bump or running-server interaction now.
