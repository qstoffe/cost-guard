# FR 000619 — AI Stats: eliminate avoidable cascading Unavailable metrics by recovering usable history evidence

**Owner-approved Ready Feature Request, 2026-11-06.** Permanent identity **000619**, queue priority **000370** after existing FR000618 (000360). **FR-only publication now**: write this standalone Ready FR and update identity state, without product edits, tests, release or version changes.

## Owner-observed problem and intended result

On **Cost Guard Web Beta → AI Stats**, after a report has **finished loading**, **almost every metric card** can display **`Unavailable`** despite the owner having substantial recorded usage. This is surprising and makes the page largely useless. The owner wants the metrics to **work with the available history**, not simply report `Unavailable` for most cards.

**Primary goal:** Diagnose and correct the **causal evidence/aggregation problems**, so a normal, healthy, well-populated dataset yields as many actually supported values as possible. A single missing or malformed historical field should **not automatically blank all otherwise computable metrics or unaffected date windows**. Show accurate full values wherever provable; otherwise use specifically qualified **observed/partial** metrics where mathematically safe, and explain actual missing evidence. Do **not** merely replace `Unavailable` with fake `Loading` after the job completes, invent zeros, assume missing end times, or hide real source corruption.

The owner has not provided private history files or a per-card diagnostic trace in this request. The repository evidence below proves a mechanism **capable of generating 7–9 unavailable cards**, not which exact private record(s) caused the owner's latest observation. Reproduction and accountable source diagnosis are part of this FR.

## Root cause candidates established directly in current code

1. **One unknown interval can invalidate the entire timing family.** `src/analysis/ai_stats.py::_timing(roots, start, now)` sets a single **`unknown=True`** when any considered execution/compaction interval has `start <= 0`, `duration is None`, or `duration < 0`. `_time_metrics()` then returns **`None`** for **AI Working Time, Longest Session, Busiest Day, Night Owl, Coding Streak and Peak Parallel Sessions**; `_cost_metrics()` also cannot compute **AI Hourly Rate** without known duration. A single problematic interval can therefore yield **seven of ten** unavailable cards, even while other intervals have valid evidence. This is a **per-period global invalidation**, not seven independent calculation failures.
2. **One incomplete snapshot can affect nearly all cards.** `period_stats()` currently computes **`source_complete = source_complete and all(root.source_complete for root in roots)`**. `src/reports/ai_stats_evidence.py::payload()` derives each root's `source_complete` directly from `snapshot.complete`; the global source/migration warning is an additional gate. One incomplete root currently blocks time metrics and the **exact** cost-derived records, and can cause **nine of ten** cards to be unavailable when combined with missing-cost status, while Total AI Cost retains only a `partial` observed subtotal. Investigate why the source marks the root incomplete, not only the presentation of the resulting false-looking blank grid.
3. **Any incomplete pricing/usage can suppress independent exact cost results.** `_cost_metrics()` aggregates `source-incomplete`, `unpriced-requests`, `missing-token-usage` and `pending-usage` into one `complete` Boolean. When false, **Average Cost per Session** and **Most Expensive Session** return null even when part of the data is valid. **AI Hourly Rate** depends on both complete pricing and complete execution time. Preserve the original meaning of “exact” while exploring honest partial, lower-bound or provably safe alternative presentations instead of suppressing every useful observation.
4. **Period/window locality may be too coarse.** `StatsAcquisition.project()` in `src/reports/ai_stats.py` can verify which *still-pending* roots can be safely excluded based on `ai_stats_evidence.coverage()/exclusion()`, but then builds `evidence` for **all currently loaded roots** before calling `period_stats(..., start=period_start)`. The latter gates `source_complete` over **every passed root** and checks unknown timing conservatively. Verify whether source-/interval-incomplete **old roots that are independently provably outside Today/7/30-day windows** still poison those periods. It is **not** safe to exclude a root merely because its title/update timestamp is old: a root with unknown end may cross the boundary, and missing events may conceal recent work. Any exclusion must be based on authoritative coverage/revisions, not metadata guesses.
5. **The `Unavailable` text comes from completed-result display logic.** `src/application/ai_stats.py::stat_tokens()` deliberately renders `Unavailable` for **`value is None`** except genuine `no-data`. The Browser `src/web/assets/ai-stats.js::View.update()` displays those already prepared values. Changing CSS, extending the loading timer or replacing the label in JS cannot repair unknown canonical metric values.

## Required diagnostic first step

Before modifying formulas, obtain a **sanitized, reproducible root-cause matrix** for each of the ten cards in at least one synthetic heavy fixture and an **authorized read-only real-source probe if available** (do not require the owner's private data to be pasted into public GitHub). Differentiate:

- chosen period and whether **the requested scope is truly complete** versus worker still running/resuming or stale cache;
- source generation/revision/migration warnings, count of incomplete `snapshot.complete` roots and whether those roots are proven relevant to the period;
- counts of unknown/negative/missing execution start/duration, provisional running intervals, compaction/child provenance and their period boundaries;
- missing token fields, unpriced model requests, pending usage and how many distinct root sessions they affect;
- per-metric causal reason codes, **first-level root/evidence categories (counts only in public output)** and which supported known contributions survive independently.

Use internally scoped, **opt-in local diagnostics** with no raw prompts, titles, paths, IDs, credentials or source exception text in GitHub artifacts/logs. If local in-memory identities are necessary to trace the specific failure, do not publish them; provide a sanitized summary. Establish whether the dominant cause is (a) a legitimate source gap, (b) incorrect/overbroad root or period completeness gating, (c) a time/usage normalization bug, (d) cache evidence lost or mismatched, or (e) a stale view mistakenly treated as a completed scope. Do not declare one of these established for the owner's installation without evidence.

## Correctness and recovery requirements

1. **Fix recoverable evidence at the source.** Trace ordinary recorded execution start/end and model/token telemetry through V1/V2 normalizers, causal child/compaction attribution, `StatsRoot` interval preparation and compact cache. Where source has authoritative end timestamps, durations, request usage or completed-state evidence, **recover them rather than propagating null unnecessarily**. Separate truly missing source evidence from an implementation omission or too-early partial snapshot. Revalidate recovered values by source revision/identity and keep read-only boundaries intact. Never derive execution time solely from wall-clock session age, prompt completion guessed from adjacent unrelated events, or provider/model price guesses.
2. **Localize incomplete evidence to the affected period and metrics.** Stop one objectively irrelevant old root or one unrelated missing field from invalidating the entire currently displayed Today/7/30-day report. Use safe per-root/per-interval temporal proof, global membership completeness and specific dependency proofs, including active roots with old metadata, missing ends, source warnings and migration gaps. Keep fail-closed semantics where overlap cannot be ruled out. Check 30 days/This month/All time separately; do not silently exempt old unknown roots from All time.
3. **Independent metric computability.** Determine for each of the ten cards whether its exact value is provable *independently* of other fields. Preserve a fully known cost when timing is unknown and vice versa. Missing price on one request must not erase a separately verified time total; a missing duration must not erase a verified prompt count/cost. Only suppress the part of a result that needs unavailable evidence. Do not use one global `source_complete` or `unknown` flag to blank outputs whose correctness can actually be established with a narrower, explicit proof.
4. **Meaningful, safe partial answers when exact is impossible.** Prefer source-backed **`Observed ≥ X`**, `Partial X`, `Observed total X` or similarly concise in-card values **only where a mathematically valid bound or measured subtotal exists**. For example: a known union of valid intervals can be an observed lower bound on total working time, but **not** an exact total; a current record winner can be a *known so far* leader, not a guaranteed longest/most expensive overall. Do not manufacture mathematically invalid averages, hourly-rate denominators, streak records, night-owl shares or peak concurrent-session maxima from incomplete unknown overlap. Use existing `Partial`/`Provisional` states, clear explanations and accessible per-card help; establish unambiguous semantics for any new bound. Keep unsupported figures explicitly unknown rather than fake precision.
5. **Do not mislabel processing as evidence failure.** While FR000614 is still acquiring/resuming and lacks a coherent selected-period result, show the FR000609 progress/wait state. When a report genuinely finishes, do not leave it indefinitely `Loading`. Legitimate empty input is **`No data`** (or real zero where defined), not unavailable. Truly unprovable results may still require an explicit **`Insufficient data`** / reasoned unavailable state; the owner goal is to **eliminate avoidable mass unavailability**, not to conceal irrecoverable source absence.
6. **Robustness on large/recently modified histories.** Support multiple active prompts, nested agents, compactions, archived/deleted roots, source changes during acquisition, in-progress entries without final usage, genuine missing price catalogs, partial migrations, and source V1/V2 differences. Retain canonical root/child dedup, overlapping execution union, local timezone/DST, event-time cost and source-history completeness. No hidden full-history rescan, new paid model calls, arbitrary inferred ends, source writes or unbounded process/CPU load.
7. **Cache/checkpoint correctness.** Any change to evidence completeness/interval meaning must version/revalidate `src/reports/ai_stats_evidence.py` and FR000614's compact checkpoint/coverage proofs. Old cached `source_complete` and known-end signals may not silently become stronger guarantees after an algorithm change. Recompute only affected roots when safe, but do not accept invalid/stale cached evidence to fill the UI. Preserve correct 30-day and narrow-scope resumption; cooperate with pending FR000617 shared dispatcher without inventing global validity.
8. **UI remains concise.** Keep the existing ten cards, headings, traits for complete results, optional eleventh matched-input card and stable content geometry. Healthy common histories should show actual values rather than a grid of `Unavailable`. Per-card precise limitations remain available via the current shared help interface, not a verbose diagnostic dump or a redundant new summary card.

## Targeted acceptance criteria for implementation

1. **Single bad timing datum**: synthetic multi-session 30-day/All-time evidence with dozens of valid intervals plus one genuinely unknown duration. Confirm all independent valid metrics remain visible; safe known time subtotal/bound may be shown as qualified partial, but no exact full duration/hourly rate, Night Owl, peak or winner is fabricated. When the one bad duration can be legitimately recovered from supported source data, full canonical results return and match the independent reference.
2. **Single incomplete root**: one of thousands of session snapshots returns `complete=False`. Prove it triggers appropriately localized reasons and **does not indiscriminately blank all unaffected metrics or independently excluded periods**. When source coverage is genuinely unprovable, do not claim false 100% completeness; expose the correct affected metrics and precise reason.
3. **Old error vs recent periods**: construct (a) an old root whose authenticated, revision-checked complete end is provably before Today/7/30-day boundary and (b) an old-looking root with an unknown end and possible recent activity. Only case (a) can be safely excluded from the recent period; case (b) must remain in scope. All time still includes both as relevant. Test missing snapshot `complete`, source migration gaps, rollover and Stockholm DST.
4. **Cost-field independence**: individually create missing price, token field, pending usage, bad duration and a correctly priced complete session. Assert the correct remaining numerical results and targeted reasons with no false Cost/Time linkages. A true zero cost/zero duration/empty observed set must not be conflated with unknown.
5. **Full-corpus parity**: for completely healthy synthetic histories (including 2,700-root/54,000-request-scale and V1/V2 cases), *all ten outputs and optional matched fact* remain identical to the previous canonical calculation. Large sparse/partially corrupt histories should yield **more provably supported numeric information** than the old broad-invalidation model where possible, never less correct information or fabricated full values.
6. **Real-source diagnosis and timing**: if an eligible authorized local read-only installation reproduces many `Unavailable`, record redacted **reason/count distributions**, identify the factual failure categories, and compare before/after count of actual complete vs partial vs genuinely unknown cards for the same source/revision as possible. Disclose if the owner's exact run remains unverified; never present synthetic results as proof of that private incident. Measure incremental source/catalog I/O, CPU, memory, first-completion and warm revalidation versus FR000614 to prevent a performance/Watch regression.
7. **Lifecycle/display**: test pre-ready versus complete, 30 → 7 → All, stopped source, cache corruption/price revision, Credits/USD, Classic/Web themes, hover/focus/touch explanations, keyed cards, repeated visit/quiet refresh and no fake `100%`. Product code remains read-only; one failed card must not poison other cards' observable state.
8. Extend focused `development/tests/test_ai_stats.py`, `development/tests/test_ai_stats_resume.py`, reporting/evidence projection tests and `development/tests/integration/probe_ai_stats.cjs` / `probe_ai_stats_states.cjs` as warranted. Update current Web/AI Stats documentation and knowledge **when implementing**. Do not impose unrelated permanent release/testing gates during authoring.
