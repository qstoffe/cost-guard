# FR 000602 — Unify Web Beta tables with Watch styling and fix Sessions loading, dates and detail layout

**Owner-approved executable Ready Feature Request, 2026-11-06.** Cost Guard Web Beta only. Permanent identity **000602**, Ready priority **000185**. **Sequence:** after **FR000596** (priority 000180, two Token Mix tables), before currently queued FR000597 (priority 000190). This is one cohesive multi-page UI consistency and Sessions behavior FR, not a rewrite of the independent source/price accounting engine.

## Owner observation

The recently rebuilt **Sessions** catalog and single-session detail tables look unlike **Watch → Running Prompts**: oversized headers, different background and cell treatment, missing matching rounded table outlines, and a large apparent gap between **Prompt** and **Model** in the detail history. The **Models** table also needs the same visual language. The user wants the **two future Token Mix tables** from FR000596 reviewed and conformed to the same Watch look after that FR lands.

Further observed problems:

- Sessions catalog **Last activity** shows an undesirable machine/browser-dependent date/time representation (including possible 12-hour **AM/PM**) instead of consistent **year-month-day and local 24-hour clock**.
- **Model, CCost, Prompts, Duration** may display **N/A** while their underlying session summary is *still being loaded/indexed*. The user wants **Loading…** for genuine incomplete acquisition, not a misleading terminal unknown.
- Later catalog pages sometimes already have metrics while many **page-1** sessions still have none. The user expects the **currently viewed, newest first page** to be populated before unrelated older pages; prioritize the actual visible page when navigating, without starving all background history or falsifying a global sort.
- If a session has an actually **running prompt**, **every text value in its Sessions catalog row** should be yellow (the established Watch running color), and the session-name cell should begin with literal **[RUNNING]**.
- **Previous/Next** below Sessions should be recognizable **buttons** rather than ordinary links, with visibly disabled first/last-page states. Try **Previous — centered range/page label — Next**.
- When entering a session, the pending **“Waiting for session source observation…”** should become a proper **loading progress indicator**, not a static stale-looking message. Show honest indeterminate progress when progress cannot be measured.
- Some session details pan horizontally too readily. **Prompt** must shrink early, allowing its preview to ellipsize after **around 20 characters** on constrained widths; other columns retain their meaningful readable values. Only if genuine minimum content still exceeds the viewport should horizontal scrolling become necessary. No nested vertical table scrolling.
- The session detail **Ictx** cell currently can show a **delta → next-context** string even though the user wants only **the incoming context of that prompt's first request**. Remove the arrow/right-hand resulting Ictx *for the Web session detail only*, preserving actual CLI/Watch semantics.

## 1. One shared Watch-derived table visual system

Implement/reuse a narrow shared visual style for **actual Web Beta data tables**, primarily:
1. **Sessions catalog** (6 columns, 50/page, sortable).
2. **Sessions detail** (one full unpaged chronological prompt table, initially 10 columns; see Ictx change below).
3. **Models** reference/model comparison table.
4. **Token Mix → by model and by publisher** (two 13-column sortable tables delivered by FR000596).

Retain each table's *distinct data, column count, interaction and sorting contract*, but unify presentation:

- **Watch Running Prompts look and feel:** compact, short header height and row padding, same surface-tone header, similar font/weight, subtle full per-cell gridlines, consistent numeric/text alignment, and a **single thin rounded table border/corners** with correct clipping and coherent left/right/top/bottom corners. Do not add a separate giant panel/card or duplicate border on every containing div.
- **All columns are real aligned cells** under their headers with no discontinuous 20–40px visual gap or track drift. Use robust shared CSS variables/classes where practical rather than fragile page-specific copies or a global blanket `th/td` override that damages other views.
- Preserve sortable header buttons and their accessible `aria-sort`/arrows but make the *actual visible header text* the compact target; no oversized button padding/min-height, standalone `?` icons or hover hit area spanning dead cells. Keep meaningful context help and FR000590 focus/tooltip behavior.
- Use the existing Classic, Web light and Web dark theme tokens; no accidental Watch-running yellow on ordinary Models/Token Mix/Sessions rows. Keep Models' data-specific promotional/new/relative-tier presentation and sorting. Keep token-mix single-line long names where required.
- Prefer responsive content-fit with only the intended flexible text column (e.g., **Session name** or **Prompt**) growing/shrinking; numeric/metric columns use truthful intrinsic minima and never ellipsize the number to disguise overflow. A 13-column Token Mix table **may require horizontal panning** at common widths; scrolling should be deliberate, keyboard/focus accessible and not introduce a fixed-height inner vertical scroller. Ordinary document scrolling stays vertical.
- Preserve exact semantic table structure (`table`/`thead`/`tbody`/`tfoot`, real header associations), selection/focus, accessible table navigation, live row reconciliation and sorting. Do not replace semantic tables with unrelated cards merely to imitate the look.

## 2. Sessions catalog: local time, loading semantics, active rows and priority

### Last activity timestamp
Render exact source epoch milliseconds as **YYYY-MM-DD HH:mm** (seconds `:ss` acceptable if consistent), **24-hour**, using the **viewer's local computer/browser timezone** while retaining a deliberately Swedish year-month-day *display pattern*. Example: `2026-11-05 23:14`, **never AM/PM**, no US month/day ordering. Use real timezone/DST conversion, including timezone offsets at DST transitions; **do not hardcode Stockholm/UTC offset**, parse locale strings, or change sorting. Sorting continues on the raw timestamp. Reuse a supported shared formatting helper if appropriate, but do not inadvertently change other pages' date semantics.

### Loading / unknown / failure
- Distinguish **unindexed / awaiting pending source work** from **canonically indexed but truly unknown/unsupported**. While the per-row model, CCost, prompt count or duration has not yet been populated, show a restrained **Loading…** in that cell (with truthful accessibility metadata), not `N/A` or `0`. Once populated, display actual values; **a real 0 stays 0** and a verified unavailable/unknown value may legitimately stay **N/A**.
- Do not leave a permanently failed/unavailable row falsely `Loading…`: expose an accurate compact unavailable/retained/partial state after actual bounded error or source trouble, preserving source health and any last valid observations. Different metrics may have different availability; do not turn true unknown into alleged pending or fabricate progress.
- A new/visible page must remain usable while other rows load. No clearing already-known good values on routine refresh; keep source-revision/cost-completeness protections, avoid unnecessary flicker, and do not restart all visible loading at each five-second poll.

### Work priority and global sorting
- For the default **Last activity descending** ordering, prioritize indexing the **current visible 50-session page**, especially the newest page 1, **ahead of arbitrary older catalog roots** in normal healthy acquisition. When the user navigates to a later page, shift priority to those actually visible 50; when they navigate back, any retained validated metrics should appear immediately.
- Fix cases where later, nonvisible sessions are fully indexed while the visible first page stays pending **without a defensible fairness/source-error reason**. Use a bounded current-page-first policy combined with explicit background fairness/progress and healthy source/CPU limits. An optional next-page prefetch is fine only if it does not delay the current page.
- Preserve FR000593's **full-catalog** sorting semantics for all six keys, including its explicit temporary `pending_sort` behavior while exact metric keys for every root are not ready. Never pretend globally sorted Model/CCost/Prompts/Duration rows based only on the visible page or estimates. Improve readiness/progress for visible rows independently of the global index.
- Preserve page 2+ stable epoch/membership as new sessions arrive, exact 50/page count, new-session placement on live page 1, and source/revision/identity boundaries. A running session still updates truthfully within the appropriate visible epoch.

### Running row
When canonical evidence confirms **any currently running prompt** in that root/session, apply the established **`--watch-running` yellow to all displayed text**, including date, clickable session name, model, cost, prompt count and duration, across themes. Prefix the name cell with literal **`[RUNNING]`** before the actual title, with a separating space; the prefix is a status marker, **not** part of the stored title or sort key. Keep the title a normal navigable link and the state readable without color. Remove the marker/color when the last running prompt genuinely ends; do not infer it merely from “recently active”, stale observation or absent finishing data.

### Pager
Replace hyperlink-looking Previous/Next with visually obvious **button-styled navigation controls**, real or equivalent accessible buttons, with clear **disabled state** on first/last page (not just a grey anchor losing `href`). Maintain normal URL/history navigation, browser Back/Forward, keyboard/touch, total/range correctness and no duplicate clicks during loading. Arrange footer as **Previous (left) | Showing A–B of N · Page X of Y (centered) | Next (right)**, centered independent of button width where practical. On narrow viewports wrap cleanly in a defined order without overlap, clipping or a floating label. Test actual result on both short and long count labels; adjust only if centered layout proves unusable at narrow widths.

## 3. Session detail: Watch appearance, compact Prompt, isolated Ictx and progress

- Keep FR000593's **single complete chronological prompt history**, one semantic table and `Complete session` totals, with the same Watch-derived compact header/cell/border/corner styling. Maintain running/error color/marker, context-warning line and all existing source metrics unless explicitly changed here.
- Repair **Prompt → Model excessive space**. The first track currently has a wide flexing minimum; make **Prompt** the only adaptive text track, but **do not force it to fill huge unused space** if doing so creates an apparent multi-table split. Keep clock and `[RUNNING] #` legible. As width tightens, truncate the *preview* early; **around 20 visible characters before ellipsis** is an acceptable compact target, with complete original text obtainable from the existing tooltip/accessibility label. Do not cap all previews to 20 characters even on spacious displays merely to remove a gap. Do not truncate date, cost, Calls, context or tokens first.
- At normal desktop widths, fit without horizontal panning when the actual content permits. If the full set of important minimum headers/values still cannot fit (including zoom/narrow screens), allow **one clear horizontal table-region scrollbar/pan** rather than clipping or introducing a misleading second side-by-side table. **No nested vertical scroll**: document itself owns vertical scrolling. Verify the responsive fallback and avoid forcing document-wide horizontal overflow or unexpected double scrollbars.
- **Ictx column:** its cell shows **only the first-request incoming context value** for that prompt, using the canonical unmodified `incoming_context_tokens` and existing compact formatting, e.g. `17K`. **No `Δ → next Ictx` string, no arrow and no resulting/context-after value.** Unknown remains N/A/appropriate loading based on actual source state. This affects **Web Sessions detail only**; preserve CLI's richer context transition display, Watch's separate Ictx/Δ Ctx meaning, and the raw context computation. Adjust the detail's `Complete session` footer if needed to keep this one-column meaning consistent without silently changing other metrics. Keep current distinct `Ictx CCost` and `Extra CCost` columns.
- Replace idle text **“Waiting for session source observation…”** (and equivalent initial pending text) with an accessible, visually unobtrusive **indeterminate HTML progress bar/spinner** with succinct `Loading session…` context. If actual measurable completed/total steps exist, real progress may be shown, but **never invent a percentage based on elapsed time**. Show it only during actual initial/detail acquisition and pending continuation, not when a complete retained history is merely being background-checked. Preserve usable previously loaded table during refresh. On genuine source unavailable/auth/partial/error, show truthful status instead of an endless “loading” bar. Prevent the bar from causing layout jumps or stale pending states after successful revision-pinned chunks arrive.
- Keep the existing source-owning bounded `/api/detail` lease, revision pinning, 25-row chunks, 5-second checks, cleanup/Stop, and no frontend polling fanout. Preserve scroll anchors, selection and keyboard focus for 1,000+ prompt sessions and for running-to-completed updates; the whole history must remain complete rather than truncating rows to improve appearance.
