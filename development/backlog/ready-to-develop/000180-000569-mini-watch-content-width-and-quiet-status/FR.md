# FR 000569 — Mini Watch: content-sized metric columns and quiet retained-data status

## Owner request, scope and queue

**Owner-approved executable feature request — 2026-11-03.** Permanent identity **000569**; Ready priority **000180**, following the existing Ready FR000566–FR000568 (the latest currently at 000170).

Scope is **Web Beta → the floating Mini Watch Document Picture-in-Picture window only**. The owner requests two related presentation refinements in one FR:

1. **Give every prompt-table column except Session its minimum content-fitting width.** Both the entire column heading and all currently displayed cell values must fit without ellipses or clipping. **Session** gets *all remaining usable table width* and may ellipsize long **session titles**.
2. **Stop displaying transient update/freshness problems as orange warnings and extra status text.** In particular, the Mini Watch header must not routinely append **“Not current”** to **Total Today**, and the prompt area must not flash **“not live”**, **“waiting”**, **“retrying”**, or similar warnings merely because an update is temporarily late or incomplete. Keep the last valid figures quietly visible. Only a *sustained, exceptional* failure should warrant one unobtrusive status indication.

This request concerns the **compact display and warning policy**, not a new accounting method, new polling mechanism, or changes to the ordinary full-size Watch.

## Inspected current behavior

Reviewed `qstoffe/cost-guard` main on 2026-11-03:

- `src/web/assets/mini.css` applies `table-layout: fixed` and assigns fixed percentage widths to the five prompt columns **Session 34%, # 10%, CCost 18%, Duration 21%, CTX 17%**. This wastes space on short metrics and needlessly truncates session titles. Headers are centered today; numeric cells are right-aligned and the Session title is ellipsized.
- `src/web/assets/mini.js::View` builds the table headings **Session | # | CCost | Duration | CTX**. `drawPrompts` supplies the actual live per-prompt strings and exposes the full session title on focus/hover. `drawDaily` builds the canonical `Total Today <CCost> · <N> prompts` line, then appends **“Partial”** or **“Not current”** when completeness, acquisition state, or freshness indicates a warning; it applies `mini-warning`, making the entire line orange.
- `View.update` also sets a prominent `mini-health` line for reconnecting, waiting, missing source observations or partial prompt/pricing data. Some subscription lines visibly append `quota stale/unavailable`. `Controller.render` treats more than 15 seconds without a fresh publication as overdue and checks this using a visible-PiP 5-second timer. This is a reasonable *internal freshness signal*, but an unsuitable threshold for repeatedly alarming the owner in a compact always-visible window.
- Existing `docs/web-mini-watch.md` correctly distinguishes retained observations, canonical day scope, genuinely unknown costs, real quota restrictions and terminal connectivity problems. Preserve those **data meanings**, while adjusting what is shown prominently and when. Completed FR000561 defined the current Mini tables; completed FR000565 defined the centered headings, Total Today header, compact initial geometry and native-height testing.

## 1. Minimum-width metrics; Session receives the remaining width

- Size **#, CCost, Duration and CTX** according to the **maximum intrinsic width actually required by each column**, considering both its **full header text** and **all visible cell values** (including formatted numbers, signs, approximation/unknown markers such as `~`, `?` and `N/A`, and padding/borders). Do **not** use the current fixed percentage allocations or arbitrary equal-width columns.
- These four columns must occupy **no more width than needed** to show their complete current content, yet must **never truncate or use ellipses**, including in the headings. Avoid undesirable line wrapping that disguises clipping or unnecessarily enlarges the column vertically.
- **Session** is the only elastic column: its heading remains legible, and the **rest of the available horizontal space** goes to session titles. Long session titles may use single-line ellipsis, with the existing full-title focus/hover accessibility preserved. Do not truncate a metric just to give Session more width.
- Keep **centered column headings**, **left-aligned Session titles** and **right-aligned numeric values** as established in FR000565. Preserve table order, row/status colors, prompt identity, sticky headings, scrolling regions and the compact Mini geometry. The empty-row `colSpan` must not distort column sizing.
- Column requirements must adapt when rendered values change (e.g. a prompt number becomes multi-digit, duration/cost gains digits, CTX changes from `N/A` to a larger number). At ordinary Mini width, all extra space belongs to Session. At extremely narrow manually resized widths where even the full headings/metrics cannot all physically fit, favor **horizontal scrolling of the prompt region** over clipping any non-Session column or allowing layout to escape/overlap the native PiP frame. Do not require a larger initial PiP window.

## 2. Quiet transient stale/retry/partial states

- When **Total Today** already has a usable observation, keep showing the last valid **CCost and prompt count** during brief gaps, retries, reconnections or incomplete refreshes. Do not append **“Not current”**, **“Partial”**, **“not live”** or similarly noisy operational suffixes to the prominent Total Today text during ordinary fluctuations; do not color the entire summary orange merely because a refresh is late.
- Apply the same quiet behavior to the **prompt table and its nearby health/status area**. Retain previously valid prompt values/rows when a publication is merely missing/temporarily unusable; do not substitute alarming source-state text for real retained numbers, turn the table orange, flash banners or emit repeated status lines on each freshness tick. Fresh, valid canonical publications still update rows and may legitimately remove completed prompts according to the existing grace policy. The implementation must distinguish an actual valid empty state from a failed read.
- Minimize equivalent **transient acquisition/stale notices** in Mini subscription summaries as well. Preserve real quota values, genuine provider restrictions, exhausted states, partial/unknown *numeric* provenance (`?`, `N/A`, etc.) and the established running/success/error row colors; this FR does **not** turn unknown or estimated figures into falsely precise ones.
- **Sustained failures only:** for recoverable connectivity/freshness/source-read problems, treat the first **10 continuous minutes** without a usable new observation as the threshold for **one short, non-flashing, unobtrusive message** such as “Updates unavailable · showing last values”, placed **separately from the Total Today numbers**. Reset this timer after a genuinely fresh usable observation; repeated minor retries must not reset it without recovery. If the host definitively stops, authentication is irrecoverably lost, or the source identity changes, a concise actionable notice may appear sooner, since this is not an ordinary transient retry. Avoid multiplying warnings between the header, prompt region and subscriptions.
- **Truthfulness and safety:** retaining a displayed value is **not** a new live observation. Keep freshness/state tracking accurate internally and preserve accessible disclosure of when values were last observed, e.g. a suitable nonintrusive tooltip/description, without visual status spam. Do not extrapolate cost, duration, prompt count or quota metrics. Before any usable first observation, a neutral **Loading…** / empty state is appropriate rather than invented numbers.
- Respect the **configured local-day boundary** for Total Today. Never present yesterday's retained amount as today's fresh total after midnight; use the existing canonical day/date metadata and its publication policy. A real correction, source-side state change or new day must still replace old figures when valid data arrives.

## Acceptance criteria

1. In a normal Mini Watch window with multiple concurrent prompt rows, **#, CCost, Duration and CTX** are each only wide enough for their full visible data or header, whichever is longer; no metric/header ellipsis or forced wrap occurs. **Session** visibly takes up the freed width and alone truncates long session titles. Full titles remain available via keyboard focus and hover.
2. Verify single/multi-digit prompt numbers, short/long duration, formatted CCost, CTX including **`~`/`N/A`**, partial pricing marks, empty table, and live updates that change the longest value. Check no column overlap, clipping, or excess blank metric space. Confirm sticky headers, row alignment and scroll work at the default **560-DIP requested width**, the owner's **150% Windows display scaling**, and a manually narrowed PiP.
3. Simulate a normally healthy stream followed by intermittent delayed publications, reconnects, daily refresh retries, partial or unavailable prompt reads and quick recovery. **Total Today and prompt figures remain visible without orange “Not current” or rapid operational warning text.** Brief failures and the ordinary 15-second overdue signal do not surface as visual alarm states.
4. Simulate a real sustained outage **just before and after 10 minutes** and verify a single restrained, accurate retained-data notice appears only after the threshold, clears on genuine recovery and does not duplicate across areas. Verify definitive host stop/auth failure is actionable, while retained figures are never claimed to be current.
5. Verify real zero/unknown/partial values, pricing provenance, local-day rollover, legitimate prompt completion/eviction, subscription exhaustion/restriction, accessible descriptive text, and that the full-sized Watch remains unchanged. Reuse existing Live/SSE ownership—no new readers, requests, timer-driven metric extrapolation or backend accounting changes.
