# FR 000537 — Unify Web Beta Models, improve model-table browsing and OS launch handoff

## Owner goal and existing behavior

Turn the current minimal **Overview** into one useful **Models** page, without the redundant old Models view. The page should be a wide, naturally page-scrolling comparison of Copilot-priced models, with two clear inclusion filters, genuine numeric/date sorting, and no subscription cards. Make Windows/macOS Web launcher handoff visibly continuous rather than closing the launch window and leaving several silent seconds before the browser appears.

This **intentionally supersedes the relevant UI decisions in completed FR000535**: its Overview-specific internally scrolling/fixed-body table, no-sort policy, account cards and placement of new-model notices. Preserve FR000535's uncluttered shell, accurate four-column relative-price formatting, subtle column dividers, collapsed explanations and honest first-report progress unless explicitly changed here.

Code inspection (2026-11-01):
- The current Overview uses `src/web/assets/render.js::overviewModels` with `.overview-model-table tbody { max-height: 60vh; overflow-y: auto }`; the page also renders `overviewAccounts`. `index.html` exposes both Overview and Models navigation.
- `src/web/assets/reports.js` still routes `#/models` to a separate selectable view and `#/models/all` to an all-models view with extra native-price column. This FR **retires that old view**, not its useful underlying pricing/catalog facilities; revisiting its extra functionality is future scope.
- `src/reports/service.py::_model_comparison` already intersects Normal's Copilot pricing catalog with **globally selectable OpenCode model IDs** through `selectable_catalog`; all-models instead uses the complete price catalog. If availability is unverifiable, the existing intentional fail-open behavior displays the full catalog **with a warning**. This is not separate proof of each subscription's entitlement. Preserve truthful status; test the default scope explicitly.
- The current Windows `.cmd` intentionally starts hidden, detached PowerShell and exits immediately; the PowerShell/Python launcher already has sanitized stage reporting. macOS `.command`/Finder launchers use separate, native-supported paths. The early closing window is a real handoff/design issue, not necessarily slow report calculation.

## 1. One Models page and navigation

1. Rename the visible **Overview** menu entry to **Models** and make it the primary page, at canonical `#/models`. Remove the old, separate **Models** navigation entry/page, including its selectable-vs-all catalog tabs, separate search/pager and optional `GitHub USD/M I/C/W/O` table column. Do **not** revive these old controls within the new page.
2. Keep exactly four table columns in order: **Publisher | Model | Relative CCost | Release date**. The new page otherwise inherits Overview's compact look and initial browser/report progress/error states.
3. Safely normalize legacy `#/overview` and `#/models/all` bookmarks to the unified page (without extra history entries or broken bootstrap-credential removal), rather than leaving a broken route or duplicate view. Ensure the active navigation marker and keyboard focus match the new route. Other tabs/routes remain unchanged.
4. Remove **all account/subscription cards and account-specific overview sections from Models**. The existing **Accounts** page continues to show supported subscription, quota and billing details; keep canonical data/acquisition behavior correct. Do not remove shared account data merely because it is no longer rendered here.

## 2. Table width, scroll and content order

1. The Models table uses the **entire available main-content width**, with its outer left/right edges aligned to the navigation's content margins. On wide screens it must not look like a short/narrow card. Keep Publisher/Model/Relative CCost compact and content-led where practical; Release date can consume remaining width, without truncating actual model names or stretching internal price-tier segments.
2. **No independent vertical scrollbar, fixed-height body or vertical paging** for the Models table. Remove its `60vh` body limit and any other container-height/overflow trap. Render all matching rows and let the **whole document/page** scroll past them to content below. Standard horizontal overflow remains acceptable only where needed on narrow screens, without creating a second vertical scroll region.
3. Arrange the ready page as:
   - **Above the table:** genuine **New Models** notice on the left *when applicable*; the two model-filter checkboxes grouped neatly at the top right. If no notice, leave no blank placeholder. Wrap cleanly on mobile.
   - **Table:** complete four-column model comparison, including original new/promotion markers and accurate ratio/tier text.
   - **Below the table:** collapsed-by-default **More information** (including existing CCost Credits/USD selector and accurate explanatory text) and genuine **Price Promotion** notice(s). Keep explanation and promotion below the table, without bulk headings or redundant wrappers. Do not render account cards.
   - Preserve compact, actionable partial/unverified/empty-source warnings where they matter; do not present unverified fallback as successful availability.
4. **No greying/fading of superseded rows anywhere in the unified Models table.** When shown, old and new stable model versions get the same base text contrast. Keep distinct actual promotion/recent-release styling when appropriate; remove misleading “older stable variants are muted” descriptions from this page.

## 3. Two independent, clearly named checkboxes

Place both above the table, right-aligned on desktop; real accessible checkbox controls, with explanatory title/help if needed. **On every fresh page load**, default to:

- **`Show all Copilot-priced models` — unchecked.** Off: show only models in the parsed GitHub Copilot priced catalog that the currently selected OpenCode installation reports as selectable, across its enabled/configured usable providers/subscriptions. This is the existing Normal catalog-intersection policy; verify it and repair any regressions. Do not use mere historical usage or the complete GitHub catalog as positive availability proof. OpenCode's selectable list is the source of truth available to the app; **do not claim separately verified per-subscription entitlement when only global OpenCode availability is known**. If this list is unavailable/unreliable, retain the existing explicit fail-open warning (and full-catalog fallback), not a misleading “available” label. On: include **all models actually present in the GitHub Copilot priced catalog**, regardless of their OpenCode selectable/access state, without adding the retired native-rate fifth column. Do not silently omit a priced model only because its relative ratio is unavailable; keep unknown/uncomparable ratios explicitly unknown and sorted last.
- **`Latest versions only` — checked.** On: hide conservatively recognized superseded older *stable versions* within the **currently selected candidate set**; for example, if versions 4.8, 5 and 5.5 of the same publisher/family/variant are in that set, only 5.5 is shown. If the installation can select only 4.8, the newer unselectable 5.5 must **not** hide it when Show all is off. Off: show both older and newest models at equal normal text contrast. Reuse/extend the conservative `src/analysis/model_supersession.py` classification rather than naive strings; preserve distinct variants, providers, preview/unstable names and ambiguous identities rather than hiding unrelated models.

Filter order is **selectable versus all → newest-only versus all versions → sorting**. Both checkboxes can be combined in all four states. They affect only the visible list/notices as appropriate, never relative-cost valuation, source truth or account entitlements. Use frozen, canonical comparison/catalog data where feasible for immediate toggling; avoid unnecessary repeat report/history/account acquisition. If a separate catalog snapshot is genuinely necessary, distinguish it clearly instead of silently mixing unrelated data from different snapshots. No new browser persistence, user config setting or session-to-session sticky preferences.

## 4. Accurate, visibly indicated column sorting (including multi-sort)

1. Make **each of the four column headers clickable/tappable**, with an obvious directional indicator. **Default: Relative CCost descending**, and show its active descending arrow on first render and after fresh reload, including when filters change. Default is a Web presentation choice, **not** a change to CLI ordering, shared analytical ranking or price data.
2. Relative CCost is a special **numeric, tier-aware lexicographic sort**. Compare the **first/base numeric `x` ratio** first, using the canonical unrounded decimal values, **never** formatted `10.0x` text. If equal, compare the second relative `x` ratio (then further tiers, if present), in the selected sort direction. Price thresholds such as `>272K`/`≥1M`, operators, promotion asterisks and annotations **must not determine ratio rank**. Missing base values go last for both directions; when tiers differ in number, use deterministic missing-last tie handling. Avoid IEEE-754 precision loss.
3. **Release date** uses chronological date comparison (not locale string order); missing/invalid dates last. **Publisher** and **Model** use normal case-insensitive locale-aware textual sorting, with deterministic ties. The selected sort uses stable original-order fallback for equal keys.
4. Normal header click/tap sorts that single column and toggles ascending/descending; switching to another header replaces the current single sort. **Shift+click** adds/toggles secondary/tertiary sort keys, maintaining explicit priority order (1, 2, 3…). Shift+keyboard activation should follow the same behavior; offer a modest accessible way to add secondary keys without hardware Shift on touch devices, rather than a full sorting configuration panel. Display an arrow **and sort-priority number** on active multi-sort headers, plus descriptive accessible labels/help and proper primary `aria-sort` semantics.
5. Within a multi-sort, a column's own Relative CCost base/tier keys are compared **before** moving to the next selected column. All sorting applies after filtering, across **every matching model row**, not just a viewport slice. No table library, server repricing or extra acquisition is necessary for presentation sort alone.

## 5. Smoother Windows/macOS native Web launcher handoff

1. When launching Web Beta via the provided **Windows `.cmd` or macOS `.command`**, do not leave a silent multi-second gap between clicking the launcher and opening the web page. Keep a **visible, brief launch/status surface** alive during Python discovery, native preflight, verified host readiness and browser handoff: show **`Launching web…`** with an unobtrusive indeterminate spinner/activity animation and, if useful, the existing sanitized stage label. Never invent a completion percentage.
2. **Windows:** the currently hidden/asynchronous `.cmd` delegation immediately closes the visible console. Adjust the handoff so a status-bearing launch console remains until the OS browser-open attempt succeeds, then exits naturally. The managed Web host **still stays detached/tray-owned**; this status window must not become the server's lifetime owner. Reuse the existing PowerShell/Python startup messages and allowlisted failure paths rather than a new worker/supervisor.
3. **macOS:** give the `.command`/Terminal path equivalent visible feedback and a smooth exit/handoff where Terminal's supported behavior allows. Preserve the optional Finder app's no-Terminal/no-Automation design; where no console is launched, avoid opening one only for the spinner and use an unobtrusive native cue if feasible. **Do not script closing unrelated Terminal windows, request invasive Automation permission or kill the browser** merely to force exact window-close timing.
4. The endpoint for handoff is **validated host ready + successful OS/default-browser launch request**, *not* an unverifiable guarantee that the browser has already painted the page. Once the browser can open, let the existing in-browser branded shell/progress take over. On failures/timeout/Python missing/failed OS launch, keep a concise actionable diagnosis visible or in existing supported native feedback; do not vanish silently. Respect deliberate restarts, overlapping launch coalescing, existing security/instance controls and read-only safety.
5. Leave `--foreground` developer mode (intentionally console-lived), stable CLI/Watch launchers, browser authentication/bootstrap and native host lifecycle contracts unchanged.

Keep the global latest-100-prompt comparison mix (FR000534), exact threshold formatting, price notices, unavailable/unknown truth, browser CSRF/credential handling, and small/memory-only Web state. Do not alter other route scroll behavior to satisfy Models.

Likely affected: `src/web/assets/index.html`, `app.css`, `app.js`, `reports.js`, `render.js`; `src/reports/model_comparison.py` / `service.py` / `src/application/projection.py` if a consistent full catalog + selectable subset is needed; `src/analysis/model_supersession.py` if classification needs adjustment; Windows and macOS Beta launcher wrappers/status plumbing; focused existing Web/models/launcher tests and `docs/web-beta.md`.
