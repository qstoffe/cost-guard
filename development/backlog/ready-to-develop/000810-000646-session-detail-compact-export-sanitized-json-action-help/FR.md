# FR 000646 — Web Session detail: compact “Export Sanitized JSON” action with contextual help

**Owner-approved Ready Feature Request / minor UX fix, 2026-11-09.** Permanent identity **000646**, Ready priority **000810** (after currently Ready FR000645 at 000800). **Backlog authoring only:** add this FR and advance `development/backlog/identity-state.json` `highWatermark` **645 → 646** together on `main`. Do not implement product source, tests, product documentation, Settings, release/version or unrelated backlog edits now.

## Owner-observed problem and desired outcome

On **Cost Guard Web → Sessions → an individual session**, the action currently says **`Export JSON`**, while an adjacent **`About export`** help button and routine **`Sanitized; review before sharing.`** text explain what the file contains. That spreads a simple action over several UI elements. The action also looks **too tall, large and heavy** compared with the established compact **`Refresh price list`** control on the Models page.

**Replace the action with one compact, normal-styled button labeled exactly `Export Sanitized JSON`.** Remove the routine adjacent explanatory UI. Instead, attach the existing **shared contextual-help tooltip directly to the export ACTION**, which explains in plain language what a native sanitized OpenCode export does and its limits. This tooltip must **dismiss immediately when the export button is activated** (mouse, keyboard or touch) and must not get stuck under the pointer, reopen while the pointer remains in place, or obstruct the browser Save As picker.

Preserve the actual export implementation and safeguards; this FR changes the **visible label, compact visual styling and help/feedback presentation**, not the data, security boundaries or file-saving workflow.

## Confirmed source and external documentation

1. **`src/web/assets/session-export.js::SessionExport.Action`** creates:
   - `button` with visible text **`Export JSON`**;
   - a second **`ContextHelp.button('About export', help)`** beside it;
   - a persistent `notice` span with `role=status`. On ordinary successful readiness `update()` fills it with **`Sanitized; review before sharing.`**; startup also displays `Export unavailable until the selected session is observed.`.
   The existing `help` string says native sanitized JSON, review before sharing, point-in-time running export and browser-controlled fallback download. These facts should move to the action's own help, not vanish.
2. **`src/web/assets/app.css`** currently sets `.session-export > button { min-height: 2rem; }` but otherwise inherits the global button font/padding (**`font: inherit`, `padding: .5rem .8rem`, `min-height: 2.65rem` before override**). By contrast the compact Models control has **`.model-price-controls { font-size: .8rem; }`** and **`.model-price-controls button { min-height: 2rem; padding: .25rem .65rem; font-size: inherit; }`**, plus a `@media (pointer: coarse)` larger touch-target rule. Prefer that **same compact font/padding/height/weight design vocabulary**, appropriately scoped to the export action; don't globally shrink all buttons or make this a prominent `primary`/large button.
3. **`src/web/assets/help.js::ContextHelp.attach(target, content, passive=false)`** supports help on the **actual action target**, with action-style click dismissal; `ContextHelp.button()` creates a **passive** separate button that can pin the popover. `ContextHelp.dismiss(target)` is also available where a synchronous explicit dismissal is necessary. Use the existing action semantics and preserve focus, hover delay, keyboard/touch help and Escape. Attach/help dismissal should be performed **without an async step before the native Save As gesture**.
4. **`src/sources/opencode_v2_export.py::native_export()`** already validates the registered V2 native export capability and requests **`/api/experimental/session/{sessionID}/export?sanitize=true`**. It returns the upstream native `{info, messages}` shape, **not** Cost Guard's rendered session-summary JSON. The export is selected-session-scoped, read-only and bounded; this FR must not replace its sanitizer with a homegrown redaction.
5. **OpenCode's official CLI documentation**, <https://opencode.ai/docs/cli/commands>, documents **`opencode session export <sessionID> --sanitize`** and describes the flag as **redacting sensitive transcript and file data**. This is the right source for a small help explanation, but **does not guarantee that every secret, error field, path, provider message or other sensitive value is removed**. Keep the existing **review before sharing** advice. Do not claim the export is anonymous, safe to publish or guaranteed credential-free.
6. Completed **FR000631** introduced native sanitized export and its Save As/download behavior. This FR intentionally polishes **only the action UI**; its existing cancellation, source identity, CSRF, size/timeout, concurrency, browser picker/fallback, and current-session export behavior remain valid.

## UI and behavior requirements

1. Rename the sole export action to exactly **`Export Sanitized JSON`**, including its accessible name. It stays in its present session-detail location near the heading, and still invokes **the same existing `save()` action**. No separate unsanitized option, dropdown or second button.
2. **Visually match Models → `Refresh price list`:** use a compact regular app UI font (roughly `.8rem` at the normal root), approximately **2rem height** and **`.25rem .65rem`** padding in the same neutral button family. Retain normal hover/focus/disabled states and a reasonable bigger coarse-pointer target. The slightly longer label may make the button wider, but **not unnecessarily taller/bolder**. Inspect *computed* CSS and actual geometry in rendered Edge/Chrome; don't simply assert the classes match.
3. Remove the separate adjacent **`About export`** control and its extra occupied space. Remove **routine passive** side text such as **`Sanitized; review before sharing.`** and the unnecessary default explanatory sentence once an observed session is ready; the tooltip carries that guidance. On a healthy idle/ready state the area should contain **the one action button only**, with no empty status gap.
4. **Preserve essential operational feedback** on action/picker state or genuine failure. The existing `notice[role=status]` may remain as an **empty/hidden status region** when idle, becoming visible for meaningful **Exporting…**, **Export cancelled**, **Saved/download requested**, **unsupported source/unavailable**, **expired selection**, **oversize** or other actual error states when appropriate. Do **not** remove actionable failure messages, transient progress, native Save As cancel status or screen-reader announcements merely to satisfy the “no explanatory text beside the button” requirement. Empty messages must take up no layout space, and a normal refresh should not turn the old passive review warning back on.
5. **Attach tooltip to the actual export button**, using **action** semantics (e.g. `ContextHelp.attach(this.button, help, false)` or a strictly equivalent shared pattern). This must not create a second focusable element, change its button semantics, hijack clicks, add a native `title`, or duplicate the label as a help icon.
6. Suggested short on-hover/focus/touch text (English, fitting existing UI):
   ```text
   Exports this session as native OpenCode JSON using sanitized mode.
   OpenCode redacts sensitive transcript and file data. Review the file before sharing.
   Running sessions are saved as a point-in-time snapshot.
   Supported browsers open Save As; otherwise your browser handles the download.
   ```
   Use precise user-friendly wording; do not promise every private value was removed, that the JSON is an anonymized Cost Guard report, or that every browser always opens Save As. Keep any detailed limit/CLI fallback in existing error help or docs, not a huge default tooltip. The user-facing tooltip should not need to show a command line to be helpful.
7. **Dismiss the tooltip synchronously on activation:** a pointer click, Enter or Space (and touch activation) starts the original action and immediately closes active/pending hover/focus help, with suppression until the pointer leaves or focus intentionally re-enters. It must not stay pinned behind/in front of a native Save As dialog or pop back up merely because a cancelled picker restores focus. If reactivation is deliberately focused later, normal keyboard help still works. Use the established shared `ContextHelp` controller rather than a separate timer or custom tooltip.
8. **Do not change export semantics:** retain exactly the selected full native sanitized OpenCode session; running sessions are point-in-time, no raw export, no missing-message workaround, no model calls, new source requests, new dependencies, private transcript staging, changed auth/CSRF or download location promises. Disabled/loading/source-unavailable cases remain truthful and accessible. Don't start work until the user actually activates the action and, where supported, chooses a native save destination.
