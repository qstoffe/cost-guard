# FR 000638 — Fix Web account Remaining per day/workday to use selected CCost units

**Owner-approved Ready bugfix Feature Request, 2026-11-09.** Permanent ID **000638**, Ready priority **000800** (ahead of the currently pending UI work at 000815/000817/000818/000820). **Backlog publication only now:** add this FR and advance the shared identity high-watermark. No product code, tests, docs, version/release, active sessions, other FRs or runtime state change in this commit.

## Owner-observed bug and intended result

On **Cost Guard Web → Watch and Accounts**, account/subscription cards with a fixed-period allowance and supported `Remaining per day` and `Remaining per workday` (currently printed as `Remaining: <amount>/day` and `Remaining: <amount>/workday`) continue displaying **native AI-credit-style numbers** even when **Settings → CCost display** is **USD**. The shipped Web default is now USD (completed FR000625), making the mismatch conspicuous.

**Desired behavior:** the two remaining-allowance pace lines are **CCost remaining**, displayed in the **same currently selected CCost reference unit as all other Web CCost values**:

- With **USD** selected, show actual converted **reference USD** with the `$` prefix, correct conversion and two-decimal style, followed by `/day` and `/workday`.
- With **Credits** selected, show remaining **reference CCost Credits** in normal Web Credits styling, with the same rate suffixes.
- The quantity represented is **remaining reference CCost allowance per calendar day and per remaining workday before the quota resets**, not merely the provider-native unit and not monetary billing. A brief optional tooltip on the pace value may say `Remaining CCost per day/workday, in your selected CCost display unit`. No new question-mark icon, extra status row, caveat banner or duplicated technical explanation.
- Both account-card locations (full **Watch** and the separate **Accounts** page) must agree and follow live Settings changes. Reset timing, remaining day/workday counts and the quota's native used/remaining bar should keep their existing meanings.

**This is not just a string-formatting or dollar-sign fix.** If a provider's raw quota balance is not already on the reference CCost scale, showing that balance as dollars or AI Credits would be mathematically wrong. Use the same *valid reference CCost capacity/remaining basis* that the card's own CCost fields use; do not convert arbitrary native tokens, messages, requests, money, percentages or unrelated units as if they were CCost.

## Verified cause in current source

1. `src/analysis/quota_pace.py::quota_pace()` computes `QuotaPace.per_day` and `per_workday` by dividing **`QuotaComponent.remaining`** (native quota units) by the remaining days/workdays. That behavior is intentional and still powers CLI/native quota presentation.
2. `src/reports/accounts.py` builds those per-quota native `QuotaPace` records from the provider's current quota state. `src/application/watch_accounts.py::watch_quota()` sends `unit per_day days workdays per_workday` to Web Watch; `src/application/projection.py::account()` sends ordinary account `pace` rows to Accounts.
3. `src/application/display.py::amount_tokens()` currently renders `per_day` and `per_workday` with **`remaining_capacity()`**, which is deliberately unit-independent; it therefore produces the **same unprefixed number in both `display` and `display_units`**, regardless of `ccostDisplayUnit`.
4. `src/web/assets/account-cards.js::quotaDetails()` shows those native `pace` display tokens in full Watch; `src/web/assets/render.js::overviewAccounts()` uses them in Accounts. `ReportView.display()` already knows how to select server-prepared `display_units[credits|usd]` and `ReportView.syncUnits()` refreshes bound values when the setting changes.
5. **Critical distinction:** `src/application/quota_ccost.py::quota_ccost_tokens()` separately derives the **reference** `ccost_remaining`, `ccost_capacity`, `ccost_used` (including verified native-equivalent Copilot credits versus derived/reference-capacity cases). It explicitly refuses to assume arbitrary native units equal reference credits. New CCost pace must respect that same provenance and numeric basis rather than treating `quota_pace.per_day` as CCost for all providers.
6. `src/numbers.py::ccost_amount()` provides Credits/reference-USD formatting (100 reference Credits = $1.00), while `remaining_capacity()` historically handles native remaining allowance. Completed FR000528 introduced correct two-unit Web tokens and FR000625 switched Web's default to USD. Those foundations should be **reused**, not replaced.
7. Prior **FR000552** explicitly instructed Watch to show native `QuotaPace`; this new owner decision **supersedes that presentation requirement only for Web account-card pace**. The CLI/native-facing pace and provider quota facts remain unchanged.

## Scope and implementation requirements

### A. Correct reference-cost values, not native values with a new symbol

1. For every **eligible quota pace line** in full Watch and Accounts, calculate/reference the **remaining CCost for that same quota and window**, then divide its raw, full-precision Decimal amount by the existing valid count of remaining days or workdays (counting configured-local today and the existing configured workday calendar). Use exactly the source/basis already accepted for that quota's reference CCost Remaining/Capacity, including an existing source-verified reference CCost allowance or an accepted existing reference ratio estimate where valid. **Do not use native balance unless the source/projection already proves it shares the reference CCost scale.**
2. **Preserve the existing calendar calculation**: `quota_pace`'s fixed period/reset/date rules, local timezone, Swedish/non-Swedish workday calendar, remaining day count, remaining workday count, today inclusion and zero-workdays behavior are not being changed. CCost pace requires the same eligible fixed-period current quota/window; no trailing-30-day or account-wide substitute.
3. If the quota's existing reference-Cost Remaining/Capacity basis is **unavailable or genuinely incommensurate with native units**, don't invent a conversion or fall back to native pace with a dollar sign. Follow the current compact unavailable/omission convention for these two reference pace lines without creating an error/status banner or suggesting the native amount is reference money. Preserve native quota amounts and the original CLI native `QuotaPace` independently.
4. Preserve distinction between **known zero CCost Remaining**, unknown CCost Remaining, unlimited quota, exhausted quota and 0 workdays. On 0 workdays keep the existing **`Remaining: no workdays left`** text (or its direct equivalent) rather than dividing by zero or showing a fabricated workday amount. Never present an expiring/expired window as a valid future budget. Do not turn a negative/invalid source balance into positive CCost.
5. Keep full-precision math before converting/rounding the per-day or per-workday amounts. Present normal Web CCost rounding and explicit `$` and two decimals in USD; handle small nonzero amounts and zero deliberately, and don't overstate a remaining budget due to an inappropriate consumed/ceil rounding convention. The CCost unit switch affects the **display**, never raw amount, source observation, accounting attribution or quota countdown.

### B. All account-card surfaces and unit-switch lifecycle

6. **Full Watch:** both `primary` and relevant `secondary` quotas (when they have a valid pace) show `Remaining: <CCost amount>/day` and `Remaining: <CCost amount>/workday` immediately under their existing reset row, preserving layout and spacing. Switching Web CCost display from USD to Credits and back updates those displayed amounts immediately **without fetching new data** or recreating/reordering the cards.
7. **Accounts page:** match exactly the same CCost pace semantics in `ReportView.overviewAccounts()` for each applicable quota/pace. Do not leave `<native-unit>/day` in Accounts while Watch changes. Preserve the useful contextual quota name on multi-quota cards, but the pace amount itself is reference CCost, not provider units. Check any supported compact/alternate Web account-card renderer for equivalent rows.
8. **Default and overrides:** freshly opened Web with no explicit override uses the current **Default = USD**. Explicit Credits, explicit USD, changing and reloading Settings, navigating Watch↔Accounts, source retaining/update and multiple simultaneous cards must all use the selected unit. Never inherit a CLI setting in preference to Web Settings; Classic/Web theme does not change the amount.
9. **Optional help is short and useful**, attached to the pace amount or a small existing label if needed, e.g. `Remaining reference CCost allowance per day until reset, shown in your selected CCost unit.` Do not add question-mark badges, long provenance disclaimers, passive partial/refresh status rows, or tooltips that claim native subscription money. Make help keyboard/touch accessible if implemented, and avoid repetitive help on every ordinary update. The `$` prefix itself already communicates USD.
10. **Do not alter native quota widgets:** the quota name, provider-native Used/Remaining orientation, percentages, capacity/used bar, token/limit labels, provider money, source health, model availability and reset facts remain provider-native. The requested change is narrowly the **two per-day/per-workday pace amounts** on Web account cards. Do not change general `QuotaPace`/CLI output merely to make Web pass a test.

### C. Suggested minimal architecture

11. Prefer a **server-prepared, scoped raw CCost pace projection** (or a precisely equivalent helper) so both Web surfaces can render from one trustworthy CCost remaining basis. Reuse the existing quota CCost calculation/provenance and counts; avoid parsing formatted `ccost_remaining` strings such as `$`, `?`, `N/A` or `(guesstimate)` in JavaScript or recomputing model prices in the browser.
12. Export both preformatted `Credits` and `USD` pace tokens through existing `with_display()` / `display_units`, analogous to other CCost fields. Keep canonical raw Decimal, native `per_day` and `per_workday` intact for CLI/other reports and evidence; do not reuse the exact same generic `per_day` tokens for native and reference meanings without an explicit Web-specific distinction.
13. Share formatting/derived values across the ordinary Accounts projection and Watch's `watch_quota` projection, preserving each quota/window/model association without joining by ambiguous text label or by another account's quota. Avoid new source reads, live network calls, pricing probes, state stores, extra EventSources, timers or altered computation frequency from a presentation setting change.

## Acceptance cases

- **Simple Copilot source-verified reference allowance:** synthetic fixed quota with **10,000 reference CCost Credits remaining**, **10** remaining calendar days and **5** workdays: show **`Remaining: $10.00/day`** and **`Remaining: $20.00/workday`** with USD, and the corresponding **`1 000/day`** and **`2 000/workday`** (according to existing Credits grouping) with Credits. Same values in Watch and Accounts, independent of provider card label. This is illustrative, not a claim about a live provider balance.
- **Nonreference native unit:** synthetic quota measured in messages or tokens has a known native `per_day` but either a separately supported CCost Remaining or **no reliable reference basis**. Show the derived **CCost** pace when actually supported; otherwise never display the message/token pace as USD or reference Credits. No silent `native ÷ 100` conversion.
- **Two distinct quotas/accounts:** primary monthly and secondary fixed quotas have different known remaining budgets/resets. Each gets its own valid per-day/per-workday output, with no cross-aggregation; another account's quota data cannot leak into this calculation.
- **Unit toggle:** changes in Credits/USD update the two pace fields on every visible eligible card with no fetch, reanalysis or source change; raw quota and CCost data remain untouched, focus/scroll and card identity persist. Match default USD and explicit override in both Classic/Web themes.
- **Calendar/edge matrix:** zero remaining, tiny fractions, non-round USD pennies, 0 workdays, final day before reset, expired/reset window, daylight-saving date and Swedish holiday effects, unlimited, unknown or invalid remaining, stale source. No divide-by-zero, false usable budget, unlabelled native fallback or scrollbar/layout regression.
- **Presentation consistency:** unchanged heading, CCost Today, ratio/capacity/used amount, progress bar and reset, existing native quota tooltip semantics, Mini Watch's current account list, and terminal CLI's native `Remaining` pace. No new warning/partial banner (FR000634 quiet-Web intent).
- **Tests/docs:** extend focused `development/tests/test_web_accounts.py`, `test_web_display.py`, `test_quota_period_lifecycle.py`, applicable `test_web_watch*.py` or Watch/Accounts DOM tests (`development/tests/integration/web_watch_summary.cjs`, `web_accounts.cjs`, `probe_watch_summary.cjs`), and preserve `test_quota_used.py` / `test_token_mix_economics.py` canonical native pace checks. Update relevant **`docs/web-beta.md`** and CCost/Account support documentation **during implementation** to describe these two lines as reference CCost pacing. No release/validation gate is added by mere FR publication.
