# FR 000560 — Refine Web Watch account-card sizing, quota visuals/reset and prompt-card borders

## Owner request and backlog decision

**Owner-approved executable Web Beta UI FR, 2026-11-03.** Permanent identity **000560**; Ready priority **000090**, after FR000558 (000070) and FR000559 (000080). Scope: **Web Beta → Watch only**. Improve the subscription/account cards below the Watch content, and change **each** Running Prompts and Earlier Prompts session card into a lightly framed individual card. This is a visual/layout and reset-display improvement, not a quota accounting, pricing, source, or lifecycle change.

**Owner's final color decision overrides the earlier exploratory suggestion:** keep the existing cyan/teal usage-progress fill at **all utilization levels below genuine exhaustion**. Do **not** add green below 50% or yellow/orange at 50–99%. When a quota is **actually exhausted**, turn **that quota's** usage text and progress fill **red**, and give the **subscription card's header only** a subtle red-tinted background and matching legible text. Do **not** tint the entire card body. The owner wants less visual bulk, while preserving the current rounded/progress styling.

## Confirmed existing implementation (baseline inspected)

Inspected GitHub main at commit `b7e319f4bc2c7377cc56b4d96206e72459476838` on 2026-11-03:

- `src/web/assets/watch.js::accounts` builds `.account-grid.watch-account-grid` with one `section.account-card.watch-subscription` per subscription. The `h4` account label is the colored header; `quotaTrack` renders each primary/secondary usage text and native `<progress>`, using the server-owned `value.exhausted` signal. `quotaDetails` shows `Reset`, CCost and Remaining.
- `src/web/assets/app.css` currently defines `.watch-account-grid { grid-template-columns: repeat(auto-fit, minmax(min(100%, 19rem), 1fr)) }`; the `1fr` allows columns/cards to grow with the available page width. `.watch-subscription > h4` has `padding: .65rem .9rem`, while `.account-card progress` is `height: .65rem`. The title's existing accent colors and header background are theme-based. `.watch-quota-exhausted` currently uses `var(--warn)` (not the requested red).
- `src/application/watch_accounts.py::watch_quota` already returns a per-window fraction and `exhausted=fraction == 1`. Its `<100%` display guard prevents rounded 99.95%+ from masquerading as genuinely 100%. Preserve this semantic distinction rather than testing the rendered string in JS/CSS.
- `src/application/display.py` uses `src/display.py::format_reset` for exported reset text. Under 24 hours the current long display is total minutes (e.g. `Reset in 88min, 20:09`); 1–7 days currently uses whole hours and weekday/time. `src/display.py::duration_text` already renders Watch duration in compact forms such as `1h28m` and `1d3h`. Treat this FR's formatting change as **Web Watch-specific** unless reusing a shared primitive can demonstrably preserve other consumers.
- `src/web/assets/app.css` currently renders `.watch-card` as an unframed session container with a border-top only between subsequent cards, and gives `.watch-history` an outer frame. **FR000558**, still Ready at inspection, requests removing that *section-level* Earlier frame and retaining a visible Earlier/Running separator. This FR explicitly adds **per-session frames**, not another frame around all Earlier Prompts; coordinate CSS and acceptance with FR000558.

## 1. Subscription/account-card max width and responsive layout

1. Limit **each individual Web Watch subscription/account card** to a visually balanced width of **approximately 450 CSS pixels at the current standard desktop font size**. Use a font-relative unit such as `rem` (roughly `30rem` at the app's current 15px root) or equivalent responsive mechanism if that scales better with browser text enlargement. **~450px is a visual target, not a rigid magic-number implementation mandate.** Cards should no longer grow to occupy arbitrarily large desktop grid columns.
2. Keep a compact, naturally wrapping grid: one or more cards per row depending on available width, consistent gaps, no excessive forced stretching/blank columns, and no weird offset/misalignment of a single card on a wide page. A card may become **narrower than the max** on phones and narrow panels; the max is not a minimum or fixed width.
3. Preserve native usage fractions, full account labels, reset times, secondary windows, Today CCost, provenance, Remaining, and any conditional warnings. Long provider labels and magnified fonts must wrap rather than clip or produce page-level horizontal overflow. Maintain the card's present useful internal alignment/subgrid behavior where it still makes sense at the capped width.
4. Scope styling to **Watch** cards; avoid unintentionally changing the separate Accounts report or Mini Watch account surfaces.

## 2. Reduce header height without reducing label typography

1. Make the colored **account-card header band** noticeably less tall, aiming for a reduction of about **one third of its current *vertical padding*** (current `padding-block` is `.65rem`, so something around `.4–.45rem` per side is a plausible starting point). This is a design target, not a requirement to divide total header height by three.
2. **Do not reduce the account title's font size or line height.** Preserve modest, balanced breathing room above and below the text, including multiline account names, keyboard focus and text zoom. Keep existing horizontal padding and rounded top corners unless a necessary proportional adjustment improves the result.

## 3. Reset in: use the existing Watch Duration-style elapsed notation

1. For a **known reset less than seven days away**, show `Reset in <duration>, <HH:mm>` using the **same compact elapsed-duration style** as the Running Prompts **Duration** column, based on the existing `duration_text` rules or an equivalent shared formatter. For example, a remaining 88 minutes should display `Reset in 1h28m, 20:09` rather than `Reset in 88min, 20:09`. A multi-day example is `Reset in 1d3h, 14:30`. Short durations use the established seconds/minutes style, not a new custom dialect. Retain the comma and the **actual exact local clock time** of the next reset.
2. Relative duration must derive from the canonical deadline and current observation time, not from parsing an already-formatted string. Preserve correct user timezone, midnight transitions and DST changes; the target local time must be computed from the actual reset timestamp.
3. **At seven days or more**, retain the existing explicit calendar-date style unless a strictly clearer equivalent is needed. Preserve honest `Reset expired`, `Reset unknown`, `Window not started`, and null/unlimited/absent reset semantics. Never fabricate a countdown or let it become negative. Where a days-long reset's date could be ambiguous, make the absolute date available unobtrusively (e.g., tooltip).
4. Apply to **both primary and secondary** quotas in Web Watch. Refresh using the **existing live publication cadence**, without creating an extra provider poll, per-card background timer or browser-side authoritative clock. Keep CLI and other report reset formatting unchanged unless there is separately approved, backward-compatible scope.

## 4. Usage-progress bars: roughly double height, preserve cyan until exhaustion

1. Increase only the **vertical thickness** of Web Watch subscription progress bars from the current approximately **0.65rem** to around **1.2–1.3rem** (about twice as thick). Preserve the current pleasing rounded ends/track background, accessible progress semantics, width and overall palette across Classic and Web light/dark themes.
2. For **every finite quota that is not truly exhausted**—including the whole 0–99.x% range—keep the existing **cyan/teal filled color**. Do not use the discarded lime/yellow/orange tier thresholds. No change to bar length/fraction calculations, units or percentage precision.
3. When a **specific quota is genuinely exhausted** (canonical `exhausted`/native finite fraction at the limit), the **filled portion of that quota's bar becomes visibly red**, fully filled as dictated by its real fraction; the **associated whole usage-summary text** (period label, percentage, native Used/Total credits and suffix) becomes red as one group. Do not recolor unrelated CCost Today, Remaining or another quota's summary/bar. For a two-window subscription, a five-hour cap can be red while a still-open weekly bar stays cyan, and vice versa.
4. Preserve explicit numeric meaning and accessible labels; do **not** rely on red alone to communicate an exhausted quota. Avoid treating a visually rounded 100%, unknown denominator, unlimited quota, provider error, source-stale observation or generic `restricted` flag as proof of **numeric 100%**. If provider restriction is known without established exhaustion, retain the existing truthful warning rather than turning a hypothetical percentage/bar red. Preserve the established `<100%` boundary behavior.
5. On an authoritative **quota reset/recovery**, the exhausted styling must clear correctly when the new finite quota is below its limit. Do not let a previous red card or outdated row stick after a fresh accepted update. Conversely, preserve stale/partial/unavailable provenance and do not imply the last observed exhaustion is freshly confirmed during an outage.

## 5. Lightly red header for any exhausted quota; normal body remains unchanged

1. If **any relevant primary or secondary finite subscription quota** is genuinely exhausted, switch **only that account card's header band** to a **subtle light/desaturated red tint**, and adjust the account-name text/border accent to a complementary **readable** high-contrast shade instead of the normal cyan on red. Examples: either five-hour or weekly exhaustion should trigger the header treatment. A second, non-exhausted bar/text stays normal cyan.
2. The **rest of the account-card background remains the same**. Do not tint the entire card; do not mark unrelated cards red. Normal, not-exhausted subscriptions keep the existing cyan-title/header theme.
3. Red tint/text must remain distinct yet understated in the existing Classic dark theme and Web system light/dark theme, meeting normal readable contrast and avoiding eye-straining full-intensity backgrounds. Prefer semantic theme tokens and bounded CSS classes/data attributes driven by the exported canonical exhaustion flag, not parsing display strings or overriding unrelated warning/error states.
4. The new exhaustion indication must coexist with independently meaningful statuses such as a stale/partial observation, unavailable quota, explicit provider restriction and normal account warnings; do not silently erase, conflate or falsify those states.

## 6. Give each prompt/session card its own rounded frame

1. In **both Running Prompts and Earlier Prompts**, wrap **each individual session card** (session name/title, its Watch prompt table, any context warning below, and—only where applicable—running tool calls, custom skills and background activity) in a **subtle but distinct rounded border**. Use balanced internal padding and separation between neighboring cards, visually similar in weight to the formerly framed Earlier area but **one border per card**. It should feel like clean cards containing their own table, not a second oversized box around every section.
2. Replace/reconcile the current border-top-only between sibling `.watch-card` elements so edges do not appear doubled or visually cluttered. The contained table can retain its own thin border and horizontal scrolling. Preserve session links, single-line prompt rows, tool/skill disclosure, selection/focus, context warnings, empty/loading states, live text updates, and normal page scroll.
3. **Do not restore the former outer `.watch-history` frame** that FR000558 removes. Earlier Prompts remains a collapsible **section of individually framed cards**, not a framed group of cards. Preserve normal collapsed behavior.
4. When **Earlier Prompts is expanded**, make the boundary between its cards and **Running Prompts** clearly discernible with a **stronger horizontal section separator** than the ordinary between-card spacing/borders. Coordinate this with FR000558's existing separator requirement so one intentional divider survives, not doubled rules. Keep it correctly placed for zero Earlier results and disappearing/changing Running cards; it should not masquerade as the frame of another prompt card. When Earlier is collapsed, do not introduce a prominent orphaned divider.
5. Confirm that the framed card expands to available Watch content width without breaking the shared prompt-table updates expected from FR000558 (ten columns, new Token Mix %, hover/focus tooltips and their table overflow). Reuse common framing CSS for both types instead of maintaining divergent Running/Earlier variants.

## Acceptance and focused verification

1. At common desktop widths (including a very wide browser) account cards never grow past the approximately 450px equivalent target at default text size; at narrow widths and 150–200% browser text zoom no label/value becomes inaccessible or forces page overflow. Multiple accounts wrap naturally with useful gaps; no unbounded single stretched card. The Accounts report and Mini Watch remain unaffected.
2. Account header vertical padding is visibly slimmer while its font size stays unchanged, with comfortable padding for one- and two-line titles. Card header and progress treatments appear correct in Classic/dark and Web light/dark themes.
3. Reset examples: **88min → `1h28m`**, shorter minutes/seconds, 1d+ under seven days, exactly the seven-day boundary, expired/unknown/not-started, midnight and DST. The display includes the correct deadline's local `HH:mm` and remains consistent with Duration notation. Verify both primary and secondary quotas without regressing CLI/Accounts views.
4. For 0%, 49.9%, 50%, 75%, 99.9% and just-below-100%, the usage bar **stays cyan** and the header uses normal theme. For a genuinely exhausted primary or secondary, **only its** bar and usage summary turn red, while the **whole account's header** gets a muted red tint and legible adjusted text; body background stays normal. Reset back below limit clears it. Test five-hour and weekly exhaustion independently and together.
5. Unknown, unlimited, partial/stale/outage, provider-blocked-without-numeric-exhaustion and rounding-near-100 scenarios preserve honest independent status without fictitious quota exhaustion; aria/value semantics and contrast are usable without interpreting color.
6. Both Earlier and Running contain **separately rounded/framed** session cards; no outer Earlier box; the **expanded Earlier → Running** boundary is a deliberate strong separator, without doubled lines or an orphan separator when collapsed. Long prompt previews, narrow horizontal table scrolling, context warning, focus and tools/skills disclosures still work.
7. Exercise existing targeted Python projection/formatting tests, Web Watch DOM/CSS-responsive fixture checks and appropriate normal product/package checks. Report exactly which browser/theme/real-source conditions were verified; do not invent physical-browser evidence. No live model call or provider/quota mutation is authorized for this UI change.

## Coordination and non-goals

- **FR000558:** removes only the Earlier *section* frame; **this FR adds individual session-card frames** and explicitly preserves/strengthens the distinct Earlier/Running separator. Coordinate implementation so neither FR's acceptance contradicts the other.
- **FR000556** (completed or in progress depending on implementation time) governs the native Used/Total vs separately labeled CCost semantics; **preserve** those values and their independence. This FR only changes their display/color on actual exhaustion.
- Use the existing quota projection's source of truth and the existing Duration formatting primitive. No price/quota-provider parsing change, new polling loop, account field invention, token accounting change, browser-side quota inference, global CLI reset-format change or unrelated report redesign.
- Publication of FR000560 is **backlog-only**. It does not itself modify Watch UI, source code, product version, provider state or release records.
