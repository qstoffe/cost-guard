# FR 000562 — Compact Web Watch quota cards, inline period CCost, and contextual warning markers

## Owner request and decision

**Owner-approved executable feature request, 2026-11-03.** Permanent identity **000562**, Ready priority **000110**, following existing Ready FR000561 (000100). Scope is **Web Beta → the full Watch page**: subscription/account cards near the bottom and the Context column of both **Running Prompts** and **Earlier Prompts**. This is a presentation/layout refinement, not authorization to change quota consumption, period accounting, context estimates, warning thresholds, or lifecycle.

The owner's latest instruction takes precedence over conflicting older presentation choices: put each quota's observed-period CCost in bare parentheses immediately after its percentage Used; remove the separate CCost/Estimated row; move Reset closer to the bar; make each account card genuinely about 450px wide; reduce progress thickness by about one third and greatly reduce corner rounding; remove the visible approximation glyph from full Watch Context cells; and add an inline warning symbol before the appropriate Context number while retaining the warning underneath the session table.

## 1. Show each quota-window CCost immediately after 'used'

For **each finite, known primary or secondary quota** in each full Watch subscription card, show its **own observed CCost for exactly that quota/account/period** as a **single bare parenthesized value immediately following the usage phrase**. Example:

**5 hours · 16% used (94) · 120/750 AI credits**

Here **16% and 120/750 are provider-native quota usage**; **94 is the separate Cost Guard CCost attributed to this account's five-hour quota period**, not the native Used numerator. The native Used/Total text shown today must remain visible, correctly labeled with its native unit where applicable. A weekly quota's parentheses must instead refer to **that weekly quota's observed period CCost**, even when it differs from the five-hour value. Primary and every secondary window must be independently matched by canonical account/window identity, never by adjacent render order, text label, today's total or another provider.

- **Remove the separate 'CCost: …' quota-detail row entirely**, including the on-screen 'estimated', 'partial', 'CCost', '≈', '~' or other estimate markers associated with that row. Inside the new parentheses, show **only the formatted numeric CCost**, without those labels or approximation symbols. Preserve normal amount precision and the existing selected Credits/USD display setting; do **not** accidentally convert provider-native AI credits to USD.
- The visible compactness is intentional, even though it reverses FR000556's explicit-label layout. Restore semantic clarity nonvisually: a hover/focus-accessible title or equivalent should identify the parenthesized value as **observed CCost for this specific quota window, independent of provider-native Used**, and explain estimated/partial attribution where applicable. Keep existing structured completeness/estimated/partial data and source warnings; do not imply a more accurate calculation by hiding a visual marker.
- When period CCost is truly unavailable, **do not invent 0 or an empty pair of parentheses**. Omit the parenthesized numeric value or use a defensible minimal unavailable convention; keep any known native quota usage and other meaningful availability information. A genuine known zero may display **(0)**. Unlimited/unknown quotas retain truthful existing native-status conventions, without fabricating a finite 'used' percentage or bar simply to attach a CCost number.
- Keep **CCost Today** as its separate, differently scoped account figure and **Total Today** as the existing global daily card. Do not change period calculations, deduplication, native fractions, source acquisition, resets or attribution.

## 2. Place Reset directly beneath the matching progress bar

- With the separate period CCost row removed, the **Reset in / Reset date** line (where present and meaningful) must sit **tightly beneath its own quota progress bar**, without the old intervening CCost line, an empty spacer row, or oversized vertical margins. Make spacing consistently compact, rather than merely moving the text elsewhere in the card.
- Apply to the **primary** five-hour/monthly/etc. quota and **each secondary** weekly/model-specific quota. A secondary Reset belongs beneath **that secondary bar**, not under the primary bar, and the two windows must not exchange countdowns.
- Preserve FR000560's correct compact Duration-style reset notation, local absolute clock/tooltip, unknown/expired/inactive semantics and the existing publication cadence. Keep Remaining/day and Remaining/workday in the appropriate quota block **after Reset**; retain relevant section separators, status messages and availability/warning detail without reintroducing a cost row.

## 3. Actually constrain subscription-card width to about 450px

- The visual **target maximum is approximately 450 CSS pixels at standard desktop/browser scale**; **500 CSS pixels is an upper guardrail, not the new default**. An account card must not expand to ~670–680px merely because the viewport/grid has spare space. A responsive max-width implementation is welcome; **do not impose a fixed width or a 450px minimum**. Cards must shrink as necessary on phones and narrow Watch panes.
- Inspect the computed **rendered card width** (including actual grid sizing, ancestor constraints, CSS root font, browser zoom, subgrid and current theme). The existing nominal 30rem declaration is not proof of compliance, given the owner's observed ~680px; if rem/zoom causes visible overgrowth, use an effective cap that enforces the owner's intended result without breaking readability.
- Preserve a natural left-to-right wrapping grid with consistent gaps and no stretched singleton card, clipped account labels, missing values or page-level horizontal overflow. Do not alter Accounts-report cards or the separate Mini Watch subscription rows.
- Verify actual DOM geometry at representative **360/1366/1920/2560px** widths, all three existing themes, default text size and enlarged/zoomed text. Record the measured widths (and relevant zoom interpretation) rather than asserting compliance just from a CSS value. Accessible wrapping is still mandatory at larger text.

## 4. Slim the full-Watch quota bars and square off their ends

- Reduce the **vertical height** of the current approximately **1.25rem** full-Watch account progress bars by **about one third**, targeting approximately **0.8–0.85rem** at normal type size. Do not shrink their horizontal usage representation or change the canonical percentage/fraction.
- Replace the current almost semicircular/pill ends with a **very small corner radius** on **both the empty track and the filled portion** (a small 2–3 CSS-pixel-equivalent radius is a reasonable target). Ensure equivalent effective rendering in Chromium/WebKit pseudo-elements and Firefox/Gecko, including partial fill and true 100%, instead of rounding only the outer element.
- Keep theme-aware track contrast, cyan/teal fill below canonical actual exhaustion, red fill and associated usage summary only at **confirmed finite exhaustion**, the subtle header-only tint, and accessible native progress semantics. Never mark a rounded display percentage of 100% as actual exhaustion. Do not change Mini Watch bars, which FR000561 explicitly specifies separately.

## 5. Context column: plain number plus a contextual warning icon

Apply to the **existing Context column in both Running Prompts and Earlier Prompts tables**, not Δ Ctx:

- Remove the visible **~ / ≈** prefix before every known numeric Context value; show the existing formatted number alone when no price-threshold warning applies. The existing **Context heading tooltip already describes the number as an estimated next incoming context**, so do not remove or weaken that explanation or change the estimate itself. Unknown Context stays unknown, not zero.
- Where **that prompt's relevant canonical current/next-context state** is **approaching a price threshold** or **has crossed/exceeded a price threshold**, place the **same recognizable warning-triangle symbol immediately before the Context number** in the same table cell (for example, '⚠ 129K'). Only show it for those two valid severity states. Do not add a new column, reintroduce footnote references, paint every Context cell as a warning, or replace ordinary prompt outcome/status coloring.
- **Retain the existing full warning below the corresponding session card's prompt table**, including the icon, informative threshold text/cost impact and distinction between approaching and exceeded. The cell icon is an at-a-glance link to that explanation, **not a replacement**. When a footer warns, the relevant visible Context cell should identify the same prompt/continuation and severity; never misattribute the card-level warning to an unrelated earlier row.
- Reuse the canonical **watch_context_state / next_context_warning_state** and the actual current/focal continuation/epoch ownership, with the existing configurable approaching threshold and exact tier-crossing rules. If the current DTO lacks row attribution, extend the typed projection narrowly to carry severity/ownership; **do not infer warnings from displayed rounded tokens, string-match footer prose, reapply different thresholds in JS, or copy the same warning to every row**.
- Correctly handle new calls, multiple rows, concurrent focal prompts, Earlier's final valid continuation, compaction and context epoch changes, transitions **none → approaching → exceeded → none**, missing/partial data, stale snapshots and out-of-order publications. An invalidated pre-compaction warning must not remain on a Context cell. Where attribution is unsupported, do not invent a warning for an arbitrary row; make the normal valid footer/cell association work when evidence is available.
- Make the inline warning icon perceivable but compact, with readable severity and keyboard/focus-accessible meaning (tooltip or aria label) in addition to the footer. Preserve the Context column's compact single-line table behavior and horizontal scrolling. Keep gold/orange warning separate from red abort/exhaustion/error signals.

## Acceptance and verification

1. A card with a 5-hour 16%-used quota and observed period CCost 94 renders **'5 hours · 16% used (94)'** with no standalone CCost/Estimated row, no '≈' or '~', and the correct independently shown provider-native Used/Total. A weekly quota has its **own** parenthesized cost; swapping source-window order or having different costs must not swap values. Known zero, unavailable, estimated, partial, Unlimited, stale and reset transitions preserve correct truth. Credits/USD changes only the CCost unit, not native Used.
2. A primary quota's **Reset** is directly beneath its bar; if a secondary quota has its own Reset, it is directly beneath **its bar**, with no awkward old-row gap. Remaining/day/workday and supported warning/status text stay in the correct sections; known and unavailable reset behavior is unchanged.
3. At normal desktop scale, full-Watch account card width is **about 450px and never greater than 500px**, including a single card on a very wide page. The reported ~670–680px effect is investigated using actual rendered geometry, not assumed solved by the existing 30rem rule. Narrow and zoomed/text-enlarged layouts wrap without hiding content or overflowing the page.
4. Full-Watch quota bars are about **two thirds of their previous vertical height**, with **subtly rounded (not pill-shaped)** track and fill. Verify partially used and exhausted quota bars, independent primary/secondary exhaustion, reset/recovery, theme contrast and aria values in Classic, Web light and Web dark. Mini remains unaffected.
5. In **both** Running and Earlier, an ordinary known Context displays e.g. **129K**, without '~'. For valid approaching/exceeded warnings, it displays **⚠ 129K** (real number and label from the fixture), while the **full contextual warning still appears beneath the card table**. No-warning/disabled threshold yields no icon; compaction and warning changes update both placements together. No row receives a warning solely because another prompt/card is warned.
6. Exercise focused Python quota-projection/context-warning tests and existing JS/DOM/browser Watch/account responsive fixtures, including real rendered width/track-radius checks, keyboard tooltips, updates, crossing-boundary/severity changes, multiple sessions and exact per-window cost assignment. Run the normal applicable repository checks for implementation and truthfully document any browser/real-source limits. No live model calls, provider quota manipulation or extra source polling are authorized by this UI feature.

## Coordination and exclusions

This FR **overrides the specific visible presentation** in completed FR000556 (separate explicitly labeled period CCost row), FR000560 (approximate cap found too wide in practice; heavy pill-shaped progress), and FR000543 (no inline Context warning icon / retained visible approximation). **All underlying numerical and lifecycle guarantees from those FRs remain binding.** FR000561's Earlier Finished ordering and **Mini Watch** UI are separate and should not be silently changed, including Mini's CTX display policy. Preserve Web Watch prompt-card borders, Total Today, account Today, quota exhaustion styling and the standard Watch header/help semantics.
