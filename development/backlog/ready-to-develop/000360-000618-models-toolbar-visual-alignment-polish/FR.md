# FR 000618 — Models: compact and align the price-refresh toolbar and filter controls

**Owner-approved Ready Feature Request, 2026-11-06.** Permanent identity **000618**; Ready queue priority **000360**, after current FR000617 (000350). **Backlog authoring only:** publish the FR and increment the identity watermark; do not change product code, tests, user documentation, versions, releases or unrelated backlog entries during publication.

## User observation and requested outcome

On Web Beta **Models** (`/#/models`), the controls **immediately above the model table** look slightly inconsistent with the rest of the product. In particular:

- **Refresh price list** looks too large, with typography that feels different from the compact **Mini Watch: On/Off** control on **Watch**.
- The adjacent **Prices last fetched: …** text also looks as though it uses the wrong font/scale.
- The whole left-hand refresh/timestamp group feels a little **vertically misaligned** with the two model filter checkboxes on the right.
- These are **small UI/UX polish issues**, not a request to redo the Models page, its model table, its sorting, or every button in the product. AI Stats' period-selection buttons may legitimately retain their distinct selected-tab appearance.

**Goal:** Make this one toolbar feel visually deliberate and consistent with the compact Watch controls: a smaller, readable **Refresh price list** action; normal UI typography for the button and its explanatory/timestamp text; harmonious text sizes and spacing; and a clear shared vertical alignment between the left price controls and right checkbox filters. Keep the row unobtrusive so the model table remains the visual focus.

## Concrete source findings

1. **Likely root cause of wrong font — reused CSS class.** In `src/web/assets/app.css`, the general rule `.model-prices { display: block; font-family: ui-monospace, monospace; }` is used for *price tiers/values within model rows*. A later rule **reuses that same class name** as the flex container for the toolbar above the table: `.model-prices { display: flex; align-items: center; flex-wrap: wrap; gap: .4rem .75rem; }`. The latter changes display but **does not override the monospace font-family**. `src/web/assets/render.js::overviewModels()` builds the toolbar as `div.model-prices` with the button and timestamp inside. Global `button { font: inherit; }` means **Refresh price list inherits the monospace font**, and the adjacent timestamp `span` also inherits it. This is a specific, source-backed CSS collision that plausibly explains the owner's observation. Verify actual computed styles in the rendered browser before implementing.
2. **Size mismatch.** The global `button, input, select` rule sets `min-height: 2.65rem` and `padding: .5rem .8rem`. The compact Watch toggle `#mini-watch-toggle` instead has `min-height: 2rem; padding: .25rem .65rem; font-size: .8rem`, and its neighboring feedback text is `.8rem`. Refresh price list currently gets the larger default button dimensions, making the controls appear less related.
3. **Vertical layout mismatch.** `.model-tools` uses `display: flex; align-items: start; justify-content: space-between; gap: 1rem; flex-wrap: wrap`. Its left `.model-prices` group internally uses `align-items: center`, while the right `.model-filters` is a separate flex group with `margin-left: auto; align-items: center; font-size: .8rem`. `.model-prices > span` uses `.85rem`. The larger button and top-aligned outer group can make the checkboxes appear displaced from the price controls, especially with line wrapping and different text metrics.
4. **Existing authoritative behavior must remain.** `render.js::overviewModels()` creates the explicit **Refresh price list** button, **Prices last fetched: ...** timestamp, an inline refreshing/error status, and exactly two independent checkboxes: **Show all Copilot-priced models** and **Latest versions only**. The timestamp is the last *successful upstream pricing observation*, not page entry or normal catalog-cache access. The event calls `state.refreshPrices`, and `state.priceControls` owns disabled/refresh state. This FR changes their **presentation**, not the authenticated refresh semantics, failed-refresh retention, numeric pricing calculations, checkbox meaning, or selection/sort behavior.

## Small, intentional presentation change

1. **Separate toolbar typography from table price typography.** Resolve the accidental class/style coupling by scoping the monospace table rule to the actual price-tier cells or giving the toolbar a distinct semantic CSS class (for example `.model-price-controls`), and update its one renderer. Do not globally remove monospace from relative ratios, tiers or numeric prices that intentionally require aligned digits. Use the ordinary app **system UI font** for the Refresh button, timestamp and inline feedback. Prefer scoped selectors over another broad `button` override.
2. **Make the Refresh action compact like Watch's toggle.** Use a control height, padding and font size visually close to `#mini-watch-toggle` (approximately the same **2rem / .25rem .65rem / .8rem** compact vocabulary, adjusted for genuine legibility and pointer/touch needs). This is a **one-time action, not a toggle**: preserve the label `Refresh price list`, button semantics, focus outline, disabled/loading style and click/touch/keyboard operation. Do not add `aria-pressed` or pretend it is the same type of control as Mini Watch.
3. **Make neighboring text coherent.** Display **Prices last fetched: <existing true formatted value>** and any `Refreshing…` or failure-feedback text in the same normal UI font family and a balanced supporting size/color, comparable to Watch's compact helper text. Do not abbreviate, invent, shift timezone, hide `Unavailable`, replace the observed timestamp with the local clock or truncate an important error. An unavailable price date remains visibly distinguishable.
4. **Align all first-row controls.** The left button/date/status group and right two checkboxes should feel centered on one common visual axis on a regular desktop viewport, not staggered by mismatched intrinsic button heights or `align-items: start`. Align checkbox boxes with their label text, maintain consistent horizontal gap, keep the checkbox group right-aligned when space permits, and preserve a sensible margin above the table. Do not create a faux secondary toolbar/card or dense border frame.
5. **Responsive layout and accessibility.** At narrower widths and 125–200% browser/text zoom, the left group and right filters may wrap into **intentional separate rows** rather than overlap, force invisible content or introduce page-wide horizontal scrolling. Inside each flex row, labels must remain readable without vertical clipping. Long localized dates, error text and labels must not shove checkboxes off-screen. Respect Classic/Web light/dark color tokens, existing keyboard focus visibility, `prefers-reduced-motion`, touch/coarse pointer target sizing and native checkbox usability.
6. **No scope creep.** Leave Models' four table columns, prices/relative CCost tier alignment, sample logic, sort controls, filter defaults, all-model option, last-fetched observation provenance, explicit upstream price refresh, backend cache and HTTP security untouched. Other Watch/Mini controls and AI Stats selectors must not change. The target is **only the small controls area immediately above the Models table**, plus the minimal CSS separation needed to avoid unintended table impacts.

## Acceptance and regression checks during implementation

1. **Computed font regression:** In a rendered browser, show the current pre-fix computed `font-family` on the toolbar's Refresh button/date and on a tier-price cell, then verify after the fix that the toolbar inherits the **normal application UI font** while tier prices/ratios keep their **intended monospace**. No other model price rendering changes.
2. **Geometry/visual alignment:** With standard system fonts, desktop at 1280/1366/1920 px, the compact Refresh button is close to Watch's Mini Watch toggle in computed height, padding and font size. Price date/error text and right-hand checkbox labels align visually with it; check bounding boxes/baselines, not only that `display:flex` appears in the CSS. Screenshot comparisons of the Models control strip are appropriate.
3. **Responsive proof:** At 360px / 800px / desktop widths, Classic and Web light/dark themes, 100% / 125% / 150% / 200% zoom or equivalent font scaling, verify no overlap, clipped timestamp, hidden checkbox, unintended page horizontal overflow or jumping when the feedback span changes. Natural multiline wrap is fine at narrow widths.
4. **Interaction preservation:** Refresh success, in-progress disabled duplicate-click guard, genuine upstream failure (retaining prior price list and fetched time), retry, keyboard Enter/Space and focus retention still work. Both checkboxes and their explanatory help continue to filter exactly as before and preserve state/sorting appropriately; changing only CSS must not submit new report jobs.
5. **Regression scope:** Extend the focused existing `development/tests/integration/probe_models_refresh.cjs`, `development/tests/integration/probe_web_models.py`, and/or a small dedicated real-DOM style probe, while retaining `development/tests/integration/web_models.cjs` logic checks. Update `docs/web-beta.md` only if implementation changes user-facing instructions; do not run product gates during FR authoring. The relevant tests should inspect the actual control strip rather than invent a full UI redesign.
