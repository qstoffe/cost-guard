# FR 000568 — Windows Web Beta tray: Copy Cost Guard access link for another browser

## Owner request and intended user experience

**Owner-approved executable feature request, 2026-11-03; owner clarification incorporated.** Permanent identity **000568**, Ready priority **000170**, after currently Ready FR000565–FR000567. This is an update to the existing FR, **not** a new identity or reprioritization.

The owner launches Cost Guard Web Beta from Windows, with Chrome as the default browser. Copying the normal URL (e.g. `http://127.0.0.1:<port>/#/watch`) into another Chrome tab works because that browser already has its Cost Guard cookie. Pasting the same URL into Edge, Firefox, another profile or a private browser window displays **Authorization Required** because that browser lacks the cookie.

The owner wants an effortless way to open the *same already-running local server* in a different browser without changing the default browser, restarting the server or weakening the security model.

**Explicit UI decision: the new copy action must live ONLY in the existing Windows notification-area (system tray) icon's right-click context menu, NOT on a Web Beta page.** A button/link in the browser header, toolbar, Settings or Watch is specifically **not desired**. Right-clicking the tray icon should show three actions:

1. **Open Cost Guard** — existing behavior, open in the system's default browser.
2. **Copy Cost Guard link** — **new** behavior: put a fresh, temporary, single-use *authorized* browser URL onto the Windows clipboard, **without opening a browser**.
3. **Exit Cost Guard** — existing behavior, cleanly stop the current instance.

The user can then paste the copied link into Edge or any other browser and access Cost Guard immediately. Existing Chrome and newly authorized Edge continue to use the **same server** concurrently, including their normal Watch/Live functionality. No new HTTP port, browser preference, password dialog, external package, certificate or process is required.

Do **not** replace this with copying the plain unauthenticated `http://127.0.0.1:<port>/` address: that address cannot authorize a fresh browser without dropping the application's existing protection. The copied URL should contain the same kind of short-lived, one-time bootstrap credential already used by the launcher / tray Open action. Existing harmless page links and bookmarks work within a successfully authorized browser's normal session and server lifetime, not in a previously unauthenticated browser or across changed random ports.

## Inspected source and design constraints

Source reviewed on current CostGuard main:

- `src/web/win32_tray.py` owns the native Win32 `CreatePopupMenu`, `AppendMenuW`, `TrackPopupMenu` menu and its `OPEN = 1` / `EXIT = 2` messages; `src/web/native_windows.py::WindowsHost.dispatch` handles those events in the already-running host. Add one distinct `COPY` menu event rather than a second tray/server owner.
- `src/web/host.py::WebHost.browser_url()` already mints `http://127.0.0.1:<assigned-port>/#bootstrap=<short-lived-token>` for the launcher and tray Open. Reuse the owner-side method/contract for **copy**; it is not necessary to expose a token-minting endpoint to browser JavaScript.
- `src/web/security.py::BrowserSession` keeps one-use bootstrap credentials in server memory, checks expiry, and exchanges for an `HttpOnly; SameSite=Strict` session cookie. Cookies are browser/profile-specific, which explains the Chrome–Edge difference; the current in-memory bootstrap slot is *single-pending*, so minting one fresh link can invalidate another pending launch/Open link unless properly coordinated.
- `src/web/http.py` enforces exact Host/Origin, sensitive-read authorization, CSRF, fixed routes, local-only binding and private control. `src/web/assets/app.js` removes the bootstrap fragment from the receiving browser's history before credential exchange.
- Completed FR000300 explicitly protects sensitive localhost data: loopback-only HTTP does **not** imply safe anonymous access by every local client or visiting web page. Maintain the existing trust boundary.

**Scope clarification:** this new menu item is a **Windows tray operation**. The core existing Python bootstrap flow still works for any compatible browser, but this FR does **not** require adding an analogous macOS status-bar menu action or any web-page UI. macOS parity, if ever desired, is a separate owner decision. Preserve current native macOS and CLI behavior.

## Required implementation

1. **Native Windows menu only.** Add exactly one clearly labeled **Copy Cost Guard link** item to the current tray menu, ordered between Open and Exit. It must be accessible with mouse and ordinary native menu keyboard behavior, including at the owner's 150% display scaling. Do not add browser-side copy buttons, new API endpoints for minting links, HTML prompts or a change of Windows default browser. Keep native menu ownership and Explorer taskbar-recreation behavior. Coordinate with FR000567's separate icon/DPI changes; do not duplicate or overwrite that FR.
2. **Copy authorized URL, not open.** On explicit menu selection, mint a new unguessable, short-lived, one-use bootstrap URL for the same healthy instance and put the **complete URL** (including the transient fragment credential) onto the Windows **Unicode text clipboard** using already installed OS/Python facilities. Keep this operation bounded and nonblocking for the native event loop; if clipboard contention/failure occurs, report a simple recoverable failure and allow retry, rather than stopping the Web server. Do not spawn a browser or touch existing browser tabs. Do not change the existing Open/Exit semantics.
3. **Security and token independence.** The copy event must be issued by the **same trusted native host**, not by an untrusted page or anonymous HTTP request. Preserve the bootstrap one-time redemption, short expiry (existing 120-second convention is suitable), rejection after restart, and in-memory-only secret lifecycle. Multiple independent browser handoffs must not invalidate each other's pending links or an already pending launcher/tray Open link; use a small, bounded, lock-protected collection of pending credentials if needed, expiring and pruning entries safely. A successful copy must not revoke or interrupt already-authenticated Chrome/Edge cookies, HTTP reports, Watch Live/SSE or source acquisition.
4. **Privacy-safe clipboard feedback.** Show a concise, non-sensitive indication that the **link has been copied and expires shortly**, or a clear retry message on failure (e.g. an in-box Windows notification if appropriate). Never display the credential itself in notifications, dialogs, debug output, application logs, diagnostics or error messages. The clipboard necessarily holds a temporary bearer secret until overwritten; document that fact in a short usage note and retain the limited lifetime/one-use protection. A later Open or Copy must not silently reuse an expired token.
5. **Receiving browser and navigation.** Pasting the link into **Edge, Firefox, another Chrome profile or private window** should create a normal browser session on the existing server without requiring the launcher again. It is acceptable to land on the standard **Models** page: because the action is from the OS tray, it cannot know which page (Watch, etc.) is currently active in another browser. Do not add browser-state tracking solely to guess a target page. Standard app navigation to Watch and others then works. Preserve safe early removal of `#bootstrap` from the URL/history and all regular Host/Origin/cookie/CSRF checks. Users may copy an ordinary page URL and bookmark it later **in an authorized browser**, subject to the same host/port/session lifetime.
6. **No relaxation or extra infrastructure.** Do not remove authentication from `/api/*`, accept arbitrary origins, enable CORS broadly, expose the launcher `/control/open` authorization or other control secrets to browsers, make the server accessible on LAN, persist login tokens to disk/browser storage, add dependencies, autostart a new process or implement HTTPS. Leave CLI, report calculations, account credentials and Web Beta's current origin and assigned-port policy untouched.

## Acceptance and verification

- **Physical Windows Chrome → Edge check:** start Web Beta normally so the launcher opens Chrome. Verify normal Chrome tab duplication still works. Confirm a plain URL pasted into a fresh Edge profile still produces the existing authorization error. Right-click the tray icon, select **Copy Cost Guard link**, paste the newly copied URL into Edge: Edge authorizes, can navigate to Watch/Models and observe the **same running host** while Chrome remains connected and fully usable. Selecting Copy must **not** open or switch any browser; Open and Exit must work exactly as before.
- **Clipboard and native-menu behavior:** copied text must be a correctly formed URL with actual dynamic loopback port and transient bootstrap fragment, consumable by the receiving browser. Test temporary clipboard-in-use/failure, later retry, menu keyboard use, Explorer restart and owner cleanup. Never claim visual/native behavior was tested solely because unit tests passed.
- **Replay, expiry and concurrency:** link redeems only once, expires promptly, fails after the host restarts and is not a permanent bookmark for a new browser; repeated copy and interleaved Open/launcher operations do not break still-pending links or existing authorized sessions. Multiple browsers can use Watch/SSE concurrently within existing resource limits, without duplicate servers, unintended restarts or token leaks.
- **Security negative tests:** unauthorized browsers and plain pasted URLs still cannot access private reports, sessions, account data or settings. Cross-origin, wrong-Host, CSRF-less, expired or replayed attempts do not mint/redeem authority. Tokens never appear in query strings, referers, ordinary logs, diagnostics or persistent browser storage; the receiving page erases the transient fragment before ordinary navigation.
- Run focused tests for `src/web/security.py`, `src/web/host.py`, `src/web/win32_tray.py`, `src/web/native_windows.py` and existing `development/tests/test_windows_web.py` / HTTP security coverage, plus a **real** Chrome→Edge/native clipboard probe where permitted. Note any untested physical UI conditions explicitly. No new permanent validation gate.

**Non-goals:** a website/header/Settings copy button, a new authenticated browser-side copy API, an anonymous fixed URL, forever-valid browser links, a fixed port or cross-device access, changing the system default browser, macOS status-bar parity, HTTPS, or unrelated tray icon/menu sharpness changes from FR000567.

**Publication only:** this revision changes only FR000568's specification; it does not create a new FR, bump the identity high-watermark, modify product code/version, or touch the running Web host. Implementation remains a separate future workflow.
