# FR 000568 — Web Beta: copy a temporary access link for another browser

## Owner report and intended behavior

**Owner-approved executable feature request, 2026-11-03.** Permanent identity **000568**, Ready priority **000170**, after current Ready FR000565–FR000567. Scope: the **existing local Cost Guard Web Beta host**, with Chrome, Edge and other mainstream desktop browsers sharing one running local server safely.

The owner launches Web Beta through the Windows launcher, which opens the default Chrome browser. Copying a normal URL such as `http://127.0.0.1:<port>/#/watch` into another **Chrome tab** works; copying that identical URL into **Edge** (or another browser with a different cookie store) loads the HTML shell but displays **Authorization Required / Unable to establish the private browser session**. The owner wants to use different browsers without changing the Windows default browser, relaunching or guessing port/session details, and would like easy copy/paste and ordinary navigation or bookmarking where practicable.

**Desired UX:** provide a discoverable, simple, one-click **Copy link for another browser** (wording may vary) in the already authenticated Web Beta interface. This generates a fresh, short-lived, single-use browser access link for the **same running server**. The owner pastes it into Edge, Firefox, another Chrome profile or a private window, and that browser becomes independently authorized, loading the requested/current section where feasible. Both browsers then work concurrently against the same host, including Watch. No password, terminal command, launcher restart, HTTPS certificate or new runtime package is required.

**Important security decision:** this is **NOT** a request to disable authentication on all loopback HTTP routes, change to a fixed unprotected address or let every local process read accounts, prompts, source history or settings. The owner prefers copy/paste convenience; an authenticated one-time share link provides that outcome while retaining the original privacy model. A plain `127.0.0.1:<port>/#/watch` URL pasted into a never-authorized browser must continue to require access.

## Repository facts and existing design

Reviewed current `qstoffe/cost-guard` main on 2026-11-03:

- `src/web/security.py::BrowserSession` already owns an **in-memory short-lived one-use bootstrap**, a scoped `HttpOnly; SameSite=Strict` session cookie and CSRF. Cookies are browser/profile-specific, so a fresh Edge instance lacks Chrome's cookie. The existing browser session is valid for a bounded period (eight hours currently). There is no code defect in Edge.
- `src/web/host.py::WebHost.browser_url()` already creates `http://127.0.0.1:<assigned-port>/#bootstrap=<one-use-token>`, used from the native tray Open and launcher. `src/web/assets/app.js` removes `#bootstrap` from browser history before exchange and then accesses authenticated APIs.
- `src/web/http.py` enforces the exact assigned Host/port, exact Origin, a fixed route allowlist, authenticated sensitive reads, POST CSRF, limited request bodies, local-only binding and no CORS. It has a private launcher-only `/control/open` route; **do not expose that launcher control secret to browser JavaScript**. A newly scoped authenticated API endpoint for temporary browser links is appropriate.
- `src/web/assets/app.js` already owns global navigation / connection state. Its initial bootstrap URL currently navigates to Models. Preserving an optional intended destination after authorization should use a strictly allowlisted relative Web Beta route; never put source account data or session/controller credentials in URLs.
- Browsers deliberately do not share cookies. Plain HTTP on loopback does **not** imply that only the intended browser can send requests. The existing authentication was intentionally introduced by completed FR000300; preserve its protections.

This FR concerns **cross-browser handoff**, not an installation-wide long-lived authorization bypass.

## Requirements

1. **Easy access:** add a small, appropriately placed `Copy link for another browser` action usable from an authorized Web Beta page without leaving Watch/Models or restarting the host. A button in a persistent header/action area or another similarly accessible location is acceptable; avoid disruptive navigation or a large new settings workflow. Generate the link **only on explicit user action**. Use the browser clipboard API when available; provide a selectable/manual-copy fallback and clear, short confirmation or failure text without writing the link into console logs.
2. **Reuse the existing authentication mechanism:** a legitimate authenticated browser may request a **fresh, unguessable, one-use, quickly expiring bootstrap link** through a fixed, same-origin, authenticated and CSRF-protected API route. Use existing in-box Python / browser capabilities. Use the same validated localhost origin and dynamically assigned port; no new server instance, independently managed port, LAN binding, firewall rule, persistent token or password prompt.
3. **Independent second browser:** pasting the resulting link into a browser with no existing CostGuard cookie authorizes that browser and gives it a scoped `HttpOnly` cookie. The original browser session and tab remain working, with unchanged cookies, in-flight reads, Watch Live/SSE streams and refreshes. Subsequent regular links and same-browser tabs work **during the normal session lifetime**; no promise of permanent anonymous bookmarks or access after host restart/session expiry. Make the user-facing messaging explicit about this limit.
4. **Keep navigation intuitive:** if feasible, the copied link opens the current *safe Web view* (e.g., Watch, Models) after bootstrap rather than always switching to Models. Deep-link parameters must be validated or reduced to an allowed safe route; no arbitrary redirect, browser tab external URL, sensitive fragment, session detail secret or history payload. The one-use credential must still be removed from the receiving browser's URL/history immediately before API calls, retaining only safe navigation state.
5. **Token lifecycle and races:** an issued link works once, expires quickly (existing 120-second convention is appropriate), rejects replay, and is unusable after host stop/restart. Repeated copy clicks should not unexpectedly invalidate a still-valid launcher/tray token or the other browser's session. If needed, handle a **small bounded set of pending single-use bootstrap tokens** safely with locks/expiry and explicit limits; avoid unbounded server memory/state or a new token store. A local failure or stale token gives a helpful recoverable message and does not leak a token.
6. **Protect the existing local-server threat boundary:** do **not** remove authentication from `/api/*` (except the existing credential exchange), disable CSRF, relax Host/Origin restrictions, add wildcard CORS, enable unauthenticated control operations, expose provider credentials or local files, persist access links/cookies in JS local/session storage, or allow third-party resources. Access tokens may appear **only transiently in the URL fragment**, never in query strings, Referer, server access logs, diagnostics, telemetry or shared page URLs after successful handoff. Clipboard links are bearer credentials until redeemed/expired; present them as temporary private links and avoid automatic background generation.
7. **Platform behavior:** the core browser-link mechanism works against the same Web Beta Python host whether started on Windows or macOS (where available), without changes to the platform-specific tray/status menus or the default-browser launcher. No HTTPS work is part of this request; continue using local HTTP.

## Acceptance

- **Owner's Chrome → Edge reproduction:** open Web Beta in Chrome using the existing Windows launcher. Copy ordinary `/#/watch` URL to a fresh Edge profile: the expected existing authorization error remains. Then click the new **Copy link for another browser**, paste its fresh URL into Edge, and verify that Edge can access Watch / Models and the same underlying running host while Chrome remains connected and interactive, with no re-launch or change of default browser. Repeat with another browser/profile where available.
- Verify the single-use link can be pasted and redeemed before expiry; the same link fails on replay or after expiry; a previous session's URL does not authorize a new host after restart. Verify a second token can be issued without invalidating existing authorized tabs or an unrelated pending launcher token. Successful handoff removes the token from the URL/history without navigation confusion. Preserve the desired view when safely supported.
- **Negative security tests:** untrusted tab/profile cannot read reports, live data, sessions, account details or settings from plain port-only URL; an unauthenticated/cross-origin GET/POST cannot mint a fresh share link or invoke writes; CSRF-less/wrong-Origin/wrong-Host requests fail; leaked/reused/expired tokens do not confer access; no secrets in logs, response headers or browser storage. An authenticated clipboard action must not expose the private launcher control token.
- Verify ordinary bookmark/navigation semantics **after a browser has been authorized**, within the existing session timeout and unchanged port; normal expiry/restart fails safely with a useful renewed-access explanation. No permanent fixed port or insecure public link is introduced.
- Run focused Python HTTP/auth/security tests and browser-level Chrome/Edge/other-profile checks where accessible; document real multi-browser verification separately from mocks. Do not claim Chrome-to-Edge physical acceptance from one browser context alone. No CLI, provider, pricing, quota, model analysis or Live semantics change; no new runtime dependency or permanent test gate.

**Non-goals:** globally disabling authentication for `127.0.0.1`, permanently valid URLs or silently shared cookies across browsers, changing Windows default browser, auto-launching arbitrary browser executables, exposing Control URLs to JavaScript, HTTPS/certificate setup, sharing across devices or a LAN, and changing the unrelated tray-icon/Windows DPI FR000567.

**Publication scope:** publish this Ready FR and advance the permanent identity high-watermark only. No product code, runtime install, version or release change is authorized by publication; implementation is a separate development task.
