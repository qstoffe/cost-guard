# FR 000653 — Mini Watch: fix avoidable Δ Ctx N/A and show valid deltas for running prompts

**Owner-approved Ready Feature Request / focused context correctness bugfix, 2026-11-09.** New permanent identity **000653**, Ready priority **000880**, following currently Ready FR000650 (000850), FR000651 (000860) and FR000652 (000870). **FR-only publication:** create this FR and advance backlog identity highWatermark **652 → 653** in one documentation-only commit on main. No product code, tests, documentation, release/version, source access or unrelated FR edits in this publication.

## Owner-reported problem and desired visible behavior

On **Cost Guard Web → Mini Watch** (Document Picture-in-Picture), the single Ctx column has a value tooltip showing **Next Ctx** and **Δ Ctx**. The owner repeatedly sees **"Not Applicable" / "N/A" for Δ Ctx**, sometimes in a session with just **one user prompt**, although the regular session detail has the prompt's **incoming context**, and the current/estimated **next incoming context** appears available. A delta calculated from two valid, comparable measurements should not disappear without explanation.

The owner also reports that the **running prompt does not show a useful Δ Ctx**. Since Mini Watch is meant to monitor ongoing work, show the **current running prompt's actual supported Δ Ctx in the existing Ctx tooltip** as early and as often as the source supports it, updating while the prompt executes. The visible compact Ctx cell should continue to show the estimated next incoming context; **no fifth column, permanent verbose math text, additional horizontal row width or redesign** is needed. If the existing full Watch Δ Ctx cell differs for the same canonical prompt and snapshot, investigate the inconsistency and converge on a single correct source of truth.

**Desired concise tooltip when comparable evidence exists (fictional values):**

    Next Ctx: 142k (estimated next incoming context)

    Δ Ctx: +12k (change since the comparable incoming/baseline context)

The exact label/format should reuse existing prepared sign/compact number formatting. A delta of **0** should read **0**; negative values should be shown **only if canonical source semantics prove a supported negative change** (e.g. a verified compaction transition). Do not use **N/A** when a valid delta is present but was dropped by a projection/baseline/representative gate.

## Important semantic correction: what delta is (and is not)

The current implementation in **src/analysis/context.py::watch_context_state()** calculates **Δ = estimated next context − comparable prior baseline**, using a previous meaningful same-session root request or eligible post-compaction anchor, and falling back to the selected prompt's positive **input_context_tokens** when safe. **src/reports/prompts.py::_coherent_watch_deltas()** reconciles adjacent comparable prompt anchors. Therefore a first prompt is **not automatically a zero-baseline prompt**, and Δ is **not necessarily equal to the whole Next Ctx**.

Example: first prompt's evidenced incoming input context **100,000**, its own canonical estimated next input context **112,000**, same context epoch and comparable attribution ⇒ **Δ Ctx = +12,000**, **not** 112,000, not -12,000, and not N/A. Use **unrounded numeric inputs** rather than subtracting displayed "100k" from "112k" in the browser. If the incoming context is **genuinely missing**, stale, unverified or belongs to an incompatible epoch, the correct delta can remain unavailable. Never manufacture a zero initial baseline just because the session contains only one visible prompt. There may be system/tool/model context in the very first request.

For historical Mini rows, the **visible Next Ctx may be the latest valid session-level estimate** while the selected representative prompt's delta pertains to **an earlier prompt-local event**, per completed FR000645. **DO NOT subtract a historical prompt's incoming context from a newer session-level Next Ctx**. Determine the delta from the represented prompt's **own matched source-time context pair/anchor** (or explain the genuine absence), and keep the historical session Next Ctx column as it is.

## Verified code diagnosis and likely failure points — investigate, do not claim a reproduced incident

1. Completed **FR000645** (`development/backlog/complete/000156-000645-mini-watch-ctx-delta-and-session-prompt-preview-tooltips/`) introduced the two numeric values in Mini's Ctx **tooltip**. Its completion (v80.225) explicitly passed existing **0/positive/negative/missing synthetic examples** and accepted N/A when `watch_delta_context_tokens` is null; it **did not prove** the owner's present natural single-prompt scenario or fix baseline inference. This new FR targets *avoidable null deltas* in source/projection, not duplicate tooltip creation. FR000645's original historical semantics and prompt preview remain supported.
2. `src/web/assets/mini.js::View.drawSessions()` reads:
   - **active/running Ctx** from `item.live_context.watch_next_context_tokens`;
   - **historical visible Ctx** from `card.session_summary.context.watch_next_context_tokens`.
   `View.rowHelp()` reads the **representative prompt's** `item.live_context.watch_delta_context_tokens` separately and formats it using `ReportView.display()`. Consequently **Ctx can be known while Δ is N/A** without a browser render error; two different time/scope sources are involved. The tooltip currently writes all its lines joined with single newlines (Next, Δ, not-capacity, warnings). Keep context help short, and split genuinely different topics by one blank line when needed, per owner tooltip style.
3. `src/application/live_projection.py::card_row()` **already exports** each prompt's canonical `watch_delta_context_tokens` and `watch_next_context_tokens` in `live_context`, including running prompts, and exports `incoming_context_tokens` in `prompt`. **No extra Mini-specific HTTP endpoint or raw transcript access is necessary by default.** `src/application/display.py::metric_tokens()` (current display preparation) formats signed delta, but does not invent a missing numeric value.
4. `src/reports/prompt_rows.py::PromptRowProjector.prompt()` computes separate:
   - prompt `incoming_context_tokens = record.input_context_tokens or None`;
   - historical `next_context_tokens` / `delta_context_tokens`;
   - Watch `watch_next_context_tokens` / `watch_delta_context_tokens`, returned by `watch_context_state()`.
   `src/reports/prompts.py::_coherent_watch_deltas()` may further overwrite the Watch delta based on an adjacent prompt's valid/invalid comparable anchor. **Inspect whether this discards a valid same-prompt input/next pair** for first, only or last visible prompt.
5. `src/analysis/context.py::watch_context_state()` has several explicit N/A paths:
   - `prompt_kind == subtask` or `watch_error`;
   - **inactive/undone prompt** (`epochs.active_prompt(record) is False`) returns a historical next estimate but deliberately **sets delta to None**;
   - no positive meaningful current anchor or compatible baseline;
   - earlier compaction with unknown resulting context;
   - a boundary/retirement after moving selection;
   - a **negative difference is forcibly set to None** except supported explicit compaction.
   Some of these are valid. **In particular, investigate why a historical prompt with a valid evidenced incoming and own historical next must lose delta simply because the prompt is no longer *current* in the session.** Historical prompt-local context should not be incorrectly gated by present-day continuation eligibility.
6. `src/analysis/context.py::estimate_event_context()` is the historical event-time estimator; `estimate_next_context()` is the current future-use estimator and intentionally returns None for running, aborted, retired or missing-root cases. **Do not substitute current future-use eligibility for historical event-local delta evidence.** During a running tool loop, `watch_context_state()` intentionally has a last meaningful completed-root request path and sometimes a provisional prior baseline + current prompt text estimate. Verify this survives the actual Mini projection.
7. Existing **`development/tests/test_mini_watch.py::test_active_and_historical_help_fields_keep_prepared_prompt_delta_and_preview`** merely injects precomputed delta values, including None, and asserts pass-through. **`development/tests/integration/probe_mini_help.cjs`** likewise fakes display values and asserts that missing delta shows N/A. These tests do **not** reproduce or exonerate actual context estimation. Add true source→analysis→Live→Mini cases, rather than changing an injected fixture from N/A to a guessed number.

## Requirements

### A. Restore numerically supported delta for single and completed prompts

1. **Reproduce from canonical input**: build a real-shaped, deterministic supported OpenCode V2 (and V1 where relevant) one-prompt session with positive **first incoming context**, complete token categories and an **estimated next context** for the exact same prompt, no intervening boundary. Verify ordinary session detail reports the inputs and Mini currently/previously produces N/A, isolating whether analysis `watch_context_state`, postprocessing `_coherent_watch_deltas`, Live `card_row`, or Mini's row selection loses the value.
2. If the **same represented prompt** has verified **incoming context I and compatible estimated next context N**, and no intervening context reset/compaction/model switch makes them incomparable, the **prompt-local signed Δ should be calculated as N − I** (or from a newer, more authoritative **same-epoch prior session anchor** according to the established Watch contract). Do **not** replace an existing valid richer canonical baseline with a naive first-request input if the original anchor is more appropriate. Use actual unrounded token counts. A single prompt with positive I and N must not return N/A merely for lack of a *previous prompt*.
3. **Historical delta is a historical fact/estimate**, not proof the prompt remains the *current live continuation*. A later prompt, undo, model switch or retired anchor can mean the **session's present next-context estimate** is invalid while the **older prompt's event-time context pair remains known**. Retain a historical delta if its own event-time evidence can be compared; do not cross a real incompatible epoch or fabricate continuity. Where old history was truly removed/unverifiable, preserve N/A. Check explicit `active_prompt(record) is False` and historical-only Mini selections.
4. **Preserve cohort semantics** for compactions, resets, user-aborted prompts, detached subtasks, mixed model/provider, missing history metadata, and reparented/moved/archived sessions. Do not allow a different root or another concurrently running prompt to supply this prompt's baseline. Explicit valid negative compaction deltas may be shown as supported; unexplained negative context regressions remain unknown until a real source boundary or legitimate estimator rule proves them. Zero delta is **0**, not unknown.

### B. Running prompt Δ Ctx updates in the existing Mini tooltip

5. **Current running prompt**: when supported actual or provisional same-prompt context exists, its Mini **Ctx value tooltip must show the running prompt's numeric Δ Ctx** while the prompt is running, not wait for terminal status. Keep its Next Ctx description accurate. At least one scenario with a meaningful latest completed model request while tools continue should produce numeric **Next Ctx and Δ Ctx** with the appropriate signs; after a subsequent root model request in the *same running prompt*, recompute coherently.
6. **No blind fallback**: if the prompt has not yet made any source-proven root request and there is no valid session baseline, or a recent compaction/move invalidates its context, do not manufacture a delta equal to the entire expected Next Ctx, set zero without evidence, or silently borrow a session-summary value. Show brief **Δ Ctx: unavailable** (or N/A) only while genuinely uncomputable, preferably with a **short, specific reason** such as `waiting for request context` or `comparison baseline unavailable` when the canonical source can establish one. No warning essay.
7. **Progressive corrections**: while the prompt is active, first request, tool execution, subsequent calls, context shrink, compaction, session switch, later child return and terminal transition should update the correct values only when source revision/identity supports them. Don't display a stale previous prompt's delta while a new running focal takes its place. Preserve signed and compact formatting through server prepared tokens, not by subtracting formatted strings in JS.

For the **same canonical prompt/source revision**, align the event-local context meaning across `src/analysis/context.py`, `src/reports/prompt_rows.py`, `src/reports/prompts.py`, **Full Watch's displayed Δ Ctx**, and Mini's **Δ Ctx tooltip**. If the full Watch delta genuinely differs because of an earlier prompt anchor/compaction epoch, document and test the correct baseline; do not hide an inconsistency by forcing matching formatted output. Session detail's incoming/next may use distinct historical vs running estimates, so verify comparable semantics explicitly.

Do **not** display a "calculated" Δ from the latest session Ctx plus an earlier prompt's Ictx. Keep historical help's brief explicit scope note if the displayed next Ctx comes from a later timestamp than the representative delta. The current four columns remain **Activity | Session | CCost (Total) | Ctx**; do not add a fifth Δ column or move Mini's layout absent independent owner approval.
