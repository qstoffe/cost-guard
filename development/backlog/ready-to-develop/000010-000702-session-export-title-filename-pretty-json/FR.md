# FR 000702 — Sessions: use the session title for sanitized JSON export filenames and pretty-print JSON

**Owner-approved Ready to Develop — 2026-11-13.** Permanent identity **000702**, Ready queue priority **000010**, immediately after FR000701 (000009). **Feature-request publication only:** create this FR and advance `development/backlog/identity-state.json` from 701 to 702 in one documentation-only commit on `main`. Do not implement product code, run tests, inspect private session data, change release/version metadata, or edit unrelated backlog entries while authoring.

## Owner request and expected experience

On **Cost Guard Web → Sessions → an individual session → Export Sanitized JSON**, the browser currently suggests a filename based on `opencode-` plus the technical session ID and `-sanitized.json`. The owner wants the **actual displayed session name/title**, with **only invalid filename characters removed**, followed by `.json`. Do not add an `opencode-` prefix, a session-ID suffix, or a `-sanitized` suffix when a usable title exists.

The downloaded JSON is currently **minified onto one line**. Make the exported file **human-readable pretty-printed JSON** with normal indentation and line breaks throughout. These are **filename/serialization usability changes**, not a new export format or change to what is sanitized.

Examples of desired default filenames:
- Session title `Refactor authentication` → `Refactor authentication.json`.
- Session title `Fix:Auth|Tests?` → `FixAuthTests.json` (remove invalid characters rather than substituting underscores).
- Session title `Översyn – åäö 🚀` → `Översyn – åäö 🚀.json` (preserve valid Unicode, case, spaces and punctuation).

## Repository findings (static review, 2026-11-13)

1. `src/web/assets/session.js::SessionDetail.View` receives the displayed title from the verified detail result as `data.result.view.prompt_blocks[0].title`; its `update()` renders that title in `this.heading`. The export action is constructed as `new SessionExport.Action(api, id)` and currently gets the ID but **not** the title.
2. `src/web/assets/session-export.js::SessionExport.Action.save()` calls `window.showSaveFilePicker` directly from the trusted click, with `suggestedName` based on `opencode-` + session ID + `-sanitized.json`. Its non-picker fallback currently uses the filename returned by the API for `link.download`.
3. `src/application/session_detail.py::SessionDetails.export()` currently returns `payload` plus `opencode-` + session ID + `-sanitized.json`; `src/web/session_export.py` emits that name in `Content-Disposition`. `src/web/assets/app.js::api(..., attachment=true)` deliberately checks a strict ID-shaped `Content-Disposition` before accepting an export. **Do not accidentally break or weaken this response validation** just to change the user-visible saved name. A safe client-side display filename can be separate from the existing trusted transport filename; alternatively update both sides together with equally strict validation.
4. `src/sources/opencode_v2_export.py::native_export()` obtains the **native sanitized OpenCode** `{info, messages}` transfer with `sanitize=true`, validates the selected session, and currently serializes it with `json.dumps(..., ensure_ascii=False, allow_nan=False, separators=(',', ':'))`, which produces the observed compact one-line file. The existing 16 MiB transfer ceiling and client/content-length checks are intentional safeguards.
5. Completed **FR000631** established export/picker/download/security behavior; completed **FR000646** established the current **Export Sanitized JSON** label and help behavior. Preserve both contracts except for the filename and JSON whitespace requested here.

## A. Filename requirements

1. **Title first, exact when safe.** Use the **actual observed title of the currently selected session** as the filename stem. For a normal valid title, the proposed name must be exactly `<session title>.json`, including original capitalization, meaningful spaces, accents and valid Unicode. No provider label, timestamp, generated session ID or `sanitized` marker is added in this normal case.
2. **Remove invalid filename characters, do not transliterate.** Remove cross-platform-unsafe characters including Windows `< > : " / \\ | ? *`, NUL/other control characters and path separators. Avoid unsafe path components, trailing dots/spaces that Windows cannot save, and misleading control/directional formatting characters. Do not introduce path traversal or user-controlled directories. Do not generally replace forbidden characters with `_` or `-`; the owner's preferred treatment is **deletion**.
3. **Exceptional titles remain safe.** Handle missing/blank titles, names that become empty or only dots/spaces, reserved Windows device filenames (`CON`, `PRN`, `AUX`, `NUL`, `COM1`–`COM9`, `LPT1`–`LPT9`, including extension variants), and impractically long names. Use a deterministic, filesystem-safe fallback such as `session-<canonical-session-id>.json` only when the title cannot safely form a filename; truncate overlong titles conservatively while keeping `.json`. Do not silently create an invalid or extensionless filename.
4. **Compute before the user gesture.** The title is already in the loaded session-detail result; supply/refresh it to the export action as part of existing data update, without a new API read, source call, `await` or other asynchronous step before `showSaveFilePicker`. Preserve its required **synchronous trusted-click invocation**. Do not infer it from editable DOM text, from a prompt preview, or from the technical session ID when the actual title is available.
5. **Correct session and lifecycle.** Recompute when the observed title legitimately changes, clear previous title on selection/source change and navigation, and bind the proposed filename to the **same selected session/token** used by the export. A late response or previous session must not supply a filename for a newly opened session. Export authorization remains pinned to the selected canonical session ID, never to its nonunique title.
6. **All user-visible save routes.** Both the native Save As suggested filename and ordinary browser-download fallback (`link.download`) should use the same title-derived name. The browser remains free to adjust collision suffixes or download locations according to its normal behavior; do not overwrite existing files automatically. Keep the internal transport header/validation secure, whether it retains the current ID-based filename or is explicitly revised with matching strict checks.

## B. JSON pretty-format requirements

1. Produce **valid, conventional pretty-printed JSON**, e.g. **2-space indentation**, separate lines for nested objects, arrays and their entries, and a final newline. The exported file must not be a single minified line for a normal multiline structure.
2. Preserve the native `{info, messages}` content and JSON data types, values, ordering and Unicode behavior. Pretty printing only changes **insignificant serialization whitespace**, not characters inside JSON strings. A parse of the prettified export must be semantically identical to the former compact serialization of the same source transfer.
3. Keep upstream `sanitize=true` as the only native redaction mechanism; do not rebuild the payload from a Cost Guard summary, add an unsanitized mode, or claim exhaustive secret removal. Preserve existing **Review before sharing** guidance and the point-in-time nature of exports from running sessions.
4. Enforce the current transfer/HTTP maximum **on the final pretty-printed UTF-8 bytes**, including indentation and newlines, not only on the compact form. If it would exceed the existing safe limit, fail truthfully as too large **without saving a partial/minified substitute**. Do not silently raise the security/size cap to accommodate whitespace.
5. Preserve UTF-8, correct `Content-Type`, `Content-Length`, download response validation, cancellation and error mapping, no persistent transcript staging, and all existing source-identity, CSRF, epoch, authorization and read-only safeguards.

## Acceptance and focused verification

- **Filename:** with an ordinary named session, Save As proposes exactly `Title.json`, not `opencode-ses_...-sanitized.json`. Test punctuation removal, valid Unicode, internal spaces, reserved words, trailing period/space, dot-only/empty titles, overlong names and filename-collision behavior. A usable name never receives an unwanted prefix/suffix.
- **Picker activation:** the proposed name is available at trusted click time with **no asynchronous work before the native picker**. Cancel causes no export request or file write; successful save, keyboard/pointer activation, focus restoration, navigation and previous/current session identity behave as before.
- **Fallback download:** without `showSaveFilePicker`, an actual downloaded file uses the same sanitized title and `.json` extension; strict server response checks still reject tampered or invalid attachments. Test that browser-controlled download location/collision policy is preserved.
- **Pretty JSON:** read an actual exported file and verify indentation, multiple lines, nested objects/arrays, trailing newline, valid UTF-8/Unicode, and `JSON.parse` / `json.loads` semantic equivalence to the same native sanitized transfer. Include quotes/newlines **inside string values**, where content must remain unchanged.
- **Limits and safety:** verify a pretty-expanded payload near/over 16 MiB, invalid native export, expired/source-changed session, live/running snapshot, abort and cancellation. Oversize/invalid inputs must not leave partial files or be mistaken for success; no extra source/model calls or private content logged.
