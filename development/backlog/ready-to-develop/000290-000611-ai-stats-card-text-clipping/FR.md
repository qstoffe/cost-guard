# FR 000611 — AI Stats Fun Facts: stop clipping session links and date/detail text in cards

**Owner-approved Ready Feature Request, 2026-11-06.** Permanent identity **000611**; Ready queue priority **000290**, after existing FR000610 (000280). This is **backlog documentation publication only**, not implementation, testing or a product release now.

## Owner-observed bug and intended UX

On Web Beta **AI Stats → Fun Facts**, some linked session names appear **cut horizontally through their letter height**, as if overlaid or covered by the content above. Some date and other center-of-card text is also partially clipped. The cards should present their actual text and clickable links cleanly at normal sizes and across responsive/browser zoom states. The owner asks for a focused CSS/presentation bug fix, not a change to statistics, links, card meanings or acquisition.

**Desired result:** All Fun Facts cards (and the same shared card component in AI Stats Overview) have legible, vertically uncut values, dates, linked session names and descriptive text. The link's visible text and entire interactive focus/click area must fit without another row overlapping it. Long text should wrap or use a deliberate, readable *horizontal* truncation strategy only when truly necessary, not hide half the height of a line. Keep the compact, equal-treatment grid aesthetics without imposing a fixed height that clips genuine content.

## Concrete code findings / likely root cause

- In `src/web/assets/app.css`, `.ai-stat` is a five-row grid with `grid-template-rows: auto auto 1.5rem 1fr auto`. The **third fixed 1.5rem row** contains `.ai-stat-detail`, where `src/web/assets/ai-stats.js` places either a session `<a href="#/sessions/...">` or plain details such as the **Busiest Day date**.
- That detail paragraph also has `margin: .25rem 0; white-space: nowrap; overflow: hidden; text-overflow: ellipsis`. The inherited `:root` typography is `15px/1.55`: at the default font size, a 1.5rem track is **22.5px**, its two 0.25rem vertical margins total **7.5px**, leaving roughly **15px** for a line whose normal line-height is **~23.25px**. With `overflow: hidden`, the baseline/top/bottom of the text can be visually cropped. This is a specific CSS geometry conflict consistent with both reported symptoms; confirm the real rendered cause in a browser rather than claiming an observed screenshot or excluding additional issues such as grid shrinkage, overlap or zoom.
- The date in **Busiest Day** is supplied as `Stat(..., detail=str(busy or ''))` from `src/analysis/ai_stats.py`, and session names come from `metric.session_title` in `src/web/assets/ai-stats.js::View.update()`. Both use this same detail row. `.ai-stat-value` is a separate grid row and should also be checked for any reported middle-of-card date/value clipping under narrow widths and large text.
- There is an optional **eleventh** matched-run Fun Fact card (`Biggest AI Speed Gap` / `Original Thinker`) constructed slightly differently in `ai-stats.js` but using the same `.ai-stat` CSS. Check that this card's extra link and detail content do not inherit a related row-placement/height issue.
- Existing `development/tests/integration/probe_ai_stats.cjs` validates 10-card count, equal card dimensions, absence of outer scroll overflow, themes/widths and safe session links, **but does not assert that the actual rendered text line boxes/link rects fit inside their clipping boxes**. `scrollHeight <= clientHeight` on a card is insufficient when an inner `.ai-stat-detail` clips its own contents.

## Targeted implementation directions

1. **Fix the grid/content sizing at its source.** Make the detail row content-sized (or otherwise genuinely large enough for the inherited line-height, margins and font metrics), and remove/adjust the clipping interaction responsible for losing the top/bottom of session links and date text. Prefer a small shared `.ai-stat` / `.ai-stat-detail` CSS change to per-card patches, special casing individual strings, JS-measured fixed heights, negative margins or `z-index` stacking hacks. Confirm the card heading, value, detail, trait and status occupy separate non-overlapping usable regions.
2. **Preserve readable long-name behavior.** Long session titles, displayed dates, status details and permitted text must not cause collisions, page-wide horizontal scrolling or unreadable clipping at small widths. A consistent line wrap is acceptable/preferred when it fits the card design. If deliberate one-line ellipsis remains for a long session name, it must truncate *only horizontally*, leave the entire glyph height visible, retain the original session link's accessible name/href and ensure its focus outline/activation target is not cut off. Avoid changing data, inferring shorter dates or hiding important source/partial-status information just to fit a fixed card height.
3. **Keep the existing card visual contract.** Maintain the responsive grid, approximately equal sibling heights within each grid row, concise spacing, theme colors, emoji/header/help, selected-period controls, status semantics, and current value/CCost formatting. Let row/card height grow naturally when longer or larger text requires it; a rigid 12rem/1.5rem slot must not silently clip real content. Handle narrow mobile widths, browser zoom/text scaling and different system fonts; prevent nonessential layout jitter on period changes or quiet refresh without throwing away keyed DOM/focus.
4. **Scope and compatibility.** Fix both **Overview and Fun Facts** cards where they share CSS, especially `Most Expensive Session`, `Longest Session`, **Busiest Day**, and the optional matched-input Fun Fact. Do not alter the underlying period mathematics, source/cache acquisition, session identities/URLs, metric copy, number of primary ten cards, eleventh-card availability rule, or unrelated Web/CLI/Mini layouts. Coordinate with earlier **FR000609** (shared loading UX) without duplicating or reverting its work.
