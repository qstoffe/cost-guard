# FR 000628 — Investigate and restore reference CCost for OpenCode Claude Agent sessions

**Owner-approved Ready Feature Request, 2026-11-07.** Permanent identity **000628**; Ready queue priority **000560** (after FR000625 at 000520, before FR000626 at 000620 and FR000627 at 000720; do not interrupt the already-selected FR000624 at 000420). This transaction is **backlog documentation publication only**, not implementation, a live probe or a product release.

## Owner-observed regression and goal

Several real OpenCode Toolkit live-test sessions run via OpenCode's newly introduced **Claude Agent** provider, provider ID **claude-agent**, rather than the older integrations. Cost Guard can display their prompts, execution duration, context size and model-call counts, but **Cost / CCost appears as N/A (Not Applicable)**. The owner wants meaningful cost visibility for these sessions, including their historical results and Live updates. This is not acceptable as a permanent silent blind spot for a provider in active use.

The owner suspects that model price information may be missing for the new provider. **That is a hypothesis, not a confirmed cause.** We have no sanitized native session trace attached and must not claim to have reproduced the exact failing requests merely from the UI observations.

OpenCode introduced the built-in Claude Agent provider in **v2.2.3 on 2026-10-30**, using the Claude Agent SDK and the user's Claude Code login. OpenCode's design differentiates subscription-covered usage (potentially reporting native cost 0) from API/cloud usage and uses resolved-model pricing for some login types:
- https://github.com/anomalyco/opencode/blob/dev/CHANGELOG.md
- https://github.com/anomalyco/opencode/blob/dev/specs/v2/claude-agent-provider.md

**Cost Guard CCost is reference token valuation, not the user's verified billed spend, native quota consumption or Claude subscription deduction.** A native provider cost of 0 under a subscription must neither erase a valid positive reference CCost nor be interpreted as proof that reference usage is free. Conversely, never manufacture actual billing from reference estimates.

## Existing implementation clues (not yet a diagnosis)

- src/sources/opencode_v2_normalization.py extracts assistant providerID/modelID and step/message tokens and optional native costs. src/sources/opencode_tokens.py normalizes I/C/W/O token evidence. Correct prompt, duration, context and call display alone does **not** prove complete priceable token/model evidence.
- src/pricing/catalog.py::reference_valuation requires a resolvable, verified reference model identity with complete relevant rates and tier; src/pricing/identities.py contains bounded Claude aliases, not an arbitrary "latest Claude" mapping. src/pricing/github_copilot.py supplies Cost Guard's existing published reference price catalog, which includes multiple Claude model families. Available published model prices do not prove a Claude Agent **reported model ID** matches those prices.
- src/analysis/valuation.py::ComparisonCost distinguishes observed_requests, priced_requests, known_ccost and complete. With observed usage but no priceable calls, existing presentation correctly uses **N/A** rather than fabricated 0; a partially priced scope may show a marked known subtotal.
- A new provider's reported model name could be a short selector such as "opus" or a resolved/versioned Claude ID; the actual source shape and rate provenance must be inspected, **not assumed**. The problem could also be missing token-category fields, missing/expired catalog data, source interpretation, or cached cost projections.
- FR000625 changes only the Web default display unit; FR000627 quiets routine *daily summary* partial warnings. Neither is a correction to unpriced Claude Agent prompt/session CCost and neither may mask this issue.

## Required investigation

1. **Reproduce and localize the N/A.** Use a minimal privacy-sanitized real V2 Claude Agent observation if safely accessible, otherwise first build a representative fixture and explicitly label it synthetic. Capture only safe source facts needed to explain the failure: OpenCode/Cost Guard version, providerID, raw-versus-normalized modelID and any resolved model identity, variant/tier, token I/C/W/O availability, presence/meaning of native cost, catalog match, observed_requests/priced_requests, analysis/revision/cache state, and which Web/Watch/Sessions surface displays N/A. Do not copy raw prompts, transcripts, credentials, account tokens, worktree paths or private session logs into the public repository.
2. **Trace each possible failure boundary:** source message/step normalization; model/version/provider identity; official rate availability, refresh and tier matching; reference valuation; zero-token continuation/deduplication; aggregation of root/subagent/tool work; session-cost cache/revision; and Live, retained and historical display tokens. Establish where the first correct evidence becomes unpriceable and whether this is genuinely Claude Agent-specific.
3. **Verify pricing semantics.** Distinguish (a) zero native cost due to a covered subscription or custom gateway, (b) positive native billed/API cost, (c) reference CCost computed from token categories at published rates, and (d) truly unavailable reference rates/telemetry. Inspect which price/identity information OpenCode exposes for the actual resolved Claude model. Do not assume an alias like "opus"/"sonnet"/"haiku" always means today's newest version or that native $0 means zero reference CCost.
4. **Check source validity before a workaround.** If the provider supplies versioned, trustworthy model identity and token evidence, use the narrowest reliable mapping/valuation repair, preserving established cache invalidation and source provenance. If the necessary identity or usage fields are genuinely missing upstream, document the precise missing contract, investigate supported non-secret model metadata and consider a safe upstream dependency. Escalate the unresolved limitation with evidence rather than guessing a model version/rate.
5. **Check revaluation of existing history.** Once the model/rate becomes valid, previously acquired Claude Agent requests should reprice through normal source/catalog revision and cache-invalidation paths, without fabricating new source calls or requiring deletion of genuine usage history. A stale cache must not trap historical sessions in N/A after verified evidence becomes available.

## Required product behavior / scope

- For Claude Agent model calls with **actual positive observed token usage, verified resolved model identity and trustworthy published I/C/W/O rates**, Cost Guard computes the normal positive **reference CCost**, with the correct per-request context tier, and presents it in the selected Credits/USD unit across relevant Live Watch, Mini Watch, Sessions/Earlier Sessions and other cost-using reports. It remains explicitly reference CCost, **not real billed spend**.
- Preserve native-provider usage/billing as a separate signal. If the login reports 0 provider spend because a subscription covers the call, the reference CCost may still be positive. Do not infer an account's plan or actual charges from providerID alone. Do not alter quota/account figures to make a reference value appear.
- Preserve all observed model calls, root/subagent attribution and I/C/W/O totals; do not double-count a Claude Agent streaming update, SDK turn total, step-finish record, tool continuation, compaction or subagent. Correct CCost must correspond to the same physical requests as the displayed usage.
- If a mixed session has verified priceable and genuinely unpriceable requests, preserve the existing honest **partial known subtotal** semantics. For fully unpriceable observed usage retain **N/A**, not 0; for verified no usage preserve normal zero semantics. Do not merely replace the text N/A or globally suppress partial markers. Unknown cache writes, missing token fields, ambiguous model variants or absent prices remain unknown.
- Keep other providers, Copilot/GitHub price handling, existing reference CCost definition, billed spend, quota windows, settings, Web default unit and FR000624/625/626/627 functionality intact. Avoid a broad provider rewrite, new pricing service or unsupported direct Claude API/credential access solely to hide N/A.
- Update narrowly relevant current CCost documentation/help only if users need to understand a repaired Claude Agent path or a verified residual limitation.
