# FR 000600 — Attribute OpenCode V2 `subagent` costs to the initiating prompt

**Owner-requested executable Ready Feature Request, 2026-11-05.** Cost Guard only. Priority 000160; permanent FR identity 000600. This FR changes causal usage attribution and affected presentation, not OpenCode itself, provider billing, or repository-worker behavior.

## Incident and observed discrepancy

In a completed OpenCode V2 `/repo-backlog` session for an OpenCode Toolkit FR, Cost Guard displayed one prompt with **CCost 161 (I + E: 4 + 158)** but **Total Cost 270** for the same root session. Only **one user prompt** appears in the supplied root-session export, with **no compaction** observed. During that prompt the parent called `subagent` once to consult `decision-delegate` (a distinct model, GPT-6 Astra); the completed tool's native `state.metadata.sessionID` identifies the child, and its text begins with a `<subagent sessionID="…">` element. The prompt's model label did not indicate an additional model. The observed 109-CCost gap strongly suggests unlinked child usage; the child export was not supplied, so its exact price contribution has **not** been independently verified. The root export's native `info.cost: 0` is not the reference-priced CCost used by the display.

Source inspection identifies a concrete compatible defect:
- `src/analysis/causal.py::_task_child_session_id` only accepts tool name `task`, and structured `metadata.sessionId` or `<task id="…">`; it cannot recognize the observed `subagent` / `metadata.sessionID` tool result.
- `src/watch/tools.py::_child_session_id` also limits linked-child traversal to `task` (although it accepts both metadata-key spellings).
- `src/analysis/session_cost.py` values all physical root-tree requests independently of individual prompt attribution. Consequently, a real child can contribute to the root-session total while being excluded from prompt CCost, Calls, token mix, model marker, detailed main/subagent breakdown and linked activity.

Cost Guard's existing contract in `docs/usage-and-cost.md` assigns child/subagent work to the initiating prompt. This is **not** a requested change to make session cost always equal the sum of visible rows: compactions, genuinely unassigned work, partial history and missing prices have their own truthful semantics.

## Required outcome

1. Recognize current supported OpenCode V2 `subagent` invocations as causal child links, in addition to legacy `task`. Prefer real **structured tool state** (`state.metadata.sessionID` or `sessionId`, plus supported top-level metadata) and preserve genuine child-session identity, parentage, time boundaries, foreground/background status and nested descendants. Only treat tool-returned text as evidence when its format and provenance can be reliably verified; do not trust arbitrary prose or a copied session ID as authority.
2. Reuse or consolidate the canonical child-link interpretation across `src/analysis/causal.py` and `src/watch/tools.py` so differing tool-name/field spelling rules do not diverge again. Do not create a second accounting path or independently price child usage. Work with the existing normalized snapshots, causal prompt windows, request identities, source revisions and root-tree cost cache.
3. Attach each real child request **exactly once** to the root prompt which initiated the subagent, including continuation after an invisible subagent-completion notice. Account for children created while the original prompt is running and for late-arriving child usage; preserve correct prompt duration, live status and eventual completion. Multiple prompts must not gain each other's child requests, and overlapping/nested descendants must not be double-counted.
4. Make the corrected per-prompt CCost, I + E breakdown, Calls, model/effort and linked-subagent marker, token mix, subagent cost details/tooltips and linked activity consistent across CLI, session report, full Web Watch and Mini Watch where applicable. The existing **full root-session total remains authoritative**. Revisions and partial/unknown coverage must be represented honestly: never silently assign a session-total residual to a prompt merely to force equality.
5. Preserve independent CCost reference rates and Credits/USD conversion, actual native billing separation, original `task` links, unrelated tools, cost tiering, user-prompt counting and explicit compaction rows. Do not introduce extra paid model calls, scanning unrelated sessions, persistent reconciliation registries or new product-wide release gates.

## Acceptance tests

1. **Causal regression from sanitized incident shape:** one V2 user prompt containing one `subagent` tool with `state.metadata.sessionID`, one real child session with its own model and requests, and no compaction. After canonical snapshot loading, the prompt's **unrounded** reference CCost and Calls include parent + child once; its total matches the same root's independently computed full-session total when pricing/coverage is complete. Its display identifies the second model and exposes correct subagent detail. Before the fix this fixture must reproduce a missing child contribution.
2. Verify `sessionID` and `sessionId` key variants, the native `<subagent sessionID>` response format where relevant, original `task` tool behavior, multiple children, nested children, repeated observations and alternate model/effort tiers. Prefer authoritative structured metadata over textual fallbacks.
3. Confirm real parent-child provenance and bounded tool time window; reject malformed IDs, unrelated sessions, duplicate/replayed tool parts, copied user/tool text, wrong-parent links and impossible intervals. A child that starts in prompt #1 must not be charged to prompt #2, including after synthetic continuation or while background work finishes.
4. Check running → terminal Watch updates, late child requests, caching/source revision changes, one-prompt report/Web/Mini/CLI parity, total Main + Subagent cost detail, Calls and Token Mix. Ensure zero/unknown/partially priced child cases remain honest and full-session total does not regress.
5. Include negative cases where a greater session total is *legitimate* (separate priced compaction or unallocatable activity), so the fix does not allocate arbitrary differences or enforce unconditional equality. Show any unresolved source limitation explicitly rather than manufacturing a reconciled number.
6. Use model-free deterministic parser/causal/report/Watch tests and supported host evidence when useful; no private session export, child transcript, credentials or user-specific paths are added to source control. Run applicable existing product validation; report any unexecuted checks truthfully.
