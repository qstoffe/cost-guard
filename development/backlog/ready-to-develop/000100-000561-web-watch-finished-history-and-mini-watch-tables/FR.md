# FR 000561 — Sort Earlier Prompts by finished time and redesign Mini Watch as compact live tables

## Owner request and decision

**Owner-approved executable Web Beta feature request, 2026-11-03.** Permanent identity **000561**, Ready priority **000100**, after the currently Ready FR000559 (000080) and FR000560 (000090). One FR covers two requested **Web Watch** refinements: (a) show **Finished** instead of Started for Earlier Prompts and choose/order the eligible historical sessions by the canonical *finished* time; (b) replace Mini Watch's current three-metric card with a compact, two-section/table **per-prompt + primary-account-usage** Document Picture-in-Picture view, while making the Watch-page toggle visually reflect On.

The owner explicitly **retracted** an initial suggestion to swap the two time columns: **do not swap them**. Column 1 remains the time column (Started on Running, Finished on Earlier), and **Duration remains column 2** in both.

This FR is presentation + existing canonical time/row projection and history-selection scope. It is **not** an authorization to modify the OpenCode installation, provider quotas, model requests, desktop window policy, pricing, or source authority.

## Verified starting point and dependencies

Inspected repository `qstoffe/cost-guard` current main on 2026-11-03 (including delivered **FR000558**, completion v80.138):

The time cell uses the canonical **start** `clock` and `date_time` tokens, even for Earlier. The new FR000558 header help/tooltip and `#N`/preview column behavior are already delivered.
- `src/reports/prompt_rows.py::PromptRowProjector.prompt` already calculates `completed_at_ms` from a source-supported `terminal_time_ms` when nonrunning. `src/reports/models.py::PromptProjection` retains it and the ordinary `src/application/projection.py::prompt` exports it. The **Watch card export** `src/application/live_projection.py::card_row` currently does **not** export `completed_at_ms`; it must be routed into the browser with correctly localized finished-time display. An old running snapshot, observation receipt time or display clock is not a substitute.
- `src/reports/watch_capture.py::capture_rows` currently sets `WatchCapture.latest_ms` to the **maximum prompt start**. `src/watch/cards.py::WatchCards.historical_ids` chooses the five latest eligible session captures by this start-based key, while `WatchCards.project` orders displayed history by the selected row's `at_ms`. A **true Finished-based history** therefore requires changing authoritative representative selection, membership/ranking and ordering—not merely renaming the table header.
- `src/web/assets/mini.js` opens a real Document Picture-in-Picture via `requestWindow({width: 380, height: 270})`, has a Watch-page button with `aria-pressed`, a clickable “Cost Guard · Watch” return-to-existing-tab header, an in-app **×**, three aggregate metrics, a status area showing **Live** when healthy, and a one-line list per subscription. The owner requests removing that distracting visible approximation glyph **without discarding factual provenance**.
- `src/watch/cards.py` keeps a newly terminal focal prompt visible under an established **30-second terminal grace**. `src/web/assets/watch.js` distinguishes running (yellow/warning), successful completed (success/green), and aborted/error (red). The owner described terminal rows as “red”; the desired **parity with Watch** should preserve these actual canonical status distinctions rather than recoloring a successful completion as a failure.
- **FR000560** is a separate Ready UI FR for full-size Watch subscription cards and individual session-card borders; it doubles the *full Watch* account progress-bar height. Mini Watch must instead retain the **old thin progress-bar thickness** and does not inherit that new card framing. **FR000559** addresses stale Running lifecycle and should remain the shared correctness owner; this FR must not invent its own terminal heuristic.

## 1. Earlier Prompts: Finished column and chronological history by completion

### Visible table

- In **Running Prompts**, keep `Started` in **column 1** with the local start time and the current chronological **start-time ascending** order (oldest started above, newest started below). **Duration remains column 2**.
- In **Earlier Prompts only**, replace the **column 1 heading** `Started` with **`Finished`**, and display that prompt's **actual local finish clock** `HH:mm`—**not its start clock**. Keep **Duration in column 2**, then the other eight FR000558 columns in their existing order. Do not rename both tables or make a second Started column.
- The Earlier Finished header's accessible help/tooltip must explain canonical end/termination, including relevant unsuccessful endings, and distinguish **Finished** from **Duration**. The short visible clock must have an accessible full local date and time (`YYYY-MM-DD HH:mm`) to disambiguate dates and daylight-saving transitions.
- For a prompt without a supported terminal timestamp—even if lifecycle analysis proves it is no longer running—**do not invent its Finished timestamp** from Started, last model-call time, source polling time, Watch observation time or `start + duration`. Show a truthful unknown (`—` or `N/A`) and preserve accurate outcome/provenance.

### History membership, representatives, ordering and eviction

- Keep the existing **maximum five distinct eligible Earlier sessions**, each represented by its relevant **latest actually finished prompt** (when supported), excluding active/in-terminal-highlight sessions according to shared Watch lifecycle rules. “Latest” for this section now means **latest supported finish timestamp**, not latest start timestamp or latest catalog activity.
- Choose **the five sessions with the most recent supported finish times** and order their visible cards **ascending by that finish time**: the **oldest finished is at the top**; the **newest finished is at the bottom**. When a newer eligible finished prompt/session enters, the **oldest finished visible entry is displaced first**. A prompt that started a long time ago but genuinely ended most recently should rank near the bottom—not lose to a later-started, earlier-ended one.
- Within any session containing several prompts (including concurrent prompts or a later-started prompt that finished earlier), the representative's **prompt number, time, preview, model, Duration and metrics must all belong to the exact same terminal prompt**. Do not select a timestamp from one prompt and render a different start-selected prompt. Respect canonical event IDs and independent session/root IDs.
- Handle unknown terminal times **explicitly**: when historical eligibility is known but a reliable Finished clock is not, show `—` and use a documented stable fallback placement or exclusion policy that never claims a fabricated finish. Known-finish cards must always satisfy the requested chronological ordering. Do not silently erase otherwise valid retained usage/history or mislabel an unknown-ended attempt `Completed`.
- Stable ties by exact finish timestamp must use existing deterministic session/event identity ordering. Earlier/Running separation, ~30s terminal grace, historical source staleness and five-session cap remain coherent over publication, reload and reconnect. Do not make old status appear live simply to obtain a timestamp.
- Change the owning Python Watch capture/history ranking/export as needed; do **not** sort a start-selected five-session subset only in JavaScript, introduce a second expensive history watcher or time out a long-lived prompt merely because of age.

## 2. Mini Watch On/Off button: clearly selected while On

- On the full **Watch page**, the existing `Mini Watch: On/Off` button remains a real toggle, with correct `aria-pressed`. While **On and an actual PiP window is owned/open**, make **the entire button visibly filled/highlighted**, with emphasized border and foreground matching the **selected primary-navigation treatment** (`nav a[aria-current="page"]` / semantic `accent-soft`, `accent` theme tokens). This should be obvious but not aggressive.
- While **Off**, return to the **existing unfilled button appearance**. Native close, replaced/closed PiP, host teardown, page reload, cancelled/rejected opening and asynchronous races must all correctly clear the On fill; pending opening is not On. An unavailable/disabled button must keep its own disabled styling.
- Preserve keyboard/pointer activation, focus visibility, theme switching, and the fact that in-app navigation does **not** close an already-open Mini window.

## 3. Mini window chrome, header, status and default geometry

- **Remove the custom in-document × close button** from the Mini PiP view: the browser's **native window close** remains, and the Watch-page On/Off toggle is the fallback to close it. Native window close must synchronize the main button to Off. Do not hide or emulate browser-owned PiP security/title/return controls or add a new fake close affordance.
- **Keep** the compact clickable **Cost Guard · Watch** title/header and its existing accessible **return-to-actual Watch tab** function. Reduce excessive padding/margins around the header, and remove the separate **bordered inner `.mini-card` visual container**: the browser already frames the PiP window. Use a lightweight document layout with sensible margins, no redundant frame inside a frame.
- Remove the **healthy-state visible text `Live`** and its wasted space. **Do not remove meaningful** Source unavailable / Offline / Reconnecting / Authorization expired / Host changed / Not live / partial-coverage warnings. Show these compactly and accessibly only as needed. Never present old retained values as currently live; retain existing freshness/identity/source safety semantics.
- The current PiP request is **380×270** CSS px. Re-evaluate the requested initial **width and height** for the redesigned **five-column prompt table + up to five prompt rows + up to three subscription rows** so **typical default content fits without a PiP document/body scrollbar**, even before the user manually resizes. Exact pixel dimensions are an implementation choice bounded by browser/OS support; accept browser-owned chrome, min/max clamping and user resizing. Prefer useful compactness to unnecessary blank padding.
- Size and overflow must degrade gracefully for long labels, larger fonts, browser zoom, manual narrow/short window sizes and platforms with smaller permitted PiP sizes; avoid horizontal document overflow or clipped essential values. Keep one app-owned PiP/SSE session; do not poll separately.

## 4. Replace the three aggregate metrics with a per-running-prompt table (top)

**Remove the visible aggregate fields** `Running prompts`, `Running CCost` and `Longest running` and their values **from the Mini UI**. The underlying canonical aggregate may remain available for other consumers; do not change its accounting. Instead show the actual prompts one row per session + prompt identity, including distinct concurrently running prompts within the **same** session.

- Put a **real, compact, clearly structured table first**, above the subscription area, with ordinary table header, subtle grid/row/column borders and theme-appropriate background. Headings and columns **in this exact order**:

  | Column | Desired cell |
  | --- | --- |
  | **Session** | The session's actual title, aggressively **ellipsis-truncated** to fit the compact window, with the full title accessible via tooltip/title/keyboard focus. It identifies the session, but the costs remain **prompt-local**. |
  | **#** | Session-local canonical prompt ordinal, e.g. `#23`, never a Mini-list index or made-up row number. |
  | **CCost** | Accumulated **CCost of this one prompt only**, not session/total/account spending; same Credits/USD setting and known/unresolved provenance as Watch. |
  | **Duration** | **This prompt's** existing elapsed execution Duration, shared with Watch, frozen when terminal. |
  | **CTX** | Existing **next incoming context estimate for this prompt** (same semantics as Watch's Context, short header `CTX`). The existing `~` approximation indicator is **allowed here**, since it really is an estimate. Unknown remains `N/A`, not a fabricated zero. |

- A useful subtle table heading/tooltip should clarify that CCost/Duration/CTX are **per prompt**, not for the entire named session. Keep numeric fields compact and readable. Long titles must not push numeric fields off-screen; full title remains accessible. Do not turn each prompt into its own box/card.
- Use the **same canonical exported active/focal Watch rows and identities** (`src/application/live_projection.py::active_cards`, `src/watch/cards.py`) and existing display/CCost/context tokens, not a second source reader or browser inference from activity/time. Do not use `running.count` to manufacture row identities or equate `active_cards.length` with strictly running work; it can contain placeholders and terminal grace. Deduplicate by source session/event ID and retain one row per true prompt.
- Table order for running rows is **ascending canonical prompt start** (as full Watch). Match existing event/status lifecycle and update rows in place with fresh SSE. New prompts add rows, completed/aborted prompts keep their **final prompt-local CCost, Duration and CTX** during Watch's existing **30-second terminal highlight/grace**, then leave; do not extend grace on every SSE/reconnect and do not resurrect a stopped prompt. A separate later attempt can appear legitimately.
- **Colors:** while truly running, use the **same yellow/running tone** as the main Watch. On successful completion apply the **existing successful Watch final style** (currently green); on abort/error apply the **existing red/error style**, including readable outcome/status text/tooltip. The owner described “turns red on completion/abort”; the shipped Watch **does not** mark success red, and parity is the stronger requirement. Do not misrepresent a genuinely completed prompt as errored. Preserve explicit stop reason (quota, user, etc.) where known and meaningful accessibility when color is not visible.
- Keep row heights compact but readable with broadly the **same font scale as the existing Mini running metrics**, no giant duplicated cards. Reserve **up to five prompt rows'** vertical room. At **six or more rows**, give the **prompt table's own scrollable content area** a vertical scrollbar; keep the header visible, and do not cause the outer PiP document to grow indefinitely. With fewer than five prompts, allow the section to shrink instead of showing five empty dummy rows. When no prompt is running and no recent terminals remain, show an honest compact empty state.
- During pending, partial or source-unavailable observations, show truthful status. Do not calculate increasing Duration from a disconnected snapshot, invent zero CCost, or independently guess when a prompt has finished. Preserve existing Mini freshness/source identity safeguards.

## 5. Headerless, thin-bar primary-subscription rows (bottom)

Place the accounts **below** the prompt table, as a second separate, **visually unframed/headerless** compact row/list/table section. One entry per subscription, preserving provider-aware account identity and existing primary-quota choice. No surrounding “account card” border or column grid is needed; implementation may use semantic list/grid, accessible grouping and light separation rather than a literal HTML table.

- Each subscription entry consists of a single text row with **account/subscription label**, its **primary native quota percentage Used** (or correct Unlimited/unavailable state) and **parenthesized same-primary-quota-period CCost**, respecting current Credits/USD and attribution/period semantics; **a horizontal progress bar directly below** on its own line, filled across the **available row width** to the truthful canonical Used fraction. Do not show secondary quotas or mistake parenthesized **observed CCost** for native Used credits.
- The owner wants the visible `~` **approximately/estimated glyph removed before the parenthesized CCost**, and does not want such cost markers reintroduced elsewhere in the redesigned Mini view. Keep the underlying **estimated/partial/unavailable truth**, using a concise tooltip/focus disclosure (or accessible label) to explain cost attribution, completeness and its independence from native usage. Do not silently turn unknown/partial values into exact zeros, drop a known percentage because CCost is unknown, or mislabel observed CCost as billed spending. Existing `? / N/A` completeness conventions can be reconciled deliberately with an accessible explanation, but **do not add the visible `~` prefix back**.
- Mini's progress bar should retain the **old full-Watch thin height of about 0.65rem**, not the doubled ~1.2–1.3rem in **FR000560** for the **full-size Watch account cards**. Preserve attractive rounded ends and original track background; follow the **same final color rules** as FR000560: **cyan/teal below actual exhaustion, red only on authoritative finite 100%/exhausted**, never a green/yellow 50% step. Preserve native semantics for Unlimited, unknown/missing denominator, near-100% rounding, stale/partial quota and provider restriction. If restricted without known numeric exhaustion, show a truthful warning without fabricating a red 100% bar.
- Use **up to three subscription rows** as the normally visible portion; **more than three** requires a **separate internal vertical scrollbar in the account-list region**. With fewer accounts, shrink naturally. Account labels/values may wrap where needed, but the progress bar stays beneath the corresponding text and does not overlap the next entry.
- Both scrollable regions (**top running prompts**, **bottom accounts**) must scroll independently when their respective row counts exceed 5/3. Avoid an outer document scrollbar at the chosen normal default size with typical one-line content. Keep accounts accessible when no prompts run, and running prompts accessible when no accounts are configured.

## 6. Responsiveness, accessibility and shared ownership

- Preserve the existing **one Live/SSE owner**, session identity and publication freshness guards. Use keyed DOM rows for stable updates and avoid full re-creation/flicker as values change. The PiP app must work when the opener is in another tab/app or is hidden, where permitted by the browser; do not claim native always-on-top support where the browser lacks Document PiP.
- Retain the Watch-page toggle's supported/unavailable behaviors, native close/replacement event, return-to-Watch action, Credits/USD re-render, Classic/Web light/dark theme alignment and the existing security/CSP/sanitized rendering model. Do not use raw untrusted HTML for session/account titles.
- The user may resize the PiP window; responsive CSS should keep the two sections legible as far as space permits, with internal rather than uncontrollable nested page-wide scrolling at default size. Do not hide critical health messages or keyboard focus. Give accessible labels to progress bars and explain `CTX` and cost status.
- The full-size Watch's account-card sizing/header/progress bar and new per-session borders belong to **FR000560**, not this Mini-specific layout. **FR000558** has already delivered the common ten-column table and help behavior; this FR changes only the Earlier first column/selection and Mini UI. **FR000559** remains responsible for stale-running correctness. Avoid duplicating/adversely bypassing their logic.

## Acceptance / representative regressions

1. **Earlier time:** Running still reads `Started | Duration` and orders by start ascending. Earlier reads `Finished | Duration`, uses accurate local finish clock/full date, and orders by actual finish ascending. Five most recently **finished** eligible distinct sessions are retained; oldest finish evicted first. Test: A starts before B but A finishes after B → A sorts later. Test multi-prompt session with start order unlike finish order, exact ties, cross-day/DST, final failure/abort vs genuine success and unknown/partial end evidence.
2. **Toggle/window:** Actual PiP Open makes the full On button filled and highlighted like active nav; Off, cancellation, failed open, native close, replacement, reload and delayed events clear it. In-app navigation retains On while window exists. The Mini internal × is absent; the native close and Watch toggle still close. Clickable Cost Guard · Watch header still returns to the existing tab without requiring a new window.
3. **Mini default layout:** Requested PiP geometry fits a fully populated **five running prompt rows + three one-line account rows** and compact header without outer body scrollbar where browser grants requested dimensions. Both parts scroll **independently** from rows 6/4, respective headers/labels remain sensible, short lists collapse, no unnecessary enclosing card/frame, healthy `Live` caption absent, source/error messages still present as needed. Test resizes, long names, zoom and available Chrome/Edge real PiP behavior without claiming impossible OS chrome control.
4. **Prompt rows:** Exactly one row per distinct focal canonical active/recent prompt, with correct `Session | # | CCost | Duration | CTX`, prompt-local metrics, ellipsized-but-accessible title, stage-correct colors, multiple prompts in one session, live updates, real terminal evidence, ~30s grace and deterministic removal. Do not show placeholders/earlier sessions as running; verify terminal success and abort/error distinctly, including a quota stop. Running totals may still be published for other consumers but not rendered as the three old Mini boxes.
5. **Subscription rows:** 1/2/3/4/6 accounts show one account text + **thin full-width primary Used progress** per row with correct fraction, cyan below limit and red on genuine exhausted. Preserve correct independent primary CCost and Credits/USD, Unlimited/unknown/near-100/partial/stale/reset states. Do not show the distracting `~` before Mini's parenthesized CCost; tooltip/focus retains estimated/partial meaning. Full Watch bars remain under FR000560's separate thickness/style rules.
6. **Tests/evidence:** Extend existing deterministic Watch capture/history projection, Mini Python/Node DOM, and actual Document PiP browser tests (`development/tests/test_mini_watch.py`, `development/tests/integration/mini_watch.cjs`, `probe_mini_watch.cjs`) plus applicable product/package checks. Test native close/resize, hidden-opener SSE, keyboard and themes as the available environment safely permits. Record actual evidence and remaining physical-desktop/accessibility limits; no real model calls or shared OpenCode service manipulation.
