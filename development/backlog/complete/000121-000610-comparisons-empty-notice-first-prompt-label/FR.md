# FR 000610 — Comparisons: remove empty status box and label first-prompt preview

**Owner-approved Ready Feature Request, 2026-11-06.** Permanent identity **000610**; Ready queue priority **000280**, following **FR000609** (000270). This FR is **backlog authoring only**, not an instruction to implement product changes during publication.

## Owner observation and desired result

After the Web Beta **Comparisons** page has finished loading, an **empty framed status/notice box remains directly below the Comparisons header**. It contains no useful information and wastes vertical space. Remove it from the completed view (and any other state where that specific notice is empty), without suppressing genuine loading, warning, partial-history, error, unavailable or retry information.

Each comparison group already shows a session-title-based heading and a preview of the matched input beneath that heading. The preview is easy to confuse with generic session information. **Prefix that existing preview with the exact visible label `Prompt 1:`**, followed by the beginning of the prompt text and its existing truncation ellipsis when applicable. For example:

```text
Refactor the parser · 3 sessions
Prompt 1: Please refactor this function so that…
[existing comparison table]
```

No quotation marks are needed. **Do not add a prompt-text column to the comparison table**, because the entire group shares the same exact first input. Do not repeat the preview for each session row or introduce a second prompt-text area.

## Code findings and compatibility

1. **Identified empty box:** `src/web/assets/app.js::show()` explicitly assigns `notice.textContent = ''` for `state.section === 'comparisons'`. The shared `#notice` in `src/web/assets/index.html` is nevertheless rendered; `src/web/assets/app.css` applies border, accent stripe, background, padding and normal paragraph margins even when empty. AI Stats and Token Mix already use section-specific `#notice:empty` styling; Comparisons currently lacks the equivalent. This explains the owner's reported empty framed box from static source evidence. Fix its actual DOM/CSS visibility rather than merely changing the contents to whitespace or concealing some other meaningful status.
2. **Preserve the useful Comparisons status:** `src/web/assets/comparisons.js::View` also has a **different** status paragraph inside `.comparisons-view`, which reports source coverage, checked/excluded session counts, no verified matches and relevant failure/order notices. This is *not* the empty framed `#notice` to delete. Keep truthful meaningful status/empty/error messaging (and accessible announcements) when data warrant it; don't blanket-hide all `role="status"` elements.
3. **Existing correct first-input semantics:** `src/analysis/input_identity.py::first_input()` identifies the first real user prompt of each independent **root session**, excluding synthetic continuations/subtasks; a later genuine prompt in the same session **must never become a match candidate**. `fingerprint()` uses the **full ordered semantic input**, not a short preview, title or normalized display string. `src/reports/matched_inputs.py` builds groups from verified first inputs and acquires their preview separately. This is a **display clarification**, not a request to change the matching algorithm, historical accounting or inclusion rules.
4. **Existing safe preview:** `src/analysis/input_identity.py::preview()` produces a bounded, whitespace-compacted, display-only preview (currently up to 120 characters plus an ellipsis); it can instead return honest placeholder text such as `Attachment input` or `Input preview withheld (potentially private)`. `src/web/assets/comparisons.js::Group.update()` currently writes `group.preview` to `.comparison-preview` using `ReportView.text`. Add the **`Prompt 1:` label in this display layer** while preserving existing sanitization/escaping, truncation, placeholder, privacy and source semantics. No new raw prompt logging, persistence, network read, backend fingerprint change or length expansion is justified.
5. **FR000609 dependency:** The immediately preceding Ready FR standardizes automatic loading and progress/status presentation for Models, Token Mix, AI Stats and Comparisons. Implement this small Comparisons-specific finished-state cleanup **after or compatibly with FR000609's shared loader**, without reintroducing its old progress bar, status jitter or duplicated layout. An empty notice has no right to reserve a framed region after a successful load; actual progress, retained-source warnings and recoverable errors still need valid UI space.

## Required behavior and scope boundaries

- When Comparisons is fully loaded, **no blank box, accent border, invisible-height placeholder or unused notice margin** appears below its header. The first meaningful control, status, or comparison content follows with intentional spacing. The empty `#notice` should also remain visually absent during normal refreshes/navigation unless it contains truly meaningful content. If code is reorganized by FR000609, apply the same behavioral rule to the resulting shared layout rather than relying on an obsolete selector.
- For every populated comparison group, the text **directly under its existing session heading** begins with **`Prompt 1:`** and then the already prepared first-input preview. Keep the existing ellipsis convention for genuinely truncated text. For a short preview, don't add an ellipsis that falsely suggests truncation. For attachment-only, private/withheld or unavailable preview, retain a truthful explanation after the label; never fabricate a textual prompt.
- Continue comparing only **separate root sessions with exactly matching first real inputs**. A later identical prompt in either session does not qualify for a comparison group. The visible `Prompt 1` is a description of the eligible first real user input, not a newly calculated provider/transport ordinal; don't modify canonical prompt numbering, input fingerprint, grouping, sample counts, ordering or page sizes.
- Do not change the table's nine established columns, repeated-run rows, session links, group headings, fun facts, sorting/recency, page navigation, AI Stats matched fact, cost/duration/token math or cache/freshness policies. Use a small Web presentation/CSS fix, not a new backend feature.
