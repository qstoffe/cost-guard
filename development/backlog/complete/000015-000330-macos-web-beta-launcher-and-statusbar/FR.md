# FR 000330 — Native macOS Web Beta launchers and menu-bar Open/Exit (no added dependencies)

## Outcome and dependencies

After FR000310, deliver source-only double-click entry points `macos/Beta/Cost Guard Web.command` and, if native Finder behavior is verified, a lightweight `Cost Guard Web.app` source bundle. Use the same shared lifecycle/server owner as Windows; FR000320's OS-specific tray code is not a dependency. Retain all existing root macOS CLI/Watch and Diagnostics launchers unchanged. Follow FR000290/PLAN.md.

## Required behavior

1. **No downloads, new installations or distributed precompiled executable:** use only the already-required installed Python 3.11+, macOS system frameworks/automation facilities and source-controlled scripts/text/resources. Do not add PyObjC, pystray, Pillow, Homebrew packages, Node, Xcode/Command Line Tools downloads, a virtualenv setup or a bundled/precompiled native app binary. An **on-demand local compile with an already included OS utility** (particularly `/usr/bin/osacompile`) is permitted for a small launcher or status-bar helper, but must not require extra installation. No first-launch package consent/install flow. Existing OpenCode/pricing network requests remain independently governed by their current policies.
2. **Finder-friendly launch:** prefer a plain source-controlled `.app` directory using `Info.plist`, script entry and resources, if launching it directly from Finder without Terminal and without a compiled executable demonstrably works on supported macOS. `Cost Guard Web.command` is the alternate direct double-click entry using the same launcher logic. An app bundle must not be described as functional merely because its folder shape looks correct. If macOS Launch Services requires an actual applet, prefer **first-launch local creation** with `/usr/bin/osacompile -o ...app <source.applescript>` using committed script source and already-installed macOS tooling. Write the generated `.app`/helper into protected per-user application data **outside Git**; check source/version/OS fingerprint on later launches, reuse an unchanged artifact and rebuild only when necessary. Show concise launcher progress/status for preparation, compilation success and actionable errors. Never ship compiled outputs in the repository or install Xcode/Command Line Tools. Validate Finder launch and Gatekeeper behavior on real supported macOS; if this still fails, retain the `.command` fallback and report the blocker.
3. **Launch behavior:** restarting a verified same-checkout instance stops its server/menu owner cleanly, launches a new detached instance, waits for HTTP-shell readiness, opens the system default browser and exits the transient launch script. Do not assume an arbitrary Terminal preference will close a window left by `.command`; do not kill Terminal, change Terminal preferences or use Accessibility automation just to hide it. The tested Finder `.app` route is intended to provide the terminal-free experience.
4. **Native menu-bar UI:** show a Cost Guard `NSStatusItem` with two initial menu actions, **Open Cost Guard** and **Exit Cost Guard**. Open only navigates to the running local host; Exit stops only the verified instance and removes the menu item. Prefer built-in `osascript` JavaScript for Automation with AppKit/Objective-C bridge (or equivalent source-only AppleScriptObjC) and prove that a durable menu event loop/callback bridge works on real supported macOS. As another zero-package option a *small reviewed* Python `ctypes` bridge to AppKit/Objective-C may be used if reliable. These are feasibility options, not a claim of universal compatibility. No downloaded Python bridge, committed executable or externally built binary is approved. A locally generated helper/applet from source using already-present OS facilities is explicitly permitted; a durable native menu event loop still needs separate proof.
5. The menu GUI must run on the correct main thread while server/analysis work stays off it; callbacks must not block on HTTP, account refresh or history scans. If the server exits, the menu icon disappears or truthfully signals failure. If required GUI startup fails, report a clear error and do not leave a healthy-looking orphan instance. Closing the browser does not stop Cost Guard.
6. Resolve source/launcher files relative to the checkout, including spaces, Unicode, clones and ZIP extraction. Keep instance identity, logs and temporary state in protected user-local application data outside the Git checkout. Check Python/OS support before stopping an existing healthy instance when feasible. Record and document actual Gatekeeper/quarantine, script executable-bit and Finder semantics without trying to bypass operating-system protections.
7. Browser failure leaves an available menu Open action if the instance is otherwise healthy. Repeated launch, code-change shutdown, source failure and stale instance state all use FR000310's shared lifecycle. No login item, launch agent, daemon, service or general macOS automation permission request is added.

## Acceptance

Perform real, native macOS smoke checks of `.command`, `.app` Finder launch, no-Terminal behavior where supported, repeated restart, default browser, menu Open/Exit, responsiveness/main-thread rules, source-change exit and no orphaned GUI. Explicitly note any `.app` or system scripting limitations and do not claim platform success on mocks alone. Check fresh Git clone and ZIP, chmod/executable metadata, Python discovery on supported architectures, Unicode/space paths, offline first launch and errors. A fresh supported machine must not prompt for a Python/web/tray package or SDK/compiler download. Where on-demand OS compilation is used, test clear progress/failure handling, cached reuse, rebuild after source changes and cleanup.

If full native behavior under the no-install/no-distributed-binary constraint still cannot be demonstrated, even with local OS-tool compilation, *do not relax that constraint*: deliver only independently working pieces, mark the blocker and obtain an explicit owner decision before proposing additional packages or tool downloads. Existing CLI/Watch launchers remain usable throughout. No permanent release gate, promotion or product-version target is created by this FR.

Native references: https://developer.apple.com/documentation/appkit/nsstatusbar , https://developer.apple.com/documentation/appkit/nsstatusitem and https://developer.apple.com/documentation/bundleresources/placing-content-in-a-bundle .
