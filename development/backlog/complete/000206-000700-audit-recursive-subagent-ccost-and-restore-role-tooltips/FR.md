# FR 000700 — Bugfix: audit recursive subagent CCost and show complete main/subagent model, effort and cost attribution

**Owner-approved Ready to Develop — 2026-11-13.** Permanent identity **000700**. Priority **000008**, immediately after FR000699 / priority 000007. **FR-only publication:** add this bugfix specification and advance the backlog identity watermark in one documentation-only commit. Do not touch product code, private installed session databases, live runtime, tests, versions/releases, run paid inference, or launch an implementation worker while authoring. The eventual backlog worker owns diagnosis, repair and verification.

## Owner's observed problem (not independently reproduced)

In **Cost Guard Web → Watch**, some user prompts in a **main session using one model** launch **subagents using another model** (owner's example: a main Sol-family session that launches an Astra Max subagent). The owner sees suspicious Model- and CCost-cell tooltips in **Running / Earlier Prompts**:

- The **CCost tooltip** describes **Main prompt** but then says something like **“1 linked subagent(s) have no recorded request usage.”** No clear subagent model, effort and cost appears.
- The **Model tooltip** first says **“Linked subagents participated”**, then has a **Main prompt** paragraph and again **“1 linked subagent(s) have no recorded request usage.”** Instead of explaining which child model(s) were used, it looks broken.
- The owner cannot tell whether the child actually incurred substantial CCost that **was omitted from prompt/session totals**, or whether **only the tooltip/breakdown failed**. This is a suspected **financial-metric correctness bug**, not proof that a particular total is wrong.

**Owner's required invariant:** every physically attributable priced request from a root prompt's **full recursive linked subagent subtree** (children, grandchildren, etc.) must be included in the initiating prompt's CCost **exactly once**, and every attributable request in the whole root session tree must be included in **all relevant session and aggregate CCost totals** exactly once. **Full Watch, Earlier, Mini Watch, Sessions list/detail, and other consumers** must agree with the same canonical evidence and display the main-vs-subagent contribution transparently in relevant help. Never disguise missing data as a reliable zero or complete total.

## Verified source findings and uncertainty boundaries

Static GitHub inspection supports the following *possibilities*, not a reproduction of the owner's sessions:

1. **Existing recursive accounting is intended to work.** Completed **FR000600** changed **src/analysis/child_links.py::ChildLinkIndex** and **src/analysis/causal.py::build_prompt_record** to recover native task/subagent child links, validate parentage/time scopes, walk **nested** links and union physical request identities without duplicating them. **src/analysis/session_cost.py::reconcile_session_cost** uses distinct full-tree source request identities. **development/tests/test_subagent_attribution.py** already has a synthetic incident where main **122** + child **102** = prompt/root-tree **224 CCost**, and a multiple/nested link fixture reconciling to **387**. These tests mean a blanket claim that all subagent costs are excluded is **not established**; their data may not match the owner's missing-usage cases.
2. **The warning is generated by a difference between linked sessions and observed request parts.** **src/application/prompt_costs.py::cost_detail()** calculates `agents_without_usage = max(0, row.linked_agent_count - distinct child session IDs in row.cost_parts)`. **detail_tokens()** appends **“N linked subagent(s) have no recorded request usage.”** to **CCost, Model and Calls** help. **src/reports/prompt_rows.py** builds `linked_agent_count` from validated `linked_session_ids` and child requests, while `src/reports/prompt_costs.py::prompt_cost_parts` builds priceable/call groups only from attributed `record.entries`. Consequently the warning can mean genuinely **no child request evidence in the acquired source**, **partial/missing acquisition**, **a join/attribution defect**, **a model/usage identity defect** or a **misleading help contract**; the text alone cannot distinguish them.
3. **Possible completeness hole to investigate.** **src/reports/prompt_rows.py** currently derives `unresolved_cost = not comparison_cost(record.entries).complete`. If all *recorded* main requests are priceable but a **known linked child has no recorded request entries**, this predicate can still be `False`, making a known subtotal look complete despite a missing child. The existing **test_prompt_cost_detail.py::test_same_model_and_link_without_usage_still_prove_participation_and_survive_cache** deliberately constructs such a missing-child-usage snapshot and asserts the warning text; it does **not** settle whether the total should be marked source-incomplete. Establish correct semantics without inventing child expenditure.
4. **Group collapse hides individual subagents.** `src/application/prompt_costs.py::grouped_parts()` currently groups child `PromptCostPart` records by `("subagents", provider, model, variant, tier, selected_models)`, aggregating **multiple child sessions into one group** and reporting only a count of agents. The owner requests per-subagent entries (even when multiple children share a model), not just a collapsed `Subagents (3 agents)` line. `src/application/prompt_costs.py::detail_tokens()` prepends the standalone participation statement and appends missing-usage prose; **src/web/assets/watch.js** feeds `model_detail_help` and `cost_detail_help` to the actual Watch cells. **src/web/assets/mini.js** independently composes compact prompt details.
5. **Existing scope, caches and other FRs matter.** **src/analysis/cache.py**, **src/analysis/session_cost.py**, **src/reports/session_summary.py**, Web Live projections and Watch/catalog caches have revisions/signatures that can preserve stale results if a changed attribution/completeness contract is not invalidated. Prior FR000616/000620/000687 define contributor help, per-model/effort costs and recorded-selector truthfulness. **Ready FR000694** will refine effective default effort in relevant tooltips; **Ready FR000698** independently updates **Sessions' Model column** to show the latest main model and role-separated model lists. Coordinate these when implemented so neither change reintroduces merged/incorrect model help or overwrites the other's data contract.

## P0 — Determine whether recursive CCost is actually missing (required diagnosis, not tooltip-only)

1. **Trace one representative, privacy-safe source-shaped reproduction end to end**: root user prompt, its main model requests, one task/subagent child using a different provider/model/effort, a child spawning a grandchild, any additional siblings/reused children, physical request token usage and current reference pricing. Track **root snapshot/source coverage → native child link extraction → child ancestry/window scope → prompt entries → physical request deduplication → prompt-valued CCost → root session CCost → selected Web projection/help**.
2. **Separate the distinct failure modes in evidence**:
   - **Child usage exists and is priceable, but omitted** from the initiating prompt because of link parsing, nesting, parent/session ID/case, invocation-window boundaries, delayed source revisions, history loading, provider/model resolution, cache reuse or a projection defect: **fix root cause and recompute all affected consumers**.
   - **Child usage contributes to the numeric total, but lacks a Model/CCost tooltip row**: repair the attribution/help data contract, not the canonical amount.
   - **Child was linked but has no observable executed request** (e.g. failed-before-dispatch or genuinely unavailable source data): do **not fabricate a cost or model execution**. Preserve the known subtotal and indicate **cost coverage incomplete/unknown** where warranted. If sufficient source evidence proves that the child performed no billable/model request, allow a genuine no-usage state rather than assuming phantom spend.
   - **Child has request evidence but no supported identity/tokens/pricing**: preserve known priced subtotal and **partial/N/A** semantics with a concise specific reason, not an invented zero or a selected-but-unexecuted price guess.
3. **Check the potentially silent complete-value case:** a positive `linked_agent_count` together with `agents_without_usage > 0` must be reconciled with source completeness, child execution state and request-priceability before presenting a total as fully known. **Presence of a linked child does not automatically prove spending**, but a confirmed cost-bearing child with unavailable usage/pricing must not be silently treated as zero. Define explicit bounded **coverage/diagnostic states** (e.g. usage-confirmed, linked but not executed, linked usage unavailable, acquisition pending, unpriced child), not a blanket “all missing agents cost money” assumption.
4. **Reconciliation invariants:** for a fully observed/priced root, sum **unrounded physical request valuations once per globally unique canonical request**; every main/child/grandchild request belongs to exactly one owning prompt/compaction/out-of-prompt bucket. `root-tree session total = assigned initiating-prompt totals + distinct compactions + explicitly identified other root-tree requests` (when those categories apply), with no duplicate in overlapping child windows, shared source captures, repeated tool outputs, parallel agents, later revisions, reuse of one child ID across different initiations, or background descendants finishing after the parent responds.
5. **Request ownership must be causal.** A grandchild's usage accrues to the **root prompt that caused the ancestor chain**, not a later prompt merely because its wall-clock overlaps; background work can finish later without being dropped or counted twice. A physical child launched in one session but not within a valid owned root prompt may still count in the **root session tree total** while remaining honestly outside prompt row totals; never allocate residual cost to a random prompt just to force row sums.
6. **Same valuation across all consumers.** Review Full Watch **Running/Earlier CCost, I/E split, Calls, Token Mix, Model help and prompt history**, **Mini Watch prompt CCost and whole-session Total**, **Web Sessions catalog CCost and Session Detail prompt/session totals**, plus **CLI/session reports, per-account/day aggregates and AI Stats/Comparisons where derived from the same eligible physical requests**. Respect each scope's definition and time interval: daily account CCost is not automatically the lifetime root total. No double counting a child's physical call as both its own independent root and its parent root; no artificial multiplication of usage when an agent spawns agents.

## P1 — Model tooltip: one clear main section and one section per linked subagent

On **Full Watch Running and Earlier Prompts** and corresponding supported detailed prompt views, replace the standalone generic **“Linked subagents participated”** paragraph and redundant **“N linked subagents have no recorded request usage”** boilerplate with readable, source-qualified information.

Suggested synthetic outline (example identities are placeholders, not private-session transcripts):

~~~text
Main prompt
• Provider: provider-a
• Model: sol-example
• Effort: High

Subagent 1
• Model: provider-b/astra-example
• Effort: XHigh

Subagent 2
• Model: provider-c/model-example
• Effort: Medium
~~~

- Show the **main prompt's actual provider/model and effort** based on its *executed/source-attributed* requests, not a guessed current config. If main switched models/efforts inside that prompt, include every distinct actually used combination without falsely choosing one as the entire prompt.
- Each **distinct linked subagent/session** gets its **own identifiable section/entry**, with **recorded provider/model selector** and **selected effort** (or effective-default explanation per FR000694 once implemented), and possibly multiple model/effort entries inside one subagent if it actually switched. Preserve root-initiating relationship and sensible stable order; optionally show ancestry (Child → Grandchild) if useful, without exposing private raw IDs/prompts.
- If two subagents use the **same model/effort**, do not collapse them so the user cannot tell that two agents participated. Any bounded omission must be explicit, deterministic and still account for its costs.
- For a **truly linked child with no executed request evidence**, show a short truthful state **only where it is genuinely relevant**, such as `Subagent 2 — request usage not available; model/effort unknown`. A saved selection can be identified as **recorded selection (execution unverified)** if it is the only trustworthy evidence, never as a confirmed executed release/cost. Do not repeat a confusing global English warning in every Model/CCost/Calls help.
- Reuse existing shared value ContextHelp and focus/hover/tap/Escape behavior. Keep existing visible main model and participation marker conventions unless another approved FR changes that surface; no new question icon or raw source/browser API fetch on hover. Harmonize **Sessions Model** with FR000698's *distinct role lists* without forcing per-agent Watch sections into the Sessions table if not requested there.

## P2 — CCost tooltip: transparent main/subagent subtotals that reconcile

The corresponding **CCost tooltip** for each initiating prompt should have an easy-to-verify numeric breakdown, e.g.:

~~~text
Main prompt
• provider-a/sol-example · High
• CCost: 120 Credits

Subagent 1
• provider-b/astra-example · XHigh
• CCost: 80 Credits

Subagent 2
• provider-c/model-example · Medium
• CCost: 30 Credits

Total CCost: 230 Credits
~~~

- For **each main-prompt role/model/effort combination** and **each individual subagent** (including nested subagents), show its **own source-backed subtotal**, and a total for that role/agent when there are multiple requests/models/tiers. An agent's total includes that agent's **own physical model requests**; grandchildren should be separately listed and included in the top-level initiating total, not silently folded in twice. `Main prompt` is root/main requests only, not descendants. Each subagent gets its own `provider/model`, effort, relevant **Calls** and **CCost**; preserve existing category Input/Cached input/Cache write/Output breakdown when useful without concealing the high-level subtotals.
- **Cohesive reconciliation:** the CCost **cell value** must equal the unrounded sum of all known displayed role/agent subtotals **plus a clearly labelled bounded omitted/other known subtotal**, after normal display-unit rounding. Independently rounded integer Credits or two-decimal USD lines need not arithmetically sum exactly; include a concise rule where it matters, not made-up residuals.
- **Partial/pricing/source gaps:** mark the cost honestly partial/unavailable when relevant request-bearing subagents cannot be completely valued. If a subagent lacks any request usage, show **N/A / usage unavailable** rather than **0** unless zero execution is actually proven. A missing contribution must not disappear behind a confidently stated full total. Preserve the distinction between reference CCost and actual billing, without cluttering every group with generic caveats.
- **Per-prompt vs per-session**: Watch shows one initiating prompt's main/recursive descendants; Sessions' CCost / Session Detail session-level values must aggregate **all main prompts and all their linked child trees** (plus separately priced compactions/other valid root-tree usage). Session-level tooltips/summaries should likewise distinguish **all main prompt costs** versus **all attributable subagent costs**, with bounded per-model/agent details where supported; do not label the whole session total as merely the latest main prompt.
- **Mini Watch parity:** its compact prompt CCost help needs at least a correct **Main vs linked subagents** subtotal summary with provider/model/effort per supported child, and a coherent **whole-session Total**; preserve its intentionally smaller viewport but do not make subagent cost invisible. Do not put the full verbose Full Watch tooltip blindly into Mini's narrow Document PiP. Keep both Credits and USD amounts prepared coherently by the server.
