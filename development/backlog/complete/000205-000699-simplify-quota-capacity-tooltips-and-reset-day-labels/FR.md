# FR 000699 — Web quota tooltips: concise Capacity numbers without estimate rounding, and day after Next reset time

**Owner-approved Ready to Develop — 2026-11-13.** Permanent identity **000699**, priority **000007** (directly after FR000698 / priority 000006). **FR-only publication:** this task authoring changes only the FR and the permanent backlog-ID watermark; no product implementation, tests, runtime/source changes, version/release work or paid model calls in this transaction.

## Owner request

Cost Guard Web's account/subscription quota tooltips have become needlessly technical and verbose. A Capacity value that is deliberately displayed approximately (using the existing **5%-tolerant compact rounding**) currently reveals huge raw Decimal numbers and explanatory text such as **“Unrounded Capacity (estimate)”**, **“Unrounded Monthly Capacity (estimate)”**, **“Observed same-window CCost used”**, **“Provider-reported fraction used”**, **“Guesstimate before display rounding”**, formulas and provenance/disclaimer paragraphs. The owner does not want these implementation details.

Instead:
- Show only concise **Capacity** / **Monthly Capacity** and useful numerical values in these tooltips. Do **not** write “unrounded” or “estimate” in labels or introductory prose. An inferred value's **~ prefix** is sufficient to mark approximation, consistent with the visible card value.
- **Keep the raw calculated amount as the numeric basis in a tooltip** (do not apply the 5% estimate-rounding rule there), **but format it normally for its selected reference unit**: **Credits: whole numbers, no decimals**, using the established ordinary CCost Credits amount formatting; **USD: $ with exactly two decimal places**, using the ordinary CCost reference conversion. There is no reason to expose an arbitrary-length Decimal expansion. For example, if raw inferred period Capacity is **3065.6172839 Credits**, its tooltip should show **Capacity: ~3066 Credits** or **Capacity: ~$30.66**; the card may continue displaying a compact 5%-rounded **~3000 Credits** / **~$30.00**. Example values are synthetic, not data from the owner's account.
- Every **Next reset** / quota-reset line with a valid deadline must show a human-friendly day **after the local clock time**: **today** when the reset is on the user's current local calendar date; otherwise the **weekday in English** (Monday ... Sunday) if reset is no more than seven elapsed days away; otherwise the **local calendar date**, e.g. **2026-11-23**. Preserve the useful existing time-until-reset and local HH:mm; do not require the user to infer whether a 03:00 reset occurs today or tomorrow.
- Apply consistently to **Web Accounts**, **Full Watch account/subscription cards** (including primary and secondary quota windows), and the **Mini Watch subscription tooltip** (primary window). Avoid long “observed same window” / “provider-reported fraction used” metadata in *all* corresponding quota tooltips, not just one Capacity row.

This FR intentionally supersedes **the verbose raw-precision/calculation/provenance tooltip presentation** requested by completed FR000663. It does **not** reverse FR000663's 5% *visible estimate* rounding or change any accounting/source logic.

## Functional requirements

### A. Short, numeric quota help in all Web surfaces

1. **Visible values remain as they are.** Keep the period label, normal **5% significant-digit estimate rounding**, the **~** prefix for inferred period/monthly estimates, no **~** for source-verified native-compatible allowances, existing Used/Remaining orientation, percentage/progress bars and all current quota/CCost calculations.
2. **Hover/focus/touch: unrounded source quantity, normally formatted.** The tooltip must calculate nothing from the card's rounded text. It consumes the original corresponding unrounded **canonical Decimal** amount from the same snapshot, then formats by selected Credits/USD display unit. Credits show the full **ones place** without any fractional digits; USD shows **$0.00**-style two decimals. Do not reuse **estimate_amount()** or its 5% significant-digit selection for tooltip values. Nor may exact_number/raw_reference dump excessive decimals, double-include Credits and USD, or add precise ratio/formula strings.
3. **Labels are simple:** **Capacity:**, **Monthly Capacity:** (and **Remaining:** / **Used:** only where independently useful). The visible quota's period/title already identifies the window. No “Unrounded”, “estimate”, “Guesstimate”, “observed same-window”, “provider-reported fraction used”, “calculated from”, token/request/account-attribution dump, defensive budget caveat or explicit arithmetic formula in these tooltips. Show ~ directly before an **inferred numeric value**, just as on the card; do not label a verified amount as an estimate. Do not print the raw fraction or repeat the entire card.
4. **Monthly Capacity** uses the independently calculated unrounded theoretical **30-day equivalent** as its numeric tooltip basis, not an extrapolation of the rounded visible period amount. It retains **~** because the derived monthly equivalent is approximate even when its input period Capacity is provider verified. A native monthly allowance remains a single native monthly capacity without an invented second derived value.
5. **Usage/Remaining help must be just as restrained.** Keep only genuinely helpful directly displayed or numeric quota facts (e.g. Used, Remaining, native quota amounts and reset) without explanatory calculation/provenance paragraphs. The standalone estimated Remaining/pace help, where present, follows the same normally formatted numeric principle; no “Guesstimate before display rounding” or endless precision. Avoid adding a duplicate Capacity paragraph to the summary tooltip.
6. **Unknown/stale/invalid/unlimited/partial:** preserve truthful **N/A**, **?**, **Unlimited**, genuine unavailable/partial/restricted warnings and appropriately short human-readable reasons *when needed to avoid a misleading value*. Do not manufacture numbers, hide a meaningful error, present unknown as 0 or claim a non-guaranteed estimate is a provider-issued monetary budget. These exceptional concise statuses are not permission to restore routine provenance/metadata essays.
7. **Mini Watch:** maintain its compact, readable order **Capacity** then **Next reset**, using the same display unit and same primary quota/window as its bar. Do **not** append the old extra raw-precision/caveat paragraphs. Where Remaining is necessary for the chosen mode, keep it numeric and concise, not a second duplicated explanation. Preserve Mini/PiP accessibility, focus/touch help, sticky-help fixes, high-contrast/narrow layouts and live updates.
8. **Consistent unit switching:** Credits↔USD must change *both* visible values and tooltip digits/units together, without stale help or browser-side division. Verified native vs inferred markers, current/retained data and source-revision changes must stay coherent. Keep provider-native currency separate from reference CCost; **100 reference Credits = $1** remains the existing reference display conversion, not a billing claim.

### B. Next reset: duration + local time + calendar context

For a valid future reset, append a day token **after HH:mm**, using the same configured timezone and server-authoritative current observation time as the existing Web reset/countdown. The exact surrounding delimiter may match the existing compact design, but examples must read unambiguously:

~~~text
Next reset: in 2h15m, 21:05 today
Next reset: in 1d3h, 14:30 Saturday
Next reset: in 6d23h, 16:45 Friday
Next reset: at 09:00, 2026-11-23
~~~

- **Today** means *same local calendar date*, **not** just <24 hours away. A reset after local midnight but within the next 24 hours must show the next day's weekday instead. For any reset in the **next seven elapsed days** (up to and including exactly 7×24 hours), if not today use its actual local weekday **Monday–Sunday**. If **more than seven elapsed days** away, use local calendar date in **YYYY-MM-DD** format after the clock time. Avoid two contradictory date/weekday tokens.
- Retain the existing concise **duration_text** style and current absolute local clock. When the long-range display does not have a useful short countdown under existing rules, a truthful **“at HH:mm, YYYY-MM-DD”** is acceptable; never hide HH:mm. Keep local date/time correct across timezone offset/DST changes and near local midnight. Do not derive the day from UTC or from the browser's approximate own clock, and avoid fragile parsing of already formatted reset prose.
- **Unavailable states:** Reset unknown, Reset expired, Window not started, invalid/missing deadlines remain short and truthful, without fabricated day or negative countdown. Reset projections already update with existing Live publications; do not poll the provider again, introduce a browser timer, or alter the CLI reset conventions just to satisfy these Web tooltips.
- Apply to **primary and secondary** account quota displays in Accounts and Full Watch and **primary** Mini Watch Next reset tooltip. Ensure any reset-only help/clock disclosure tied to the same account does not misleadingly disagree with the displayed day.

## Acceptance / non-goals

1. **Synthetic formatting test matrix:** raw **3065.617283945... Credits** is shown in tooltip as **~3066 Credits** / **~$30.66**, not **3065.617283945...** and not the card's 5%-rounded ~3000; verified source allowance of **949.123... Credits** is shown normally without ~; raw Monthly Capacity independently formatted; 0, small positive (<1 Credit / <$0.01), integer, very large Decimal, negative/invalid/no amount. Preserve current ordinary-unit rounding semantics and reference conversions. Visible estimate examples keep their own 5% precision policy unchanged.
2. Render actual **Accounts**, **Full Watch** and **Mini Watch** account cards with both unit modes, inferred and native Capacity, native-monthly and derived-monthly, primary/secondary, Used/Remaining, running/retained/stale/unknown/unlimited. Assert no verbose phrases (**Unrounded**, **estimate** as prose, **Provider-reported fraction used**, **Observed same-window**, **Guesstimate before display rounding**, verbose formulas) in the relevant quota value tooltips. Confirm ~ appears on inferred amounts but not source-verified amounts.
3. **Reset timing matrix:** 5 minutes today; 23h crossing midnight; next weekday; exactly 7 days; just over 7 days; same date after DST transition; Stockholm spring-forward/fall-back; month/year boundaries; expired/null/not started. Assert HH:mm + correct **today / weekday / YYYY-MM-DD**, in that order, and honest countdown.
4. Browser/DOM checks: mouse hover, keyboard focus, tap, Escape/leave, PiP Mini, tooltips kept open during a unit change or a new account observation, narrow widths, no double text. Use the existing server-prepared view tokens and ContextHelp; no new network calls merely for hover.
5. **Do not** modify provider-usage fractions, quota-capacity arithmetic, canonical unrounded Decimal values, source account mapping, reference currency/billing, 5% visible estimate rounding, progress/exhaustion, quota windows or subscription status, account privacy, CLI reports, version/release data at FR authoring. Implementation tests and normal product release gates apply only once this FR is selected by the backlog worker.

**User-visible outcome:** a card can intentionally show the easy-to-read **~3000 Credits** while its tooltip shows **Capacity: ~3066 Credits** (or **~$30.66** in USD), with no defensive numeric provenance prose; **Next reset** tells the user **how long, what time, and which day**.
