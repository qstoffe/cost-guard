# FR 000709 — Full Watch: overhaul interactive disclosure stability across Live refreshes

**Owner-approved Ready to Develop — 2026-11-14.** Permanent identity **000709**, Ready queue priority **000017**, directly after FR000708 (000016). **FR authoring only:** publish this request and advance the high-water mark in one documentation-only commit; no implementation, real model/tool execution, release/version change, backlog migration or unrelated FR changes.

## Owner-observed regression and desired UX

In **Cost Guard Web → Full Watch → Running Prompts**, the interactive activity disclosures remain visibly unstable even after completed **FR000701**:

- Yellow **Running: tool / command / elapsed time** sections sometimes stay expanded for a long time and then spontaneously collapse on a refresh despite apparently showing the **same still-running physical invocation**; reopening is repeatedly necessary.
- Under **Tool Calls → red failed groups → individual failed calls**, expansion arrows come and go. For example, one refresh allows expanding a group of four failed calls; another turns the same group into nonexpandable text, or collapses an already-open group. The arrow and details then reappear later.
- Adding tools, changing counts or refreshing timers makes already-expanded text and nested controls jump, disappear, remount or reset. Other expandable Watch activity sections also feel unstable.
- The owner wants the display to **remain steady while actively inspecting it**, with only genuinely changed data updated. Once an unchanged group is expanded, it must not be repainted/collapsed merely because something else refreshes.

**Binding behavior:** A user-opened disclosure stays open and a user-closed disclosure stays closed while that same source-qualified group or physical invocation is still relevant, across normal Live/SSE updates, including incoming sibling tools, revised counts, tool detail corrections, timer ticks, temporary incomplete projections and ordering changes. Avoid full re-render of interactive nodes during ordinary updates; update individual changed values and actual membership only.

This is a new user-observed complaint **after FR000701**, not a claim that the previous FR did not land. The exact owner instance has not been captured. Diagnose the data-to-DOM cause rather than just silencing updates with a timer/CSS workaround.

## Required scope and behavior

### A. Running tools, foreground/background and multiple invocations

1. Preserve the native open/closed choice of the **Running parent disclosure and each existing physical invocation child** through verified same-identity changes: elapsed time, command/input revision, new or finished sibling, subgroup counts, reorder, repeated source snapshots and single→multi→single membership.
2. Keep source/owning session/prompt/call identity stable. Do not use command text, tool name, duration, sequence index or volatile revision as a physical identity. Identical commands from different calls must never share a disclosure state or confidential input.
3. Do not hide a still-eligible yellow Running summary or arbitrarily close it merely because a single refresh temporarily lacks individual invocation details while the same causal running activity remains affirmed. If safe details are unavailable, keep an honest stable summary/control with a neutral explanation, **not** a stale command. A genuinely ended/replaced/unverified source call must promptly clear sensitive text and lose invalid child identity.
4. Do not auto-reopen after a user's explicit close, or collapse all siblings because one changed. New unrelated details start with privacy-safe defaults, not inherited expansion.

### B. Failed Tool Calls: eliminate the disappearing arrow

1. **Tool Calls** remains expanded through independent updates. A verified red aggregate group such as **4 × read failed** remains the **same expandable control** while its source-qualified outcome group is still present. Existing expanded individual failures remain open if those physical calls still belong to the group.
2. **The arrow must not toggle between expandable and plain text solely because individual failed-call detail availability flickers.** Separate the aggregate failure count/outcome from the source-verified identities and potentially redacted details. For an already established group with a nonzero count and a temporarily omitted detail list, retain the group's stable structure/open state and use a short truthful availability note as needed; never invent missing failed calls or leave unverified sensitive invocation data visible.
3. A failed group that never had recoverable call-level detail must not promise invented inspectable records. Provide stable honest count/status, not an intermittently changing arrow. True authoritative disappearance, correction to success or prompt/source invalidation may remove the real group/call; a temporarily missing projection must not mimic that final state.
4. A newly arriving fifth failed call must not close the four already inspected failures or reconstruct all their summary/detail elements. Stable keys use physical identities, not labels such as 'Failed call 2' or source order. A corrected safe failure reason updates one existing child in place.
5. Apply the same user-choice and incremental-render rule to other **Tool Calls**, **Skills**, Running foreground/background and nested disclosure sections on Full Watch. Preserve their current visual indentation and colors.

### C. Stable DOM and source/readiness ownership

1. Key nodes by root/source generation, selected prompt/focal, activity group, and physical call identity. Separate **membership/source authority**, **detail availability**, **safe content revisions** and **UI open state**. A changed count/timer/full DTO JSON must not become a new DOM/control identity.
2. Reconcile existing native details/summary nodes and unchanged text incrementally rather than wholesale replaceChildren / detach-reinsert of already inspected subtrees. Keep expanded text, keyboard focus, selection, caret/ARIA state, hover and viewport/scroll position stable across repeated updates. Real new content may increase height naturally, but refresh alone must not repeatedly shift layout.
3. Distinguish transient partial, pending, retained, retrying and missing-detailed-evidence states from fresh authoritative removal. A verified aggregate count may coexist with absent detail identities. The frontend must not infer execution or call details from a label. Improve the typed backend/Live projection if that distinction is lost before render.
4. User-open state may be retained for a still-valid group without retaining its **unverified or revoked sensitive details**. On source/ownership/revision change requiring security invalidation, clear old private input immediately even under focus/selection; don't show a previous command under another physical call. Discard old UI state at genuine prompt/focal/source switches and true removal; bound all retained maps.
5. Preserve existing canonical tool and failure/cancelled counts, exact physical-call deduplication, attribution, privacy allowlists/redaction and detail-size budgets, trusted failure reasons, running elapsed clocks, CCost, session statuses and source read-only/polling limits. No new model calls, native tool execution, fetch-on-expand, speculative failed-call payloads or unbounded cached private input.

## Verified repository starting points (static inspection, not runtime proof)

- Completed **FR000701**, delivered v81.45, explicitly fixed same-physical Running revision collapse and added nested individual failed-call disclosures. Its completion states that the owner's original instance was not captured and its native probe did not naturally observe a Running DTO. This FR expands coverage to transient projection/gating transitions and long-lived mixed updates; do **not** undo FR000701.
- In **src/web/assets/watch.js::drawInvocations()**, invocation rows exist only when label and verified are both true. When the current row identities do not include a previous job, the code executes **if (!continuing) target.node.open = false**, removes unseen keyed jobs and clears their details. A temporary omission can destroy parent/child open state before the exact same call reappears. Treat this as a candidate to reproduce, not a proven explanation of the owner's browser.
- In **src/web/assets/watch.js::drawTools()**, failed group membership is derived from the current failed_invocations array. It switches between a native group.node disclosure and a group.plain text node based on members.length, hides the disclosure without members, and sets group.node.open=false in that case. This is a particularly strong static candidate for the observed **failed expansion arrow disappears and comes back** behavior while item.count still exists. Test the real source and DOM transition.
- **src/application/live_projection.py::card_row()** can publish outcome aggregates while withholding failed_invocations unless activity_verified; it withholds running_invocations unless invocation_verified. Verify whether some accepted updates provide valid aggregate activity but temporarily omit details, and precisely which omissions are intentional security decisions versus recoverable projection gaps.
- **src/web/assets/watch.js::drawDisclosure()** replaces an entire child list on changed list-signature; **drawTools()** partly keys groups and calls but can still switch node types; **drawInvocations()** reconciles 1→N members. Review UI state, focus/selection, card focal changes and DOM reconciliation; do not fix only the summary string.
- Relevant source owners: **src/watch/{tools,invocation,models}.py**, **src/application/live_projection.py**, **src/web/assets/{watch,render,help}.js** and corresponding CSS and activity tests. Coordinate with pending **FR000703** (app-wide quiet/last-good refresh), without keeping real invalidated or finished details alive.

## Acceptance and regression coverage

1. **Failing before-fix sequence:** produce a source-shaped Watch publication series, including the same Running physical call → safe details temporarily withheld while running aggregate remains → same call returns; and **4 confirmed failures → count stays nonzero but failed_invocations temporarily empty → same failures return**. Capture the actual backend projection and DOM across publications. Mark synthetic reproductions as synthetic; the owner's actual runtime defect is not yet proven.
2. **Running stable over many frames:** open foreground/background Running parent and one invocation, simulate dozens of timer changes, corrections, reorders and 1→2→1 tool membership changes. The same physical call retains the **same node object** and open state. Manually close and rerun; it remains closed. Different physical calls with the same command do not inherit state. Actual completion or verification revocation clears the old details.
3. **Failed arrow stable over many frames:** start with an expanded red 4-failure group and one expanded failed call. Add successful tools, add more failures, update red outcome count, correct one failed call reason, reorder existing calls, and interleave eligible transient missing-detail updates and recovery. Existing group's **arrow never blinks out**, opened survivors remain open and their nodes/selection/focus persist. Missing unverified private input is withheld immediately; real authoritative removal removes the correct item.
4. **Multi-group inspection:** expand some Tool Calls/Skills/failed group/individual calls/Running foreground and background sections simultaneously, leave others explicitly closed, and update each independently. The selection for one never resets siblings or other sessions/cards. Narrow/mobile, zoom, themes, mouse/keyboard/touch, ARIA and scroll behavior stay coherent with no phantom row or unnecessary jump.
5. **Strict negative/security cases:** confirmed failed→success correction, true call/job termination, new prompt/source generation, invalid child link, erased/revoked input and genuinely absent details; none retain stale private text or state under a new identity. Aggregate failure counts still include omitted detail records, and bounded detail/population limits remain intact.
6. **Real browser and tests:** verify actual rendered Full Watch DOM, not just standalone state mocks. Extend **development/tests/fixtures/watch_tool_outcomes.cjs**, **development/tests/test_watch_invocation.py**, **development/tests/test_watch_tool_activity.py**, **development/tests/integration/probe_watch_invocation.cjs**, **probe_watch_tool_outcomes.cjs** and projection tests as relevant. Assert surviving node identity/open state, actual details security clearing, no unexpected remount, and no extra source reads or unbounded client retention. Preserve completed FR000701/FR000688 regressions and document any native-only repro gaps.

**Deliverable:** Full Watch users can expand Running tools, red failed groups and individual failures and continue inspecting them while other tools run and the page refreshes. Stable controls and user choices remain stable; expansion arrows do not flicker or collapse because of incidental updates. True source or security invalidation is still immediate and correct.
