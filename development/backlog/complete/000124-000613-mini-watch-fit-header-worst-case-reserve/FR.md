# FR 000613 — Mini Watch: reserve Fit-on-open header width for 90 000 CCost / 999 prompts and both disclosure states

**Owner-approved Ready Feature Request, 2026-11-06.** Permanent identity **000613**; Ready queue priority **000310**, following FR000612 (000300). This is **backlog authoring only**: publish the specification and its identity counter, not product implementation or a release.

## Owner observation and exact requested result

The current **Mini Watch size → Fit on open** (including **Default** resolving to Fit on open) deliberately makes the initial Picture-in-Picture window as narrow as possible while fitting the first/header row. In real use, however, activating **Earlier Sessions** sometimes makes that top row shift or wrap. A narrowly fitted collapsed row is not sufficient if its disclosure button, active/focus styling or CCost Today numbers need more width after expansion.

**New opening-size reference case (owner-approved synthetic display values):**

```text
Cost Guard · Watch     Earlier Sessions     CCost Today 90 000 · 999 prompts
```

For a normal eligible Fit-on-open launch, **all three header components, including the full CCost Today amount and full prompt count, must stay visible on exactly one row whether Earlier Sessions is collapsed OR expanded**. This must remain true after repeated collapse/expand without sideways movement or clipping, including any disclosure arrow, transient border/focus treatment and normal spacing. The example is the minimum layout capacity to reserve, **not** a new real usage value, threshold, quota, cap, mock data in the live UI or fixed pixel width.

The owner prefers a *small breathing/rounding allowance around 5–10 pixels*, not a broad oversized window. **Target around 8 CSS pixels of total extra content-width tolerance**, subject to real browser/native zoom and rounding evidence; size for the *widest of the two disclosure states* plus this modest allowance. Do not make a permanent fixed 90 000-CCost minimum width in other sizing modes.

## Confirmed current implementation and likely cause

- Completed **FR000607** replaced the former ~650-DIP width with an intrinsic measurement. `src/web/assets/mini.js::OpeningMeasure.read()` updates an invisible, inert `View` from the *current* Live publication, then sizes from `headerWidth(view)` plus body horizontal padding and **only 2 CSS pixels**. `headerWidth()` clones the actual `.mini-header` into `.mini-header-measuring` as a single unwrapped flex row.
- The measured header is **collapsed at initial opening**. `mini.js::DisclosureSize.toggle()` changes `earlier.hidden` and `earlierToggle.setAttribute('aria-expanded', ...)` on actual click/keyboard activation, but it deliberately handles native **height-only** adjustments, preserving width. There is no guarantee the original header fit survives the expanded button's appearance or a larger `CCost Today` amount.
- `src/web/assets/mini.css` has distinct `.mini-earlier-toggle::before` markers for collapsed (`›`) and expanded (`⌄`), plus flex gaps, button borders/padding and `.mini-header { flex-wrap: wrap; }`. The present CSS/content measurement may therefore underestimate the width required in a later state; inspect *rendered widths* for both states, including focus/hover/transient styles, before finalizing the correction. A later scrollbar from changed content/native height can also reduce available header space.
- `mini.js::View.drawDaily()` correctly builds **`CCost Today ${cost} · ${value.prompt_count} prompts`** from real values; use the **formatted** sample string `CCost Today 90 000 · 999 prompts` only in a detached measuring clone/test fixture. Do not change cost accounting or any displayed real totals.
- Completed **FR000608** changed the tables to `Session | CCost (Total) | Duration | Ctx` and `Activity | Session | CCost (Total) | Ctx`; their intrinsic widths must **not** enlarge the initial header opening target. The two tables already have an accessible horizontal scroll fallback in the prompt region when needed.

## Required behavior and implementation latitude

1. **Stable opening-width invariant.** In Fit-on-open/Default, before `documentPictureInPicture.requestWindow()` consumes user activation, calculate a width sufficient for the **maximum** of:
   - the real opening snapshot's formatted top-row contents in both `aria-expanded=false` and `true` states;
   - the stated **90 000 CCost Today / 999 prompts** reference row in both states, using the same actual font, control/pseudo-element styling, gap, padding, theme and effective browser zoom as the real Mini header.
   
   Use content-based intrinsic measurement plus a modest ~8 CSS-pixel safety allowance. If the real opening value or prompt count already needs **more** space than this reference case, size for that larger real content rather than clipping or truncating it. Do **not** set an arbitrary fixed outer width, parse the daily figure for numeric thresholds, or pad the user's real text with fake additional metrics.
2. **Both disclosure states fit on one top line.** Verify the three **actual** rendered elements — `Cost Guard · Watch`, the complete **Earlier Sessions** button with its collapsed/expanded marker, and the complete `CCost Today 90 000 · 999 prompts` text — maintain one line, correct order and no overlap or clipped glyphs. This includes after expand/collapse, button pointer hover and keyboard focus/outline. A CSS `nowrap` declaration alone is not proof if text would overflow the native viewport; do not solve the symptom by hiding labels, shortening cost/count, removing focus states or forcing permanent document-horizontal scrolling.
3. **Preserve native sizing ownership.** Measure through existing pre-open `OpeningMeasure`/shadow layout (or equivalent inert, style-accurate measurement); do not expand the *real* Earlier Sessions or mutate authentic daily values during measurement. **Do not resize width after opening** to chase header changes. Earlier Sessions click/Enter/Space may still request its existing one native **height** adjustment; preserve user-manual width changes, including intentionally narrower windows, and the existing one-DIP native width-rounding compensation rules. No passive timer/SSE/observer geometry supervisor.
4. **Only apply this reserve to Fit on open.** `Mini Watch size: Remember last size` must remain browser-/user-owned, without a forced worst-case minimum; explicit manual resizing remains possible and may cause natural responsive wrapping. Keep the existing position/size preferences, `miniWatchSize`, Default semantics and native placement coupling. Never convert an initial preference to a permanently enforced minimum width.
5. **Browser/native limits are real.** Account for estimated frame, CSS pixels versus outer device-independent pixels, zoom, DPI, OS clamps and vertical scrollbar width. If a specific browser/monitor cannot grant the calculated opening width, do not claim a guaranteed physical fit; instead disclose the existing limitation and keep all controls/text reachable through responsive layout. Avoid using a giant guessed buffer just because the native frame size is not exactly queryable in advance.
6. **Do not regress height or content.** After selecting the slightly wider width, recompute the initial measured **height** for actual content, accounts/warnings and the existing **two-running-prompt row reserve**. Earlier Sessions begins collapsed and disclosure grows/shrinks only height; full earlier table is still accessible. Keep styling, tabular numbers, Credits/USD selection, theme inheritance, prompt/session table meaning, session titles, values, scroll positions, keyboard/touch access and native closing/return-to-tab behavior. Existing later Live changes beyond the reserved reference case must remain accessible; they must not cause forbidden passive resizing.

## Focused acceptance and verification when implemented

1. **Exact worst-case test**: in an isolated sanitized browser fixture, open with formatted **`CCost Today 90 000 · 999 prompts`** and first-row `Cost Guard · Watch` / `Earlier Sessions`. With Fit on open (and symbolic Default), test `aria-expanded=false` and `true`, repeated pointer and Enter/Space toggles, selected keyboard focus and hover/active border effects. All three elements have exactly one rendered line, intact ranges, no overlaps/clipping and no top-row shift into a second line, where native dimensions permit. Verify **achieved** inner bounds, not only requested width.
2. Test **opening on lower actual figures**, then ensure the measured request still reserves enough header width for the above **synthetic reference state** while keeping the real displayed values unchanged. Separately open with actual formatted figures **larger** than 90 000 / 999 prompts and prove the real text determines the larger width. Confirm the request remains only slightly above the actual maximal measured collapsed/expanded reference requirement, not a hardcoded 650px or arbitrary huge padding.
3. Test document/web styles: collapsed and expanded disclosure pseudo-element glyphs, regular and hovered borders, no unwanted layout shift while the button is focused, the same first-line item order, correct gaps, no horizontal page overflow and unchanged active tooltip behavior. Include narrow-but-unclamped opening vs genuine browser/OS clamps; limitation notice/accessibility remains truthful when the target is impossible.
4. Run Classic/Web light/dark, Credits and USD (including locale/format variations), system/serif fonts, browser zoom **100%/125%** (higher zoom as feasible) and device scale **1×/1.5×**. Distinguish emulated DPI from actual physical Windows display scaling; test a physical 150%-scaled Windows/Edge host if available, otherwise record the limitation.
5. Verify the native Earlier Sessions **height-only** sizing contract and stable outer width across repeated pointer/keyboard toggle, no passive Live-driven resize, manual window resizing, Remember last size and all position preferences. Preserve the two-running-row opening height reserve and accounts/warnings, including a scrollbar case where vertical space is genuinely capped.
6. Expand the existing rendered header-width and native fit probes: `development/tests/integration/probe_mini_width.cjs`, `probe_mini_fit.cjs` and the focused disclosure/layout tests; use real DOM text-range/client-rect geometry, not mere `white-space: nowrap` assertions. Adjust older tests requiring a width narrower than the **new intentional worst-case reserve** (such as a strict prior `<634` request or mandatory wrap after subtracting six pixels), without weakening actual one-line fit, bounded-slack, height, or native-limit checks. Update `docs/web-mini-watch.md`, Mini Settings help and the Mini journal when **implementing**, not while writing this FR.
