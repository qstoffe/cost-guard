# FR 000645 — Mini Watch: show Δ Ctx and Next Ctx together in context help; add short prompt preview to Session help

**Owner-approved Ready Feature Request, 2026-11-09.** Permanent identity **000645**, Ready priority **000800** (Ready queue currently empty). **Backlog authoring only:** add this FR and advance `development/backlog/identity-state.json` highWatermark **644 → 645** in the same commit. Do not implement product code, tests, user docs, Settings, release/version, or unrelated backlog changes as part of this publication.

## Owner request and scope

In **Cost Guard Web → Mini Watch**, keep the existing unified four-column session table **`Activity | Session | CCost (Total) | Ctx`**, including its compact appearance, one-row-per-session membership, current visible Ctx value, colors and hover/focus/touch help.

Make **two small improvements to the actual value tooltips**, for both running and eligible historical sessions whenever source data supports the corresponding field:

1. **Ctx cell tooltip:** show **both the represented prompt's `Δ Ctx`** (context change/delta) and **the currently displayed next-context estimate**, with clear, short labels (e.g. `Δ Ctx: +4k` and `Next Ctx: 128k`). Retain the existing **approaching/exceeded price-threshold guidance** and supported multiplier/cost impact after these two lines. No fifth column or extra always-visible numbers.
2. **Session title tooltip:** preserve the full session title and represented prompt number, and **append a short, approximately first-25-character preview of that same prompt's text**. For example:
   ```text
   Example Session Name
   Prompt #21 in this session: Implement pagination for…
   ```
   This is for identification only, not a full prompt-text popup or a replacement for the session title.

Both are **Mini-only presentation/help** features. The owner likes the existing short contextual help and wants more useful information **without making the compact window taller or wider**.

## Verified current implementation

- **`src/web/assets/mini.js::View.sessionRow()`** already attaches `ContextHelp.value()` to the Session title and the Ctx cell. **`View.rowHelp()`** builds `row.sessionHelp` from the session name and `Prompt #N in this session`; it builds `row.contextHelp` from a general next-context explanation, `card.session_summary.context.warning.text` and the prepared `warning_cost`. It currently **omits numerical next Ctx and Δ Ctx from the tooltip**, even though next Ctx is visible in the cell.
- **`src/web/assets/mini.js::View.drawSessions()`** selects **one representative prompt per canonical session** and renders the Ctx cell from **`item.live_context.watch_next_context_tokens` for active/recent rows**, versus **`card.session_summary.context.watch_next_context_tokens` for historical-only rows**. The cell and its tooltip must use the same next-context owner; do not accidentally substitute a historical prompt's local next value for the session-level summary.
- **`src/application/live_projection.py::card_row()`** already includes **`live_context.watch_delta_context_tokens`** and **`live_context.watch_next_context_tokens`** for the canonical row. **`src/application/display.py::metric_tokens()`** already prepares properly signed/compacted `watch_delta_context_tokens` via `context_delta()` and `watch_next_context_tokens` via `context_tokens()`. Reuse those server-prepared values, including zero, unknown and sign semantics; do not re-derive Δ from two displayed rounded next-context values in the browser.
- **`src/application/live_projection.py::card_row()`** already projects the representative prompt's **`prompt.preview`**, plus `prompt_number`; **`src/reports/prompt_rows.py::PromptRowProjector.prompt()`** normalizes whitespace and caps the source preview at **120 characters**. Full Watch already renders this same bounded prompt preview. The Mini tooltips therefore need **no new prompt-content read, API endpoint or full-text exposure**.
- **`src/analysis/context.py`** owns native threshold state (approaching versus exceeded). **`card.session_summary.context.warning`** is the current Mini authority for the canonical warning text, price impact and freshness; preserve it. A crossed limit must still show the provider/model-relevant **exceeded** warning, not disappear because it is no longer merely “approaching” or be incorrectly relabeled by hardcoded UI text.
- The existing `ContextHelp` controller handles delayed pointer hover, immediate keyboard focus/touch, Escape, and dynamic refresh. Preserve these behaviors, source-scoped readouts and row identity, and avoid native `title` attributes, duplicate question-mark buttons or row-wide hover zones.

## A. Ctx cell help: current next + representative Δ

1. The Ctx **visible cell stays exactly as today** (one next-context estimate, no appended delta). On hover, focus or supported touch, the **same Ctx target** exposes both numbers, distinctly named and formatted with the existing shared display tokens. Suggested compact wording:
   ```text
   Next Ctx: 128k (estimated next incoming context)
   Δ Ctx: +4k (change attributable to the represented prompt)
   Approaching price threshold >… [existing canonical guidance if any]
   … [existing multiplier/cost context if available]
   ```
   The order may be Δ then Next if more natural; it must remain clear which is which. Use the source's existing signed Δ convention and context abbreviations rather than inventing another rounded unit.
2. **Active/running and recent terminal-grace rows:** `Next Ctx` in help **must match that same row's visible Ctx value**, based on its supported `item.live_context`, while Δ comes from **the same selected representative prompt's `item.live_context.watch_delta_context_tokens`**. This is the prompt chosen by Mini's session deduplication, not any prior prompt or aggregate from concurrent sessions.
3. **Historical-only rows:** `Next Ctx` in help matches the **currently visible historical session-level summary** `card.session_summary.context`, not a stale `item.live_context` next value. When available and semantically supported, **Δ Ctx** is labeled as the *historical representative prompt's* delta from its own row's `item.live_context.watch_delta_context_tokens`; do not imply it was computed by subtracting two session-level next-context snapshots or that these are the same timestamp. If that historical prompt's delta is not available/coherent, say **`Δ Ctx: N/A`** (or equivalent honest unavailable wording), not a guessed 0 or a delta copied from another session. Keep the selected canonical historical prompt and retained context scope intact.
4. **Unavailable/zero/negative:** known zero is explicitly zero; preserve supported signs and the existing source formatter's positive/negative/unknown treatment. A null/unavailable/unverified delta or next value stays **N/A**; don't create an arithmetic estimate from the compact `128k` text. The tooltip may still contain the other known value and valid warning. Partial, source-retained or stale context must not be silently presented as a new observation.
5. **Threshold guidance is retained for all valid states:** no threshold, **approaching**, **at or past/exceeded**, refreshing, pending or unavailable price guidance. Retain the *canonical source text* (`Approaching price threshold…` while genuinely approaching, `Price threshold … exceeded` after crossing where available), model-relevant threshold, comparison multiplier/cost impact and existing refresh notes. The owner explicitly values this warning **also when the threshold has been crossed**. Do not regenerate or reinterpret warnings from rounded K values, fail to display exceeded warnings, or assume the warning refers to Δ itself rather than the appropriate next/session context.
6. **No cross-entity mix-up:** Ctx, Δ and threshold guidance must correspond to the chosen session/representative and the proper session-level context source. Reusing a DOM row after a session resumes, the representative switches between concurrent prompts, terminal grace becomes history, or a source publication refreshes must update the help atomically and not leave a stale prior session's numbers or warnings.

## B. Session title help: short prompt identity

1. Keep the **first tooltip line exactly the full existing session name** (or supported canonical ID fallback) and keep the already supported **Prompt #N in this session** / **Prompt number unavailable** semantics. Append a colon and **up to approximately 25 visible characters** of **that same selected prompt's** existing bounded preview. Example:
   ```text
   My session with a long title
   Prompt #21 in this session: Implement pagination for…
   ```
   The preview is a short hint, not a verbatim full-user-message reveal. Existing compact or ellipsized **visible session cell remains unchanged**.
2. Use **`item.prompt.preview`** from Mini's canonical selected representative, not a random row, the previous prompt in that session, a tool command, linked subagent text, an unrelated history winner, the session title, or private raw user-message contents retrieved separately. For concurrent prompts, the preview must be the **same latest selected running representative** that drives Activity/CCost; for historical-only rows, use its **verified latest eligible historical representative**. When session A resumes, the same row's tooltip replaces the old preview and prompt number with A's newly selected prompt.
3. Normalize only what is needed for a compact single-line hint: **reuse the already whitespace-normalized/safe preview**, avoid embedded newlines/control characters, trim to **approximately 25 user-visible characters at a grapheme-safe boundary** (do not split combining marks/emoji/Unicode surrogate pairs). Add **one ellipsis only if truncated**; do not append `...` to a preview of 25 characters or fewer. Avoid accidentally duplicating a preexisting ellipsis. Presentation text is literal `textContent` through existing `ContextHelp`, never HTML/Markdown injection.
4. When `preview` is empty, absent, a non-prompt placeholder, or unsupported, **keep only the existing session name and prompt-number help** (or a concise `Prompt preview unavailable` if that is already consistent with other Mini help). Do not fabricate a sentence, show `undefined`, fetch full prompt content, or leak attachments/tool payloads. For an unavailable prompt number, do not invent a number from row index; an available preview can be shown as a separate labeled snippet without implying a known ordinal, if implementation supports it clearly.
5. Preserve existing keyboard/focus/hover/touch help for the Session title, including the readable full session name, current prompt number, and no duplicate hover triggers. Source corrections, session rename and prompt changes refresh the existing tooltip target without defocusing, repositioning the table or creating new rows.

## C. Minimal scope, UX and regression boundaries

1. **Tooltips only.** Do not alter the four table columns, visible Ctx, visible Session title, CCost/Duration tooltip, running/just-finished/historical colors (including FR000643 neutral history), Activity timestamps, layout, five-row history fill, unlimited active sessions, table scrolling, Mini size/position/Fit Height, Today/account rows or full Watch.
2. No source-model change is needed unless verification reveals the already-projected `preview` or `watch_delta_context_tokens` is genuinely omitted for a supported historical representative; if so, extend the existing **bounded, allowlisted, source-owned projection narrowly** rather than re-reading user prompts, adding a new history scan, source worker, auth path or persistence.
3. Avoid a tooltip that implies **Δ Ctx** means remaining model context capacity. Next Ctx means *estimated next incoming context*; Δ is a change associated with the represented prompt (subject to compaction/context epoch rules). A historical session summary may be later than the represented prompt; don't pretend these are the same sample. Keep the canonical threshold guidance's actual semantics.
4. Respect public-repository privacy: all FR examples are synthetic. At runtime, user preview text is handled within the existing authenticated/local Web/Mini projection, capped to a very short display hint, never logged, persisted in another cache, inserted into external URLs or sent to additional providers. Maintain shared CSP/security constraints.

## Acceptance scenarios / tests

1. **Running prompt, full information:** given selected prompt `#21`, title `Example Session`, bounded preview `Implement pagination for this table`, formatted next `128k` and Δ `+4k`, the Session value help includes the title, `Prompt #21 in this session: Implement pagination for…` (at most ~25 source characters before ellipsis). Ctx value help includes **both `Next Ctx: 128k` and `Δ Ctx: +4k`**. The visible four-cell row is unchanged.
2. **No price warning / approaching / exceeded:** check the same Ctx pair with no warning and both real threshold states. Approaching retains the current canonical wording and supported cost impact; **exceeded still presents the exceeded state and multiplier after crossing**. Pending/refreshing/unavailable guidance remains truthful and does not overwrite valid Ctx/Δ values. Avoid duplicate warning sentences.
3. **Historical row:** verify that visible next context comes from **session summary** (e.g. `900k`) and tooltip says `Next Ctx: 900k`. If historical representative's delta is present, show that prompt's own Δ (e.g. `+12k`), even if that representative's own next differs. If absent, show N/A, not a delta inferred from 900k or an unrelated prompt. History threshold state uses that session's canonical warning.
4. **Same session multiple prompts/resumption:** one row for session A with prompt #21/preview A; after another running prompt #22 starts in A, its help updates to #22/preview B and new context values; after completion/grace/history, it uses the correct historical representative and session-level next. No old preview/delta/threshold text lingers, and another session's tooltip is unchanged.
5. **Preview bounds and escaping:** prompt preview shorter than 25 (no ellipsis), exactly 25 (no ellipsis), longer than 25 (single ellipsis), multiline whitespace, long Unicode combining sequences/emoji and an HTML-like value (`<img src=x onerror=...>`) displayed as harmless text. Empty/missing preview and unknown prompt number do not produce invented content or `undefined`/row-index guesses. Header/titles and prompt numbers remain available.
6. **Numeric and source corners:** 0 Δ, positive Δ, source-allowed negative Δ, N/A, absent row/context, missing historical representative, compaction/context-epoch boundaries and retained refresh. Tooltip follows server `display` tokens and does not calculate from rounded numbers.
7. **DOM and accessibility:** use `development/tests/integration/mini_watch.cjs`, `development/tests/fixtures/mini_sessions.cjs` and real `probe_mini_watch.cjs` / existing ContextHelp browser checks, plus relevant server display/projection tests. Verify actual hover, Tab focus, touch, Escape and update while tooltip is open; compare expected text, no duplicate tooltip icons, consistent four-column layout, no new scrollbars, no full prompt-content popups, no impact on Credits/USD, Classic/Web or full Watch.

Update **`docs/web-mini-watch.md`** and relevant module description **during implementation** with the two value-help additions. Do not modify product docs as part of this FR-only commit.
