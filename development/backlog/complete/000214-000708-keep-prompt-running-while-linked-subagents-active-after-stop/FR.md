# FR 000708 — Keep a stopped parent prompt RUNNING while its linked subagents are still active

**Owner-approved Ready to Develop — 2026-11-14.** Permanent identity **000708**; Ready queue priority **000016**, immediately after FR000707 (000015). **FR authoring only:** publish this standalone request and advance the permanent identity high-water mark in one documentation-only commit. Do not implement product code, interrupt/start any OpenCode sessions, run paid inference, alter versions/releases, move other FRs, or migrate the backlog repository as part of this publication.

## Owner-observed problem

In Cost Guard's **Running Prompts** view, the owner observes this sequence:

1. A parent/root prompt starts one or more subagents.
2. The parent prompt is **manually stopped/interrupted** while an **already-linked subagent is still executing**.
3. Cost Guard incorrectly removes the parent prompt from the **running** state / displays it as **finished**, even though there is ongoing execution within the same session's causal subagent tree.

**Desired rule:** A prompt with an actively executing, causally linked subagent (including a deeper nested descendant) must **continue to be shown as RUNNING for as long as that linked work remains active**, even if its own parent/foreground model attempt has been stopped. The visible RUNNING indicator describes **outstanding work for that prompt's causal tree**, not a claim that the parent model itself is still inferring.

This is a **reported user-visible scenario**, not yet a replayed, verified live-source trace. Determine whether the defect is in source observation, causal ownership, prompt lifecycle classification, retention, or display; do not declare the exact root cause without reproduction.

## Binding behavior

1. **Stop parent, child continues.** For a root prompt with confirmed linked subagent A still executing, stopping/cancelling the parent must **not** move that prompt into Earlier/Finished, clear its running highlight, drop it from the running-session selection, or announce that no prompts are running. Keep the prompt **RUNNING** in Full Watch and Mini Watch while A is active. If A finishes but another linked sibling B or qualifying nested grandchild remains active, keep the prompt RUNNING until the **last** active causally linked descendant finishes/stops.
2. **Two lifecycles, one truthful presentation.** Preserve the parent attempt's real terminal/cancellation/failure evidence separately from the derived **causal-tree-active / remaining subagent work** state. The UI can show **RUNNING (subagent activity)** or an equivalent clear indication if available, but the prompt must remain in its running area with normal running styling/accessible status while any linked descendant is executing. Never claim the cancelled parent model is still making requests, mark the parent successfully completed, erase its abort reason, or misrepresent a still-running subagent as already finished.
3. **Transition when the final descendant finishes.** On the first accepted authoritative observation that every causally linked active descendant has stopped/completed, leave the running state **once**, stop live duration growth where appropriate, and apply the correct final outcome: an explicitly interrupted parent remains **aborted/stopped**, not magically **Completed** just because the child succeeded; preserve genuine error/unknown outcomes where that is the source truth. Move the result through existing terminal grace / recent-finished / Earlier rules without oscillation, losing usage or resetting the grace on each refresh. A genuine new attempt may become running again.
4. **Exact causal ownership.** Attribute live children to the initiating root prompt/attempt using **verified parent-child session identity and invocation windows** (including supported `task` and `subagent` calls, background descendants and nested children). Do **not** declare the root prompt running merely because an unrelated session, an older unattached child, another session's active-map entry, a disconnected tool invocation, or a later unrelated prompt in the same root is active. If a new user prompt/compaction supersedes the stopped parent while its own subagent is still genuinely running, preserve the correct root-session running status and original child's causal attribution; never borrow or double-count that child's execution for a different prompt. Define/document the correct visible representative under existing one-card-per-session rules.
5. **Live source authority, not visual guesswork.** Use fresh, positive source evidence for an executing child where supported (`session.active` / native active map, source messages or tool state and validated links). An incomplete response, temporarily missing child, slow/no-token child, failed capture or unknown status must not itself prove completion. Conversely, a **confirmed terminal/inactive child with no other outstanding work** must not be kept RUNNING indefinitely from an open-ended invocation window, parent history or an old cached active flag. Respect source-generation, process-local status limitations, cancellations/retries and eventual reconstruction after reconnect.
6. **Consistent shipped surfaces.** Apply the corrected **shared lifecycle projection** to **Full Web Watch Running Prompts / Earlier Sessions**, **Mini Watch / Document PiP**, **Sessions list RUNNING marker and session detail**, **CLI Watch / session/report views where running state is shown**, and their row/tooltip/accessibility labels, duration/activity and session summaries. No separate UI-only fake RUNNING flag that disagrees with underlying canonical state. Show subagent activity in existing tool/background detail where supported, without inventing a foreground model call.
7. **Keep accounting and scheduling truthful.** Continue to ingest and attribute actual child/subagent requests and their cost/tokens while parent has stopped; do not lose late arrivals or double count reused/nested children. Preserve independent *parent foreground duration*, *outstanding tree elapsed/activity duration*, billed/reference CCost and inferred active-AI time semantics; only grow a displayed "running" elapsed clock if its existing meaning is ongoing tree activity, not a fabricated parent inference duration. Keep bounded capture scheduling, source read-only guarantees, terminal reconciliation, and the existing five-row Mini layout / quiet-refresh behavior.
8. **No unrelated changes.** Do not modify OpenCode's actual interrupt semantics, automatically restart/resume a stopped prompt, signal/abort its children, change quota, invent native statuses or extend unrelated terminal grace periods. This request changes Cost Guard's observation/classification/rendering of **real remaining subagent activity**.

## Required acceptance and focused regressions

1. **Primary red-to-green synthetic integration scenario:** parent prompt starts child A; both are running. Parent receives an authoritative manual interruption/abort while A still has affirmative running evidence. Across repeated source captures, shared analysis, Watch publication and rendered Full Watch/Mini DOM, the **same initiating prompt remains RUNNING** (visible marker, running area, accessible outcome), and continues receiving A's actual usage, while the source record still retains parent's cancellation. No false parent inference/tool claim.
2. **Multiple and nested agents:** parent stopped while A/B run; A stops before B → still RUNNING; B finishes → terminal. Parent → A → grandchild C with A ended but C active → still RUNNING. Cover foreground `task`, structured V2 `subagent`, background cases, reuse/overlapping child IDs, a parent tool row already terminal, and a child that becomes idle/terminates without a final priced request.
3. **Correct final outcome:** when last child ends, transition once to the parent attempt's actual **Aborted** / failed / finished-supported outcome, preserve final costs/calls/tokens, stop running duration and use existing recent-finished / Earlier behavior. No success relabeling, duplicate terminal row, flicker, sticky RUNNING or repeated grace.
4. **Isolation and negative cases:** user stops parent with **no** active linked child → existing correct stopped behavior; unrelated active sessions and stale/unverified links never keep the prompt running; next prompt/resumption/compaction does not steal former child activity; no double count or wrong session title/status. A genuinely long, quiet active child remains running without a heuristic time cutoff.
5. **Source lifecycle resilience:** active child on first observation, delayed/missing assistant terminal, parent interruption, temporarily incomplete/failed child fetch, stale/out-of-order publication, source process restart, cold Web host start, reconnect and complete child termination. A partial observation may retain properly qualified prior evidence, never falsely certify completion or keep stale confirmed-running data forever after authoritative terminal evidence.
6. **Cross-surface parity:** Full Watch, Mini/PiP, Sessions catalog/detail and CLI use the same underlying lifecycle truth for the same snapshot and root; activity/duration, running color/marker, summaries, tool/background details, ARIA and history selection remain consistent. Test light/dark/narrow if relevant; no Mini sixth row / status flicker regression from FR000703.
7. **Accounting/safety regressions:** unchanged exact token/CCost attribution, physical request deduplication, source read-only behavior, error/abort semantics and bounded refresh cost. Use sanitized, synthetic fixtures; no real user session modification, unnecessary polling or paid model calls are needed.

**Deliverable:** Stopping the parent prompt does **not** make Cost Guard call it finished while any **properly linked subagent is still running**; once all linked work genuinely ends, the prompt leaves RUNNING and retains its real parent outcome.
