# FR 000607 — Mini Watch: smallest Fit on open width without header wrapping

**Owner-approved Ready Feature Request, 2026-11-06.** Permanent identity **000607**; queue priority **000250**, after existing Ready FR000606 (000240). **Backlog publication only:** do not implement product changes, run product gates, change versions or move completed FRs in this authoring step.

## Problem and intended result

Completed **FR000591** introduced the shipped **Fit on open** size default, but its nominal initial width is still about **650 outer device-independent pixels (DIPs)**. That leaves the floating Mini Watch unnecessarily wide for the owner's everyday use. The Mini header currently permits flex wrapping, and Windows display scaling/browser zoom make a hardcoded pixel target misleading.

For **Mini Watch size → Fit on open**, including symbolic **Default** resolving to it, request the **smallest practical initial window width at which the entire first/header row stays on one line**. The three existing header components must fit together, in their normal left-to-right layout:

- **Cost Guard · Watch** return action;
- **Earlier Sessions** disclosure button, initially collapsed;
- the complete **CCost Today** summary with its current cost and prompt count (e.g. `CCost Today 6 152 · 106 prompts`).

This is an intrinsic **content-fit criterion**, **not an instruction to replace 650 with another fixed number**. Do not prescribe CSS pixels, DIPs or physical Windows screen pixels as the default width. The desired result is a visibly more compact PiP where possible, with no unnecessary horizontal empty space beyond the real header content, gaps, padding, native frame and a small rounding tolerance.

## Required behavior

1. **Measure the header at each eligible opening, before the native PiP request consumes activation.** Use the real rendered/styled header labels and currently available daily figures, together with actual font metrics, selected theme, browser zoom, effective scale, gaps and padding. Extend/reuse the existing inert `OpeningMeasure` path in `src/web/assets/mini.js` and corresponding `mini.css` layout; prefer an intrinsic-fit measurement over trial-and-error native resizes. Do not mistake the requested inner viewport width for achieved outer/native-frame width. Do not introduce a magic fallback width that merely replaces 650.
2. **One unwrapped first row at the achieved target, not a fake fit.** All three components must be visibly present together, without wrapping onto a second line, truncating the return/disclosure labels, cutting off the Today cost/prompt count, overlapping, or hiding content with `overflow: hidden`. A `nowrap` style alone is not proof if it causes clipping or horizontal overflow. Use just enough conservative native/zoom rounding allowance to avoid a borderline wrap, not a large safety margin. For an unusually narrow manually resized PiP, keep responsive, readable scrolling/wrapping fallback; do not lock the user's manual width.
3. **Recalculate height using that narrower opening width**, but **preserve FR000591's already-delivered height contract**: Earlier Sessions starts collapsed; all actual initial content, warnings and account/subscription lines fit if screen limits permit; there is vertical capacity for **two complete Running Prompts rows** even when zero/one exists; more than two actual rows count toward measured height. No premature vertical scrollbar within the available screen/work-area and native height limit. Smaller width may wrap account/status content and increase required height. Do not replace height fitting with a fixed number or fabricate prompt rows.
4. **Keep the existing Earlier Sessions expand/collapse behavior.** An eligible user click/Enter/Space may grow/shrink **height** using the current measured content; retain the actual current width wherever the browser permits, including a manually changed width. No passive Live/SSE-, timer- or observer-driven native resize, no repeated correction calls, no programmatic placement, and no changed browser-owned manual sizing. If native caps/clamps make a full fit impossible, keep header/content accessible and scrollable, disclose the limitation truthfully, and do not claim an exact physical result.
5. **Preserve Settings meanings.** Keep the existing **Mini Watch size: Default (Fit on open) / Fit on open / Remember last size** choices, saved key `miniWatchSize`, and **Mini Watch position** preferences as they are. Change the Fit on open description/help from the obsolete `about 650 outer DIPs` claim to **the narrowest opening width fitting all three header components on one line, plus existing content/two-row height fitting**. Make Remember last size help clear that it still lets the browser reuse a manually chosen size and **does not forcibly apply this minimal opening width**; position/size coupling and next-opening application remain honestly described. Do not change persistence, create a pixel-geometry setting, or reset an explicit user's choice.
6. **Adapt to the real opening snapshot.** Different displayed CCost magnitudes/units, prompt counts, fonts and zoom can change the minimum; a fresh Fit opening should measure again. Later Live updates must not trigger forbidden passive resizing; if later text genuinely grows beyond the opening reserve, preserve accessible content rather than hiding numbers or pretending the original measurement guarantees every future value.

## Coordination and non-goals

- **FR000591 is complete:** do not reimplement its height fit, disclosure resizing, position semantics or withdrawn hands-free Auto-height requirement. This FR only refines initial **Fit on open width**, the resulting width-aware height measurement, and relevant option help/docs/tests.
- **Ready FR000603** adds a narrow Activity column **inside the expanded Earlier Sessions table**. Its extra column must not by itself force a wider *collapsed opening header*; preserve the existing table's truthful horizontal panning on genuinely narrow widths. Coordinate with whichever of FR000603 and this request reaches `main` first without changing FR000603's requirements.
- No changes to daily/session accounting, quota, acquisition, Watch page, prompts/history membership, table value semantics, release policy, startup flow, or Remember last size behavior. No new timers, background geometry supervisor or browser-specific OS automation.

## Acceptance and verification when implemented

1. On ordinary supported Chrome/Edge Document PiP, **Fit on open / Default** opens with the three header items fully visible on **one row** and the native PiP meaningfully narrower than the former nominal 650-DIP request where content permits. Show that reducing the measured candidate further would cause a header wrap; allow only modest frame/rounding tolerance. Do not assert success from request arguments without checking actual bounds and content layout.
2. Check real populated CCost Today values (Credits and USD), short/long prompt counts, loading/unavailable states, different fonts/themes and native page zoom. Test Windows display scaling **150%** as relevant to the reported setup, including browser zoom separately, rather than converting a desired physical width into a guessed CSS width. If a physical Windows/Edge/Chrome host is available, inspect its actual opening; distinguish it from headless/emulated scale evidence if not.
3. On opening with **zero, one, two and more than two** real running prompts, multiple subscriptions/warnings and Earlier Sessions collapsed, confirm the *existing* no-premature-vertical-scroll and two-row height reserve when native limits allow. Open/close Earlier Sessions repeatedly: height changes appropriately, width is retained, manual resize remains respected, and expanded history (including FR000603's Activity column when present) stays usable.
4. Verify **Remember last size** still uses browser-managed manual bounds instead of the new Fit width, including reopening and the existing position-coupling limitations. Verify symbolic Default and explicit Fit options, accurate updated Settings helper text, and next-opening-only application.
5. Use focused existing Mini Watch/Settings tests and real browser layout probes where feasible (e.g. `development/tests/test_mini_watch.py`, `development/tests/integration/probe_mini_fit.cjs`, `mini_watch.cjs`). Update `docs/web-mini-watch.md` and applicable Settings/architecture wording that still asserts an approximately 650-DIP default. Preserve fallback accessibility under native clamps; do not add unrelated or fragile project-wide validation requirements.
