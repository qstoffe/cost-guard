# FR 000707 — CCost: show zero instead of Not Applicable everywhere

**Owner-approved Ready to Develop — 2026-11-14.** Permanent identity **000707**; Ready queue priority **000015**, immediately after FR000706 (000014). **Feature-request authoring only:** publish this specification and advance the permanent ID high-water mark in one documentation-only commit. Do not implement product code, change actual valuation, run live/paid tests, update product versions or releases, move other backlog items, or migrate backlog repositories as part of this authoring task.

## Owner-observed problem

Newly appearing **running prompts in Mini Watch** intermittently display **`Not Applicable` / `N/A` in the CCost column**, apparently while usage and reference-cost valuation are still being acquired/calculated. The owner explicitly rejects this presentation: **CCost must show zero instead, in the selected Credits or USD unit**. A new running prompt should immediately show **0 Credits** (or the existing USD formatter's zero, e.g. **$0.00**) until a calculated amount is available. The same rule applies **everywhere else CCost is displayed**, not only Mini Watch.

This is an owner-requested **CCost display contract**, including cases where the current source cannot yet yield a cost. It is not permission to record invented zero usage, claim that unpriced requests are free, or change billing/cost arithmetic.

## Required behavior

1. **Never expose an unavailable placeholder as a CCost amount.** In every visible field whose purpose is to display **CCost/reference cost**—prompt, call, session, subtotal, category, period or account—replace any pending/unknown/unpriced `Not Applicable`, `N/A`, dash, empty cost slot or equivalent unavailable cost-value placeholder with a correctly formatted **numeric zero**, using the current Credits/USD presentation setting. This includes initial acquisition of a new active prompt and a legitimately unpriceable cost amount. Do not replace unrelated `N/A` values, such as unknown context, duration, usage, native billed spend or quota metadata.
2. **Prefer a real value over the zero fallback.** Show the canonical currently available numeric CCost, including a legitimate zero or any positive known-priced subtotal. As soon as a qualified new cost is computed, update **0 → actual cost**, without a transient `N/A`. Missing prices for some calls must not erase an available known-priced subtotal. A later verified result may legitimately return to actual zero when it really describes the current scope.
3. **Retain already known same-scope values while recalculating.** If the very same prompt/session/period has already displayed a valid cost, normal polling, provider/price acquisition, retries, partial snapshots and background refreshes must not revert it to a display fallback of 0 or `N/A`. Preserve the last qualified CCost until a genuinely newer qualified value replaces it, following FR000703. **Use the zero fallback only where no applicable cost value is yet displayable**; a new prompt must never inherit the previous prompt's amount. Clear/re-scope appropriately on source, identity, selected period or account changes.
4. **The zero is only a presentation fallback.** Preserve underlying `null`/unknown/unpriced states, provenance, completeness flags, observed token counts, request identities, exact Decimal-priced subtotals, model/version resolution, price-catalog availability, deduplication, aggregation and historical data. **Do not** coerce unknown CCost to a canonical zero, set `cost_complete` or `priced_requests` artificially, classify an unpriced call as free, treat a display zero as proof of billing $0, or silently change totals. Sorting, reports and calculations must use canonical underlying data and established unknown/partial handling, **not** the zero-only fallback string. Existing diagnostic/help content may describe incomplete evidence, but the **CCost amount itself** must never say `N/A`.
5. **Honor Credits and USD consistently.** CCost zero and real amounts follow the selected existing formatter, precision and unit, in both currencies and immediately after toggling units. Numeric values must not have a leading uncertainty `?` (FR000706). Do not introduce a replacement warning prefix, pseudo-number, status badge, spinner or new `Loading` placeholder into CCost amount cells.
6. **Application-wide audit, not a Mini-only string replacement.** Cover at minimum:
   - **Mini Watch / Document PiP:** running/new prompt CCost, previous/finished prompt CCost, session CCost and Total columns, cost help/tooltip lines and refreshed/reopened snapshots.
   - **Full Web Watch:** Running Prompts, Earlier Sessions, prompt and session values/totals, CCost Today, relevant cost help and hover/focus/accessibility representations.
   - **Sessions catalog and session detail**, Accounts/account cards and their CCost Today totals; **Token Mix** model/publisher/period/category CCost including upcoming percentage-cell cost tooltips; **AI Stats**, applicable Comparisons and historical or aggregate CCost displays.
   - **CLI normal/history/report/Watch** and any shared formatter/DTO or other shipped surface that presents a CCost amount.
   Keep the same display policy in visible text, popup values and appropriate accessible labels; avoid a hidden `N/A` in ARIA while the cell shows 0. Do not blanket-replace `N/A` across the application.
7. **Scope exclusions.** Do not change native **Billed** versus reference CCost meaning, quota **Capacity/Remaining/Used**, token/model telemetry, context, duration, standalone published per-token pricing rates (where "not applicable" can be a legitimate catalog fact), or provider/auth diagnostics. No alternative price source, speculative valuation, extra scanning/polling or persistent source mutation is requested.

## Implementation leads (static source inspection, not proof of the exact live incident)

- `src/numbers.py::ccost_amount()` currently returns `"N/A"` when the amount is `None` **or** `unresolved` is true with numeric zero. Its consumers need a scoped **CCost presentation** treatment, not a blanket semantic change for all metrics.
- `src/application/display.py::amount_tokens()` has CCost-specific `"N/A"` paths, including daily CCost and unknown incoming/context costs. Inspect the shared display-token path for Live/Watch/Mini and other report consumers; preserve the raw valuation state.
- Start from `src/web/assets/mini.js`, `watch.js`, `render.js` and related session/account/report/token-mix renderers, as well as CLI presentation. Trace **the newly running prompt's first snapshot → CCost DTO → formatted display token → Mini cell**; verify the actual cause before picking an implementation boundary.
- Check whether an app-wide numeric fallback at the wrong layer would falsely affect a standalone *published price*, native billed/quota value, sort key, completeness flag or source payload; choose typed, narrowly scoped formatting/projection instead.

## Relationship to other FRs

- **FR000703:** keep valid same-scope CCost during quiet refresh; its general prohibition on fabricating unknown metrics still governs data, while **this owner's later CCost-specific display rule** intentionally represents a previously unvalued cost as 0 in the UI.
- **FR000704:** Mini CCost/Total model- and subagent-group tooltips use the same zero-for-unavailable cost **amount** policy, without inventing source evidence or a made-up group.
- **FR000705:** Token Mix category/total CCost fields and cost tooltips obey this policy; the requested table structure, period attribution and sort semantics are unchanged.
- **FR000706:** its no-leading-`?` rule for numeric CCost remains; its earlier permission to display standalone `N/A` for entirely unpriceable **CCost amount fields is explicitly superseded by FR000707**. Do not remove legitimate non-CCost unknown states.
- Completed **FR000700** retains ownership of accurate recursive subagent CCost attribution. Historical unpriceable reference valuation still stays unknown in the source model; this FR changes only what the user sees in a CCost amount slot.

## Acceptance and regression verification

1. **Primary Mini Watch reproduction:** create a synthetic newly started running prompt with no computed CCost. Its CCost cell **immediately shows formatted 0**, not `N/A`, `Not Applicable`, blank, dash, spinner or `Loading`. Multiple pending/partial first snapshots keep it at 0; the first supported priced amount replaces it directly. Repeat in Document PiP and with USD selected.
2. **Price unavailable:** an observed request with no usable reference price and no priced subtotal still **displays zero in every CCost amount field** while retaining raw unknown/incomplete status. An observed mixed priced + unpriced request displays its **actual known priced subtotal** (without `?`), never a manufactured complete cost. A genuinely measured zero displays zero too.
3. **Retained known → background refresh:** after showing an actual positive amount, loop through pending, partial, retry and recovery snapshots: there is **no flash back to 0 or `N/A`** for the same qualified scope. On a new prompt/period/source/account, no stale amount leaks across identities; a new truly unvalued item starts at 0.
4. **Cross-surface and units:** check every audited Full/Mini/PiP/Web/CLI CCost value, subtotal, Today total and cost help line for both Credits and USD, including old records, live updates, unit toggles, reload and user navigation. DOM **and accessible cost labels** show numeric amounts rather than unavailability text in CCost value positions. Ordinary unrelated unavailability labels remain truthful.
5. **Data integrity:** compare typed underlying cost/coverage/unknown flags, source request counts, exact known subtotals, valuation, sort keys, numerical totals, quotas and billing before and after. The zero fallback is never fed back into canonical arithmetic, persistence or false zero-billing/complete-valuation claims. Exercise missing provider/catalog price, unknown usage, real zero, zero with incomplete coverage, mixed models/subagents and repeated prompt transitions.
6. Run the focused formatting/projection tests and relevant Mini/Full/browser/CLI regressions when implementing; report actual coverage. No paid-model inference is needed to test this display behavior.

**Deliverable:** every displayed CCost amount is a numeric amount in the selected unit, with **0 instead of `Not Applicable` whenever no qualified amount is yet available**, while actual valuation truth and already known same-scope values remain intact.
