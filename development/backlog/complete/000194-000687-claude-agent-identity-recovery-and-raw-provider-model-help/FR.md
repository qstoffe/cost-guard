## 1. Owner-observed regression — local 2026-11-12 history is the primary evidence

## 2. Verified code-level reasons this can recur (static findings, not a diagnosis of the owner's workstation)

**A. A source-selected alias is not the executed release.** `src/domain/model_identity.py::unverified_alias` explicitly renders versionless `sonnet`, `opus`, `haiku`, `fable` and moving defaults as `Claude ... (version unverified)` on known provider routes. `src/pricing/catalog.py::display_name` checks that before ordinary catalog formatting. `src/pricing/reference_diagnostics.py` and `PricingCatalog.reference_valuation` deliberately refuse to price still-unverified model aliases; consequently **the version-unverified display and CCost `N/A` can share an identity-resolution cause**. Missing I/C/W/O telemetry, unsupported price tier, stale reference prices or incomplete session evidence are independent alternative causes; inspect the actual CCost diagnostic reason before asserting identity is the sole problem.

**B. The approved FR000651 fallback is deliberately narrow and can return no mapping.** `src/sources/opencode_v2.py::_normalize_messages` calls `DesktopModelCatalog.resolve(message.model, native.directory)`. `src/sources/opencode_v2_model_identity.py` resolves **only recorded `provider == claude-agent`** on a nonempty exact session directory; it fetches `/api/provider` and `/api/model` with `location[directory]`, requires matching response location/provider and exact selected `id`, skips deprecated entries, and takes concrete `modelID` or a sufficiently specific observed model name. It memoizes a **negative lookup for up to 30s** and records a resolution signature. `src/domain/model_identity.py::desktop_catalog_candidate` accepts opaque selected names but deliberately excludes already pinned concrete releases.

A session created under an **ephemeral test workspace, relocated/deleted project, different profile/config scope, changed provider catalog, empty/unsupported location-specific response or different provider ID** may therefore bypass the mapping and revert to the old alias label. **These are hypotheses to distinguish with actual source evidence**, not grounds to globally borrow a different project's alias mapping. Also test model identifiers containing suffixes such as `[1m]`, `-latest`, `default`, aliases with a concrete catalog `modelID`, and future/new model names.

**C. The current OpenCode implementation does not persist all executed identity evidence.** In public OpenCode source, the Claude Agent stream converter emits `response-metadata` with actual `message_start.message.model`:
- <https://github.com/anomalyco/opencode/blob/dev/packages/core/src/plugin/provider/claude-agent/language-model/convert-claude-stream.ts>
- <https://github.com/anomalyco/opencode/blob/dev/packages/core/src/aisdk.ts> — `streamPartEvents` currently drops `response-metadata` (empty LLM event array).
- <https://github.com/anomalyco/opencode/blob/dev/packages/core/src/session/message-updater.ts> — assistant `model` comes from selected step model.

Therefore OpenCode's **present-day Desktop model name**, sourced from a mutable current location catalog, is **not an executed-model certificate for old alias requests**. Prior FR000651 investigation identified a narrower historical recovery possibility: exact plugin session/checkpoint UUID → official Claude Agent SDK transcript assistant `message.model`. This join has **not** been proven on the owner's specific historical session; don't pretend it was. Upstream changes since historical OpenCode 2.2.6 must be verified against the **installed service** before selecting a strategy. Never equate a current SDK default, visible session title or nearby response to a particular historical release.

**D. Existing derived data can preserve a now-wrong conclusion.** Relevant owners include `src/analysis/model_identity.py` / `src/analysis/cache.py`, `src/reports/session_summary.py` (`session-summary-3`, source/catalog-scoped dependency checks), `src/analysis/session_cost.py`, root-cost and Token Mix caches, AI Stats/Comparisons compact evidence, `src/application/session_catalog.py`, and ongoing Watch/Mini publications. `MODEL_IDENTITY_SEMANTICS` currently has version 3. Prior FR000651 explicitly covered *negative-lookup recovery*, fresh-process cache hits and revision-qualified reuse. Determine whether the failing 2026-11-12 sessions have no mapping **now**, a previously negative or stale cache, incorrect source-location dependency, or a projection that lost a corrected identity. A fixed standalone resolver with stale Web Sessions rows is **not fixed**.

**E. Existing help mixes friendly and raw identities inconsistently.**
- `src/web/assets/mini.js::View.promptDetails` constructs `Main model: {friendly label} [provider/model]` sometimes, from cost groups; its model value can differ from the *originally selected* alias after current-catalog resolution. The user wants the **raw provider/model**, without repeating the friendly label inside tooltips.
- `src/application/prompt_costs.py::detail_tokens` emits `Main prompt — {friendly model}` / `Subagents — {friendly model}` and appends `[provider/model]` or a second indented identity, sometimes conditionally. `cost_detail_help`, `model_detail_help` and `calls_help` share this formatter, so a piecemeal Mini-only change is insufficient.
- `src/web/assets/watch.js` uses `model_detail_help` only when supported, while CCost/Calls may contain model labels. `src/web/assets/session.js` uses the same cost detail. `src/web/assets/sessions.js` has a **generic single-model** hover and a multi-model list built from `contributor_models` rather than an always-visible raw provider/selected-model disclosure. `src/web/assets/comparisons.js::provenance` renders a mixed `provider/{friendly} [{effective model}]` form. These paths must be audited together, along with any new model-bearing AI Stats fact and other source-prepared help surfaces.
- `src/reports/prompt_costs.py::PromptCostPart` currently carries provider, **effective/resolved** `model_id`, friendly name and `selected_models`. A resolved model can differ from the **original raw recorded model**. The raw tooltip needs access to the real selected provider/model pair **per attributable request**, not a label-derived string or the reference-price manufacturer/publisher.
