# FR 000620 — Watch/Accounts: shared subscription capacities, tooltip clarity and Today cleanup

**Owner-approved Ready Feature Request, 2026-11-06; amended per owner on 2026-11-07.** Permanent identity **000620** and unchanged Ready queue priority **000380**, after FR000619 (000370). **Backlog-only revision:** no code/tests/product docs/version changes or new ID allocation.

## Owner's requested visible changes

This is a targeted **Full Watch tooltip/day-summary refinement plus shared Watch/Accounts subscription-card enhancement**, not a new report or wholesale redesign. **Full subscription cards must default to identical visible fields, ordering, calculations and tooltips on every page where they appear**, unless a future owner decision explicitly requests a divergence.

1. **CCost (I + E) heading help:** remove the sentence **“A displayed zero shows two zero components in this unit, even when component evidence is unavailable.”** It is confusing and unnecessary. Also remove its final paragraph in full: **“N/A — Cost unavailable, not zero. / ? — Part of the cost cannot be priced. / I is a cost here, not the Input token share.”** Keep the meaningful concise explanation of estimated prompt CCost and the first-request **I** / other-requests/subagents **E** split, and the total relationship.
2. **Model column heading help:** preserve the two simple bullets **Main prompt** and **Linked subagents**, but amend the linked-subagent bullet to explain that hovering over, focusing, or tapping the **Model cell** (typically marked with `*`) can reveal the **models and effort levels actually used by linked subagents** when supported by recorded evidence.
3. **Model cell and CCost cell details:** remove the textual **price-tier descriptions** such as **“Default (0–272000 input tokens)”** (and analogous `Default 0 to 272 000 input tokens` text) from **both** tooltips. This tier interval does not help interpret the observed subagent model/effort/cost breakdown. **Do not remove price-tier selection from pricing calculations or grouping**; just stop putting the tier name/token-boundary argument in these two helper texts.
4. **Model cell must actually reveal linked subagents:** today a single-model main+subagent combination may show a `*` but not open a useful model tooltip. Ensure the Model value's contextual help is available whenever linked subagent evidence warrants it, **even if the same model ID was used by main and all subagents**. Show known main model/effort and the linked subagents' actual model and effort, preserving honest unknown/unreported fields. The heading's new promise must match this behavior.
5. **CCost cell tooltip — one new bullet:** keep existing **Input / Cached input / Cache write / Output / Subtotal** breakdowns for **Main prompt** and grouped **Subagents**, unchanged in meaning. At the **top of each Subagents group's bullets**, add **“• Number of prompts: N”** from actual canonical, distinct **subagent prompts** contributing to that group. Do **not** add the new bullet to Main prompt. The owner particularly wants to distinguish a grouping of e.g. ten same-model/same-effort subagent prompts from one. Avoid confusing number of prompts with number of distinct agent sessions or physical model-request Calls.
6. **Capacity labels and a visible monthly-equivalent line for Watch AND Accounts:** On **primary and secondary quota cards** on both pages, replace the generic Capacity text with its factual window length: **Monthly Capacity**, **5-hour Capacity**, **Weekly Capacity**, etc. An eligible **nonmonthly** quota gets **a second, visible line directly underneath**, **Monthly Capacity: [30-day equivalent] (guesstimate)**, before its progress bar, and the same facts in its Capacity tooltip. A natively monthly quota has one **Monthly Capacity** line, not a duplicate extrapolated one. Unknown/nonconvertible nonmonthly capacities show **Monthly Capacity: N/A** and why, not fabricated totals. The period's original numeric Capacity and existing (guesstimate) qualifier stay intact.
7. **Watch's day summary above subscriptions:** retain only the existing **CCost Today** total and **today's prompt count**, along with essential error/partial/retained-source indicators. Remove **Token Mix %**, all four **Input / Cached input / Cache write / Output** daily-share items, and token-mix-specific explanation/clutter from that particular summary. Token Mix remains available on the dedicated page and per-prompt cells; no historical/usage data is deleted.

8. **Cross-page subscription parity and smart alignment:** Watch and Accounts already share a full-size subscription-card component; require them to **remain identical by default** for equivalent data, including primary/secondary layout, capacity, tooltips, percentages, resets, warnings and accessibility. When a native-monthly primary card is displayed beside a nonmonthly primary card with a second Monthly Capacity line, reserve **one visually empty, noninteractive alignment row** on the monthly card so their **progress bars line up**. When there is only a monthly card (or no comparison peer requiring the additional row), omit the empty row. Preserve responsive and secondary-quota layouts. All future deliberate exceptions need explicit owner approval.

No changes are requested to the CCost numerical display in the Watch prompt row, original I+E accounting, source attribution, native quota balances, full Token Mix page, **separately compact Mini Watch layout**, or per-prompt Token Mix column.

## Confirmed code findings and boundaries

### Watch heading help, row cells and Today summary

- `src/web/assets/watch.js::columns` presently contains **the exact unnecessary CCost heading sentence and last paragraph**. The Model heading has two bullets and currently says only that linked subagents may use other models, without describing the Model-cell hover/focus mechanism.
- The same file's row rendering obtains the Model value via `display(prompt, 'model_detail_help')` and CCost value via `display(prompt, 'cost_detail_help')` using shared `ContextHelp.value`. A model with linked subagents gains a visible `*` and an accessible label, but an empty detail-help string does not guarantee a popup. The real subagent model/effort details come from the application's canonical prepared tokens, not browser-side inference.
- `watch.js::daily()` renders `CCost Today`, `value.total`, **`value.prompt_count`**, **`Token Mix %`** and each token-category share from `value.mix`. `src/application/live_projection.py` publishes `daily_usage.prompt_count`, `prompt_count_complete`, `total`, `mix`, `day_start_ms` and the configured-local day end. This count **already means today's prompts with model activity, including activity before Watch opened**; do not relabel it as “prompts this Watch run”. Some current UI notices are derived from `value.mix`; simplify specifically token-mix notices while retaining legitimate partial **CCost** and **prompt-count completeness** warnings, unavailability and retained observation signals.
- `src/web/assets/account-cards.js::AccountCards.View` **already renders the same full-size subscription cards** on Watch (embedded by watch.js) and Accounts (embedded by app.js). Its quotaTrack() and the shared render.js::quotaHelp(quota) own primary/secondary Capacity text and help. Current CSS uses a **seven-row subgrid** for primary card alignment. Extend this shared component and its row-template/geometry for a second **visible** Monthly Capacity line and the **conditional blank primary alignment row**. Never fork into Watch-only vs Accounts-only cards or two sets of tooltip copy. Mini Watch intentionally has a separate compact presentation and is out of scope.

### Price-tier copy and grouped subagent accounting

- `src/reports/prompt_costs.py::prompt_cost_parts()` groups canonical physical model requests within a prompt by session/provider/model/variant and **`price_tier`**; `_price_tier()` formats tier text like `Default (0–272000 input tokens)` when a model has multiple price tiers. The tier remains essential to pricing correctness and to avoiding aggregation of requests with different rates.
- `src/application/prompt_costs.py::grouped_parts()` then aggregates those values into main/subagents groups keyed by **role, provider, model, variant, price tier**. It provides `agent_count` (distinct linked session IDs) and `calls` (physical model requests), plus the four category costs and subtotals. `detail_tokens()` appends the price-tier text to both the **Model** and **CCost** group headings at present. **Remove it from both *presentations* only**, keeping underlying grouping and rates intact.
- `detail_tokens()` currently exposes `model_detail_help` only if `model_count > 1`. This explains the documented **same-model linked-subagent star without popup**, even when model/effort/agent evidence is available. Change tooltip eligibility to include correctly evidenced linked subagents, while allowing a meaningful “subagent usage/model not yet recorded” qualification when links are known but usage is absent. Keep the existing multi-model, same-model, model-switch-without-agents and provider-identity semantics.
- `agent_count` and `calls` are **not the requested “Number of prompts”**. A single subagent session can issue multiple prompts/requests; one logical prompt can issue many physical requests, and the same agent may contribute via multiple tier/model groups. Introduce a deterministic source-backed distinct **subagent-prompt identity/count for each exported group** using canonical causal attribution, not `len(entries)`, `calls`, `agent_count` or row counts. Prove the mapping to actual child prompt boundaries; the current `PromptCostPart` only carries `session_id` and request-derived fields, so additional narrowly scoped evidence may be necessary. Deduplicate requests belonging to one prompt **within the group**; retain group-specific membership if one agent's separate prompts use different efforts/models/tiers. Unknown/incomplete prompt boundaries show `N/A`/qualified observed count instead of fabricated exact `0` or `1`.
- Preserve the existing maximum 24 displayed role/model/effort/tier groups, omitted-groups count, attributed known subtotals and incomplete-agent/call notes. The grouped numeric amounts and prompt-count evidence must be computed server-side; the Web should receive only allowlisted bounded fields, not raw session IDs, prompt text or request payloads.

### Period Capacity, card parity and monthly-equivalent comparisons

- **Same shared cards on both routes, by default:** Both Watch and Accounts use the same AccountCards subscription renderer over the same canonical Live account/quota DTO. Ensure the period Capacity line, additional Monthly Capacity, secondary quota rows, tooltip content, source warnings, controls, units and ARIA are identical with identical inputs. Normal surrounding page content and initial loading feedback may differ. This default extends to future surfaces displaying the **same full-size subscription cards** unless the owner expressly authorizes a different card contract.
- **Display factual period names:** Use normalized quota metadata (period, duration_seconds and verified monthly window), not arbitrary provider-label guessing. An actual monthly quota reads **Monthly Capacity**; verified 18,000-second / 5-hour quota reads **5-hour Capacity**; verified seven-day quota reads **Weekly Capacity**. Apply to all primary/secondary quotas on Watch and Accounts. A quota of unknown period uses the honest generic **Capacity** label rather than a guessed duration. The existing capacity *value*, including its per-window (guesstimate) flag for a native-percent extrapolation, is unchanged.
- **Visible secondary monthly-equivalent line:** For **each nonmonthly quota**, insert **Monthly Capacity** immediately after its own period Capacity line and before its own usage progress track, in the card itself — **not just in the tooltip**. It uses the existing reference CCost basis. Monthly native quotas do not get a redundant second line. If a nonmonthly window is known but the CCost-equivalent capacity is unprovable, show **Monthly Capacity: N/A** with a short honest tooltip reason. The existing contextual help on Capacity should explain both figures and which one is native or estimated; no extra visible help icon.
- **One comparison standard:** For a source-verified nonmonthly full-window duration D seconds and independently valid same-window reference CCost Capacity C, calculate **Monthly Capacity (30-day guesstimate) = C × (30 × 24 × 3600) / D** in Python using unrounded Decimal, with normal Credits/USD formatting applied only at the display boundary. 5-hour example: **C = 1,000 CCost → 144,000 CCost per standardized 30 days (guesstimate)**. A seven-day weekly quota scales by **30/7**. The standardized 30 days, rather than the actual current month's 28/29/30/31 days, keeps plans directly comparable.
- **What it does not mean:** The estimate assumes each period could theoretically be used repeatedly at full capacity for 30 days. It is **not** a native monthly entitlement, invoice, spending forecast or proof that rolling windows refill independently. A five-hour quota may be constrained by an additional weekly quota. **Show both separate monthly equivalents** so the user can compare the restrictions; never add them together or imply the larger figure is actually attainable. The model/account scope of a secondary quota still matters.
- **Per-period Capacity provenance:** quota_ccost_tokens() currently distinguishes a compatible provider-reported **native monthly reference limit** from a **ratio-based reference estimate** (same-window Used CCost divided by native fraction used) and **unknown/unlimited**. Preserve these distinctions and all existing Used/Remaining, native fractions, source status, reset times and warnings. A fixed weekly quota with **truly verified reference CCost capacity** also gets a monthly extrapolation, always marked guesstimate even when the weekly figure itself is exact. **Do not equate other native credit units, token limits, request limits or billing money with reference CCost** simply because a unit name looks similar.
- **Trust and completeness:** The 30-day value requires a verified full duration (not time remaining to reset), current compatible source, unexpired window, coherent quota fractions and valid CCost conversion; for unlimited, stale/unavailable, incomplete priced usage, contradictory native data, missing/zero duration, inactive/unknown rolling window or uncertain recurrence it must be **N/A rather than numeric fabrication**. Reset-only evidence does not establish a full period. Monthly quotas retain the one real/original Capacity line; that value may still be a guesstimate if originally ratio-derived.
- **Align progress bars only when necessary:** The existing CSS primary-card subgrid uses an explicit row span. Update it to accommodate the **monthly-equivalent row** and a **conditional empty spacer** on native-monthly primary cards **when a peer primary card in the same visible comparison group uses the extra Monthly Capacity line**. The spacer is aria-hidden, non-focusable, not tooltipable and contains no false value. If only one monthly card exists, or no primary card requires an extra line, remove the spacer/track and restore compact height. Dynamically re-evaluate when cards enter/leave, window size changes or source quota periods change; preserve aligned progress and coherent reset/secondary group geometry. Secondary quotas each use their own real monthly-equivalent line if nonmonthly; **do not fill all other cards with artificial secondary quotas**.
- **No duplication:** Use one backend source of Decimal/display tokens and one shared full-size component. The Accounts and Watch card output should be structurally equivalent, not merely visually similar. Keep Mini Watch's deliberately compact subscription help and format unchanged unless separately requested.
