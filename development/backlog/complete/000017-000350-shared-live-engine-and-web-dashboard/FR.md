# FR 000350 — Shared live engine and SSE-backed global Web dashboard

## Outcome and dependencies

After FR000310 and FR000340, make the Web Live page genuinely live through one application-owned acquisition engine. Reuse existing Watch lifecycle/source/account logic without putting a new WatchCoordinator in every HTTP request or browser tab. Follow FR000290/PLAN.md. Stable CLI Watch must retain its existing behavior and remain independent of the Web process.

## Required behavior

1. Extract the smallest presentation-independent orchestration seam from `src/watch/coordinator.py` and related owners. Publish immutable results/status rather than invoking terminal rendering from the shared engine. Retain V1 revision gating, V2 live hints plus authoritative rehydration/resync, existing cadence, lifecycle evidence, pricing/account freshness and bounded worker ownership. Hints are not usage; network loss and idle status do not prove prompt completion.
2. One Web process owns one source-selection/lifecycle and account scheduling policy. Tabs and routes subscribe to projections, not separate provider refresh loops. A second tab with the same scope must not double source reads, quota calls or run totals. Adding a different session scope may legitimately require that tree's acquisition. Shared mutable clocks/snapshots and one-shot report cleanup remain under FR000290's ownership model.
3. Use normal authenticated HTTP for snapshots/commands plus one multiplexed SSE connection per tab for view updates, progress and source/runtime status. Each stream has application-instance identity and monotonically ordered update identifiers. Bound queues/replay retention; a slow or disconnected consumer cannot block acquisition or grow memory indefinitely. If replay cannot cover a gap, signal resync and fetch authoritative state, not an invented continuation. Publish coherent row/total updates; duplicates, older events and old-instance events must not corrupt the view.
4. Keep browser authentication on the same-origin session, not reusable control secrets in EventSource query strings. Heartbeats/reconnect have bounded behavior. A new server instance requires compatible reinitialization and fresh authorization as necessary; do not reuse stale credentials silently. A terminal `source_changed`/shutdown notification stops automatic retry where received and explains that the launcher must be run again. Lost connections remain visibly offline; the browser never starts a server or assumes an unknown disconnect was a code update.
5. Deliver the global Live view with the existing global Watch metrics, grouping, lifecycle/abort/error semantics, tool/skill activity, context warnings, configured row retention, quota freshness and Today accounting. Web styling/navigation may differ; semantic scopes may not silently change. Clearly label the run total's origin: in Web it starts when the single Web live engine starts, not whenever a tab opens. Existing CLI run totals still start with that CLI run. Normal account month figures stay distinct from Watch rolling/day figures.
6. Keep one live runtime alive while the host runs, including when tabs are closed, using existing bounded idle cadence. Reopening the page observes that runtime rather than resetting it. Expensive finite reports are queued/sliced with source timeouts and fair scheduling so they do not starve live publication, control or quota work. Preserve selected source and reconnect classifications; do not silently merge V1/V2 histories or launch recurring helper subprocesses.
7. CLI's source/account/cache and error contracts are protected. Refactor adapters to share mechanisms, not to force CLI through Web authentication, optional packages, HTTP or GUI. Do not make per-process observations into a persistent billing/history ledger.

## Acceptance

Compare global Web and CLI projections on identical synthetic snapshots, catalogs, clocks and equivalent run scopes. Cover active-to-terminal transitions, compaction, errors/aborts, background work, midnight/DST, partial pricing, quota staleness and source recovery. Two equivalent tabs must produce one acquisition cadence and consistent values; reconnect/replay/resync must neither duplicate requests nor reset run totals. Test slow consumers, bounded queue overflow, old-instance updates, account-only changes and a heavy report running beside live work. Confirm the stop/control path remains responsive and all owned workers close.

Use the existing Watch/source/account fixtures and focused UI/transport tests; no permanent new release gate. Session detail's uncapped logical history and scroll behavior are delivered separately in FR000360, not by widening global retention. SSE reference: https://html.spec.whatwg.org/multipage/server-sent-events.html .
