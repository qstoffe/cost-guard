# FR 000628 — Explain unavailable CCost with reason-specific value tooltips

**Owner-approved Ready Feature Request; revised scope 2026-11-07.** Permanent identity **000628**, unchanged Ready priority **000560** (after FR000625 at 000520, before FR000626 at 000620 and FR000627 at 000720). **This revision completely supersedes the original Claude Agent valuation/repair request.** The present transaction is backlog-documentation-only: no implementation, live tests, product/version changes or interference with the already-selected FR000624.

## Owner observation and corrected decision

Cost Guard displayed **N/A / Not Applicable** for the reference **CCost** of some OpenCode Toolkit live-test sessions while their prompts, duration, context and model-call counts were available. The owner has now identified the upstream test-configuration mistake: those tests ran **Claude Sonnet 4**, not the intended newer model, and that older model does **not have a usable reference price in Cost Guard's currently acquired GitHub Copilot price list**. The resulting unpriced CCost is therefore **expected**, not proof of a Cost Guard valuation bug. The wrong model selection is being resolved separately in OpenCode Toolkit.

The original FR demanded making these sessions priceable, changing model identity resolution and repricing history. **Withdraw all of that original work.** Do **not** introduce alternative price sources, fuzzy aliases, speculative retired-model rates, provider-specific hacks, upstream SDK changes, retroactive repricing or a general Claude Agent fix under this FR.

The actual desired improvement is a **clear, concise tooltip directly on a displayed CCost `N/A`**, explaining **why that particular value cannot be calculated**. The owner should be able to understand the same situation immediately without having to investigate whether Cost Guard, a provider, or the model selection failed.

## Desired user experience

1. In **Cost Guard Web** and **Mini Watch**, whenever an *actual reference-CCost value* is displayed as **`N/A` because observed usage cannot be valued**, make the **visible N/A value itself** the tooltip target using the existing shared `ContextHelp` interaction. Cover the meaningful CCost cells on Full Watch (running/earlier prompts and session/day totals), Mini Watch (prompt and parenthesized session total), Sessions list/detail, and other existing user-facing Web CCost values with the same state. Review scope-specific implementations; do not attach one irrelevant generic popup to all N/A strings. Exclude non-CCost metrics (e.g. unavailable context, quota, model, effort or actual billed spend).
2. **Tell the user the actual known reason, rather than restating that N/A means unavailable.** For a verified missing model-price match, include the affected model name and the source of reference rates. Example *only when supported by the acquired price evidence*:

   > CCost can't be calculated: Claude Sonnet 4 has no price in the available GitHub Copilot model price list. N/A does not mean zero cost.

   Prefer short plain-English language and the original currently rendered UI language. One concise explanation suffices; no lengthy pricing/legal boilerplate.
3. Different causes must yield **different accurate explanations**, using existing source/pricing/valuation evidence or a narrowly scoped, typed diagnostic derived at the existing analysis boundary:
   - **Model absent from the verified available price catalog:** say the model (if safely known) has **no listed reference price in the available GitHub Copilot list**. The owner-observed Claude Sonnet 4 case must be covered.
   - **Model identity cannot safely match a price** (missing, ambiguous or unrecognized model/version/variant): say the model could not be matched to a verified price; **do not falsely claim GitHub omits it** when only lookup/identity is uncertain.
   - **Model found, but a required category/tier rate is missing:** explain that a needed price/rate is unavailable; don't pretend the whole model is absent.
   - **Usage/token evidence missing or unsupported:** state which required usage information cannot be established when known. Do not attribute it to price-list omission.
   - **Catalog temporarily unavailable, failed or not yet acquired:** explain the price data cannot currently be checked; don't claim definitive list absence or turn genuinely pending data into terminal N/A.
   - **Mixed-priceable scopes:** if the display is truly N/A, explain the unsupported calls; if a known priced subtotal is displayed with an existing partial marker, keep that subtotal and qualifier rather than replacing it with N/A. Scope-specific help may note which calls/models are unpriced.
   - **Insufficient proof to classify a more specific reason:** give a truthful fallback, e.g. “CCost cannot be calculated from the available model pricing and usage information.” Never invent a precise failure.
4. A combined prompt/session may contain **multiple models and subagents**. An N/A tooltip must not blame only the visible/main model when the actual unpriceable request came from a different contributing model. Name the correct affected model(s) if the canonical request evidence supports it; otherwise use neutral scope-level wording. Keep detailed model lists bounded, deterministic, and privacy-safe. For Mini paired `prompt CCost (session CCost)`, distinguish the specific unavailable component if only one is N/A and preserve the useful existing Mini prompt-details tooltip; do not collapse or overwrite the other component's explanation.
5. **Reuse existing contextual help.** `src/web/assets/help.js` and `development/architecture/modules/web-help.md` own value-sized hover targets, 600ms pointer delay, immediate keyboard focus/tap help, Escape and dismissal, retained DOM, accessibility, and Mini's separate PiP document. Integrate the new reason into the applicable **existing cost-value help**, including Full Watch's rich CCost breakdown and Mini's compact prompt details; don't stack competing popovers, add standalone `?` icons, native `title` attributes, dotted underlines, new permanent warning text, extra columns or large hover hit areas.
6. Preserve live/revision/unit behavior. When a value changes from pending to N/A, N/A to a known/partial cost, or one unavailable reason to another after a verified price refresh, its tooltip must reflect the **same current data snapshot** as the displayed value. Credits/USD display changes, historical/retained values, Live rerenders, session switching and Mini opening/closing must not cause stale explanations, focus churn or additional price/source acquisition.
7. Keep **visible CCost semantics unchanged**. Positive computed reference CCost remains a reference valuation rather than actual billed spend; `0` is not the same as N/A; a priceable partial subtotal retains its `?` or other existing scope-specific presentation; no model rate is fabricated. This FR changes **only explanatory presentation and the smallest safe diagnostic data needed to support it**, not source interpretation, valuation, accounting, provider billing, subscription quotas, pricing catalog rules, defaults or the model selection.
8. **Respect existing tooltip decisions:** FR000582/FR000590/FR000601/FR000621 prefer meaningful contextual help, not popups on every generic N/A. This FR expressly authorizes a reason-specific tooltip **only for unavailable CCost values**, superseding their generic no-tautology guidance for that case. FR000627 will remove passive *daily partial-warning text*; the new hover explanation on a genuinely **N/A daily CCost** must not reintroduce warnings/icons or tooltips on ordinary positive partial daily amounts.

## Implementation notes, bounded scope

- Candidate owners: `src/pricing/catalog.py` and `src/analysis/valuation.py` can distinguish a missing resolvable reference model, absent selected tier/rate and token availability; canonical request/group projections and `src/application/display.py` can expose a small **allowlisted reason code and safe model label(s)** to the browser without making pricing decisions in JavaScript.
- `src/application/prompt_costs.py::cost_detail` currently has generic wording for zero priced requests (“no reference price for recorded usage”), even though missing usage evidence can be a separate cause. Reuse/adjust this only as warranted by proven reason codes.
- Existing `ContextHelp.value`, `ContextHelp.refresh`, Full Watch row cost details and Mini's `promptDetails` should be extended rather than replaced. Avoid per-row network requests, duplicate model-price lookups on hover, raw provider payloads/errors, long prompt/session content or a new tooltip framework.
- A presentation-only reason must be derived from trustworthy **already-observed** data. If a price snapshot is stale/failed/ambiguous, qualify the diagnosis rather than claiming “not listed.” Avoid introducing a persisted diagnostic ledger, a broad global status framework or new load/performance regression.
- Keep this FR independent of FR000624 performance and FR000625 Web default USD change; preserve their selected work, behavior and scope.

## Acceptance

1. A deterministic case with positive observed Claude Sonnet 4 usage and an acquired reference catalog **without a matching model rate** still displays **CCost N/A**, but hovering/focusing/tapping that **specific cost value** explains **Claude Sonnet 4 is not in the available GitHub Copilot price list**. No made-up number and no provider repair.
2. Other fixtures verify **unmatched model identity**, **missing rate/tier**, **missing tokens**, **temporarily unavailable catalog**, **insufficient evidence**, **multiple contributing models**, **one priced plus one unpriced request**, **verified zero usage**, **known cost** and **genuinely pending loading**. The tooltip must never misattribute an unsupported request or collapse distinct causes into the “model absent from Copilot” claim.
3. The same reason/semantics remain correct across a representative Full Watch prompt, Mini Watch prompt-and-session pair, Sessions list/detail and other N/A CCost presentations where the data are supported. Existing rich breakdown/help for valid costs remains intact. Check chronological revisions, history reentry and Live updates; unit switching must not alter reason.
4. Existing help UX passes actual hover, keyboard focus, touch/tap, Escape and PiP cases; target is the **text N/A**, accessible and selectable, without new buttons or intrusive banners. Use appropriate existing targeted Python/Node/Web fixtures and the repository's normal applicable implementation checks. No paid model live tests or new universal gate.
5. Delivery explains the diagnostic classification boundary and records any case where a **specific** cause cannot be proven. It must not claim the original Claude Agent model-selection bug was fixed by this UI change.
