# FR 000612 — AI Stats: consistent selected-period hover and honest All Time metric states

**Owner-approved Ready Feature Request, 2026-11-06.** Permanent identity **000612**; Ready queue priority **000300**, after existing FR000611 (000290). **Backlog authoring only:** this publication must not implement code, run product checks, change the product version, or alter unrelated backlog items.

## Owner report and intended outcome

On Web Beta **AI Stats**, the five period buttons should have the same reliable appearance when hovered, focused and selected. **Today**, **7 days** and **30 days** look normal, but on selected **This month** or **All time** the button's label visually disappears when hovered. These two also feel different from the other period controls.

Separately, after selecting **All time**, some metric cards show **`Unavailable`** accompanied by the generic playful line **`The evidence is still in the vault.`** (the owner observed this as a confusing evidence/unavailable message). The page does not make clear whether this means *still loading*, *history incomplete*, *not enough activity*, or *genuinely impossible to calculate*. This is especially puzzling if another period yields values.

**Deliver** (1) consistent readable selected/hover/focus behavior for every period button, retaining useful explanatory help; and (2) distinct, accurate and accessible **Loading / Partial / Unavailable / No data** states, with metric-specific plain-language reasons where a value is not available. Do not label a finished unsuccessful/incomplete calculation **Loading** indefinitely, invent missing historical evidence or show falsely exact numbers.

## Confirmed code findings: period-button hover

- `src/web/assets/ai-stats.js::View` creates the five period buttons, but only **`month`** and **`all`** call `ContextHelp.heading(button, ...)` to provide scope explanations. In `src/web/assets/help.js`, `heading()` wraps their text in an inner `span.help-label` and gives the parent the `help-action` class; Today/7 days/30 days remain plain-text buttons.
- `src/web/assets/app.css` sets the selected button to **`background: var(--accent); color: var(--accent-ink)`** through `.ai-stats-periods [aria-pressed="true"]`. The global `.help-label:hover { color: var(--accent); }` then overrides the inner label's foreground **on the two help-enabled buttons**. On a selected button this makes the text the same color as its accent background, so it apparently vanishes. This explains the reported discrepancy from the current CSS and DOM structure; validate the computed colors in an actual browser.
- Fix the **color-contrast interaction at the appropriate shared/component boundary**, not by disabling these two buttons' useful hover/focus/touch explanations or introducing a different selected style. All five should retain the same visible selected-state appearance and pointer/keyboard behavior. If their contextual help differs in content, the basic button label must never disappear.

## Confirmed code findings: `Unavailable` / evidence text

- `src/web/assets/app.js::selectStats()` requests `stats_scope='all'` for All time (and `month` for This month), while initial 30-day evidence covers the smaller periods; broader scopes intentionally extend history lazily through `src/reports/ai_stats.py::build_ai_stats()`. Before the requested period result arrives, `ai-stats.js::View.update()` already has an acquisition/waiting state. A returned period result is not automatically complete proof for *every* individual metric.
- `src/analysis/ai_stats.py::period_stats()` returns per-metric `value` and `status` with causes that can vary by metric. **Unknown interval duration** and **incomplete source coverage** make some aggregate timing values unprovable (`_timing()`, `_time_metrics()`); **missing prices/token-category evidence**, pending unpriced work or source gaps can leave cost-derived results partial or null. A **genuinely empty but completely observed period** is another case (e.g. no denominator for rate/average), distinct from failed coverage. All time may encounter older/archived records with evidence gaps absent in shorter windows. Do not assume any one of these causes was proven for the owner's particular All time run; reproduce and classify it.
- `src/application/ai_stats.py::stat_tokens()` displays **`Unavailable` whenever `value is None`**, and displays the stock line **`The evidence is still in the vault.`** whenever the value is null **or `status == 'partial'`**, even if a partial numerical value exists. This generic text explains none of the reasons. `src/web/assets/ai-stats.js` renders `metric.display.value`, `metric.display.trait` and a terse `metric.status`, but each heading's current ContextHelp is a *static metric definition*, not an explanation of the actual current period's missing evidence.
- `src/application/projection.py` currently transports `metric value status session_id session_title detail`; if actual cause codes need exposing, add a minimal **source-derived, allowlisted reason/coverage signal** through canonical analysis/projection/display layers rather than fabricating causes from JavaScript, parsing free-text errors or exposing raw source/private prompt material.

## Requirements — consistent period selectors

1. **All five buttons**, selected and unselected, keep legible text on hover, focus, press and pointer departure in **Classic, Web light and Web dark**. Use correct selected text/background contrast; fix the nested `.help-label` styling without altering selected-period semantics. No temporary disappearance, invisible text or misleading hover style even when a tooltip is visible.
2. Preserve the period explanations for **This month** (configured-local calendar-month start through observation) and **All time** (all available recorded history, with missing/deleted-history limitations) through the shared `ContextHelp` hover delay, keyboard focus and touch activation. Selected button can still be hovered/focused and explained; hover must not accidentally trigger another period acquisition. Avoid duplicate native `title` tooltips or new layout shifts.
3. Keep button geometry, labels, `aria-pressed`, focus indication, accessibility, active period, automatic navigation and period switching unchanged beyond the visual fix. Scope the color correction to AI Stats selectors if a global help-style change would cause regressions elsewhere.

## Requirements — truthful All time and other-period metric states

1. **While work is actually running or waiting:** show a clear **Loading** state for the requested not-yet-available scope (or shared FR000609 centered progress/status). Preserve previously completed useful data for another period and accurate active selection. Do not prematurely fill empty cards with `Unavailable`, pretend a stale result is current, or display a completed `100%` for a scope whose job has not finished. Cancellation, timeout, source/host failures and retry follow the shared finite-job lifecycle.
2. **After a coherent result is received:** classify each metric from actual evidence into meaningful states:
   - **Complete**: show supported numeric/date/session outcome.
   - **Partial / provisional**: show supported observed/qualified information and clear limitations without implying full coverage or precision; preserve existing canonical partial-cost/unknown semantics.
   - **No data / not applicable**: when *complete, genuinely empty* period evidence or a mathematically absent denominator means the particular statistic cannot be defined. Do not equate no observations with failure, and preserve real zero where semantically correct.
   - **Unavailable**: when needed source, timestamps, price/usage evidence or trustworthy completeness cannot be established, or a genuine terminal failure remains. Explain which type of evidence/condition prevents the metric; never say **Loading** once no acquisition is pending.
3. **Explain reasons beside the affected card.** Prefer concise, understandable in-card status or detail plus a metric-specific `ContextHelp` description accessible via hover, focus and touch. Examples of *conditional explanations only when actually evidenced*: **“Some historical executions have unknown end times; the full working-time total cannot be verified”**, **“Historical source coverage is incomplete”**, **“Reference prices are missing for some requests”**, or **“No completed executions in this period”**. When the cause is not known, explicitly say so rather than attributing it to a guessed server issue. Clarify that `All time` means **all available recorded history**, not guaranteed complete lifetime history.
4. Replace the uninformative **`The evidence is still in the vault.`** fallback **for missing/partial states** with useful status-related language; retain the playful trait copy for *supported real values*. A partially supported number must not get a cheerful complete-data claim or a generic line that implies it is merely loading. If an explanation is too long for a card, show a short reason and additional help without crowding/overlapping content.
5. **Do not “fix” `Unavailable` by guessing a 0, assuming old events ended, dropping failed/archived records, using later prompts as substitutes, fabricating source completeness, or relaxing the existing price/time/coverage checks.** Investigate whether current null results are conservatively correct, overly broad invalidation, or a distinct bug with a warranted focused calculation correction. If a correct calculation is possible using already available canonical evidence, repair it with targeted tests; otherwise improve provenance/UX and retain honest unknowns.
6. Maintain period window definitions, Stockholm/local calendar and DST handling, source V1/V2 boundaries, revisions, stable 30-day/This month/All time cache/coalescing, AI Stats' ten original metric cards and optional matched-input fact. Do not trigger a separate full Comparisons scan, new paid model requests or unnecessary background acquisitions. Retain selected period/scroll/focus during quiet refresh and coherent updates.
