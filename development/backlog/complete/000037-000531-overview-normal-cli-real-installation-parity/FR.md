# FR 000531 — Make Web Overview a complete, verified mirror of the CLI Normal report

## Owner-observed regression (2026-10-28)

The Web Beta Overview does **not** show the same information as `python cost-guard.py` (the default CLI Normal report) on the owner's running OpenCode Desktop/V2 installation. In particular, the model comparison table does not appear to list all models that the CLI lists. The owner expects every CLI Normal section, row and meaningful explanatory/warning line to be represented **on Overview itself**, not lost or only available by visiting a different Web route. The model table should have the **exact same row membership, order and displayed column values** as CLI Normal for equivalent input, and be immediately recognizable in structure and visual hierarchy.

This is a reported real-installation failure despite completed FR000430 (shared display tokens), FR000450 (Overview/CLI parity), and other completed Web parity work. The FR000450 proof relied in part on synthetic canonical DTOs and a 5-model sample; it does not establish completeness on the owner's actual installation. The shared Web table component currently paginates with `size = 50` and renders a `slice` of rows. That is one **candidate cause of rows appearing to be missing**, not an established explanation for all discrepancies. An upstream catalog/source mismatch, implicit filters, report-scope differences, DTO loss, unstable ordering or table scrolling could also be involved.

## Required result

- Treat the **actual default CLI Normal report** as the authoritative reference for the Overview page at the same Cost Guard revision, OpenCode source/configuration, model catalog, observation window and report scope. First inventory all its top-level sections, summary/definition lines, model table columns/rows, notes, promotions/new-model notices, account/quota/billing observations and partial/unknown/warning states; build an explicit CLI-line/section → Overview-element parity checklist. All materially meaningful CLI Normal information must be present somewhere **within Overview** (inline or in clearly discoverable details for secondary prose), not silently removed, substituted, or delegated to Models/Accounts.
- **Model table is the immediate primary failure:** show every model row belonging to the CLI Normal comparison, in the same default reference ranking, with the same publisher/model identity and rendered Relative CCost, context-tier arrows/thresholds, release date, markers and unknown/partial semantics. Do not confuse CLI Normal's selectable/reference set with the separately requested all-models catalog. Do not use implicit browser filters, result caps, hidden page states or a default 50-row slice that makes the Overview table appear incomplete. The full Normal table should be accessible as one coherent table by default, with practical scrolling and no user action required to reveal otherwise-omitted model entries; preserve readable columns at narrow widths. Existing paging on **unrelated** Sessions/large-history tables need not change.
- Match the CLI's **information hierarchy and table appearance** as closely as sensible in a modern browser: headings/section order, column order, aligned values, separators/grouping, notices, distinguishable status colors and compactness. This is semantic and visual parity, **not** a literal ANSI/terminal-width pixel copy. The owner should be able to compare the two presentations without hunting across routes. Default sorting matches CLI; explicit browser sorts/filters may be offered but must be reversible, conspicuous and never rewrite canonical row totals.
- Investigate differences **at every boundary**: actual V2 source selection; CLI vs Web report request and sampled scope; pricing/model catalog and selectable models; report projection; serialized DTO/size limits; browser route/state; filtering, 50-row rendering/paging, CSS clipping and scroll. Fix the proven cause(s), not just a cosmetic label or a fixture that happens to pass. Never invent missing catalog rows, fabricate pricing or silently broaden the CLI's model selection. If a legitimate temporal difference exists between separately acquired snapshots, identify it explicitly and prove deterministic same-input parity.
- Preserve source read-only behavior, running/live vs frozen-report boundaries, quota/account native meaning, privacy of actual installation data, existing pricing/attribution semantics and Web security. Keep this FR focused on **Overview**; other page-specific parity tasks are out of scope and can be raised separately after the Overview comparison is proven.

Run the real CLI Normal report (default `python cost-guard.py` or its supported OS launcher), preserving its complete output privately for comparison. Start the normal Cost Guard Web Beta host/launcher against the same installation and open **Overview** in the real browser. Do not launch paid model inference, alter OpenCode history, terminate an unrelated shared OpenCode instance or publish real user/account data in Git.
2. Record revision, effective source selection, relevant config/catalog version, refresh/snapshot times and whether data changed during capture. Compare CLI output **line-by-line/section-by-section** to actual Web content; compare model rows by stable publisher+model identity, count, order, column value and notices. Check the browser's full data/DOM, filter defaults, row count, scrollable portion and any pagination; explicitly report if CLI has more than 50 model rows. Use sanitized counts, focused examples and local/private evidence instead of uploading tokens, prompts, credentials or raw personal history.
3. If independent acquisitions move during the comparison, capture/freeze equivalent normalized input or repeat with a stable acquisition and compare the same canonical projection in CLI and browser. A difference in acquisition time is **not** permission to waive a missing-row or display-data bug.
4. Re-test in a real browser after repair (desktop and narrow window, usable mouse/keyboard scrolling). Capture a concise parity matrix and any genuine limitations. Synthetic/unit tests are supplemental; **do not mark this FR complete on fixture-only parity** or on the assertion that both use a shared DTO.

## Acceptance / regression proof

- With matching inputs: CLI Normal vs Overview has **identical model row count, ordered model identities, columns and canonical display values**, including **more than 50 models** if the tested source exposes them; no silent truncation or hidden default page/filter. All CLI Normal sections and material notes/warnings/definitions are present on Overview with intelligible placement and the same status/unknown meaning.
- Focused deterministic regression tests cover 0, 1, 49, **50, 51, 100+** models, duplicate model names across publishers, catalog fallback/unverified availability, tier transitions, promotions, no priced sample, unknown prices, all CLI notes and multiple account states. Assert actual **rendered DOM** row membership/order and usable list navigation, not only a Python projection or raw JSON array.
- Real local OpenCode V2 + CLI + running Web host + actual browser parity is demonstrated with sanitized recorded evidence; any unavailable desktop proof is explicitly recorded as **not verified**, not replaced by synthetic PASS. No pricing/provider-history mutations or changes to the CLI Normal report merely to make Web tests pass.
