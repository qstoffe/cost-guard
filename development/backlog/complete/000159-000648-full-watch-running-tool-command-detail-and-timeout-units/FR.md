# FR 000648 — Full Web Watch: show useful native running-tool commands and labeled timeouts

**Owner-approved Ready Feature Request / targeted correction, 2026-11-09.** Permanent ID **000648**; temporary Ready priority **000830**, after the two currently Ready FRs FR000646 (000810) and FR000647 (000820); FR000645 had already moved to Complete. **Authoring only:** add this FR and update backlog highWatermark **647 → 648** on current main; no executable code/tests/docs, release/version, settings or unrelated FR changes in this commit.

## Owner observation, concern, and desired outcome

On **Cost Guard Web → Full Watch → Running Prompts**, a long-running tool appears in yellow as **Running: shell ...**, and expanding its details often shows little useful content, with a generic notice similar to:

    Limited source input: sensitive, unsupported or oversized fields omitted.
    Not the complete invocation.

In **OpenCode Desktop**, expanding the same shell tool usually reveals the invoked executable, e.g. **python.exe**, the actual Python script path and command-line arguments. The user wants essentially that same practical **source-observed invocation** in Cost Guard's **already-collapsed-by-default** Running disclosure. It is frustrating when ordinary local Python commands are hidden or misleadingly described as "sensitive"; the data may be available, but a conservative filtering rule can remove it.

The user also likes the currently exposed **timeout** parameter, but a raw number without a unit is unclear. For supported OpenCode **shell/bash** tool input, timeout numbers mean **milliseconds**. Show that explicitly, optionally with a friendlier duration in parentheses, while retaining the raw meaning.

**Desired visible example (entirely synthetic and not a capture of any personal command):**

    Running: shell 37s                   [collapsed by default]
      command:
      "C:\Python313\python.exe" "D:\dev\tools\scripts\inspect.py" --mode=fast --limit=25

      workdir: D:\dev\project
      background: false
      timeout: 120000 ms (2 min)

An ordinary source command with an option like **--mode=fast**, a benign script name containing **token**, or a harmless **NAME=value** assignment must not be rejected wholesale as though it contained a credential. Preserve the original command's argument order, quoting, spaces, line breaks, executable, script and supported options. This is read-only display, not executing anything.

## Source findings: actual filtering problem, not proof the command is unavailable

1. Completed **FR000632** introduced the expanded Full Watch invocation and consistent yellow Running colors, intentionally using a tightly bounded, allowlisted, privacy-filtered server-side copy. Its completion confirms delivery and explains why the UI can show limited input. This new owner request **refines that earlier policy**: the goal of seeing real command and arguments was already approved but the implementation is overly restrictive in ordinary cases.
2. **src/watch/tool_contracts.py::tool_input()** reads the already-normalized **state.input** or legacy **input**; **src/watch/tools.py::observe_tools()** selects the real physical running call after the existing 10-second threshold and binds optional invocation to that call. **src/application/live_projection.py** passes bounded **identity/revision/text/qualification** to the browser. Thus there is already a source-proven path; this is primarily **server-side invocation extraction/filtering/presentation**, not a need to launch OpenCode or collect a new session history.
3. **src/watch/invocation.py::_FIELDS** includes **command, workdir/cwd, description, background, timeout** and other scalar options, but **invocation()** evaluates **_SENSITIVE** against the *entire freeform string*. The regex includes broad word fragments such as **token** and **password**, and the pattern for **NAME=value** expressions, as well as more focused credentials, authorization headers and environment assignments. If any match is found **the entire command field is withheld**, even if the suspect part is an innocuous script name or ordinary CLI flag. **code** is categorically excluded; nested/unknown/oversized fields are also omitted.
4. The resulting single generic **"sensitive, unsupported or oversized"** qualification does not say which condition occurred or whether a secret was actually detected. **It does not prove OpenCode supplied no command, nor that a specific field contained private data.** The source might genuinely omit command input, in which case the UI must be honest about that too.
5. **src/web/assets/watch.js::drawInvocation()** already renders the Python-filtered invocation into a **preformatted, selectable text area**, preserving expanded state and DOM focus/selection during duration-only updates, and clearing on call identity/revision changes. Keep it; do not invent a new always-open display or alter current yellow Running styling.
6. **OpenCode official Tools docs**, <https://opencode.ai/docs/tools/> and its upstream documentation source at <https://github.com/anomalyco/opencode/blob/dev/services/www/src/docs/content/tools.mdx>, describe shell input as **command, workdir, timeout** (milliseconds), optional background execution and source-specific default behavior. Cost Guard's current `timeout` in the invocation is copied as an unformatted scalar with no unit. Treat **a supplied source input timeout** as the caller's configured limit; do not confuse it with elapsed **Running: 37s**, a dynamically computed remaining countdown or a proven eventual process termination. No timeout field means **not supplied**, not automatically proof of 120 seconds; actual defaults can vary by version/config/background mode.

## Requirements

### A. Native command/argument parity for supported shell-like tools

1. **Source-proven command takes priority:** for a verified currently running shell/bash/execute-like physical call whose recognized native `state.input.command` is a bounded string, the expanded details must show **the actual recorded command including executable, script path, quoting, flags, equal-sign assignments and ordered arguments**. No re-parsing/reconstruction from the human `description` or tool name. Preserve multiline commands exactly in the read-only selectable preformatted text.
2. **Fix broad false positives.** Ordinary Python invocations (absolute executable path + script + arguments), plain flags **--mode=fast**, **--limit=25**, harmless **FOO=development**, and benign filenames such as **tokenizer.py** must no longer cause the **whole command** to disappear simply because an unrestricted regex matched an English substring or any equals sign. A command can be marked sensitive **only when a credible secret-bearing input is present**, not on generic equality/word matches alone.
3. **Targeted treatment of actual secrets:** prioritize faithfully showing the **nonsecret command portion** over withholding the entire invocation. When actual credential material or an evidently sensitive option/value is recognized, mask/omit the **specific sensitive value/argument** if safely possible (e.g. **--api-key=[redacted]**) while preserving useful executable/script/other flags and an explicit **redaction note**. If individual-value masking is not dependable for the given shell syntax, fall back to safe limited disclosure with the **specific reason**, rather than printing a credential or pretending the entire line is complete. Never forward raw environment blocks, bearer tokens, authentication headers, cookies, private keys or arbitrary tool outputs merely to achieve UI parity.
4. **Scoped source-native behavior:** only disclose what is already present in the source for **that selected physical tool call** and its canonical prompt/child scope. Do not borrow another running tool's command, reconstruct a missing command from logs, infer it from a file path/description, or show stale contents from another source generation. Retained/unverified/terminal captures still suppress claims of current execution.
5. For **other tool types** (grep, read, etc.), retain already supported named input parameters with current truthfulness/size constraints. When a clearly benign scalar supported source field can be shown without exposing arbitrary nested/file content, consider it; do not turn a JSON body/script/content field into a shell command. The main acceptance target is **shell with Python executable + script + arguments**, not displaying every native tool's unlimited metadata.

### B. Informative omission instead of a blanket scare message

6. Replace the blanket **"sensitive, unsupported or oversized"** qualification with **accurate, brief, cause-specific status**. Distinguish at least:
   - **Complete observed command/input** (no false limited notice);
   - **Specific sensitive argument/value redacted** (identify the presence and scope of redaction, **never the secret**);
   - **Unsupported/structured/content-bearing field omitted** (which class of input, with no false secret assertion);
   - **Oversized command/field omitted or visibly truncated** (explicitly not complete, with a bounded useful safe prefix only when justified);
   - **No source command/input available** (source fact absent rather than filtered).
   Do not claim all three possible causes when only one occurred, or claim an input is complete if it is not. Keep copy understandable to the person operating the Watch page, not a security-policy paragraph on every normal invocation.
7. **Normal, safe command:** no extra paragraph about hypothetical sensitive fields or excessive warnings. Expanded detail should start with the actual command, readable in a few lines. Disclosure stays **collapsed by default**, protecting against accidental over-the-shoulder visibility without adding a second "reveal" switch. No need to click an additional question-mark or request a new explicit disclosure permission each time.
8. **Size and provenance:** preserve a bounded, authenticated, source-owned payload (current ~4 KiB formatted input, 2 MiB event / 8 MiB replay budgets) and current deterministic identity/revision semantics; for genuinely long invocations either show a bounded safe preview with explicit **truncation** or implement a narrow authenticated, already-observed-evidence retrieval only if necessary. Do not silently chop command arguments and label that text "complete". Don't add arbitrary raw source metadata, bulk traces, output, script file contents, new background polling, storage/logging/telemetry or model calls.

### C. Timeout units and meaning

9. For recognized OpenCode **shell** source-input `timeout` with a finite, positive numeric **millisecond** value, show the raw number **with `ms`** and optionally a human-friendly equivalent, e.g.:
   - **timeout: 1500 ms (1.5 s)**
   - **timeout: 120000 ms (2 min)**
   - **timeout: 3600000 ms (1 h)**
   Default formatting should be compact, legible and deterministic; grouping digits may follow existing UI convention. Preserve the native numeric value and precision, and never silently treat milliseconds as seconds.
10. **Timeout is the requested/configured tool limit**, not time already running or remaining. The yellow **Running: tool 37s** line retains its separate measured elapsed duration and 10-second visibility threshold. If `timeout` is genuinely absent, omit that detail or say **Timeout: not supplied**; don't invent a default of 120000 ms without supported evidence for the exact source/version/config. Do not relabel **other tool types' timeout** units without a verified schema; keep their raw documented semantics or an honest unknown unit.
11. Handle valid zero/special/native alternatives carefully: don't divide by zero, invent "unlimited" from 0, print NaN/Infinity as human durations, or mislabel a string `'120s'` as `ms` without source validation. Never change the actual timeout or how OpenCode executes/stops work; **presentation only**.

### D. Preserve existing Running UX and boundaries

12. Keep **`Running: shell <elapsed>`**, separate foreground/background rows, tool-call count/Skills/outcomes, yellow theme-aware Running color, red errors/cancellations, initially collapsed native `details` control and keyboard/mouse/touch support. No expansion fetch or OS execution is required for ordinary safe commands. The UI renders literal text, not HTML; command-looking text is **never executed by Cost Guard**.
13. For **background shell jobs**, preserve FR000632's unique original-job/physical-call identity requirement; do not show the wrong foreground command for a generic **2× shell** or a job lacking a source-proven link. When a single linked job exists, improve its displayed input on the same terms as a foreground tool.
14. Keep expansion state, text selection, focus and scroll stable over duration-only SSE updates. On changed physical call ID, accepted source revision/input correction, end/abort/host disconnect, or superseded prompt, invalidate/reset rather than continue showing a stale command. No new source access, secret persistence or broad global change to Cost Guard's CLI, Mini Watch, Sessions, billing or account UX.
15. **This FR deliberately relaxes the overbroad whole-command rejection of FR000632 for useful local authenticated display**, but **does not authorize publishing actual credentials** or weakening authentication/CSP. OpenCode's own desktop disclosure is a useful usability reference, not proof that an independently accessible Web surface must stream every unrestricted environment or secret. The owner has already chosen an intentional collapsed-on-demand UI; avoid adding redundant blanket notices for safe input.

## Acceptance and regression cases

1. **Common Windows Python invocation**: canonical running shell input includes `command = '"C:\Python313\python.exe" "D:\dev\scripts\report.py" --mode=fast --limit=25 --verbose'`, `workdir = 'D:\dev'`, `timeout = 120000`, `background = false`. The same expanded disclosure shows the **whole source command including executable/script/ordered flags**, workdir, **timeout: 120000 ms (2 min)** and background; no generic sensitive/unsupported/oversized warning. Verify any Windows backslashes are preserved, not interpreted as escaping/HTML.
2. **False-positive regression**: harmless **--mode=fast**, **NAME=development**, **tokenizer.py**, quoted paths with spaces, Unicode paths, PowerShell quoting and multiline shell commands are readable; no blanket rejection on equals signs or ordinary word fragments. If the source already lacks `command`, show a factual absence reason rather than a fake recovered invocation.
3. **Real secret case**: `--api-key=secret-value`, `Authorization: Bearer <token>`, credential-bearing URL or an explicit environment/secret field must **not expose the secret** in the command, note, displayed source input, attributes, Live DTO, diagnostics or test artifacts. Where possible **mask only the sensitive component**, retaining a useful command head and unsensitive arguments. If safe masking cannot be proved, withhold the affected input and give a specific, truthful redaction explanation. Do not mistake harmless variables/options for secrets.
4. **Omitted input categories**: unknown simple scalar, genuinely nested dictionary, freeform `code` body, oversized command and absent/invalid input get distinctly correct omitted/limited/unavailable text. Strong negative cases must not introduce raw output, tool metadata, entire environment, source paths outside the chosen call or HTML injection.
5. **Timeout data**: explicit 1500, 120000, 3600000 milliseconds format with `ms` and human-scale equivalence as desired; absent timeout does not imply a default; numeric zero/negative/non-finite/other tool schema do not get invented units or false countdown. Elapsed Running time continues increasing separately.
6. **Actual Running states**: both foreground and one unambiguously linked background shell call have the right command; unlinked or aggregated background jobs never borrow it. Same canonical physical call remains stable across Live duration updates, while revision/call changes invalidate content. Test linked subagents, a later starting running prompt, terminal clearing and retained/unverified source data.
7. **Rendered browser**: Classic/Web light/dark, desktop and 360px, Windows-style paths, long wrapped command, keyboard Enter/Space, mouse disclosure, touch, text selection, focus/scroll retention, source correction, Live replay and real running elapsed updates. No new viewport overflow, repeated disclosure collapse or general prompt/runtime regression.
8. **Performance/privacy**: verify a bounded 100-card Live publication, payload and replay budgets, source/V1/V2 normalized shapes, no raw transcript or secrets in DTO, no source query from expanding, no persistent command cache and no new AI model/OS invocation. Compare real available non-sensitive source data read-only if supported without claiming live proof from synthetic fixtures.

Update **docs/watch-activity.md**, current **docs/web-beta.md** and active Watch architecture/journal references during implementation; preserve FR000632 historical completion documents.
