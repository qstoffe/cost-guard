# FR 000650 — Promote Cost Guard Web to the default Windows/macOS product (v81.0); preserve CLI under Legacy

**Owner-approved Ready Feature Request, 2026-11-09.** New permanent identity **000650**, Ready queue priority **000850** (after the currently Ready small Web polish FRs). This FR is the **freshly approved, rewritten implementation plan derived from parked Suggestion 000390**, not a reactivation of reserved historical identity 000390. The owner now explicitly approves promotion. **FR-only publication now:** create this FR, advance `development/backlog/identity-state.json` highWatermark **649 → 650**, and annotate the old suggestion as superseded by FR000650 while preserving its original text. **Do not implement product code, tests, docs, product version, release or launcher changes during this authoring commit.**

## Product decision and goal

The Web Beta has matured enough to become **the normal Cost Guard experience** on Windows and macOS. Stop presenting Web as an optional Beta while the terminal report and CLI Watch remain the primary product.

Make the **existing secured, locally launched Cost Guard Web** the **default user-facing app**, with the same browser, Live Watch, Models, Sessions, Accounts, Token Mix, AI Stats, Comparisons and Settings. **Retain the two working CLI entry points** (normal report and terminal Watch), but move their platform launchers into **`Legacy/`** for people who need them. This is **promotion + coexistence**, **NOT deleting or disabling the CLI engine**.

The owner chose **`Legacy`** instead of `Old` or `Obsolete`: those launchers still work and are supported as compatibility/fallback tools, but are no longer the primary entry point.

Make this the next **major product generation, v81.0** (a displayable **Cost Guard v81.0**), from the current **v80.x**. **Remove the "Web Beta" label throughout the current, user-facing Web application and launch experience**. The main Web heading should show **Cost Guard** followed by its **actual running product version**, without Web/Beta descriptors, duplicate branding, a separate Beta badge or a new Settings option. Retain the useful dynamically supplied version number.

**Do not rewrite current accounting, subscriptions, request attribution, source adapters, prices, calendars, saved preferences or history merely because the primary UI moved.** The same underlying Python engine must keep serving Web and Legacy CLI.

## A. New OS launcher arrangement — exact target paths

**Desired top-level user-facing launcher structure** after implementation:

```text
windows/
  Cost-Guard-Web.cmd             ← normal/default Cost Guard application
  Legacy/
    Cost-Guard.cmd               ← old terminal Normal report, still working
    Cost-Guard-Watch.cmd         ← old terminal Watch, still working

macos/
  Cost-Guard-Web.command         ← normal/default Cost Guard application
  Legacy/
    Cost-Guard.command           ← old terminal Normal report, still working
    Cost-Guard-Watch.command     ← old terminal Watch, still working
```

1. **Move/rename rather than duplicate or change behavior:**
   - `windows/Beta/Cost-Guard-Web.cmd` → **`windows/Cost-Guard-Web.cmd`**
   - `macos/Beta/Cost-Guard-Web.command` → **`macos/Cost-Guard-Web.command`**
   - `windows/Cost-Guard.cmd` → **`windows/Legacy/Cost-Guard.cmd`**
   - `windows/Cost-Guard-Watch.cmd` → **`windows/Legacy/Cost-Guard-Watch.cmd`**
   - `macos/Cost-Guard.command` → **`macos/Legacy/Cost-Guard.command`**
   - `macos/Cost-Guard-Watch.command` → **`macos/Legacy/Cost-Guard-Watch.command`**
   The macOS AppleScript *source template* currently in `macos/Beta/launcher.applescript` must move to an appropriate non-Beta source path (e.g. **`macos/launcher.applescript`**), with the generated Finder app compiler and all fingerprints updated accordingly. **No Beta subfolder should remain necessary for the standard source checkout.**
2. Use the **existing Web launcher system** and its runtime identity, not new Web infrastructure. Windows continues its PowerShell short-lived startup/status handoff to the native tray; macOS continues its zsh → Python → in-box AppKit/macOS menu-bar flow and locally generated optional Finder app. Do not spawn a second server, wrap the CLI in Web, install dependencies, require Node/Playwright/SDK at runtime, or introduce OS login autostart.
3. **Repair relative-root path resolution after moves:** existing Windows Beta CMD resolves `../..` to repo root, but the new top-level CMD needs `..`; macOS Web `CG_ROOT` similarly changes from `../..` to `..`. Conversely moving CLI launchers into Legacy adds one parent level; Windows calls `src/windows_launcher.ps1` by an adjusted path, and macOS CLI scripts discover the root and call the correct explicit Legacy Python entry. Test spaces, non-ASCII directory names and escaped/quoted paths on both OSes; preserve executable permissions, LF line endings for zsh/AppleScript, known trusted path rules and existing independent exit semantics.
4. **Remove Beta from active end-user path names and help.** Prefer removing now-obsolete Beta directories rather than leaving two full copies of the launcher. If a narrow compatibility forwarding shim for an existing Beta desktop shortcut is retained, it must be demonstrably safe and forward to the **same** single Web runtime, never restart a second instance; however **the supported/main advertised paths are the two non-Beta top-level Web launchers**, and the clean product tree should not rely on old Beta paths. Clearly explain the one-time shortcut/path update.
5. Keep Diagnostics out of `Legacy/`, under its currently supported `development/user-tools/diagnostics/{windows,macos}/` paths. They remain usable for both Web failures and Legacy startup troubleshooting. Do not move Diagnostics accidentally with the CLI pair.
6. **Legacy launchers still operate offline from the browser**: double-clicking the report launcher produces the original terminal report, Watch launches the actual CLI Watch; native terminal Ctrl+C, persistent/ordinary terminal behavior, exit codes and error/diagnostic paths remain correct. Legacy must neither start a Web server/tray nor depend on Web, GUI or an authenticated tab.

## B. Root Python entry and CLI compatibility

1. **Default user intent:** on supported Windows/macOS, **`python cost-guard.py` with no CLI-specific arguments should enter the existing managed Web launcher path**, making the named product's ordinary command agree with the OS launchers, without a second host/launch implementation. The existing **`cost-guard-web.py`** remains a narrow actual Web runtime entry for managed start and documented `--foreground` developer mode.
2. Provide **one explicit retained CLI Python entry**, suggested **`cost-guard-cli.py`**, which invokes the same current `src.bootstrap.main()`/RuntimeErrors boundary and supports **all existing report, date, session, `--watch`, `--token-mix`, help and version arguments** as before. The moved `Legacy` launchers must call this CLI path rather than calling a root script that now starts Web. Keep the shared Python analysis, Watch and presentation modules; do not rename, fork or delete them.
3. **Do not silently reinterpret old arguments.** `cost-guard.py --watch`, `--sessions`, a date range, a session ID or other legacy CLI syntax must **not** silently open Web and ignore the requested report. Choose a clear compatibility behavior: prefer forwarding well-understood explicit legacy flags to the same CLI entry during transition **or** fail quickly with an actionable **`use cost-guard-cli.py ... / windows/Legacy or macos/Legacy`** message and a nonzero exit code. Document the chosen policy and test it. Preserve actual old-flag semantics via the explicit CLI entry in all cases; avoid an accidental breaking change with no instructions.
4. **`--version`** and **`--help`** remain useful even when no GUI/host is available. They should report the same canonical **v81.0**, explain default Web, show supported launchers and explicit Legacy CLI syntax, and avoid hanging or starting a Web instance just to print help. Maintain existing predictable Python minimum-version errors and sanitized runtime fault handling; `--help` must not turn into terminal CLI help without explaining the new default.
5. Linux/headless and developer automation must not accidentally start an unmanaged browser or native GUI. Existing `cost-guard-web.py --foreground`, test/diagnostic direct-service calls and explicit CLI entry continue to work; choose/document the normal `cost-guard.py` behavior outside supported desktop platforms explicitly rather than silently attempting Windows/macOS native launch.
