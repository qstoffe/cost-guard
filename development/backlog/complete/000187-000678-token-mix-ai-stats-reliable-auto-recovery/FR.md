# FR 000678 — Web Token Mix and AI Stats: fix broken reports, automatic recovery and false zero values

**Owner-approved high-priority Ready bugfix, 2026-11-11.** Permanent identity **000678**; Ready priority **001085**, before currently Ready FR000675 (001090) and FR000677 (001100). **FR-only backlog publication**: add this file and advance `development/backlog/identity-state.json` highWatermark **677 → 678** in one direct-`main` documentation commit. Do not implement product changes, run product tests, alter version/release files or modify unrelated tasks now.

## Owner-reported regression and required behavior

Two previously functioning **Cost Guard Web** pages are now unusable or misleading; the owner suspects a regression in roughly the last several versions but has **not observed the local OpenCode source disconnecting**.

**Token Mix (`/#/token-mix`):**
- Opening the route repeatedly shows red **“Source/report unavailable. Check the local source and retry Refresh.”**
- **“Retry Token Mix”** starts progress, reaches approximately **43%**, then shows the same error again. Returning to the page repeats loading and failure.
- The page should automatically load its historical summary and both model/publisher tables, retain valid cached results and update itself quietly. **No Retry button or required manual Refresh.**

**AI Stats (`/#/ai-stats`):**
- Opening the route shows **“The robots are counting their adventures…”**, then apparently fails. **All ten stats display 0**, despite formerly nonzero historical data. Reentering repeats the load/failure.
- A **“Retry AI Stats”** button appears. Remove it. AI Stats must automatically obtain/reuse correct data and refresh dynamically, rather than require user interaction.
- All-zero output may be an **artificial failure fallback**, not loss of history/cache. Determine the real failure(s) before attributing them to the cache engine.

**Outcome:** restore reliable live-source-backed historical report acquisition, cached-result reuse and automatic recovery on both pages. Never present failed acquisition as an empty successful AI Stats period or claim source disconnection without source evidence. Fix real backend/cache/job issues rather than merely hiding UI symptoms.

## Verified code-level findings (not an observed live traceback)

1. `src/web/assets/ai-stats.js::View.update()` currently chooses `empty()` whenever there is no valid selected-period result and `state.failed || state.interrupted`. That creates ten synthetic zero metrics. **Confirmed UX defect:** a report error can masquerade as a valid all-zero history. Truly empty periods and FR000633's fun-first best-effort results are different; retain them.
2. `src/web/assets/app.js::show()` explicitly reveals **“Retry Token Mix”** / **“Retry AI Stats”** when `state.failed`. `failure()` collapses unrecognized internal errors into the generic **“Source/report unavailable...”** copy. `acquire()` uses `retry = !!state.failed && !background`, making a manual attempt special even when the underlying source remains healthy.
3. `src/web/dispatch.py::DataDispatcher._collect()` marks unsuccessful jobs **terminal when `error.retryable` is not true**; `lookup(retry=True)` clears this state whereas ordinary automatic demand may not. Determine whether misclassified report/cache/continuation errors or stale publications strand a previously healthy report until manual Retry.
4. The **~43%** Token Mix clue maps into the `history-cache` **30–45%** progress band in `src/web/assets/report-loading.js`. `src/reports/token_mix_cache.py::build_cached_token_mix()` verifies revisions and reads optional derived SQLite evidence during that stage. **This does not prove the actual exception or that the source/cache is gone**. Inspect job phase, server error code, cache hit/miss, checkpoint, and source revision before identifying the cause.
5. Token Mix involves `src/reports/token_mix_cache.py`, `src/reports/history_work.py`, `src/web/history_jobs.py`, shared `src/web/jobs.py` and `src/application/service.py`; AI Stats involves `src/reports/ai_stats.py::StatsAcquisition`, `src/web/stats_jobs.py` and resumable SQLite evidence. `TokenMixView.valid()` and `AIStatsView.valid()` can reject a published result shape independently of source availability.
6. Prior completed FR000596/FR000599 and FR000617/FR000624 establish **automatic first acquisition, valid snapshot retention, host-owned demand, cached reuse, bounded automatic retry and quiet freshness** (Token Mix normally ~5 minutes, AI Stats ~15 minutes). This FR restores that intended UX, without introducing another scheduler or restrictive gate. FR000633 allows playful estimates/zeros **from genuinely empty or qualified best-effort evidence**, not zeros manufactured due to a loading error.
7. Review recent changes including **v81.19–v81.24**, source/model identity and reference-price invalidation (v81.24 and earlier v81.6), SQLite cache lifecycle, work continuation and host dispatch. The suspected version range and cache-engine cause are **hypotheses**, not established root causes.
