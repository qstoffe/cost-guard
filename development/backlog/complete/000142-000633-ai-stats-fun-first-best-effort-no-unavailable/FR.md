# FR 000633 — AI Stats: fun-first overhaul, best-effort numbers everywhere, zero availability disclaimers

**Owner-approved Ready Feature Request, 2026-11-08.** Permanent ID **000633**, proposed Ready priority **000800** (ahead of existing Ready FR000629 at 000820). **Backlog publication only**: create this standalone FR and advance the permanent ID watermark. No application code, tests, version/release, active sessions, or unrelated backlog changes in this publication.

## Owner decision — intentionally change the product philosophy

**Cost Guard Web Beta → AI Stats is an entertainment / fun-stats page, NOT an audit, accounting, billing, completeness, or evidence-verification report.** The owner explicitly accepts approximations, rough guesses, even wildly inaccurate outcomes when historical evidence is messy. A funny number is substantially better here than an unavailable card. The present technical caveats and refusal to calculate have destroyed the intended experience.

**Absolute UI rule: the page gives its best-effort result and moves on. Period.**

- **All ten original cards must always produce an actual displayable result for a selected period**, irrespective of missing durations, token fields, pricing, incomplete/old/active sessions, incomplete source coverage, migration warnings, or other isolated source problems. Use actual recorded information where possible, a sensible deterministic approximation when necessary, and a harmless neutral numeric fallback when there is literally nothing usable.
- **No UI code path for any AI Stats metric may ever render** "Unavailable", "Partial", "Provisional", "No data", "N/A", "Unknown", "Observed", "≥", a question-mark uncertainty suffix, or a substitute euphemism for missing evidence. Remove the relevant status/fallback presentation *capability*, not just its CSS. A fully empty period should still have sensible zero-style numbers and playful copy. No empty metric cards.
- **No disclaimers, apologies, audit language, caveats, limitation messages, source diagnostics or technical explanations ANYWHERE in the AI Stats experience**, including values, subtitles, trait lines, status rows, interval/freshness summaries, per-card state badges, tooltips, help text, period-button help, accessible descriptions/live announcements, and the optional matched-comparison card. In particular ban phrases about executions with unknown start/end, incomplete source coverage, missing prices/tokens, observed subtotals, unverifiable winners, not being actual billing, provisional data, archive completeness, or snapshot intervals.
- **All ten trait lines must always be the original lighthearted/playful kind**, selected from the resulting number, never replaced by an evidence explanation. Session names/date details can remain where appropriate, but must not acquire technical warnings. Help is allowed only when it briefly and playfully explains what the metric *means*; no precision or provenance lesson.
- This is **deliberately not a request to add a caveat such as "Estimated", "Approximate", "For entertainment only", "Based on incomplete data", "Results may vary", or a hidden explanation tooltip**. The user has already made that trade-off. Do not reintroduce it in the name of transparency, conservative reasoning, accessibility, or defensive implementation.
- Maintain the existing playful card layout, emojis, sections **Overview** and **Fun Facts**, ten metric identities, five period selectors, useful actual session links, original humorous tone, unit selection, and optional eleventh matched-comparison fact where present. Improve fun wording if needed; do not replace the page with a different dashboard.

This FR is an **explicit owner override, for AI Stats ONLY**, of earlier requirements to preserve conservative unavailable/null/partial/provisional presentation. There is no requirement for displayed AI Stats values to be provably exact.

## Existing-code findings and root cause

1. **Calculation suppresses numbers.** src/analysis/ai_stats.py::_timing() sets a broad unknown flag on one missing duration; _time_metrics() suppresses full working time, Night Owl, streak and parallel results; _cost_metrics() suppresses rate/average/winners when prices or denominators are incomplete. Whole-period source_complete and missing timestamps amplify one faulty record into several empty cards.
2. **Even recovered data is shown apologetically.** Completed FR000619 (v80.199) recovered measured lower bounds/observed leaders, but intentionally left 4–5 unavailable cards and five "Partial" cards in its same-observation diagnostic. This was appropriate under its former acceptance criteria, **but is no longer the owner's desired policy**.
3. **Server display explicitly emits the unwanted content.** src/application/ai_stats.py::REASONS/explanation()/stat_tokens() produce "Unavailable"/"No data"/"Observed"/"≥"/"Partial"/"Provisional" and sentences such as "Some executions have unknown start or end times; full execution time cannot be verified." They also replace playful traits with serious prose whenever status != complete.
4. **Browser adds another layer of disclaimers.** src/web/assets/ai-stats.js::definitions contains ten long caution-heavy metric tooltips; View adds period-button archive caveats, concatenates dynamic card explanations, appends each card's evidence state, exposes report snapshot intervals, and calls ReportView.historyWarning(). It also shows "Retained scope lacks valid observation or interval evidence..." while waiting and has an overtechnical optional matched-fact tooltip.
5. **Readiness is still evidence-gated.** src/reports/ai_stats.py::StatsAcquisition.project() and src/web/stats_jobs.py use verified/excluded/omitted root coverage for publishing a scope; one unresolved root can block an otherwise interesting period. src/web/assets/ai-stats.js and src/web/assets/report-loading.js surface technical progress/stages/failure copy. Broad source-history proof is the wrong prerequisite for a fun page.
6. **Shared fallback risk.** src/web/assets/render.js::ReportView.display() can return "N/A" when a display token is missing. src/application/display.py and src/application/projection.py transport the metric fields; any new happy-path projection must also guarantee a usable display token in USD and Credits and must not accidentally fall into the shared N/A fallback.

**Previous FR compatibility:** FR000612 deliberately added accurate explanatory states; FR000619 deliberately preserved unknowns instead of computing unsupported ratios/winners. **This new owner instruction supersedes those constraints *inside AI Stats*; do not carry their "never guess" requirements forward to block this work.** FR000614's resumable acquisition and FR000617's shared dispatcher are performance infrastructure, not excuses to keep the conservative presentation. Other source, Watch, Sessions, Comparisons, Token Mix, and CLI semantics remain as they are.

## Required best-effort computation, not just concealment

1. **Actually compute ten usable values.** Refactor the AI Stats-specific analysis/projection so a missing datum never terminates a metric at None/unavailable. Prioritize (a) exact evidence, then (b) currently known observed contributions, then (c) deterministic, bounded heuristics inferred from remaining relevant activity, then (d) a neutral zero-style fallback. Never present an empty metric or a technical reason string. Do not solve this by replacing all unknowns with zero when substantial activity is already measurable.
2. **Time family:** union reliable intervals first. For incomplete or unknown-ended activity, use plausible bounded intervals derived from available request/prompt/compaction timestamps and execution activity; where even those are absent, use a documented internally consistent fallback heuristic. For running work, use the available observation cut-off. Produce AI Working Time, Longest Session, Busiest Day, Night Owl, Coding Streak and Peak Parallel Sessions from this best-effort timeline even if it is imperfect. Preserve period clipping, reasonable overlap deduplication, selected-local calendar dates and DST as far as feasible. Do not let one corrupt interval reset all the others.
3. **Cost family:** use known reference CCost first, supplement unpriced/missing-usage requests with bounded deterministic fallback valuation where sensible (for example, supported adjacent/last-known rate, a consistent generic cost assumption, or activity-proportional heuristic). Do not interpret one unpriced request as requiring all cost-derived numbers to disappear. Calculate Total AI Cost, Average Cost per Session, Most Expensive Session and AI Hourly Rate even if cost or time evidence was imperfect. Use a zero-style outcome for truly empty denominators instead of N/A or a warning. This is a *fun* number, not a new authoritative billing estimate.
4. **Winners, ratios and edge cases:** rank the best candidates actually available; when a candidate is missing, estimate from available activity if possible. For percentages and ratios, calculate from the best-effort numerator/denominator, with deterministic safe guards against divide-by-zero, NaN, infinity, absurd formatting, negative durations and invalid percentages. For a completely empty set use fun-friendly values such as 0/h, 0%, 0 days and 0 sessions, with a humorous neutral trait; never invent a session ID, link, title, date, or real-world event that did not exist. A card without a real record can simply omit its record-detail link while retaining a numeric primary value.
5. **Scoping and readiness:** publish a coherent best-effort selected-period snapshot from all currently available valid evidence without waiting for globally perfect historical coverage. One broken, stale, changing, unpriced or unavailable root must not stall the entire page. New/updated root slices should improve the figures automatically as they arrive; previously loaded fun results stay visible during warm refresh and period switching. Preserve sensible prioritization, resumable slices, cached reuse, bounded work and period isolation. Internal job progress/readiness must not be equated with whether the user is allowed to see numbers.
6. **Failure/empty behavior:** during a genuinely cold acquisition, a short, *nontechnical and ideally playful* loading state is fine; do not fill the cards with unavailable markers. Once any usable data exists, show and keep the ten results. On a stalled/failed refresh use the last usable fun snapshot; on an absolutely empty or never-acquired history use deterministic zero-style fun results rather than internal error prose. A simple nontechnical retry affordance may be retained for genuine host outages. Do not promise a finished scan that did not occur or start unbounded retries. Operational/security/authentication protections must still work, but must not inject technical report-error copy into the ten cards.
7. **Scoped semantics:** separate the deliberately relaxed AI Stats calculation/display from financial or historical reporting contracts elsewhere. Existing canonical telemetry/provenance, private source diagnostics, structured logs, cache integrity, security, source authorization, read-only collection and bounded resource handling may remain strict internally. Do not rewrite authoritative Watch/CLI/Token Mix/Comparisons/Sessions numbers or globally redefine what None, unavailable, source_complete, or CCost means. No new paid AI/model calls, background services or source mutations. This requirement is about making **this one fun page** enjoyable, not silently changing the rest of Cost Guard.
8. **Cache coherency:** invalidate/version any AI Stats-specific compact facts, derived projections, browser/host retained results and algorithm dependencies whose prior conservative null/status semantics could resurrect old "Unavailable"/reason strings. Preserve unaffected base evidence, efficient warmed history and revision behavior. Historical, cached and fresh results must agree on the new fun-first policy, without manual user cache deletion.

## Full presentation and copy overhaul

- Replace all ten definition/help texts with **short, amusing, human-language descriptions**, not forensic explanations. Examples of the desired *tone* only: "How much the silicon crew burns per hour", "Your token bonfire", "The longest robot marathon", "The calendar's boss level", "How nocturnal the robots got". Avoid a footnote explaining the imprecision.
- Restore one engaging trait for **every** card at every data status, including incomplete/ongoing/zero-value input. No diagnostic/measurement-specific subtitle, technical badges, unattractive filler, supplementary warning card or new legend.
- Remove AI Stats-only .ai-stat-state status output, explanatory data bindings, any stale generic state fallback and the technical .ai-stats-status snapshot/warnings/interval text. Drop their obsolete DOM and presentation surfaces where practical, instead of hiding with CSS. Do not leak a status via title, aria-label, screen reader, focus help, expandable detail or keyboard/touch tooltip.
- Make Today / 7 days / 30 days / This month / All time selectors and their tooltips succinct and friendly. The optional matched fact may remain conditional if there is no sensible candidate, but if rendered it must be fun and disclaimer-free. Keep any existing genuine Comparisons navigation/link.
- Use playful loading copy if acquisition is underway, not "Verifying shared history; unknown older roots may affect this period", root counts, source-coverage proofs or raw error codes. App-wide critical connection/security controls still function outside the AI Stats presentation; do not strip system safeguards to achieve cheerful wording.
- Avoid adding a replacement "About these estimates", help appendix, accuracy icon, superscript, parenthesized "(estimated)", "approximately", "lower bound", "probably", tilde, uncertainty markers, or any other hidden or visible statement of limitations. **Just show the fun result.**

## Acceptance criteria (non-negotiable)

1. **All ten cards are numerically populated:** for each of the five periods after an initial usable result, on both cold and warm paths, all ten original cards have a finite, correctly formatted primary value (money, duration, percentage or count). No None/null/NaN/Infinity becomes visible, and none of their display paths can emit Unavailable/Partial/Provisional/No data/N/A/Unknown/Observed/≥ or a technical placeholder.
2. **One bad record never spoils the party:** synthetic mixed histories with a single missing end, missing start, incomplete root, changing revision, unpriced model, missing token category, running invocation, migration/source warning and arbitrary old archived records continue to produce ten numbers. Compare healthy complete-input outputs against the existing formulas, then verify best-effort behavior on broken inputs. Partial results must actually use available activity rather than becoming ten indiscriminate zeros.
3. **Empty and extreme inputs:** no roots, only corrupt roots, no measurable time, no priced usage, zero denominators, source offline after prior success, all-time partial archive, active/compacted children, local midnight and DST. These cases still have playful number/trait outcomes, stable formatting and no fabricated real session link or browser crash.
4. **ZERO caveats across the complete rendered page experience:** inspect visible text, tooltips after hover/focus/touch, period-help text, accessibility names/descriptions, live regions, statuses and text restored from persisted cache. Test forbidden tokens and representative phrases, including "Some executions", "Historical source coverage", "not a verified overall winner", "missing reference-price evidence", "snapshot interval", and "The evidence is still in the vault". A CSS-hidden caveat or appended tooltip fails acceptance.
5. **Always playful:** every one of the ten cards shows an enjoyable trait regardless of previously partial/provisional/unavailable/no-data internal classification. Long cards still wrap cleanly without clipping, original emoji/headings are intact, all five selectors remain usable, real session links still navigate, and the optional eleventh matched card adds no technical caveat.
6. **Progress and refresh:** 30 days → Today → All time → 7 days → This month, repeated switches mid-acquisition, slow archive, source/root changes during scan, failed refresh, cached restart and Credits/USD change. Retained best-effort values remain visible and update coherently; no technical source/revision/coverage copy flashes and no fake progress completion, indefinite spinner, excessive archive scan or performance regression.
7. **Regression isolation:** Watch, Sessions, CLI and precision-oriented financial/history reports keep their existing accurate/qualified values, warnings and lifecycle/security behavior. AI Stats alone deliberately tolerates numeric approximations. No paid requests or source writes.
8. **Tests and docs:** update development/tests/test_ai_stats.py, test_ai_stats_recovery.py, test_ai_stats_resume.py, Python display/projection/cache tests, and rendered-browser integration probes such as probe_ai_stats.cjs, probe_ai_stats_states.cjs and AI Stats progress/slice probes as needed. Replace obsolete assertions *requiring* Unavailable/Partial/No-data in AI Stats. Verify actual browser interaction in light/dark and mobile widths. Rewrite the AI Stats section of docs/web-beta.md to describe its entertaining behavior, without injecting accuracy caveats into the page. Document heuristic rules and retained internal diagnostic behavior **only in developer documentation/tests**, not in the user-facing AI Stats.
