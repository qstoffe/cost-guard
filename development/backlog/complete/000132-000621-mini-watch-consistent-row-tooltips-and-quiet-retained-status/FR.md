# FR 000621 — Mini Watch: consistent Session/CCost row tooltips and quiet short-lived retained status

**Owner-approved Ready Feature Request, 2026-11-07.** Permanent identity **000621**; next Ready queue priority **000390** following FR000620 (000380). **Specification publication only**: no product code, tests, release, version, additional FR edits or product docs during this authoring operation.

## Owner request and desired experience

On the floating **Mini Watch** Document Picture-in-Picture window, active/running prompts and expanded **Earlier Sessions** are intentionally two different tables, but their targeted contextual help should feel the same.

- **Session (both tables):** hovering, keyboard-focusing or tapping the actual ellipsized session name should show **the entire real session name and the prompt number for the corresponding row**. The running table already does this; Earlier Sessions should behave identically, using its **latest actual representative historical prompt**. No new visual column, question-mark icon, row-wide popup or long redundant diagnostics.
- **CCost (Total) (both tables):** the historical table's cost value already shows the latest prompt's **Prompt #, Model, Effort, Duration, known Calls** and relevant subagent/mixed/pricing/outcome notes in its tooltip. Give the **running/recent cost value** this *same Mini-scoped prompt-detail help*, but for that row's **focal active/recent prompt**. Do **not** transplant full Web Watch's lengthy I/C/W/O cost breakdown, and **do not modify the existing two displayed amounts** (prompt CCost followed by full-session CCost).
- **Quiet retained/partial status:** brief status text such as **“Retained / partial data · not current”** currently appears next to Mini session titles for seconds during ordinary updates. The owner does **not** want these short-lived messages displayed. Review the same kind of **transient retained/partial/retrying copy on other live Web surfaces** (especially full Watch and Accounts), and keep routine short refresh/reconciliation silent when valid values are still retained. Sustained, material problems or genuine source/authorization failures still need truthful feedback; the owner suggested a roughly **one-minute** delay as an example of when a non-current warning might start adding value.

This is a **targeted UI/content consistency FR**, not a request to suppress all backend partial/unknown evidence, alter the live engine, replace the cost tooltip with Web Watch's detailed valuation breakdown, disable error messaging, or create new data acquisition.

## Verified implementation evidence and where the gaps originate

1. **Current row help is intentionally asymmetric.** In `src/web/assets/mini.js::View.sessionRow(historical)`:
   - for **running/recent** rows, `ContextHelp.value(title, () => row.promptHelp)` is attached to the Session text, **but not to the CCost value**;
   - for **Earlier Sessions**, `ContextHelp.value(cost, () => row.promptHelp)` is attached to the CCost value, **but not to the Session text**.
   This is exactly why only one target per table currently exposes useful help. Adding the missing two targets should be presentation-only over existing canonical data.
2. **The existing content is already prepared.** `View.drawPrompts()` creates `row.promptHelp = `${session}\nPrompt #${prompt.prompt_number} in this session`` for the focal prompt. `View.drawHistory()` already chooses `card.rows[0]` as the authoritative latest earlier-session representative and creates `row.promptHelp = this.promptDetails(item)` for that prompt. `promptDetails(item)` summarizes the source-backed model, effort, duration, calls, linked subagents, mixed models and relevant qualifiers. `drawCost()` already presents **`prompt CCost (whole-session CCost)`** in both tables. Split/normalize the two help payloads (e.g. distinct `row.sessionHelp` and `row.costHelp`) so each **Session** target gets the same concise full-title/ordinal contract and each **CCost** target gets the same Mini-specific detail contract, without giving the historical Session cell the whole cost-details essay.
3. **A temporary retained label is hard-wired to raw status, with no duration threshold.** `View.drawSession()` tests whether `card.session_summary?.state` or `card.state` is `partial` or `unavailable` and immediately writes **`Retained / partial data · not current`** into an extra `.mini-source-note` under the title. This happens even if values were intentionally retained for one short re-observation cycle. `Observations.update()` explicitly retains previous card/history figures during incomplete publications; state changes are not necessarily new observations.
4. **Other potentially noisy live messages exist independently.** `mini.js::drawDaily()` adds `Partial daily data`, `Daily source unavailable · retained values` and token/pricing warnings; `drawAccounts()` adds `Retained quota · not current` or `Partial quota data`; `src/web/assets/watch.js::Card.update()` writes `Partial / retained evidence`, `Source unavailable; retained contents are not current` and delayed/retry text, while `watch.js::daily()` and `src/web/assets/account-cards.js` have their own source status warnings. Do **not** globally delete these strings indiscriminately. Audit the **cause and actual duration** of short-lived status visibility across these live surfaces; preserve semantic source failure, user-actionable provider restrictions, and independently meaningful incomplete values.
5. **Already-established quiet-warning policies must be respected.** Completed FR000569 intended Mini's ordinary brief retries to stay silent, with a sustained **10-minute** overall no-progress `Updates unavailable` health notice via `Observations.delayed()`. Completed FR000586 addressed transient Full Watch notices, typically making brief attempts quiet and reserving a roughly **30-second** delay for some initial loading copy. The **new owner request specifically targets missing per-cell polish and renewed flashing retained/partial labels**; preserve the already working overall health owners and their appropriate thresholds rather than adding duplicate timers/warnings.
6. **The shared help controller is sufficient.** `ContextHelp.value` handles hover after about 600 ms, keyboard focus, touch and Escape. Mini has its own PiP document, existing keyed row maps, on-update `ContextHelp.refresh(this.root)` and normal session-name ellipsis. No separate tooltip engine, native `title` popup or network request is needed.

## Requirement A — symmetric, prompt-specific Mini tooltip targets

1. Both Mini tables keep their exact existing four visible columns and order:
   - running/recent: **Session | CCost (Total) | Duration | Ctx**;
   - expanded Earlier Sessions: **Activity | Session | CCost (Total) | Ctx**.
   The compact paired cost remains unchanged: **`this prompt's CCost (whole-session CCost)`**, using existing Credits/USD, independent partial/unknown/zero values and canonical pricing.
2. **Both Session cells:** attach the shared value tooltip to the **visible session-name text**, not unused whitespace. Display **full untruncated session title** (or canonical fallback when genuinely unnamed) and **Prompt #N in this session** sourced from the exact represented prompt. For Earlier Sessions, N is the latest **actual canonical historical representative** and is not inferred from total session prompt count, activity timestamp, a random row or today's latest prompt. When ordinal is unknown show `Prompt number unavailable`, not guessed `#1`. If names are long/ellipsis they remain accessible and selectable.
3. **Both cost cells:** attach a second independent `ContextHelp.value` to the existing `.mini-cost-value` text. Reuse the **same `promptDetails(item)` renderer** or a shared canonical helper for both running/recent and historical prompt rows. Running/recent uses each focal `card.rows[]` entry and preserves its prompt number, live duration, model, effort, known calls and relevant linked/partial/outcome flags. Earlier Sessions uses its **latest historic representative** with canonical finished duration. Do not borrow total-session information to fill a missing prompt field. Never expose raw prompt text or confidential source data in tooltips.
4. **Keep each tooltip useful and scoped.** The Session tooltip should be compact (full title + latest/represented Prompt #), and the CCost tooltip should be the existing Mini prompt-detail summary (model, effort, duration, calls and relevant conditions). Do not add detailed Web Watch per-request price-tier or Input/Cached input/Cache write/Output breakdown here; **FR000620** separately owns that full Watch presentation. The same prompt may have different temporal status in a running vs finished row; the facts must reflect that actual state, not force identical literal duration numbers.
5. Both tooltips must survive Live value corrections, running→terminal grace→Earlier Sessions, resumed sessions moving back to running, multiple concurrent prompts in one session, unit/theme switching, tooltip focus/selection, and Earlier expand/collapse. Do not replace focused nodes on every tick, reopen dismissed popup automatically, double-bind `ContextHelp`, or trigger any new history or pricing acquisition. Preserve value/accessibility and existing header, Activity, Ctx and Return-to-Watch help.

## Requirement B — suppress rapid retained/partial visual noise without hiding real evidence

6. **Do not immediately render `Retained / partial data · not current` below a session name** on a single `partial`/`unavailable` publication if the last coherent row remains useful and the same source/host is still recovering. The user particularly objects to the extra line that appears for seconds, changes Mini row height and then vanishes. Remove this redundant in-row caption during ordinary short refreshes; don't rename it to another flashing string, change the whole row color or show a temporary warning icon instead.
7. **Apply a consistent quiet-transient policy to analogous live UI text.** Audit Mini's row, CCost/daily/account status areas, Full Watch prompt-card/status/day summary and shared Watch/Accounts subscription cards. If a value remains supported by a previously verified observation while a *brief* ordinary attempt refreshes the same scope, **keep displaying that last valid value quietly**. No new `Retained`, `Partial`, `Retrying`, `Not current` or similar fleeting prose should be rendered and removed within seconds merely because a background refresh temporarily lacks fields. Avoid duplicating the same issue across mini header, row, quota and full Watch cards.
8. **Threshold and severity semantics:** treat **about 60 continuous seconds of no genuinely fresh, usable evidence for a particular impacted surface** as a *candidate* for one concise, non-flashing “Updates delayed · showing last values” notice, if existing more specific thresholds do not already own the user-visible health state. Do **not** force Mini's existing 10-minute aggregate unavailable health notice down to a minute merely to introduce another warning; retain that existing independent owner unless profiling establishes a product need to change it. In Full Watch respect its existing bounded initial-loading notice rules. Persistent source errors, host stop, expired auth/identity changes, provider restrictions and actually unpriced/unavailable **critical data** can be shown promptly where actionable; a blinking transient status must not mask these.
9. **Truthful retained/partial data:** the absence of a visually noisy caption does not mean cached values are current or fully priced. Preserve `partial`, `retained`, `unavailable`, canonical age/observed-at, `N/A`, `?`, source/availability and typed error flags internally and in accessible semantically meaningful values/help. If a **new** value is genuinely incomplete/unknown with no previously verified figure, show the correct `Loading…` or `N/A`, not a fake zero or a stale number treated as fresh. The current local-day boundary, real successful completion and terminal-grace removal must continue working. Avoid suppressing pricing incompleteness just because the user dislikes a transient retained *status sentence*.
10. **Source-aware, minimal timing/ownership:** existing Live/Observations clocks must not be advanced by repeat SSE snapshots, arbitrary wall-clock polls, cost-only unverified publications or a different lane's progress. Any threshold or stale copy decision must be based on the **relevant** source observation/identity and reset only after actual successful coverage. Avoid new browser polling, background history scans, native PiP resizing, layout expansion, unbounded timers or new persistent cache. If a genuine outage is still unresolved beyond the appropriate existing threshold, a restrained actionable notice may appear; do not hide it permanently.
11. **Other pages:** the owner explicitly noticed similar short-lived “retained/partial” copy elsewhere. Inventory *live* Watch/Accounts and any other current pages showing the same symptom, remedy only **redundant transient revalidation prose** via shared presentation policy where feasible. Do **not** indiscriminately remove AI Stats/Token Mix/Comparisons' **completed report** evidence statuses: final `Partial`/`Unavailable` or >60-minute stale/withheld reports describe real limitations and are not the same as a 3-second Watch retry. Preserve genuine offline/source/security warnings at the normal host level. Coordinate with Ready FR000617's future dispatcher/freshness semantics without implementing that architecture here.

## Acceptance criteria and focused verification at implementation

1. **Tooltip matrix:** With synthetic running and three Earlier rows, the **Session text on every row** is a hover/focus/tap target with exact full untruncated session name and that row's correct `Prompt #`/unknown fallback. The **CCost (Total) value on every row** is a *separate* help target showing actual prompt model/effort, duration and known calls plus conditional linked/mixed/partial/outcome details. Earlier and running values share the same renderer while keeping their independent represented prompts. Nothing is attached to entire rows, unused padding, or a duplicate native title.
2. **Existing cost/display unchanged:** Assert prompts with different costs, full-session totals, two simultaneous prompts in one root, earlier latest-prompt cost different from session total, unknown/partial/zero/Loading, Credits/USD and running→Earlier→running transitions. The paired cost numeric values, relevant scopes, table columns and layout must remain identical to pre-FR behavior; this FR only adds targeted contextual help and reduces status noise.
3. **Tooltip behavior:** Real browser Document PiP in Classic and Web light/dark; pointer hover >600ms and rapid exit, keyboard Tab/focus, touch, Escape, tooltip transfer, focus/selection retaining keyed DOM after Live corrections, no auto-reopen, no horizontal/vertical clipping at normal/narrow widths and 100/150% zoom. Keep native Picture-in-Picture controls, collapse/height-only resize and no passive width expansion.
4. **Short-lived retained states:** Begin with healthy values. Inject a 1–5s, 10s and 30s `partial`/`retrying`/`unavailable` card/session-summary refresh while retaining authoritative prior values; **Mini's session extra-line remains absent** and analogous Full Watch/Accounts areas show no fleeting “Retained/Partial/Not current” captions solely from the retry. All existing true costs, `?` markers and known rows remain. Verify no row height jiggle, rerender-induced focus loss, tooltip content stale to another prompt or flash on recovery.
5. **Distinct real failures:** Inject sustained no-progress over ~60s and over Mini's existing 10-minute aggregate threshold, an actual partial-priced row, stale quota, source unavailable/authorization expiration, identity change, host stop, day rollover, confirmed empty history and genuine failure of a newly requested prompt without a previous valid result. The owner should see **one truthful, proportionate status where appropriate**; per-surface statuses and aggregate health do not double-announce. Unknown/billed/pricing data are not reclassified as complete. Repeated nonfresh publications never reset the true lateness clock. Actual error cases remain accessible/visible.
6. **Cross-surface audit:** Visit Mini, Full Watch (active and Earlier), Accounts and cached-report routes with representative normal refresh and real final partial/error conditions. Verify that **transient** retained/retry copy is consistently quiet on live surfaces but **final** evidence limitations, 60+minute report staleness and disconnected-host warnings still display correctly. No accidental changes to source acquisition/valuation, quota percentages, subscription cards, AI Stats result states or FR000617 progress.
7. **Focused test files:** update `development/tests/test_mini_watch.py`, `development/tests/integration/mini_watch.cjs`, `development/tests/integration/probe_mini_session_alignment.cjs`, the shared Mini help probe, and focused `web_watch_summary.cjs`/`probe_web_help.cjs`/Accounts status tests as relevant. Test DOM and actual pointer/focus tooltip geometry rather than relying on CSS-text assertions. Update `docs/web-mini-watch.md` and Web help guidance **during implementation**, not authoring; correct any old written claim that only historical CCost / running Session have help. No new global product test/release gate.
