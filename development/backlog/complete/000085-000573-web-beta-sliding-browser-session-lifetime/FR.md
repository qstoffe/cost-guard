# FR 000573 — Keep CostGuard Web Beta browser sessions authorized during prolonged use

## Owner request and intended behavior

**Owner-approved executable feature request, 2026-11-04.** Permanent identity **000573**, Ready priority **000130**, after currently Ready FR000570–FR000572.

The owner had **CostGuard Web Beta** open and in use for at least four–five hours, possibly longer, when its browser suddenly displayed an **authorization expired/not connected** error and lost Live updates. Without restarting the already-running CostGuard server, the owner used Windows tray **Copy Cost Guard link**, pasted the fresh authorized link into a new page, and immediately regained access to that same server. The exact elapsed time from initial authorization was not measured; do not claim the failure occurred at exactly four–five hours.

**Desired UX:** a still-running and authenticated Web Beta should **not unexpectedly sign out after a fixed number of hours while the browser is open and Live is working**. Use a **rolling seven-day inactivity window** for ordinary authorized browser sessions. Continued authenticated Web/Watch/Live use should renew authorization transparently, including use where the owner leaves an active Watch tab open for hours or days without clicking. A previously authorized normal browser/profile reopened within seven days of its last valid activity should work on the **same still-running host**. After seven full days without valid activity, reauthorization via a fresh trusted OS launcher/tray link is acceptable.

This is a **browser session lifetime** change, not a request to make the **Copy Cost Guard link** itself last a week. The 120-second, one-use bootstrap handoff must remain short-lived.

## Verified current cause and boundaries (main, 2026-11-04)

- `src/web/security.py::BrowserSession.exchange` sets `self._until = now + 8 * 60 * 60` only when a bootstrap is redeemed. `authenticated()` merely checks `time.monotonic() < self._until`: normal valid requests and long-running EventSource traffic **never slide the server deadline**.
- `src/web/http.py::reply` sets `HttpOnly; SameSite=Strict; Path=/; Max-Age=28800` on bootstrap exchange; ordinary authenticated API replies do **not renew the browser cookie**. The browser's independent eight-hour cookie expiry must be fixed along with the server-side deadline; changing just one is insufficient.
- Protected `/api/*` routes return `401 authentication_required` when this expires; `stream_events()` sends `authorization_required` and closes the SSE stream. `src/web/assets/app.js` and `live.js` deliberately treat that as terminal and direct the user to a fresh launcher link. This explains the reported experience without a host restart.
- `src/web/assets/live.js::probe` already performs lightweight authenticated `/api/live` synchronization roughly every **10 seconds**, and triggers resync on wake/visibility changes. Reuse the existing authenticated traffic to maintain liveness rather than adding expensive report scans or unnecessary per-tab polling.
- `BrowserSession` currently shares one instance-local session/CSRF token across handoffs to multiple authorized browsers, with checkout-scoped cookie naming. New bootstrap redemption within the existing session does not itself refresh the cookie already stored by earlier browsers. Preserve correct multi-browser operation and existing FR000568 browser-link behavior.
- `src/web/host.py::WebHost.browser_url` issues the trusted one-use `#bootstrap` handoff. Existing Host/Origin, CSRF, loopback-only and private OS control restrictions from FR000300/FR000568 remain non-negotiable. No evidence currently points to a connectivity problem or server crash as the primary cause.

## Required change

1. **Sliding seven-day session lifetime.** Replace the fixed eight-hour absolute authorization expiry with a rolling **seven days since the last successful authenticated activity** for the current running host. Authorized API traffic, including the ordinary Live/Watch polling path, should keep that browser's effective authorization valid. Do not require user clicks, navigation, manual Refresh, tray Copy or browser reload during continuous healthy operation. No arbitrary eight-hour/day cutoff should disconnect an actively used tab.
2. **Refresh both sides of the lifetime.** Renew/extend the in-memory server-side validity and the browser's `HttpOnly; SameSite=Strict; Path=/` cookie lifetime together. Reissue `Set-Cookie` on an appropriate authenticated response **before** the client cookie can expire (e.g., a throttled/coalesced renewal on existing `/api/live` responses); do not send it on each 10-second poll without need. Account for a long-lived SSE response **not being able to renew headers after the stream starts**. If the existing sync cadence needs adjustment for suspended/backgrounded browser tabs, keep that change minimal and safe.
3. **Seamless ordinary reuse.** A normal browser with a valid cookie must survive navigation, reload, tab reuse, browser sleep/wake, ordinary background throttling and a return within the seven-day idle window while the **same host** is still running. A newly opened browser/profile still needs a trusted one-time handoff. A genuine idle expiry should reject stale cookies and display the existing clear recovery guidance; do not misreport an identity change/source outage as mere inactivity.
4. **No cross-browser invalidation or unstable CSRF.** Two or more authorized browsers/tabs should remain functional independently through renewal, including one browser's renewal, a second browser's bootstrap redemption, simultaneous requests, Live/SSE and settings POSTs. Do not unnecessarily rotate an active bearer session or CSRF token during routine renewal; retain existing expiration/revocation behavior for truly expired or replaced instances. Keep multiple checkouts isolated.
5. **Preserve the short-lived bootstrap and trust boundary.** Keep native Open/Copy links **single-use, 120 seconds, instance-bound** and erased from browser history; no permanent shareable/bookmarkable authorization URL. Continue to reject anonymous, foreign Host/Origin, wrong-CSRF, expired/replayed bootstrap, cross-checkout and old-host requests. Do not persist bearer secrets in disk, browser JS-accessible storage, URLs, logs or diagnostics, or enable broad CORS/LAN access. Host restart, deliberate Exit/source shutdown and browser-private-mode clearing remain valid reasons to require a fresh link.
6. **Low overhead and truthful presentation.** Prefer the existing session/HTTP infrastructure and lightweight ten-second Live status path over a new login service, heartbeat flood or expensive report source access. No extra background process, port, dependency, authentication UI or report calculation changes. Keep `AUTHENTICATION EXPIRED` terminal handling for **real** expiry, while ensuring routine refresh never trips it spuriously. Update `docs/web-beta.md` to document the distinction between 120-second handoff and rolling seven-day authorized session.

## Acceptance and verification

- **Reproduce old boundary:** controlled clock/browser-cookie tests show the present eight-hour absolute session and cookie cutoff. After the fix, an open authenticated Watch tab remains connected **past 8 hours and across multiple days** with continuing normal Live sync; `/api/*`, SSE and Settings writes still work with valid CSRF, and no fresh tray URL is needed.
- **Seven-day idle policy:** at six days plus after last valid activity, a still-running same-host browser can resume/reload and extend its session. At seven days with **no** successful authenticated activity, an old cookie is rejected and only a fresh trusted 120-second handoff reauthorizes. Browser cookie expiration and server expiry agree; renewal works across repeated windows, not only the first week.
- **Actual renewal, not just long initial TTL:** tests prove that authenticated polling refreshes the browser cookie before expiration, honors `HttpOnly`/`SameSite=Strict`/path and does not leak token values. Assert renewal is throttled and unauthenticated/failed requests never extend sessions. SSE stays healthy throughout; sleep/wake and temporarily suspended polling recover within the valid window.
- **Multiple clients:** simulate Chrome + Edge and multiple tabs through successive renewals and handoffs; renewing one does not disconnect another active authorized browser or break CSRF/Live. Old-instance cookies remain invalid after host restart; one-use/replay/concurrent-bootstrap restrictions remain intact. Separate checkouts cannot authorize each other.
- **Security and regression:** extend deterministic clock-driven `development/tests/test_web_runtime.py`, `test_web_browser_links.py` and relevant Live/HTTP/SSE browser/integration tests (`development/tests/integration/web_connection.cjs`, `serve_web_connection.py`, or their current equivalents). Verify 401/403 boundaries, Host/Origin/CSRF and wrong-instance behavior, and confirm no additional heavyweight report polling or misleading live status. Real long-running/browser verification should be recorded honestly rather than inferred from a short simulated test.
