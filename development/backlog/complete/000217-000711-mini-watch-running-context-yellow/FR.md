# FR 000711 — Mini Watch: keep Ctx yellow on running prompt rows

**Owner-approved Ready to Develop — 2026-11-14.** Permanent identity **000711**; Ready queue priority **000019**, following FR000710 (000018). **FR authoring only:** publish this standalone request and advance the permanent-ID high-water mark in one documentation-only commit. Do not implement product code, run paid prompts, change releases/versions, migrate backlog repositories, or alter unrelated FR statuses while authoring.

## Owner-observed regression and desired behavior

In **Cost Guard Web → Mini Watch** (the web Document Picture-in-Picture window), the **Ctx** value on an actively **Running** prompt's row now appears in the ordinary text color (white in the affected theme), while the other row values are yellow. A Ctx price-threshold warning may instead make that value red. This breaks the owner's intended visual convention: **every displayed cell value in a verified Running row must have the same existing running-yellow text color, regardless of the Ctx value or warning state**.

The owner suspects this changed when normal-versus-red Ctx threshold coloring was introduced. Threshold-specific **ordinary/red Ctx coloring is for non-running / Earlier prompt rows, not for Running rows**. This is a visual precedence correction, not a request to remove price warnings or change context calculations.

## Required presentation policy

1. **Verified Running row takes color precedence.** When a Mini row represents a genuinely running prompt and receives its existing `mini-running` status, the visible text/value content of **all five cells — Activity, Session, CCost, Total and Ctx — uses the same `--watch-running` yellow**. Ctx cannot become ordinary white/neutral, red, orange or another foreground solely because its own context/warning class sets a color. Apply this consistently to a known numeric Ctx, unknown/pending Ctx and relevant source-valid threshold states, without recoloring the header or other rows.
2. **Threshold styling remains for non-running / Earlier prompts.** When the prompt is **not** verified Running, preserve the established Ctx policy: ordinary theme-appropriate text in the normal/non-exceeded case; **red Ctx text only when the existing canonical exceeded-price-threshold eligibility is satisfied**. Do not make every earlier/finished row red, and do not change its other cells or established completion/error/historical styling as collateral. Do not interpret approaching or unverified guidance as a proven exceeded threshold.
3. **Keep warning meaning and help.** Preserve the underlying context source, exact threshold/severity/guidance conditions, numerical Ctx text, accessibility semantics, and existing Ctx hover/focus/touch help when the canonical exceeded warning exists. A Running Ctx can be visually yellow while retaining its truthful warning help. Do not suppress, falsify or reclassify a warning to achieve the yellow text.
4. **Correct color after transitions and refresh.** A session may move from Running to recently finished and then Earlier/history, or start another prompt. After each real lifecycle transition or Mini refresh, recompute the *applicable display color* from the current status: no stale yellow on an Earlier row, and no inherited red/neutral override on a new verified Running row. Execution-unverified is not silently promoted to verified Running merely to paint it yellow.
5. **Mini-only visual scope.** Limit the change to Mini Watch's prompt table in the web PiP window, reusing the existing theme colors. Keep Full Watch, Sessions, quotas, CCost accounting, thresholds, row selection, source polling, and context calculations unchanged. Preserve Classic/Web themes, light/dark schemes and legible keyboard/focus affordances.

## Verified static repository leads (not a runtime reproduction)

- `src/web/assets/mini.js::View.drawSessions()` assigns the `mini-running` class to a verified running prompt's table row and `rowHelp()` also assigns a separate `mini-context` class to the Ctx `td`, optionally adding `mini-context-exceeded` when source-qualified exceeded guidance exists. This is re-applied on updates.
- `src/web/assets/mini.css` already defines `.mini-running { color: var(--watch-running); }`, but also defines `.mini-context { color: var(--ink); }` and `.mini-context-exceeded { color: var(--error); }`. The directly assigned cell foreground overrides the color inherited from the Running row. This is a strong source-level explanation for the reported white/red Ctx; verify computed colors in the actual rendered browser before claiming a browser-observed root cause.
- Fix the **row-status-versus-Ctx color precedence**, for example with appropriately scoped and ordered selectors or equivalent presentation semantics, rather than changing the global `--ink`, `--error`, `--watch-running` roles or deleting the exceeded warning state.

## Acceptance and focused regression checks

1. **Running color matrix.** In a real browser Mini Document PiP render, a verified Running prompt shows **all five visible cell values in the same computed running-yellow foreground**, including Ctx with (a) normal/current value, (b) approaching guidance, (c) eligible exceeded guidance, and (d) temporarily unknown/pending value. Inspect the actual `td`/value computed styles, not only `tr.className`.
2. **Earlier color matrix.** A historical/Earlier prompt shows ordinary Ctx color without an eligible exceeded warning, and red Ctx only for eligible canonical exceeded guidance. Other row cell colors and any recent-finish/error semantics remain unchanged. A stale/unsupported warning does not falsely generate red text.
3. **No semantic regression.** For an eligible exceeded warning, both Running and Earlier Ctx continue to expose the same supported help content, keyboard/touch access and source severity; only Running foreground takes priority. Ctx numbers, source status, session costs, time labels and row identity remain identical.
4. **Lifecycle and themes.** Exercise Running → finished → Earlier and a subsequent new Running prompt through repeated publications, verifying no stale foreground. Cover Classic/Web themes and light/dark scheme with actual Mini PiP browser assertions, alongside focused static/fixture tests. If a read-only live running row is naturally available, record observed results; do not start paid model requests or claim live proof from a synthetic fixture.

**Deliverable:** Mini Watch's active Running rows are uniformly yellow across all cell values, while ordinary/red threshold-specific Ctx styling remains confined to non-running rows.
