# FR 000360 — Complete live session detail with stable long-history navigation

## Outcome and dependencies

After FR000200 and FR000350, make the detailed session report available in persistent Web live mode, retaining all available session prompts instead of using the compact global Watch table or its row cap. Reuse FR000340's session page and the same report metric definitions. Follow FR000290/PLAN.md; existing CLI session Watch is not redesigned here.

## Required behavior

- A session page can switch explicitly between Snapshot and Live. Default a normal historical/session-report link to Snapshot; a link from the Live dashboard may explicitly request Live. Mode and observation time are visible. Snapshot freezes the whole result, including duration; Refresh requests a new snapshot. Entering Live obtains current authoritative state, not just events received after the old snapshot. Leaving Live freezes a consistent result without stopping the shared server engine.
- Live starts with the complete available session/root-tree report, not just prompts observed since the server started. New prompts are appended in canonical chronology; all running/changed rows, compactions, model boundaries, totals and warnings update as needed. No automatic end on idle, prompt completion or abort: the view keeps waiting for future prompts until the user leaves/stops Live. Several running prompts and delayed child evidence are supported; do not assume only the last row can change.
- Preserve the eight detailed report columns and FR000200's provisional observed running metrics, honest missing/partial data and execution-duration semantics. Never substitute Watch-only duration/context fields merely because live acquisition is reused. Numerical results must match a snapshot report from the same normalized evidence/catalog/time, except for explicitly labeled live observation/status metadata. Keep token percentages, input/extra CCost, cache distinctions and child contribution in shared Python owners.
- No product-imposed logical prompt cap, TTL eviction or global `watchDashboardMaxRows` cap for this view. All source-available rows remain navigable. Pagination, virtualized DOM, bounded transport and reclaimable fetched-page caches are allowed; they may limit memory/visible elements, not access to history. Give rows stable canonical identities rather than array-position keys. Totals cover the full selected report, not the current viewport or loaded page, and incomplete loading must be visible.
- Use revision-aware paging and updates so new prompts do not skip/duplicate older pages. Keep already observed rows across temporary source gaps or compaction projection omissions with honest last-observed provenance, not false completion timestamps or duplicated valuation. Distinguish an authoritative deletion/archive from a transient omission. No durable history ledger or reconstruction of data deleted before observation is required. The UI must explain source history loss rather than silently pretending that a page limit caused it.
- When at the bottom, optional default follow-latest keeps new activity visible. Scrolling up disables follow and preserves a stable row anchor/pixel offset while acquisition continues. Show a compact new-activity indicator and a clear Jump to latest action. Do not steal focus, selection or scroll position on updates, reconnect, warning/model-row changes or viewport resize. Virtualized rows must support accessible navigation and useful copy/text selection; document any genuine limitation.
- A missing or archived session retains a readable last-known result/status where available and offers return navigation. Do not turn a source outage into an empty successful session or kill the whole server. Global Live retention and other views remain unaffected.

## Acceptance

Use synthetic 100, 1,000 and 10,000-prompt sessions as scale probes, not limits or universal timing guarantees. Verify access to first/middle/latest rows while new prompts arrive, bounded DOM/event payloads, stable scrolling/focus and correct whole-session totals. Count work to ensure a timer-only display tick does not reload/revalue the entire history; unchanged source revisions reuse existing analysis and expensive work is scheduled fairly.

Cover concurrent running prompts, abort/error, background-only work, compaction, late child totals, same-timestamp events, partial prices, missing telemetry, deletion/source reconnect, snapshot-to-live transitions and a session that stays idle then resumes. Test multi-tab subscriptions without extra account polling, replay gaps and stale page cursors. Compare shared numerical semantics with CLI/session fixtures. No new permanent validation gate, custom terminal UI, browser billing engine or persistent ledger is authorized.
