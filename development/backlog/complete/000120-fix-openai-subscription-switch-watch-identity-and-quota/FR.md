# FR 0120 — Fix OpenAI subscription upgrade: duplicate Watch rows and rejected quota

## Observed problem and evidence
User upgraded an OpenAI ChatGPT subscription from a roughly USD 20/month Plus offering to a USD 100/month higher tier, removed the prior OpenCode account and added the newly authenticated account. Two visible symptoms were captured in **Cost Guard v80.65 on 2026-10-23**:

1. **During account replacement without process restart** (Watch started at 16:17:03 local time), Cost Guard displayed TWO separate OpenAI account lines (`OpenAI · account 1`, `OpenAI · account 2`), both `Quota unavailable`, one saying `Sign-in rejected; reconnect OpenAI in OpenCode`. This looks like the old account surviving alongside the replacement and may be an account-inventory/identity lifecycle bug. Other providers' entries continued normally.
2. **After restarting Watch** (started at 16:27:22 local time), the duplicate disappeared, but the single OpenAI row still displayed `Quota unavailable · Sign-in rejected; reconnect OpenAI in OpenCode`; the upgraded subscription/quota was not represented.

A user-supplied privacy-filtered Diagnostics ZIP from the same day reports: version v80.65, V2 healthy, full validation and package tests PASS; `report.accounts_quotas.accounts` contains one OpenAI account with `availability: unavailable`, `plan: null`, `quota_shape.http_status: 401`, `parser_reason: auth_failure`; quota-observation histories show zero successful OpenAI quota observations. Copilot and Claude account quota acquisition succeeded. The source `src/accounts/openai_subscription.py` uses the fixed `chatgpt.com/backend-api/wham/usage` endpoint and maps HTTP 401/403 to sign-in rejection; `src/accounts/acquisition.py` manages incremental account replacements. **This evidence establishes the rejected request, not whether the USD 100 tier is supported by the backend or whether the new credentials were actually valid.** The user's source screenshots and original archive are intentionally **not committed** to this public repository: images show session activity and the archive contains machine metadata. The sanitized facts in this FR are the durable test basis. This request must remain independently implementable without the author's chat.

## Required behavior
- Correctly model authenticating, removing, replacing, re-adding and upgrading one OpenAI account in both Watch (while running) and one-shot report. A superseded/revoked old account must not persist as a second visible subscription after an authoritative credential inventory change; legitimately distinct simultaneously configured OpenAI accounts must **still** appear separately.
- Pin a request to the credential generation used for that request, discard stale in-flight old-generation responses, and de-duplicate multiple credential aliases (e.g. V2 and legacy/integration aliases) only when they refer to the same true active identity. Prefer the canonical authorized OpenCode V2 active account without resurrecting old authentication from a legacy fallback after a definite V2 record exists. Be robust to temporary auth-storage updates and Watch refreshes.
- Investigate why the new account receives HTTP 401: verify selected OAuth token/account ID/header, actual canonical active identity, expiry and the documented quota endpoint's applicability. Separate a genuinely invalid/expired/rejected token or inaccessible quota endpoint from software selecting an obsolete/wrong account. Never fabricate a working quota, guess a paid tier or report a false success if upstream rejects the request. Maintain truthful, actionable, nonsecret error status, potentially recommending the user renew sign-in in OpenCode when that is truly necessary. Cost Guard is strictly **read-only** to OpenCode auth and persistence; never repair/refresh tokens, extract secret credentials into diagnostics or sign into external services on the user's behalf.
- When upstream returns an authoritative successful payload for the upgraded tier, show exactly the real returned plan/quota windows/usage and correct label, with available state; handle new tier names/unknown API shapes without losing valid quota or forcing an invented `Plus`/`Pro` label. Avoid assuming subscription dollar amount is a protocol contract.
- Keep display/account identity and source change logic consistent between Watch, one-shot reports and diagnostics. Removed accounts and failed retrievals must not retain stale quota values. Preserve Copilot/Claude and other provider behavior, Watch geometry, source read-only guarantees and all unrelated CCost/timing displays.

## Tests and evidence
Add focused deterministic tests using synthetic old→new OAuth identity and account identifiers, including:
- old plus → removal/addition → replacement in one running Watch session; intermediate in-flight old request; valid one-new-account state without restart;
- restart after upgrade; no duplicate from stale legacy and V2 identity records, and true two-account case still displays two;
- wrong/stale account ID or token → HTTP 401, correct/current token → HTTP 200; accurate and safe distinction with no unauthorized retries;
- 200 payload advertising a changed/novel subscription plan and two quota windows; truthful UI when plan cannot be identified;
- transient expired/rejected token, provider/backend 403, network failure and parser failure with no fake success; quota recovery once valid credentials are externally refreshed;
- no secrets in diagnostics, URL/headers or logged errors; no writing to OpenCode auth/database.

Use existing `development/tests/` and safe fake HTTPS responses/temporary synthetic V2 SQLite + auth fixtures. No tests requiring real user credentials, actual OpenAI subscription, proprietary session databases or paid network probes. If this FR is executed after folder migration, move its `FR.md` and attach ONLY sanitized, minimized text evidence relevant to regression; do not commit the original diagnostics archive or screenshots without a deliberate privacy review.

## Acceptance criteria
1. After a real account switch, Watch and report show one current OpenAI subscription for one current identity, without phantom old rows; deliberate separate accounts remain distinct.
2. Upgraded subscription quota is rendered when OpenAI supplies authoritative successful data; otherwise exactly one clear, truthful unavailable state with cause, not a duplicate or fabricated plan.
3. The known 401 failure is analyzed and either resolved for valid current auth or explicitly attributed to verified external sign-in/backend rejection; mere error-message relabeling is insufficient.
4. Focused account acquisition/provider and Watch recovery regressions, Quick/Full/validator as applicable, and root VERSION_HISTORY/README/src.version release metadata pass current repository rules; no unintended provider changes.
