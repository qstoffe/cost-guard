# Toolkit-owned portable development contract

**Authority for generic repository development procedures.** This repository consumes the active, compatible **installed** [OpenCode Toolkit shared repository contract](https://github.com/qstoffe/opencode-toolkit/blob/main/skills/shared-repository-contract/SKILL.md), especially its [FR authoring and publication reference](https://github.com/qstoffe/opencode-toolkit/blob/main/skills/shared-repository-contract/references/fr-authoring.md), together with the installed /repo-backlog and shared development/maintenance contracts. These Toolkit contracts supersede conflicting generic procedure text remaining in this repository (including older AGENTS, FR_GUIDE, MAINTAINER and pending migration FRs). A fresh GitHub-only author should read the linked published sources; an OpenCode session uses the **verified installed** skills, not downloaded executable code.

## Immediate authoring boundary (approved 2026-10-24)
- Brainstorming/drafts perform no Git writes. A user-approved **FR-only specification creation/edit/correction/reprioritization** for an unselected pending FR commits directly to the verified actual default branch (`main`) after collision/ownership/privacy/protection checks. **No authoring PR, release proposal, product version/date/history/README change, package/build, or releasetests.** Verify exact intended FR content on `main`. GitHub protection must not be bypassed; use its minimum required safe path if direct publication is restricted. This is the same rule as Toolkit, not a CostGuard variant.
- An FR-only document may remain in legacy flat format until an authorized migration. New bundle `NNNN-slug/FR.md` with optional sanitized relative `attachments/` uses Toolkit's canonical format. Numeric priority is **not** a product version; exact allocation, future width, retention and unsafe-attachment handling are governed by the applicable Toolkit contract, not frozen local patterns.
- Actual implementation, a selected FR's todo→complete delivery, or mixed source/test/skill/config changes follow the Toolkit-controlled protected implementation workflow, with appropriately qualified PR/verification and Cost Guard's product-specific functional release adapter. Nonfunctional updates do **not** bump product version; shipped Cost Guard functionality **does**, with correct version/date/README/history. Never interpret direct-main FR authoring as permission to ship code without review.
- Preserve selected/paused /repo-backlog work, another author's branch, scratch and state, protected tests, privacy, source-read-only boundaries and the existing ordinary checkout.

## Contract sync rollout
The planned [Toolkit FR0191](https://github.com/qstoffe/opencode-toolkit/blob/main/development/backlog/todo/0191-portable-repository-contract-sync/FR.md) will add **change-driven** Contract Sync priority before normal consumer FRs on the next explicit /repo-backlog invocation *when installed and compatible*. Cost Guard's first pending [FR0090](backlog/todo/0090-bootstrap-toolkit-contract-sync/FR.md) bootstraps this repository then; **neither FR specification is the deployed scheduler or a forged applied-revision receipt**. Missing required installed capabilities must stop truthfully, not emulate an automatic migration. No background/updater/automatic Desktop restart is authorized.

## Non-inherited product facts
Cost Guard uniquely owns Python 3.11+/stdlib-first, thin entrypoint, read-only OpenCode persistence and credentials, account/Watch/analysis semantics, architecture, test membership/coverage, file budgets, structure policy, source distribution/privacy and functional release metadata. Their authoritative local sources remain `development/ARCHITECTURE.md`, `development/CODE_MAP.md`, `development/MAINTAINER.md` (product-only facts until FR0090 migrates it), `development/tests/`, `development/tools/`, `src/version.py`, the root README and `VERSION_HISTORY.md`. A generic Toolkit update cannot silently erase, weaken or reinterpret these; material conflicts require diagnosed reconciliation.

**Until Contract Sync is implemented, only the explicitly approved rules above are effective.** Repository development is not automatically migrated merely by referring to newer Toolkit text.
